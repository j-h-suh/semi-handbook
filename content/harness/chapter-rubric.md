# 챕터 품질 기준 (rubric)

> 기준 챕터 `01_2_다섯_가지_공통_부품.md`를 역산해 뽑은, **매 챕터가 통과해야 할 합격선**.
> 상위 스타일은 `/CLAUDE.md`, 세부 표기는 `docs/handbook-conventions.md`. 이 문서는 그 위에 얹는 체크리스트다.
> **A(객관 가드)**는 `grep`·카운트로 기계 검증, **B(질적 기준)**는 적대적 비평으로 소진.

## A. 객관 가드 — 기계 검증 가능 (`/goal` 종료조건으로 직결)

1. **구조 4요소** — `## 이 챕터에서 배우는 것`(3~5개) · 본문 H2 ≥2 · `## 핵심 정리`(3~5개, 굵은 한 줄 + 부연) · 끝에 `*다음 챕터: …*`
2. **직교** — Claude Code 내부 메커니즘·깊은 메모리 원리·자체 하네스 구현 재설명 **0건**. 필요하면 "자매서(클로드/메모리/Agent SDK 핸드북) 참조"로 위임. (금지 신호: "내부적으로 …를 한다", 특정 하네스의 소스 파일명·함수명 해부)
3. **시점 태그 (낡음 관리)** — 구체 제품 사실(버전·점유율·기능 유무)에 "(2026년 6월 기준)" 또는 출처가 붙어 있는가. 시점 없는 단정 0건.
4. **축 중심 (카탈로그 금지)** — 챕터가 *축*을 중심으로 여러 하네스를 가로지르는가. 한 제품을 처음부터 끝까지 소개하는 "카탈로그 페이지"가 아닌가.
5. **용어 도입** — 새 전문용어 첫 등장은 **굵은 한국어(영어)** + 한 줄 정의
6. **백틱** — 코드로 타이핑 가능한 식별자·CLI·설정 키만 백틱. 하네스 이름·개념은 평문
7. **분량** — 개념형 ~4–5p

## B. 질적 기준 — 적대적 비평으로 소진

1. **중심 비유 1개 + 한계 명시** — 엔지니어가 *몸으로 아는* 것에 매핑. (기준: 1.2의 웹 프레임워크 관심사, 💡로 한계 박음)
2. **비교 시연 — 축으로 가로지르기** — 추상론이 아니라, 여러 하네스가 *같은 축을 다르게 푸는* 구체 대조를 보여주는가. (기준: 1.2의 "같은 부품, 다른 답" 표)
3. **평서체 `~다` 일관**
4. **챕터 연결** — 앞 장 핵심 1문장 회수 + 다음 챕터 티저
5. **문단 리듬** — 짧은 선언 / 중간 설명 / 긴 서술 섞음 (CLAUDE.md §9)
6. **한 챕터 = 한 메시지** — 핵심이 한 문장으로 줄어드나 (기준: 1.2 "겉이 달라도 같은 다섯으로 분해된다")
7. **축으로 닫기** — 제품 사실 나열로 끝내지 않고 "그래서 고르거나 만들 때 이렇게"로 의사결정에 잇는다. 공정성: 각 하네스의 약점도 숨기지 않는다.

## `/goal` 종료조건 템플릿

```
/goal content/harness의 <NN_제목> 챕터를 매 턴 개선한다.
매 턴 끝에 반드시 출력:
 (1) A1~A7 체크표(통과/미달 + 근거 — 직교 위반·시점 태그 누락은 grep으로, 분량은 줄 수로)
 (2) 적대적 비평가가 chapter-rubric.md B1~B7 관점에서 찾은 잔여 약점 목록(심각도)
완료: A1~A7 전부 통과 · B 잔여 약점 심각도 '중' 이상 0개.
```

> 자기선언 함정 방지: A는 `grep`/줄 수로 *증명*, B는 "약점 0"이 아니라 "심각도 중 이상 0"으로 둬 무한 다듬기를 끊는다.
> 사실 검증: 제품 주장은 LLM이 자기선언하지 말고, 시점 태그·출처로 *검증 가능하게* 남긴다. 신생 하네스는 GitHub 1차 출처 권장.
