# 에이전트 하네스 핸드북 — 목차 (초안)

**대상 독자**: 에이전트 하네스를 고르거나 직접 만들려는 엔지니어
**목표**: 제품 카탈로그가 아니라, 어느 하네스든 읽어내는 *비교의 축*을 손에 쥐기
**분량**: 약 140페이지 (26챕터 · 대부분 개념형 4–5p)
**언어**: 한국어 (기술 용어 영어 병기)
**자매서**: 클로드 핸드북(Claude Code 내부 해부) · Agent SDK 핸드북(자체 하네스 만들기) · 메모리 핸드북(기억 원리)

> 컨셉: **"하네스는 뜨고 진다. 비교의 축은 남는다."**
> 이 책을 쓰는 며칠 사이 OpenClaw는 이름을 세 번 갈았고 Hermes는 2개월 만에 1위를 뺏었다. 제품을 나열하는 책은 인쇄 전에 낡는다. 그래서 *축*을 가르친다.

## 작성 가이드 (이 핸드북 특유)

상위 스타일은 `/CLAUDE.md`, 세부 표기는 `docs/handbook-conventions.md`. 아래는 이 책만의 추가 가드레일.

- **축 중심 (카탈로그 금지)**: 제품을 한 권씩 소개하지 않는다. *축*(상태·확장·메모리·협업)을 세우고, 그 축 위에서 여러 하네스를 가로질러 비교한다.
- **직교**: Claude Code 내부 메커니즘은 클로드 핸드북, 깊은 메모리 원리는 메모리 핸드북, 자체 하네스 구현은 Agent SDK 핸드북에 위임. 이 책은 *축 위의 좌표*만.
- **시점 태그 (낡음 관리)**: 구체 제품 사실에는 "(2026년 6월 기준)" + 출처를 명시. 신생 하네스(OpenClaw·Hermes)는 GitHub 소스 직접 확인.
- **축으로 닫기**: 제품 사실 나열로 끝내지 않고, "그래서 자체 하네스라면 이 축을 이렇게 고른다"로 의사결정에 잇는다.
- **각 챕터**: CLAUDE.md 챕터 구조 — "이 챕터에서 배우는 것" → 본문 → 핵심 정리 → 다음 티저.
- **품질 합격선**: `chapter-rubric.md`. 기준 챕터 = `01_2_다섯_가지_공통_부품.md`.
