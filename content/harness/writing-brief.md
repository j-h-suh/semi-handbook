## 1. 한 줄 미션

에이전트 하네스를 고르거나 만들려는 엔지니어에게, 제품 카탈로그가 아니라 *어느 하네스든 읽어내는 비교의 축*을 주는 책. 컨셉: **"하네스는 뜨고 진다, 비교의 축은 남는다."**

## 2. 절대 가드레일

- **축 중심 (카탈로그 금지)**: 제품을 한 권씩 소개하지 않는다. 축(상태·확장·메모리·협업) 위에서 여러 하네스를 가로질러 비교한다.
- **직교**: Claude Code 내부=클로드 핸드북, 깊은 메모리 원리=메모리 핸드북, 자체 하네스 구현=Agent SDK 핸드북에 위임.
- **시점 태그**: 제품 사실에 "(2026년 6월 기준)" + 출처. 신생 하네스(OpenClaw·Hermes)는 GitHub 1차 출처 확인.
- **축으로 닫기**: 제품 나열로 끝내지 말고 "그래서 고르거나 만들 때 이렇게"로 의사결정에 잇는다. 약점도 공정하게.
- **톤**: 평서체 `~다`. 중심 비유 1개 + 한계. 기준 챕터(01_2)의 결.

## 3. 전체 양산 커맨드 (새 세션에서 이거 하나)

```

[준비] 첫 턴에 content/harness/writing-brief.md 와 §0 링크 파일(handbook-toc.md,
  chapter-rubric.md, 기준 챕터 01_2, /CLAUDE.md, docs/handbook-conventions.md)을 읽어
  컨텍스트를 잡는다.
[작성] writing-brief.md §5 권장순서대로 미집필 챕터를 하나씩 쓴다. 각 챕터는
  handbook-toc.md 방향을 출발점, chapter-rubric.md를 합격선, 기준 챕터(01_2)를
  톤 견본으로 삼는다.
[매 턴 출력] (1) rubric A1~A7 체크표(직교 위반·시점 태그 누락은 grep으로, 분량은
  줄 수로) (2) 적대적 비평가가 본 B1~B7 잔여 약점(심각도).
[완료] writing-brief.md §4의 모든 미집필 챕터가 각각: 파일 존재 · A1~A7 통과
  · B 잔여약점 심각도 '중' 이상 0개.
[사실 게이트] 신생 하네스(OpenClaw·Hermes) 사실은 "(2026년 6월 기준)" 태그 +
  출처 표시. 단정적 주장은 GitHub 1차 출처로 검증 권장(실 검증은 goal 밖).
```

> Part 단위로 좁히려면 `[완료]`를 `Part 3(3.1~3.4)만`처럼 변경. `/goal`로 진행 확인, `/goal clear`로 중단.

## 5. 권장 작성 순서

1. **자를 완성** — Part 1 나머지(1.1·1.3). 비교의 틀이 서야 나머지가 그 위에 얹힌다.
2. **무게중심 상태 축** — Part 3 (3.1~3.4).
3. **1차 분류** — Part 2. 축을 보기 전 범주를 가른다.
4. **나머지 축** — Part 4·5·6 (확장·메모리·협업).
5. **종합** — Part 7. 축을 모아 의사결정으로.
6. **도입·에필 마지막** — Part 0과 에필로그는 전체를 조망한 뒤.

## 6. 하지 말 것
