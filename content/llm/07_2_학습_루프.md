## 골격에 살을 붙인다

6.5의 학습 루프는 돌아가긴 해도 *맨몸*이었다. 진지한 학습에는 세 가지가 더 필요하다 — 제대로 설정한 옵티마이저, 학습률 스케줄, 그래디언트 클리핑. 학습 엔진에 다는 안전장치들이다.

```python
import math
import torch

from minigpt import MiniGPT          # 6.3

model = MiniGPT(vocab_size, n_embd=128, n_head=4, n_layer=4, block_size=128)
# 1권의 Adam 의 사촌 — Transformer 의 사실상 표준 옵티마이저
optimizer = torch.optim.AdamW(
    model.parameters(), lr=3e-4, betas=(0.9, 0.95), weight_decay=0.1
)
```

`AdamW`는 1권에서 본 Adam에 weight decay를 깔끔히 분리해 붙인 변종으로, Transformer 학습의 기본값이다. `betas`와 `weight_decay`는 경험적으로 굳어진 값을 쓴다.

## 학습률을 다루는 법 — 워밍업과 코사인

가장 중요한 손잡이는 *학습률*이다. 그런데 이걸 처음부터 끝까지 고정하면 학습이 불안정하다. Transformer 학습엔 두 단계의 스케줄이 거의 표준이다.

```python
def lr_at(step, warmup, max_steps, max_lr, min_lr):
    if step < warmup:                                   # 1) 워밍업: 0 → max_lr 로 선형 증가
        return max_lr * (step + 1) / warmup
    ratio = (step - warmup) / (max_steps - warmup)      # 2) 코사인 감쇠: max_lr → min_lr
    return min_lr + 0.5 * (max_lr - min_lr) * (1 + math.cos(math.pi * ratio))
```

**워밍업(warmup)**은 학습 초반 학습률을 0에서 목표치까지 *천천히 올리는* 구간이다. 왜 필요할까. 학습 시작 시점의 가중치는 무작위라, 큰 학습률로 곧장 때리면 LayerNorm과 잔차로 쌓은 깊은 네트워크가 출렁이며 발산하기 쉽다. 살살 데우다가(워밍업) 본격적으로 학습하고, 후반엔 **코사인 감쇠**로 부드럽게 학습률을 낮춰 안정적으로 수렴시킨다. 차에 비유하면 워밍업이 부드러운 출발, 코사인 감쇠가 도착 전 감속이다.

## 그래디언트 클리핑 — 폭주를 막는 차단기

언어 데이터에는 드문 토큰, 희귀한 패턴이 섞여 있어, 가끔 비정상적으로 큰 그래디언트가 튄다. 한 번의 폭주가 그동안의 학습을 망칠 수 있다. **그래디언트 클리핑(gradient clipping)**은 그래디언트의 전체 크기(norm)가 한계를 넘으면 그 한계로 깎아, 폭주를 막는 차단기다.

```python
for step in range(max_steps):
    lr = lr_at(step, warmup=100, max_steps=5000, max_lr=3e-4, min_lr=3e-5)
    for g in optimizer.param_groups:
        g["lr"] = lr                                    # 스케줄대로 학습률 갱신

    x, y = get_batch("train", batch_size=32, block_size=128)
    logits, loss = model(x, y)
    optimizer.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # norm 을 1.0 으로 클리핑
    optimizer.step()
```

`clip_grad_norm_(..., 1.0)` 한 줄이 그 차단기다. 평소엔 아무 일도 안 하다가, 그래디언트가 튀는 순간에만 깎아낸다.

## 재면서 학습한다 — 과적합 잡기

학습 손실만 보면 함정에 빠진다. 모델이 학습 데이터를 *외우기*만 해도 학습 손실은 내려가기 때문이다. 그래서 주기적으로 *검증* 손실을 함께 잰다.

```python
@torch.no_grad()
def estimate_loss(model, eval_iters=50):
    model.eval()
    out = {}
    for split in ["train", "val"]:
        losses = torch.zeros(eval_iters)
        for k in range(eval_iters):
            x, y = get_batch(split, 32, 128)
            _, loss = model(x, y)
            losses[k] = loss
        out[split] = losses.mean().item()
    model.train()
    return out
```

학습 손실은 내려가는데 검증 손실이 *올라가기* 시작하면, 모델이 일반화 대신 암기로 빠진 신호 — 과적합이다. 7.1의 perplexity로 환산해 보면 그 갈림이 더 또렷이 보인다. `model.eval()`과 `model.train()`을 오가는 건 dropout 같은 장치를 평가 때 끄고 학습 때 켜기 위해서다.

이제 안정적으로, 재면서 학습할 수 있다. 그렇다면 모델의 *크기와 모양*을 바꾸면 무엇이 달라질까. 층을 더 쌓고, head를 늘리고, 차원을 키우면? 다음 장에서 직접 돌려 본다.

## 핵심 정리

- **AdamW가 Transformer의 기본 옵티마이저다.** 1권의 Adam에 weight decay를 분리해 붙인 변종이며, 경험적 기본값을 쓴다.
- **워밍업은 초반의 발산을 막는다.** 무작위 가중치를 큰 학습률로 때리면 깊은 네트워크가 출렁인다. 살살 올렸다가 코사인으로 부드럽게 내린다.
- **그래디언트 클리핑은 폭주 차단기다.** 드문 토큰이 만든 비정상적 그래디언트를 norm 한계로 깎아, 한 번의 폭주가 학습을 망치는 걸 막는다.
- **검증 손실로 과적합을 잡는다.** 학습 손실만 보면 암기를 못 본다. 검증 손실이 오르기 시작하면 과적합 신호다.
- **이제 재면서 안정적으로 학습한다.** 다음은 모델의 크기·모양을 바꿔보는 실험이다.
