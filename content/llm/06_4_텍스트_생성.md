# 6.4 텍스트 생성 — 토큰 하나씩 샘플링

## 이 챕터에서 배우는 것

- 학습된 GPT로 텍스트를 만드는 자기회귀 루프 — 2.5의 패턴을 Transformer로
- temperature — 분포를 날카롭게/부드럽게 돌리는 다이얼
- top-k·top-p — 엉뚱한 토큰으로 새는 걸 막는 샘플링
- block_size라는 유한한 문맥 창의 의미

---

## 다시, 자기회귀

6.3의 `MiniGPT`는 각 위치에서 다음 토큰 logit을 낸다. 텍스트 생성은 2.5에서 본 그 자기회귀 루프 그대로다 — 다음 토큰을 뽑아 *도로 입력에 넣고* 반복한다. 바뀐 건 엔진이 LSTM에서 Transformer로 교체됐다는 것뿐이다.

```python
import torch
import torch.nn.functional as F


@torch.no_grad()
def generate(model, idx, max_new_tokens, temperature=1.0, top_k=None):
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -model.block_size:]        # 문맥을 block_size 로 자른다
        logits, _ = model(idx_cond)
        logits = logits[:, -1, :] / temperature      # 마지막 위치 logit, temperature 적용
        if top_k is not None:                        # 상위 k 개만 후보로
            v, _ = torch.topk(logits, top_k)
            logits[logits < v[:, [-1]]] = -float("inf")
        probs = F.softmax(logits, dim=-1)
        idx_next = torch.multinomial(probs, num_samples=1)   # 분포에서 한 토큰 샘플링
        idx = torch.cat([idx, idx_next], dim=1)              # 이어 붙이고 반복
    return idx
```

`@torch.no_grad()`는 생성 중엔 학습이 없으니 기울기 계산을 끈다. 루프 안에서 마지막 위치의 logit만 꺼내(`logits[:, -1, :]`) 다음 토큰을 뽑는다. 모든 위치의 logit이 나오지만, 우리가 원하는 건 *맨 끝 다음에 올* 토큰뿐이다.

## temperature — 날카로움의 다이얼

5.1에서 √d_k를 설명하며 "이건 temperature가 아니다"라고 미뤄둔 그 temperature가 여기 등장한다. logit을 softmax에 넣기 전에 `temperature`로 나누는 한 줄이다.

$$p_i = \text{softmax}(z_i / \tau)$$

$\tau$(타우)가 분포의 *날카로움*을 조절한다.

- **$\tau < 1$ (낮음)**: logit 차이가 벌어져 분포가 날카로워진다. 가장 확률 높은 토큰에 더 쏠린다 — 안전하지만 단조롭고 반복적이다.
- **$\tau > 1$ (높음)**: 차이가 좁혀져 분포가 평평해진다. 덜 확률적인 토큰도 잘 뽑힌다 — 다양하지만 횡설수설할 위험이 있다.
- **$\tau \to 0$**: 사실상 argmax. 늘 최고 확률 토큰만 — 완전히 결정론적.

ML 엔지니어에게 익숙한 그림으로, 이름 그대로 *온도*다. 통계물리에서 온 비유로, 온도가 높으면 입자가 제멋대로 튀고(무작위), 낮으면 질서 있게 가라앉는다(결정론적). 같은 모델이라도 이 다이얼 하나로 "안전한 글"과 "과감한 글" 사이를 오간다.

> ⚠️ **temperature는 지식을 더하지 않는다**: 높은 온도가 "더 창의적"이라는 말은 절반만 맞다. temperature는 *이미 있는* 분포의 모양만 바꿀 뿐, 없던 지식을 만들지 않는다. 너무 높이면 창의가 아니라 그냥 잡음이 된다. 모델이 모르는 건, 온도를 올려도 여전히 모른다.

> ⚙️ **top-k와 top-p**: temperature만으로는 가끔 확률이 아주 낮은 엉뚱한 토큰이 뽑혀 글이 샌다. 이를 막으려고 후보를 추린다. *top-k*는 확률 상위 k개만 남기고, *top-p(뉴클리어스)*는 누적 확률 p까지의 토큰만 남긴다. 나머지는 0으로 막는다. temperature와 함께 쓰면 "다양하되 새지 않는" 생성이 된다.

## 유한한 문맥 창

코드의 `idx[:, -model.block_size:]`에 주목하자. 생성할 때 문맥을 *최근 `block_size`개로 자른다*. GPT는 그보다 먼 과거를 보지 못한다.

이건 LSTM과 흥미로운 대조다. LSTM은 원리상 hidden state에 임의로 먼 과거를 담을 수 있었다(실제로는 희미해졌지만). GPT는 그 반대다 — `block_size` 안의 모든 토큰을 *또렷이* 보지만, 그 창을 벗어난 건 *아예* 못 본다. 거리를 1로 만든 대가로(4.3), 볼 수 있는 범위에 단단한 벽이 생겼다. 이 문맥 창을 넓히는 것이 후대 모델들의 큰 숙제가 된다.

생성까지 갖췄다. 이제 흩어진 조각 — 데이터 로드, 모델, 학습, 생성 — 을 하나의 흐름으로 꿰어, 처음부터 끝까지 도는 모습을 다음 장에서 본다.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요.** 이 장의 `generate`를 포함한 Part 5~7 코드는 본문 설명용이다. `multinomial` 샘플링, top-k 마스킹, 문맥 자르기는 실제 실행으로 확정한다.

## 핵심 정리

- **생성은 자기회귀 루프다.** 마지막 위치 logit으로 다음 토큰을 뽑아 도로 입력에 잇는다 — 2.5의 패턴 그대로, 엔진만 Transformer로 바뀌었다.
- **temperature는 분포의 날카로움을 돌린다.** $\tau<1$은 안전·반복, $\tau>1$은 다양·위험, $\tau\to0$은 결정론적 argmax.
- **temperature는 지식이 아니라 모양을 바꾼다.** 너무 높이면 창의가 아니라 잡음이다. 모르는 건 온도로 풀리지 않는다.
- **top-k·top-p가 새는 걸 막는다.** 확률 낮은 엉뚱한 토큰을 잘라내, 다양하되 무너지지 않게 한다.
- **GPT의 문맥은 유한하다.** `block_size` 안은 또렷이 보지만 밖은 아예 못 본다 — 거리를 1로 만든 대가로 생긴 단단한 벽이다.
