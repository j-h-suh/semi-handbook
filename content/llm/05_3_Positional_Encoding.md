# 5.3 Positional Encoding — 순서 정보를 어떻게 주입하나

## 이 챕터에서 배우는 것

- Self-Attention이 순서를 못 보는 이유를 한 번 더, 이번엔 코드의 눈으로
- 가장 단순한 해법들(인덱스 그대로, 위치 임베딩)이 어디서 막히는가
- 사인·코사인으로 위치를 새기는 발상 — 서로 다른 속도의 바늘들
- 왜 더하는가(concat이 아니라) — 같은 벡터에 위치를 태운다는 의미

---

## 다시, 순서가 없다

5.2의 끝에서 짚었다. `MultiHeadAttention`에 "나는 학생이다"를 넣든 "학생이다 나는"을 넣든, 토큰 집합이 같으면 출력이 사실상 같다. 점수표가 query·key 내적으로만 만들어지는데, 그 내적 어디에도 "몇 번째 토큰인가"가 들어 있지 않기 때문이다.

이걸 정확히 말하면 이렇다. Self-Attention은 입력의 순서를 바꾸면 출력도 *똑같이* 순서만 바뀐다. 위치를 구별하는 정보가 구조 안에 없다. LSTM이 토큰을 왼쪽에서 오른쪽으로 처리하며 순서를 *공짜로* 갖던 것과 정반대다. 4.4에서 "recurrence를 버리며 순서 정보를 잃었다"고 한 그 청구서가 여기 도착했다.

그러니 순서를 *밖에서* 주입해야 한다. 각 토큰 벡터에 "너는 0번째", "너는 1번째"라는 표식을 새기는 것이다.

## 단순한 해법들이 막히는 곳

가장 먼저 떠오르는 건 위치 번호를 그냥 더하는 것이다. 0번 토큰에 0을, 1번에 1을, …, 500번에 500을. 하지만 이건 곧장 막힌다. 임베딩 값은 보통 −1~1 근처인데 거기에 500을 더하면 위치 숫자가 내용을 완전히 덮어버린다. 게다가 학습 때 못 본 긴 위치(예: 5000번)가 들어오면 값이 폭주한다.

두 번째 해법은 더 그럴듯하다. 토큰 임베딩처럼, *위치마다 학습되는 벡터*를 두는 것이다(1.3에서 정수를 벡터로 바꾼 그 방식 그대로, 이번엔 위치 정수에). 실제로 GPT가 쓰는 방식이 이것이다. 잘 작동한다. 다만 한계가 하나 있다 — 학습 때 본 최대 길이까지만 위치 벡터가 존재한다. 그보다 긴 문장이 오면 줄 위치 표식이 없다.

원 Transformer 논문은 세 번째 길을 택했다. 학습 없이, *수식으로* 위치를 새긴다. 긴 위치든 짧은 위치든 공식만 있으면 즉석에서 표식을 만들 수 있다.

## 서로 다른 속도의 바늘들

핵심 발상은 이렇다. 위치를 *여러 개의 회전하는 바늘*로 표현한다. 각 바늘은 서로 다른 속도로 돈다.

ML 엔지니어에게 익숙한 그림으로, 이진수의 자릿값을 떠올려 보자. 0,1,2,3,…을 이진수로 쓰면 맨 오른쪽 비트는 매 칸 뒤집히고(빠름), 그 왼쪽은 두 칸마다(느림), 그 왼쪽은 네 칸마다 뒤집힌다. 비트들의 *조합*이 모든 수를 유일하게 구별한다.

**위치 인코딩(Positional Encoding)** — 각 위치를, 서로 다른 주파수의 사인·코사인 값들로 이루어진 벡터로 표현하는 기법 — 은 이 아이디어를 연속 버전으로 옮긴 것이다. 비트의 0/1 대신 사인·코사인의 매끄러운 −1~1을 쓴다.

바늘과 사인·코사인이 어떻게 이어질까. 회전하는 바늘의 *끝점 좌표*가 바로 $(\cos\theta,\ \sin\theta)$다. 위치 $pos$가 커질수록 바늘이 더 돌아 좌표가 바뀐다 — 빠르게 도는 바늘(앞쪽 차원)은 가까운 위치들을 잘게 구별하고, 느리게 도는 바늘(뒤쪽 차원)은 먼 위치까지 겹치지 않게 짚는다. 그 좌표들을 죽 늘어놓은 게 한 위치의 벡터다.

> ⚠️ **이진수 비유가 깨지는 곳**: 이진 비트는 *이산*이라 7에서 8로 갈 때 여러 자리가 한꺼번에 *반전*한다. 사인·코사인은 *연속*이라 위치가 조금 움직이면 좌표도 조금만 돈다. 비유는 "여러 속도의 자릿값"까지만 빌려오고, 매끄러움은 사인·코사인의 몫이다 — 그리고 그 매끄러움 덕에 $PE(pos+k)$가 $PE(pos)$의 *선형 회전*이 된다는 성질이 따라온다(바로 아래에서 본다).

$$PE(pos, 2i) = \sin\!\left(\frac{pos}{10000^{2i/d}}\right), \quad PE(pos, 2i+1) = \cos\!\left(\frac{pos}{10000^{2i/d}}\right)$$

여기서 $pos$는 위치(몇 번째 토큰), $i$는 벡터 안의 차원 인덱스, $d$는 임베딩 차원이다. 차원 인덱스 $i$가 커질수록 분모 $10000^{2i/d}$가 커져 주파수가 낮아진다 — 앞쪽 차원은 빠르게 도는 바늘, 뒤쪽 차원은 느리게 도는 바늘이다. 이 바늘들의 조합이 각 위치를 유일하게 새긴다.

> 💡 **왜 하필 사인·코사인인가**: 단지 위치를 구별하기만 한다면 다른 방법도 많다. 사인·코사인의 진짜 미덕은 *상대 위치*에 있다. $PE(pos+k)$는 $PE(pos)$의 선형 변환으로 표현된다 — 바늘을 고정 각도만큼 돌리는 건 선형 회전이기 때문이다. 덕분에 Attention이 "k칸 떨어진 토큰"이라는 상대 관계를 쉽게 학습할 수 있다. 절대 위치를 새기면서 상대 위치까지 거저 따라온다.

## 왜 더하는가

만든 위치 벡터를 토큰 임베딩에 어떻게 합칠까. 옆에 이어 붙이면(concat) 차원이 늘어 비용이 커진다. Transformer는 대신 *그냥 더한다*. 같은 차원의 위치 벡터를 토큰 임베딩에 원소별로 더해, 하나의 벡터에 내용과 위치를 함께 태운다.

내용과 위치가 한 벡터에 섞이면 구별 못 하지 않을까. 그렇지 않다. 모델은 학습을 통해 둘을 분리해 읽는 법을 익힌다. 위치 신호가 *규칙적인 패턴*(매끄러운 사인파)이라, 불규칙한 내용과 구분하기 쉽다.

```python
import math
import torch
import torch.nn as nn


class PositionalEncoding(nn.Module):
    """사인·코사인 위치 인코딩을 입력 임베딩에 더한다."""

    def __init__(self, d_model: int, max_len: int = 5000):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(max_len).unsqueeze(1).float()       # (max_len, 1)
        # 차원마다 다른 주파수: 10000^(2i/d) 의 역수
        div_term = torch.exp(
            torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model)
        )
        pe[:, 0::2] = torch.sin(position * div_term)   # 짝수 차원 = sin
        pe[:, 1::2] = torch.cos(position * div_term)   # 홀수 차원 = cos
        self.register_buffer("pe", pe.unsqueeze(0))     # (1, max_len, d_model), 학습 안 함

    def forward(self, x):
        # x: (B, T, d_model) — 앞 T개 위치 벡터를 더한다
        return x + self.pe[:, : x.size(1)]
```

`register_buffer`에 주목하자. 이 위치 벡터는 *학습되지 않는다.* 공식으로 한 번 만들어 고정해 둔다. 그래서 학습 때 본 적 없는 위치도, 공식만 돌리면 표식이 나온다 — 위에서 본 "학습 위치 임베딩"의 한계를 비켜 간 셈이다.

> ⚙️ **사인 인코딩 vs 학습 임베딩**: 둘 다 현역이다. 원 Transformer는 사인·코사인을, GPT 계열은 학습되는 위치 임베딩을 쓴다. 학습 임베딩이 데이터에 더 잘 맞을 때가 많지만, 본 적 없는 긴 길이로 *외삽*하는 데는 사인 쪽이 유리하다. 이 책의 Mini GPT(Part 6)에서는 단순함을 위해 학습 임베딩을 쓸 텐데, 원리를 보는 데는 이 사인 버전이 가장 투명하다.

## 이제 벡터는 무엇을 담는가

여기까지 오면, 모델에 들어가는 각 토큰 벡터는 두 가지를 함께 담는다 — *무엇인가*(내용)와 *어디인가*(위치). 그리고 5.1·5.2의 Attention이 이 벡터들을 섞는다.

그런데 Attention이 하는 일을 자세히 보면, 본질적으로 value들의 *가중 평균*이다. 가중치가 아무리 똑똑해도, 평균은 선형 섞기다. 입력을 비선형으로 *변형*하는 자리가 아직 없다. 깊은 표현력은 비선형에서 나오는데 말이다. 그 비선형의 자리가 다음 장, Feed-Forward Layer다.

> ✅ **코드 검증됨 — `playground/handbook/llm` 프로브 통과.** 이 장의 `PositionalEncoding`은 검증 레포에서 실행 확인했다(probe_5_posenc). `div_term` 주파수 스케일·짝홀 차원 분배·값 ∈ [-1,1]·비학습(buffer) 정상.

## 핵심 정리

- **Self-Attention은 순서를 구조적으로 못 본다.** 점수표가 위치를 모르므로, 토큰 집합이 같으면 출력이 같다. 4.4에서 예고한 "잃어버린 순서"의 청구서다.
- **단순한 해법들은 한계가 있다.** 인덱스를 그대로 더하면 값이 폭주하고, 학습 위치 임베딩(GPT 방식)은 잘 되지만 학습 길이를 넘으면 표식이 없다.
- **사인·코사인은 서로 다른 속도의 바늘로 위치를 새긴다.** 이진수 자릿값의 연속 버전이며, 공식으로 즉석에서 만들 수 있어 길이에 얽매이지 않는다.
- **상대 위치가 거저 따라온다.** $PE(pos+k)$가 $PE(pos)$의 선형 변환이라, Attention이 "k칸 떨어짐"을 쉽게 학습한다.
- **위치는 더해서 태운다.** concat 대신 더하기로 내용과 위치를 한 벡터에 싣고, 모델이 규칙적 패턴으로 둘을 분리해 읽는다. 다음은 비선형의 자리, Feed-Forward다.
