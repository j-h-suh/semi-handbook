# 5.4 Feed-Forward Layer — 비선형성의 자리, 왜 필요한가

## 이 챕터에서 배우는 것

- Attention만 쌓으면 왜 깊이가 무의미해지는가 — 선형의 함정
- Feed-Forward Layer가 채우는 비선형의 자리
- "위치별로 독립" 처리가 Attention과 어떻게 분업하는가
- 왜 중간 차원을 4배로 부풀리나, 그리고 모델 파라미터의 대부분이 왜 여기 있나

---

## Attention은 섞을 뿐, 변형하지 않는다

5.3까지 우리는 각 토큰 벡터에 내용과 위치를 실었고, Attention으로 그 벡터들을 섞었다. Attention이 하는 일을 한마디로 줄이면 *재배치*다 — 각 위치가 다른 위치의 value들을 가중합으로 끌어와 자기 자리에 모은다. 정보를 토큰 *사이로* 옮기고 섞는다.

여기서 한 가지를 분명히 하자. Attention은 입력에 대해 *선형이 아니다* — 가중치 자체가 softmax(QK^T)로 입력에 비선형하게 의존하기 때문이다. 그러니 "Attention은 선형이라 깊이가 무의미하다"는 말은 옳지 않다. 함정은 다른 데 있다.

Attention이 *하지 않는* 일이 있다. 각 토큰의 내용을 *그 자리에서* 비선형으로 변형하는 것이다. Attention은 값들을 옮겨 섞을 뿐, 한 위치의 특징 벡터를 풍부하게 주물러 다른 모양으로 바꾸지는 않는다. 1권에서 활성화 함수가 표현력을 준다고 배운 그 비선형 변형이, Attention 안에는 *위치별로* 들어 있지 않다. 그 변형을 맡는 자리가 따로 있어야 한다.

## 위치마다, 작은 신경망 하나

그 자리가 **피드포워드 층(Feed-Forward Layer, FFN)** — 각 토큰 위치에 *독립적으로* 적용되는 작은 2층 신경망이다. 식으로는 단순하다.

$$\text{FFN}(x) = W_2 \,\cdot\, \text{GELU}(W_1 x + b_1) + b_2$$

입력을 한 번 선형 변환($W_1$)하고, 비선형 활성화(GELU)를 통과시킨 뒤, 다시 선형 변환($W_2$)으로 원래 차원에 되돌린다. 핵심은 가운데 활성화다 — 이 한 겹의 비선형이 Attention이 못 주던 변형력을 준다.

"위치마다 독립"이라는 말이 중요하다. FFN은 1번 토큰을 변형할 때 2번 토큰을 보지 않는다. 각 토큰을 *따로따로*, 같은 신경망으로 변형한다. 이게 Attention과의 분업을 만든다.

> 💡 **통신과 사고의 분업**: Transformer 블록 안에서 Attention과 FFN은 역할이 갈린다. Attention은 토큰들이 서로 *대화*하는 자리 — 정보가 토큰 사이를 오간다. FFN은 각 토큰이 자기 자리로 돌아가 *혼자 생각*하는 자리 — 받은 정보를 비선형으로 곱씹는다. ML 식으로는 Attention이 토큰 축의 섞기(reduce), FFN이 위치별 변형(map)이다. 한 블록은 "대화 → 사고"의 반복이다.

## 왜 4배로 부풀리나

$W_1$은 차원을 $d_{model}$에서 $d_{ff}$로 키우고, $W_2$는 다시 $d_{model}$로 줄인다. 관례적으로 $d_{ff} = 4 \times d_{model}$이다. $d_{model}=512$면 가운데서 2048차원으로 부풀렸다 줄인다.

왜 부풀릴까. 좁은 차원에서 곧바로 비선형을 걸기보다, 일단 넓은 공간으로 펼쳐 더 풍부한 중간 특징을 만들 여유를 준 뒤 다시 압축하는 편이 표현력이 높다. 넓은 작업대에서 펼쳐 작업하고 서랍에 정리해 넣는 셈이다.

```python
import torch.nn as nn


class FeedForward(nn.Module):
    """위치별 2층 신경망. 가운데서 4배로 부풀렸다 줄인다."""

    def __init__(self, d_model: int, d_ff: int | None = None):
        super().__init__()
        d_ff = d_ff or 4 * d_model        # 관례: 4배 확장
        self.net = nn.Sequential(
            nn.Linear(d_model, d_ff),     # 펼치기
            nn.GELU(),                    # 비선형 — 이 한 겹이 핵심
            nn.Linear(d_ff, d_model),     # 되돌리기
        )
        # dropout 은 여기 두지 않는다 — 5.6 블록의 잔차 더하기에서 한 번만 적용한다

    def forward(self, x):
        # x: (B, T, d_model) → 같은 shape. 각 위치를 독립적으로 변형.
        return self.net(x)
```

`nn.Sequential` 한 줄로 끝나는 단순한 모듈이다. 화려한 구조가 아니라, *비선형 한 겹*을 끼워 넣는 게 전부다. 그런데 이 단순한 층에 Transformer 파라미터의 대부분이 들어 있다.

> ⚙️ **모델 무게의 대부분은 FFN에 있다**: 4배 확장 때문에 $W_1$과 $W_2$가 큰 행렬이 된다. 전형적인 Transformer에서 전체 파라미터의 약 2/3가 FFN에 있다. 모델이 학습한 "지식"의 상당 부분이 이 위치별 신경망의 가중치에 저장된다고 보는 해석도 있다. Attention이 *어디를 볼지*를 정한다면, FFN은 *본 것을 무엇으로 바꿀지*의 용량을 쥐고 있다.

## 조각은 다 모였다, 그런데

이제 블록의 두 일꾼이 갖춰졌다 — 토큰을 섞는 Attention(5.1·5.2), 위치별로 변형하는 FFN(이 장). 순서 정보(5.3)도 입구에서 실었다. 원리상 이 둘을 번갈아 쌓으면 Transformer가 된다.

문제는 *깊이*다. 이 둘을 6번, 12번, 24번 쌓으면 신호가 그 많은 변형을 통과하며 흩어지거나 폭주한다. 깊은 네트워크가 학습이 안 되는 그 고질병이다. 조각을 쌓기 전에, 깊이를 견디게 해주는 두 장치를 먼저 끼워야 한다. Residual Connection과 Layer Norm이다.

> ✅ **코드 검증됨 — `playground/handbook/llm` 프로브 통과.** 이 장의 `FeedForward`는 검증 레포에서 실행 확인했다(probe_1_forward). dropout 을 5.6 블록의 잔차에 일임한 정합도 함께 확인.

## 핵심 정리

- **Attention은 섞을 뿐 변형하지 않는다.** 토큰 사이로 값을 재배치할 뿐, 각 위치를 그 자리에서 비선형으로 주무르지는 않는다. (Attention 자체는 입력에 비선형이지만, *위치별 변형*은 그 안에 없다.)
- **FFN이 비선형의 자리를 채운다.** 펼치고(선형) → 비선형(GELU) → 되돌리는(선형) 2층 신경망이며, 가운데 활성화 한 겹이 깊이에 의미를 준다.
- **FFN은 위치별로 독립이다.** Attention이 토큰 축의 섞기(통신)라면, FFN은 위치별 변형(사고)이다. 한 블록은 "대화 → 사고"의 반복이다.
- **중간 차원을 4배로 부풀린다.** 넓은 공간에서 풍부한 특징을 만들고 다시 압축한다. 이 확장 때문에 전체 파라미터의 약 2/3가 FFN에 모인다.
- **이제 깊이를 견딜 장치가 필요하다.** Attention과 FFN을 깊이 쌓으면 신호가 흩어진다. 5.5의 Residual·Layer Norm이 이를 잡는다.
