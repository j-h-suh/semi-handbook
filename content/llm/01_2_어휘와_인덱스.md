## 어휘는 텍스트가 정해준다

1.1에서 문자 단위를 택했다. 이제 글자를 정수로 바꾼다. 캐릭터 레벨의 장점이 여기서 빛난다 — 어휘를 따로 학습할 필요 없이, *텍스트에 등장하는 고유한 글자들*이 곧 어휘다.

학습 텍스트를 한 번 훑어 등장 글자를 모으고, 정렬해 번호를 매긴다. 이게 전부다.

```python
import numpy as np

text = open("input.txt", encoding="utf-8").read()

# 등장하는 고유 글자 = 어휘 (정렬해 번호를 고정)
chars = sorted(set(text))
vocab_size = len(chars)
print(vocab_size)        # 예: 65 (영문 셰익스피어 기준)
```

`set(text)`이 중복을 없애 고유 글자만 남기고, `sorted`가 순서를 고정한다. 정렬해 두는 건 *재현성* 때문이다 — 같은 텍스트면 언제 돌려도 같은 번호가 나오게.

## 두 개의 사전 — stoi와 itos

번호를 매긴다는 건 두 방향의 사전을 만든다는 뜻이다. 글자에서 번호로, 번호에서 글자로.

```python
stoi = {ch: i for i, ch in enumerate(chars)}   # string  → int
itos = {i: ch for i, ch in enumerate(chars)}   # int     → string

def encode(s: str) -> list[int]:
    return [stoi[c] for c in s]                 # 텍스트 → 정수 리스트

def decode(ids: list[int]) -> str:
    return "".join(itos[i] for i in ids)        # 정수 리스트 → 텍스트
```

이름 그대로다. **stoi(string-to-index)**는 글자를 번호로, **itos(index-to-string)**는 번호를 글자로 옮긴다. 책의 색인과 같다 — 단어를 찾으면 페이지 번호가 나오고(stoi), 페이지를 펴면 내용이 나온다(itos).

```python
encode("hi")        # 예: [46, 47]
decode([46, 47])    # "hi"
```

`decode(encode(s)) == s`가 항상 성립한다. 손실 없이 왕복하는 가역 변환이다. 모델은 정수만 다루고, 사람이 읽을 때만 `decode`로 되돌린다.

## 정수는 크기가 아니라 라벨이다

여기서 반드시 짚어야 할 함정이 있다. `stoi["a"]`가 39이고 `stoi["b"]`가 40이라고 해서(앞의 `encode("hi")`가 `[46, 47]`이었으니 `a`는 39다), `b`가 `a`보다 "1만큼 크다"는 뜻이 *아니다*.

이 번호는 **라커 번호**와 같다. 39번 라커와 40번 라커가 나란히 있다고 둘 안의 물건이 비슷하지 않듯, 39번 글자와 40번 글자는 아무 관계가 없다. 번호는 그저 구별을 위한 *라벨*이지, 크기나 순서의 의미가 없다.

이게 왜 중요한가. 만약 이 정수를 신경망에 *숫자 그대로* 넣으면, 모델은 `b(40)`를 `a(39)`보다 큰 값으로, `z(64)`를 훨씬 큰 값으로 잘못 해석한다. 존재하지도 않는 "글자의 크기 순서"를 학습 신호로 받아들이는 것이다. 라벨을 크기로 오해하는 이 문제를 피하려면, 정수를 *크기 정보가 없는 형태*로 바꿔 넣어야 한다.

## one-hot — 가장 단순한 다리, 그리고 그 한계

크기 정보를 지우는 가장 단순한 방법이 **원-핫 인코딩(one-hot encoding)**이다. 어휘 크기만큼의 벡터를 만들어, 해당 번호 자리만 1이고 나머지는 0으로 둔다.

```python
def one_hot(idx: int, vocab_size: int) -> np.ndarray:
    v = np.zeros(vocab_size)
    v[idx] = 1.0           # 그 글자 자리만 1
    return v

one_hot(2, 5)             # array([0., 0., 1., 0., 0.])
```

이제 39번과 40번은 서로 다른 자리에 1이 선 벡터일 뿐, 크기 비교가 사라진다. 모든 글자가 서로 *정확히 같은 거리*에 놓인다. 라벨을 크기로 오해할 위험이 없다.

그런데 바로 그 "모두가 등거리"가 한계다. one-hot에서는 `a`와 `b`의 거리가, `a`와 `z`의 거리와 똑같다. 글자들 사이의 *어떤 유사성도* 담지 못한다. 게다가 어휘가 수만이면 벡터도 수만 차원인데 그중 단 하나만 1인 — 거대하고 텅 빈 표현이다.

우리가 원하는 건 다르다. 비슷한 토큰은 가깝고, 다른 토큰은 먼, *조밀한* 벡터. 그리고 그 유사성을 사람이 정하는 게 아니라 *데이터에서 학습되는* 벡터. one-hot의 두 한계 — 등거리와 희소성 — 를 동시에 푸는 그것이 다음 장의 임베딩이다.

---

## 핵심 정리

- **어휘는 텍스트가 정해준다.** 캐릭터 레벨에서는 `sorted(set(text))`가 곧 어휘다. 외부 의존 없이 한 줄로 만들어진다.
- **stoi·itos 두 사전이 인코딩·디코딩을 이룬다.** 글자↔번호의 가역 변환이며, `decode(encode(s)) == s`로 손실 없이 왕복한다.
- **정수 인덱스는 라벨이지 크기가 아니다.** 라커 번호처럼, 39번과 40번 글자 사이엔 아무 크기 관계가 없다. 정수를 그대로 넣으면 모델이 가짜 순서를 학습한다.
- **one-hot은 크기 오해를 없애지만 두 한계가 있다.** 모든 토큰이 등거리라 유사성을 못 담고, 어휘 크기만큼 희소하다.
- **조밀하고 학습되는 벡터가 답이다.** 비슷한 토큰이 가까운 표현, 그것이 1.3의 임베딩이다.
