# 1.3 임베딩 — 정수를 벡터로, 무엇이 학습되는가

## 이 챕터에서 배우는 것

- 임베딩이 one-hot의 두 한계(등거리·희소)를 어떻게 동시에 푸는가
- 임베딩 행렬과 "행 꺼내기"로서의 룩업
- 임베딩 룩업이 사실 one-hot × 행렬과 같다는 것 — 1.2와의 다리
- 학습되는 것은 무엇인가 — 의미가 기하가 된다

---

## 조밀하고, 학습되는 벡터

1.2에서 one-hot의 두 한계를 봤다. 모든 토큰이 등거리라 유사성을 못 담고, 어휘 크기만큼 희소하다. 둘을 동시에 푸는 게 **임베딩(embedding)** — 각 토큰에 대응하는, 조밀하고 학습되는 저차원 벡터다.

핵심은 두 가지다. *조밀*하다 — 수만 차원의 희소 벡터 대신, 이를테면 64차원이나 128차원의 빽빽한 실수 벡터다. 그리고 *학습된다* — 이 벡터의 값을 사람이 정하지 않고, 모델이 데이터로부터 스스로 채운다.

## 임베딩 행렬 — 한 줄이 한 토큰

임베딩은 하나의 행렬로 구현된다. 크기가 `(vocab_size, d_embed)`인 행렬 `E`를 두면, `i`번째 *행*이 곧 `i`번 토큰의 벡터다.

```python
import numpy as np

vocab_size, d_embed = 65, 64
rng = np.random.default_rng(0)
E = rng.normal(0, 0.02, size=(vocab_size, d_embed))   # 임베딩 행렬, 작게 초기화

def embed(ids: list[int]) -> np.ndarray:
    return E[ids]            # 행 꺼내기: (len(ids), d_embed)

embed([46, 47]).shape       # (2, 64) — 두 글자, 각 64차원
```

토큰을 벡터로 바꾸는 일이 그저 *행을 꺼내는 인덱싱*이다. 정수 ID가 행 번호가 되고, 그 행이 벡터가 된다. 책의 색인(1.2)이 페이지 번호를 줬다면, 임베딩 행렬은 그 페이지의 *내용*을 준다.

## 룩업은 사실 one-hot 곱이다

여기서 1.2와 깔끔하게 이어진다. 행을 꺼내는 인덱싱은, 사실 *one-hot 벡터와 행렬의 곱*과 똑같다.

```python
# i번 행 꺼내기 == i번 one-hot @ E
i = 2
onehot = np.zeros(vocab_size); onehot[i] = 1.0
np.allclose(onehot @ E, E[i])     # True
```

one-hot 벡터 `[0,0,1,0,...]`을 `E`에 곱하면, 1이 선 자리의 행만 살아남고 나머지는 0으로 지워진다. 결국 그 행 하나가 나온다. 그래서 임베딩 층은 *입력이 one-hot인 선형 층*으로 봐도 정확히 같다. 다만 실제로는 거대한 곱셈 대신 인덱싱으로 빠르게 처리할 뿐이다.

이 관점이 중요한 이유는, 임베딩 행렬 `E`가 곧 *학습되는 파라미터*임을 분명히 해주기 때문이다. one-hot은 고정된 입력이고, `E`는 학습으로 채워지는 가중치다.

## 무엇이 학습되나 — 의미가 기하가 된다

`E`의 행들은 처음엔 작은 난수다. 아무 의미가 없다. 학습이 시작되면, 1권에서 본 바로 그 최적화가 이 행들을 조금씩 움직인다. 무엇을 향해 움직일까.

비슷한 자리에 쓰이는 토큰일수록 비슷한 벡터를 갖도록 움직인다. 문맥이 닮은 글자들이 임베딩 공간에서 가까이 모인다. 학습이 끝나면, 벡터 사이의 *거리와 방향*이 의미를 띤다 — 가까우면 닮았고, 멀면 다르다.

캐릭터 레벨 모델을 충분히 학습시킨 뒤 임베딩을 들여다보면, 이 기하가 눈에 보인다. 모음끼리, 숫자끼리, 공백·줄바꿈 같은 구분 문자끼리 각각 무리를 이룬다. 누구도 "`a`,`e`,`i`,`o`,`u`는 한패야"라고 알려주지 않았는데도, 이들이 비슷한 문맥(자음 사이에 끼는 자리)에 등장한다는 통계만으로 한곳에 모인다. 의미가 라벨이 아니라 *위치*로 표현된다는 게 이런 뜻이다.

> 💡 **추천 시스템과 같은 원리**: 임베딩은 추천 시스템이 사용자·상품 벡터를 학습하는 방식과 똑같다. 누가 무엇을 봤는지(행동)로부터 사용자 벡터가 정해지듯, 토큰이 어떤 문맥에 등장하는지로부터 토큰 벡터가 정해진다. 명시적으로 "이건 모음이야"라고 알려주지 않아도, *쓰임*이 벡터를 빚는다.

> ⚠️ **차원에 이름표는 없다**: 학습된 임베딩의 64개 차원 각각이 "모음 여부", "자주 쓰임" 같은 깔끔한 의미를 갖지는 않는다. 의미는 특정 축이 아니라 벡터 *전체에 분산*되어 있다. 그래서 한 차원만 떼어 해석하려 들면 대개 실패한다 — 의미는 방향들의 조합으로 흩어져 있다.

토큰이 벡터가 되었고, 그 벡터의 *방향*에 의미가 깃든다. 그렇다면 이 방향을 더 밀어붙일 수 있을까 — 의미를 아예 *벡터 연산*으로 다룰 수 있을까? "왕 − 남자 + 여자 ≈ 여왕" 같은 식으로. 그 유명한 결과를 다음 장에서 본다.

## 핵심 정리

- **임베딩은 조밀하고 학습되는 벡터다.** one-hot의 등거리·희소 한계를, 저차원 실수 벡터로 동시에 푼다.
- **임베딩 행렬의 한 행이 한 토큰이다.** 토큰을 벡터로 바꾸는 일은 행을 꺼내는 인덱싱이다.
- **룩업은 one-hot × 행렬과 같다.** 임베딩 층은 입력이 one-hot인 선형 층이며, 행렬 `E`가 학습되는 파라미터임을 분명히 해준다.
- **학습되는 것은 기하다.** 행들이 움직여, 비슷하게 쓰이는 토큰이 가까운 벡터가 된다 — 의미가 거리와 방향이 된다.
- **차원 하나하나엔 이름표가 없다.** 의미는 특정 축이 아니라 벡터 전체에 분산된다. 이 방향성을 벡터 연산으로 다루는 게 다음 장 Word2Vec이다.
