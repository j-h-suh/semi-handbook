- 마스크가 어떻게 *완전한 병렬*을 지키면서 자기회귀를 가능하게 하나

## 미래를 보면 안 된다

6.1에서 Part 5의 부품 중 단 하나를 비워뒀다 — Attention을 *causal*하게 만드는 마스크다. 왜 필요한지부터 보자.

GPT의 과제는 다음 토큰 맞히기다(2.5). "hell"을 보고 "o"를 예측해야 한다. 그런데 5.2의 self-attention은 *모든* 토큰이 *모든* 토큰을 본다 — 양방향이다. 그대로 두면, "hell"의 자리에서 다음 글자 "o"를 예측할 때 Attention이 이미 "o"를 슬쩍 본다. 답안지를 보고 답을 쓰는 셈이다.

그래서 막아야 한다. **각 토큰은 자기보다 앞선 토큰까지만 본다.** 미래는 가린다. 이렇게 미래를 차단한 self-attention을 **causal self-attention(인과적 셀프 어텐션)**이라 한다.

ML 엔지니어에게 익숙한 그림으로, 이건 *책을 읽을 때 아래 줄을 카드로 가리는 것*과 같다. 지금 줄까지만 보이고, 다음 줄은 카드에 덮여 있다. 미리 엿볼 수 없으니 정직하게 예측해야 한다.

## 하삼각 마스크 한 장

이 "카드"의 정체는 놀랍도록 단순하다. T×T 점수표에서, *대각선과 그 아래만 살리고 위쪽 삼각형을 가리는* 하삼각 행렬 하나다.

```
        key →   k0  k1  k2  k3
query ↓
  q0           [ ✓   ·   ·   · ]   q0 은 k0 만
  q1           [ ✓   ✓   ·   · ]   q1 은 k0,k1 만
  q2           [ ✓   ✓   ✓   · ]   q2 는 k0~k2 만
  q3           [ ✓   ✓   ✓   ✓ ]   q3 은 전부
```

`i`번 query는 `j ≤ i`인 key만 본다. 위쪽 삼각형(미래)은 가려진다. 5.1에서 미리 뚫어둔 마스크 슬롯이 바로 이 자리를 위한 것이었다 — 그때 "0=가림, 1=살림" 규약으로 만들어 둔 그 슬롯이다.

```python
import torch

def causal_mask(T: int) -> torch.Tensor:
    # 하삼각이 1(살림), 상삼각이 0(가림) — 5.1 의 mask 규약 그대로
    return torch.tril(torch.ones(T, T))      # (T, T)

# 5.1 의 scaled_dot_product_attention 에 그대로 넘긴다:
#   scores = scores.masked_fill(mask == 0, float("-inf"))
#   → 가린 자리는 softmax 후 정확히 0 의 가중치
```

`torch.tril`이 하삼각만 1로 남긴다. 이걸 5.1의 함수에 넘기면, 가린 자리의 점수가 −∞가 되고 softmax를 지나며 가중치가 정확히 0이 된다. 미래 토큰의 기여가 깔끔히 사라진다. 새 연산을 만든 게 아니라, 5.1에 끼울 마스크 한 장을 추가했을 뿐이다.

## 마스크가 병렬을 지킨다

여기서 가장 우아한 점을 놓치지 말자. 이 마스크는 *완전한 병렬을 지키면서* 자기회귀를 구현한다.

언뜻 "미래를 가리려면 토큰을 하나씩 순서대로 처리해야 하지 않나?" 싶다. 아니다. 학습할 때는 시퀀스 전체를 *한 번에* 넣는다. T×T 점수표를 통째로 만들고, 하삼각 마스크를 씌우면, 각 위치가 자동으로 자기 과거만 보게 된다. T개 위치가 *동시에*, 각자 자기만의 다음 토큰을 예측한다.

> 💡 **마스크 한 장이 5.7의 약속을 지킨다**: 5.7에서 "causal mask가 공짜 감독을 만든다"고 했다. 그 정체가 이것이다. 길이 T 문장 하나로 T개의 예측을 *병렬로* 학습한다 — q0은 k0만 보고 다음을, q1은 k0·k1을 보고 다음을, … 동시에. 4.2에서 사수한 병렬성을 한 톨도 잃지 않으면서, 미래만 정확히 가린다. 순차 처리로 흉내 내면 T배 느릴 일을, 삼각 마스크 한 장이 단번에 해낸다.

> ⚠️ **학습과 생성은 다르다**: 위의 병렬은 *학습* 때 이야기다. 생성(6.4) 때는 토큰을 하나씩 만들어 가므로, 새 토큰은 늘 시퀀스의 *마지막*이라 그 자체로 과거만 본다 — 사실상 마스크가 저절로 만족된다. 같은 모델이 학습 때는 병렬로, 생성 때는 순차로 동작하는 셈이다.

이제 디코더의 심장까지 갖췄다. 임베딩, 위치, 블록, 그리고 미래를 가리는 마스크. 다음 장에서 이 모두를 하나의 `MiniGPT` 클래스로 조립한다.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요.** 이 장의 `causal_mask`를 포함한 Part 5~7 코드는 본문 설명용이다. `torch.tril`의 dtype·디바이스, 마스크 broadcast는 실제 실행으로 확정한다.

## 핵심 정리

- **다음 토큰 예측은 미래를 보면 안 된다.** 양방향 self-attention을 그대로 쓰면 답을 미리 보는 부정행위가 된다. 각 토큰은 자기 과거까지만 봐야 한다.
- **causal mask는 하삼각 행렬 한 장이다.** `i`번 query가 `j ≤ i`인 key만 보게 가린다. 위쪽 삼각형(미래)을 −∞로 막는다.
- **5.1의 마스크 슬롯이 여기서 채워진다.** "0=가림" 규약 그대로, `torch.tril` 마스크를 넘기면 가린 자리의 가중치가 0이 된다.
- **마스크는 병렬을 지킨다.** 학습 때 시퀀스 전체를 한 번에 넣어도, 삼각 마스크가 각 위치를 자기 과거에 가둔다 — T개 예측을 동시에, 5.7의 "공짜 감독"이 이것이다.
- **학습은 병렬, 생성은 순차다.** 생성 땐 새 토큰이 늘 마지막이라 마스크가 저절로 만족된다.
