# 10.2 스킬 만들기 — SKILL.md 프론트매터와 자동 발견

---

## 이 챕터에서 배우는 것

- 9.3의 **Tool Protocol 5 구성**과 **SKILL.md frontmatter**가 같은 일을 완전히 다른 형식으로 한다
- 디렉토리가 단위인 스킬 형식 — 부속 스크립트 + 설정 + 마크다운이 한 곳에 산다
- **사용자 invoke**와 **모델 invoke** — 두 가지 경로의 교차 가능한 두 게이트
- 충격적인 발견: 클로드 코드 내부에서 슬래시 명령과 스킬은 모델 입장에서 같은 것
- 1% 컨텍스트 예산 + 번들 스킬 항상 보호 같은 production 디테일
- `${CLAUDE_SKILL_DIR}`가 진짜로 풀어주는 문제 — 디렉토리 형식의 이유
- 10.2 끝의 결과물: **직접 만든 SKILL.md** 한 개가 사용자도 부를 수 있고 모델도 발견할 수 있는 스킬로 동작

---

## 사용자 경험에서 출발

10.1에서 우리는 `.claude/commands/today.md` 한 파일로 `/today` 명령을 만들었다. 매일 같은 5줄을 안 쳐도 됐다. 그게 작고 매일인 자리.

그런데 — 더 큰 자리가 있다. 예를 들어 **PR 리뷰**. 이건 5줄이 아니다:

- `git diff`를 받아서
- 보안 패턴을 찾고 (별도 Python 스크립트)
- 코드 스타일을 체크하고 (별도 yaml 룰)
- 리뷰 코멘트를 한국어로 다듬는다

이걸 마크다운 한 파일에 다 박는 건 어색하다. 스크립트를 본문에 문자열로 박을 수 없으니까. 그리고 — 모델이 언제 이 명령을 부를지를 자기가 결정해주면 좋겠다. 매번 사용자가 `/pr-review`를 기억하고 치는 건 피곤하다. 모델이 알아서 부를 수 있다면.

이 두 가지 — 부속 스크립트와 함께 사는 더 큰 단위 + 모델이 발견해서 부를 수 있는 형태 — 를 푸는 게 SKILL.md다.

```
.claude/skills/pr-review/
├── SKILL.md              ← 메타데이터 + 본문 (10.1의 마크다운)
├── security_check.py     ← 부속 스크립트
└── style_rules.yaml      ← 부속 설정
```

이 챕터에서 그게 어떻게 생겼는지, 그리고 모델이 발견하는 마법이 어떻게 동작하는지 본다. 마지막에 — 충격적인 한 줄이 박혀 있다.

## 본문

### **가장 작은 SKILL.md** — 디렉토리 한 개

```
.claude/skills/today/
└── SKILL.md
```

```markdown
---
description: 오늘 한 git 작업을 한국어로 요약한다
when_to_use: 사용자가 "오늘 뭐 했지", "오늘의 작업", "today" 같은 표현을 쓸 때
allowed-tools: Bash(git log:*), Bash(date:*)
---

오늘 (`!\`date +%Y-%m-%d\``) 한 작업의 커밋들:

!`git log --since="00:00" --oneline`

위 커밋들을 한국어로 *3 줄* 요약해줘. *명사형 종결*.
```

10.1의 `today.md`와 거의 같다. **다른 것은 단 두 가지**:

- 파일 위치: `.claude/commands/today.md` → `.claude/skills/today/SKILL.md` (디렉토리 안)
- 새 필드: `when_to_use`

이 두 가지가 세 가지 큰 차이를 만든다 — 디렉토리가 단위, 모델이 발견, 번들 파일 동봉 가능.

### 디렉토리가 단위 — 평탄 .md가 명시적으로 거부된다

10.1에서 본 walker (`getProjectDirsUpToHome`)는 **같은 함수가 commands/와 skills/를 둘 다 처리**한다. 그런데 그 안에서는 — 완전히 다른 패턴으로 갈라진다. `loadSkillsDir.ts:407`의 `loadSkillsFromSkillsDir`를 보면:

```typescript
// loadSkillsDir.ts:424-431
// Only support directory format: skill-name/SKILL.md
if (!entry.isDirectory() && !entry.isSymbolicLink()) {
  // Single .md files are NOT supported in /skills/ directory
  return null
}

const skillDirPath = join(basePath, entry.name)
const skillFilePath = join(skillDirPath, 'SKILL.md')   // ← 고정된 이름
```

**3가지 강제**:

1. 디렉토리가 아니면 거부 — 평탄 .md 파일은 **명시적으로 reject**
2. 디렉토리 안에 정확히 `SKILL.md` (대소문자 그대로)
3. 디렉토리 이름 = 스킬 이름

평탄 .md를 그냥 무시하는 게 아니다. 명시적으로 거부한다. 코드의 주석 **"Single .md files are NOT supported"**가 그 의도를 박아둔다. **`.claude/skills/foo.md` 같은 걸 깜빡 만들면 조용히 사라진다** — 사용자가 디렉토리 형식이 강제라는 사실을 반드시 알아야 한다.

왜 강제? — 답은 다음 항목에 있다.

### `${CLAUDE_SKILL_DIR}` — 디렉토리 형식의 진짜 이유

스킬은 부속 파일들과 함께 살 수 있다.

```
.claude/skills/pr-review/
├── SKILL.md
├── security_check.py     ← 본문이 부르는 Python 스크립트
└── style_rules.yaml      ← 본문이 읽는 설정
```

`SKILL.md` 본문 안에서:

```markdown
---
description: PR의 보안과 스타일을 리뷰한다
allowed-tools: Bash(python3:*), Bash(git diff:*), Read
---

현재 PR의 변경사항을 리뷰한다. 다음 단계:

1. `git diff main...HEAD`로 변경사항을 본다
2. `${CLAUDE_SKILL_DIR}/security_check.py`를 `python3`으로 실행해서 보안 패턴을 확인
3. `${CLAUDE_SKILL_DIR}/style_rules.yaml`을 Read로 읽어서 스타일 룰을 본다
4. 위 결과를 한국어 **3줄 코멘트**로 정리
```

호출 시점에 — `${CLAUDE_SKILL_DIR}`가 해당 스킬의 절대 경로로 치환된다 (`loadSkillsDir.ts:362` — 로컬 스킬, `SkillTool.ts:1077` — 원격 MCP 스킬, 둘 다 같은 패턴). **스킬이 자기 디렉토리 안의 부속 파일을 절대 경로로 참조**할 수 있다. 그래서 본문은 마크다운, 보안 체크는 **Python**, 스타일 룰은 **YAML** — 각 도구가 자기에게 맞는 형식으로 살면서 한 디렉토리 안에 묶여 있다.

**디렉토리 형식이 강제인 진짜 이유**: 부속 파일을 어디서 찾는지를 정의하기 위해. `${CLAUDE_SKILL_DIR}`가 유일하게 잘 정의되려면 스킬 = 디렉토리 한 개라는 1:1 대응이 필요하다. 평탄 .md 형식에서는 이게 없다.

> 💡 **`${CLAUDE_SESSION_ID}`도 같이 산다.** 진짜 코드의 주입 자리에 두 변수가 같이 박혀 있다 (`loadSkillsDir.ts:362, 366-369` 로컬 + `SkillTool.ts:1077-1081` MCP). `${CLAUDE_SESSION_ID}`는 **현재 세션의 ID**로 치환 — 스킬이 세션별 임시 파일을 만들거나 세션 로그에 접근할 때 쓴다. 정적 변수가 아니라 호출 시점 동적 값.

### 두 가지 invoke 경로 — 사용자 vs 모델

여기서부터가 SKILL.md의 진짜 새 컨셉. 10.1의 마크다운 명령은 사용자가 `/myCmd`로 부르는 한 가지 경로뿐이었다. 스킬은 **두 가지 경로**가 있다.

```
┌──────────────────────────────────────────────────┐
│ 경로 1: 사용자가 직접 부른다 (slash command)      │
│                                                  │
│   사용자: /pr-review                              │
│        ↓                                         │
│   user-invocable: true면 → 자동완성에 등장        │
│        ↓                                         │
│   클라이언트가 SKILL.md 본문을 LLM으로 보냄       │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│ 경로 2: 모델이 알아서 부른다 (SkillTool 발견)    │
│                                                  │
│   사용자: "이 PR 한 번 봐줘"                     │
│        ↓                                         │
│   모델: (시스템 프롬프트의 스킬 목록에서)         │
│        "pr-review가 매칭하네"                     │
│        ↓                                         │
│   모델이 SkillTool 호출:                         │
│     skill: "pr-review", args: ""                 │
│        ↓                                         │
│   클라이언트가 같은 SKILL.md 본문을 LLM으로 보냄   │
└──────────────────────────────────────────────────┘
```

**두 경로의 끝은 같다** — 둘 다 같은 SKILL.md 본문이 LLM으로 흘러간다. 차이는 누가 부르느냐. 그리고 그 누구가 어떤 게이트를 통과해야 부를 수 있느냐.

### 두 게이트 필드의 교차 가능

```yaml
user-invocable: true            # 사용자가 /로 부를 수 있는가
disable-model-invocation: false # 모델이 SkillTool로 발견하는 걸 막는가
```

**두 필드가 독립적**이다. 4가지 조합이 모두 의미 있다:

| `user-invocable` | `disable-model-invocation` | 결과 |
|---|---|---|
| `true` | `false` | 둘 다 부를 수 있음 (기본값) |
| `true` | `true` | 사용자만 — 모델은 발견 못 함 |
| `false` | `false` | 모델만 — 사용자 자동완성에 안 보임 |
| `false` | `true` | 둘 다 못 부름 — 비활성 |

언제 이런 조합이 쓰이나?

- **사용자만** (`disable-model-invocation: true`): `debug`, `batch` 같은 메타 도구. 사용자가 명시적으로 골라야 의미 있는 것들. 모델이 자동으로 부르면 오용 가능성.
- **모델만** (`user-invocable: false`): 백그라운드 자동화 — 모델이 알아서 부르되 사용자 자동완성을 어지럽히지 않게.
- **둘 다** (기본값): 일반적인 케이스. `simplify` 같은 거.

### 모델이 보는 **진짜 SkillTool 시스템 프롬프트**

이게 10.2의 가장 큰 발견이다. 진짜 코드 (`tools/SkillTool/prompt.ts:173-196`)의 `getPrompt` 함수가 모델에게 정확히 어떤 텍스트를 보여주는지 — 인용한다 (축약 — examples 4 → 2, 마지막 `<command_name>` bullet 생략).

```
Execute a skill within the main conversation

When users ask you to perform tasks, check if any of the available skills 
match. Skills provide specialized capabilities and domain knowledge.

When users reference a "slash command" or "/<something>" (e.g., "/commit", 
"/review-pr"), they are referring to a skill. Use this tool to invoke it.

How to invoke:
- Use this tool with the skill name and optional arguments
- Examples:
  - skill: "pdf" - invoke the pdf skill
  - skill: "commit", args: "-m 'Fix bug'" - invoke with arguments

Important:
- Available skills are listed in system-reminder messages in the conversation
- When a skill matches the user's request, this is a BLOCKING REQUIREMENT: 
  invoke the relevant Skill tool BEFORE generating any other response about the task
- NEVER mention a skill without actually calling this tool
- Do not invoke a skill that is already running
- Do not use this tool for built-in CLI commands (like /help, /clear, etc.)
```

5분만 들여다 보면 두 가지 충격이 박혀 있다.

**충격 1**: **"When users reference a 'slash command' or '/<something>' (e.g., '/commit'), they are referring to a skill. Use this tool to invoke it."**

**클로드 코드 내부에서는 슬래시 명령과 스킬이 같은 것**이다. 사용자가 `/commit`을 친다 → 그건 **commit 스킬을 invoke 하라**는 뜻으로 모델에게 전달된다. 10.1의 **commands_DEPRECATED** 폭로의 진짜 의미가 여기서 회수된다. **두 시스템이 미래에 합쳐질 거라는 게 아니라 — 모델 입장에서는 이미 합쳐져 있다**. 디렉토리 두 개는 사람의 멘탈 모델을 위해 남아 있는 과도기적 구분.

**충격 2**: **"this is a BLOCKING REQUIREMENT: invoke the relevant Skill tool BEFORE generating any other response. NEVER mention a skill without actually calling this tool."**

**모델이 스킬을 말로만 언급하는 걸 막기 위해 명시적 금지가 박혀 있다**. "이 작업은 verify 스킬로 하면 좋겠어" 같은 말만 하는 건 안 됨. 반드시 도구 호출로 이어져야 함.

이건 **흔한 LLM 프롬프트 엔지니어링 함정** — 모델이 도구를 부르는 대신 도구 이름을 텍스트로 답하는 케이스 — 을 **프롬프트 안에 BLOCKING REQUIREMENT로 명시**해서 막는다. **production의 작은 디테일**. 그리고 **대문자로 BLOCKING REQUIREMENT라고 적은 게** 우연이 아니다 — LLM은 대문자 강조에 민감하다. 책의 어떤 페이지라도 적용할 수 있는 작은 트릭.

### `getSkillToolCommands` — 모델에 노출되는 필터의 한 블록

모델이 어떤 스킬의 목록을 보느냐 — `commands.ts:565`의 한 블록이 결정한다.

```typescript
// commands.ts:565 — getSkillToolCommands
return allCommands.filter(
  cmd =>
    cmd.type === 'prompt' &&
    !cmd.disableModelInvocation &&        // ⭐ 모델 게이트
    cmd.source !== 'builtin' &&
    (cmd.loadedFrom === 'bundled' ||
      cmd.loadedFrom === 'skills' ||
      cmd.loadedFrom === 'commands_DEPRECATED' ||  // ⭐ deprecated 도 노출
      cmd.hasUserSpecifiedDescription ||
      cmd.whenToUse),
)
```

**5 가지 조건의 합**:

1. `type === 'prompt'` — 마크다운에서 만들어진 것만
2. `!disableModelInvocation` — 모델 게이트
3. `source !== 'builtin'` — 내장 명령은 제외 (`/help`, `/clear` 같은 거)
4. `loadedFrom` 이 스킬류 (`'bundled' || 'skills' || 'commands_DEPRECATED'`)
5. 또는 `hasUserSpecifiedDescription || whenToUse`

**`commands_DEPRECATED`가 그대로 모델에 노출**되는 게 보인다. 10.1에서 만든 `.claude/commands/today.md`도 — 모델이 발견해서 부를 수 있다. 그게 **deprecated라도** 그렇다. **호환성이 코드에 박혀 있다**.

`hasUserSpecifiedDescription`의 의미: **자동 추출된 description** (본문 첫 줄)만 있는 건 충분하지 않다. plugin/MCP 명령은 **명시적 description 또는 when_to_use**가 있어야 모델에게 노출. 자동 추출은 질이 낮을 수 있어서 모델 발견에는 안 쓴다.

### `when_to_use` — 모델 결정에 직접 들어가는 자리

```typescript
// SkillTool/prompt.ts:43-50 — getCommandDescription
function getCommandDescription(cmd: Command): string {
  const desc = cmd.whenToUse
    ? `${cmd.description} - ${cmd.whenToUse}`
    : cmd.description
  return desc.length > MAX_LISTING_DESC_CHARS
    ? desc.slice(0, MAX_LISTING_DESC_CHARS - 1) + '\u2026'
    : desc
}
```

`description`과 `when_to_use`가 합쳐져서 모델 시스템 프롬프트에 박힌다. 형식:

```
- pr-review: PR의 보안과 스타일을 리뷰한다 - 사용자가 "리뷰 좀", "PR 봐줘" 같은 표현을 쓸 때
- today:     오늘 한 git 작업을 요약한다 - 사용자가 "오늘 뭐 했지", "today" 같은 표현을 쓸 때
```

**`description`은 무엇인지, `when_to_use`는 언제 쓰는지**. 두 필드가 역할이 명확히 분리돼 있다. 모델은 이 두 줄짜리 설명만 보고 지금 부를지 말지를 결정한다.

> 💡 **good description vs bad description.** "코드 리뷰" 같은 description은 너무 일반적이다 — 모델이 언제 부를지 모른다. "PR의 변경사항을 보안 패턴 + 스타일 룰로 검사하고 한국어 코멘트를 만든다" 같은 구체적인 description이 좋다. `when_to_use`가 자연어 트리거를 박아두면 더 강력. 모델이 매칭할 만한 단어 (사용자의 자연어 표현)를 박아두는 게 핵심.

### 1% 컨텍스트 예산 — 스킬 목록은 발견용

```typescript
// SkillTool/prompt.ts:21-29 (축약 — CHARS_PER_TOKEN=4 상수 + 다중 줄 코멘트 생략)
export const SKILL_BUDGET_CONTEXT_PERCENT = 0.01      // 1%
export const DEFAULT_CHAR_BUDGET = 8_000              // Fallback: 1% of 200k × 4
export const MAX_LISTING_DESC_CHARS = 250             // 한 항목 cap (per-entry hard cap)
```

스킬 목록은 컨텍스트 윈도우의 1%만 차지한다. 200k 윈도우면 8000자. 한 항목당 cap 250자.

왜 1%인가? — 라인 25-28의 주석:

> "The listing is for discovery only — the Skill tool loads full content on invoke, so verbose whenToUse strings waste turn-1 cache_creation tokens without improving match rate."

**스킬 목록은 발견용이지 내용 전달용이 아니다**. 매칭 정확도는 **짧은 description**으로 충분. 긴 `when_to_use`는 **prompt cache의 turn-1 cache_creation 토큰만 낭비**. 모델이 "이 스킬이 매칭한다"고 결정하면 — 그때 전체 본문이 로드된다 (10.1의 lazy load 패턴이 여기서도).

그리고 — **번들 스킬은 절대 트렁케이션 안 됨**:

```typescript
// prompt.ts:92-93, 124-141
// Partition into bundled (never truncated) and rest
// Extreme case: non-bundled go names-only, bundled keep descriptions
```

예산이 빠듯해지면 **사용자/플러그인 스킬 description부터 잘리고**, 최악의 경우 비번들은 이름만 노출. **번들 14개는 항상 풀 description으로 보호**. 클로드 코드의 번들 스킬에 대한 신뢰도가 코드에 박혀 있다. 사용자가 만든 스킬보다 번들 스킬이 우선 — 매칭 정확도와 시스템 일관성을 위해.

## Python으로 옮기면

9.3의 **Tool Protocol 5 구성**과 나란히 SKILL.md 로더를 보여준다. **둘 다 같은 도구 풀에 들어간다**는 게 핵심.

```python
# src/mini_claude/skills/skill_md.py
from __future__ import annotations
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any

# 10.1 의 markdown_loader 의 일부 함수를 재사용
from ..commands.markdown_loader import (
    parse_frontmatter,
    substitute_arguments,
    _parse_allowed_tools,
)


@dataclass
class Skill:
    """SKILL.md 가 변환된 스킬. 9.3 의 Tool 과 *같은 자리* 에 산다.

    9.3 의 Tool 은 Python 클래스 + Pydantic 모델 (5 개로 압축 —
    name, description, input_model + call, is_read_only/is_destructive).
    이 Skill 은 *같은 일* (도구를 LLM 에 노출) 을 *완전히 다른 형식*
    (마크다운 + 메타데이터) 으로 한다. 둘 다 mini-claude 의 도구 풀에
    들어간다.
    """
    name: str                                    # 디렉토리 이름
    description: str
    when_to_use: str | None = None               # ⭐ 모델 결정에 들어가는 자연어
    body: str = ""
    base_dir: Path | None = None                 # ${CLAUDE_SKILL_DIR}
    allowed_tools: list[str] = field(default_factory=list)
    user_invocable: bool = True
    disable_model_invocation: bool = False
    argument_names: list[str] = field(default_factory=list)

    def get_prompt(self, args: str = "", session_id: str = "") -> str:
        """*호출 시점* 에 본문을 변환해서 LLM 으로 보낼 텍스트를 만든다.

        진짜 코드의 createSkillCommand (loadSkillsDir.ts:344-401) +
        SkillTool.ts:1077 (MCP) 의 정수를 한 자리에 모은 미니 버전.
        """
        content = self.body

        # ① 인자 치환 (10.1 의 함수 재사용)
        content = substitute_arguments(content, args, self.argument_names)

        # ② ${CLAUDE_SKILL_DIR} — 부속 스크립트 절대 경로 참조
        if self.base_dir:
            content = content.replace(
                "${CLAUDE_SKILL_DIR}",
                str(self.base_dir.absolute()),
            )

        # ③ ${CLAUDE_SESSION_ID} — 세션별 임시 파일/로그용
        content = content.replace("${CLAUDE_SESSION_ID}", session_id)

        # ④ 진짜 코드는 여기서 inline shell 도 실행 + 권한 슬롯 inject
        # (10.1 의 closure 패턴). 미니에선 단순화.

        # ⑤ baseDir 박아두기 — 스킬이 자기 위치를 알 수 있게
        if self.base_dir:
            content = (
                f"Base directory for this skill: {self.base_dir}\n\n{content}"
            )

        return content


def load_skill(skill_dir: Path) -> Skill | None:
    """*디렉토리 한 개 → Skill 한 개*.

    진짜 코드의 loadSkillsFromSkillsDir 의 미니. *디렉토리가 아니면*
    또는 *SKILL.md 가 없으면* None.
    """
    if not skill_dir.is_dir():
        return None  # ⭐ 평탄 .md 거부 — 진짜 코드 425 라인의 미니

    skill_md = skill_dir / "SKILL.md"  # ⭐ 고정된 이름
    if not skill_md.exists():
        return None

    text = skill_md.read_text(encoding="utf-8")
    frontmatter, body = parse_frontmatter(text)

    # description fallback (10.1 과 같음)
    description = frontmatter.get("description")
    if not description:
        first_line = next(
            (line.strip() for line in body.split("\n") if line.strip()),
            "",
        )
        description = first_line[:80]

    return Skill(
        name=skill_dir.name,             # ⭐ 디렉토리 이름 = 스킬 이름
        description=description,
        when_to_use=frontmatter.get("when_to_use"),
        body=body,
        base_dir=skill_dir,
        allowed_tools=_parse_allowed_tools(frontmatter.get("allowed-tools", "")),
        user_invocable=frontmatter.get("user-invocable", True),
        disable_model_invocation=frontmatter.get("disable-model-invocation", False),
        argument_names=str(frontmatter.get("arguments", "")).split(),
    )


def discover_skills(cwd: Path, home: Path) -> list[Skill]:
    """*walker* — 진짜 코드의 getProjectDirsUpToHome 의 미니.

    cwd → 부모로 걷다가 *git 경계* 에서 멈춤. 그 다음 home dir 도 추가.
    각 .claude/skills/ 디렉토리 안의 *모든 서브 디렉토리* 를 스킬로 시도.
    """
    dirs: list[Path] = []

    current = cwd.resolve()
    home_resolved = home.resolve()
    while current != current.parent and current != home_resolved:
        skills_dir = current / ".claude" / "skills"
        if skills_dir.is_dir():
            dirs.append(skills_dir)
        if (current / ".git").exists():
            break
        current = current.parent

    user_skills = home_resolved / ".claude" / "skills"
    if user_skills.is_dir():
        dirs.append(user_skills)

    seen: dict[str, Skill] = {}
    for d in reversed(dirs):  # 낮은 우선순위부터
        for entry in d.iterdir():
            skill = load_skill(entry)  # ← 디렉토리만 통과
            if skill is None:
                continue
            seen[skill.name] = skill   # 같은 이름은 높은 우선순위가 덮음

    return list(seen.values())
```

이제 **모델 invoke 경로** — `SkillTool`의 미니 버전.

```python
# src/mini_claude/tools/skill_tool.py
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any
from pydantic import BaseModel, Field
from .base import Tool, ToolContext
from ..skills.skill_md import Skill


# 진짜 코드의 SKILL_BUDGET_CONTEXT_PERCENT = 0.01
SKILL_BUDGET_CHARS = 8_000
MAX_LISTING_DESC_CHARS = 250


class SkillToolInput(BaseModel):
    skill: str = Field(description="The name of the skill to invoke")
    args: str = Field(default="", description="Optional arguments")


def format_skill_listing(skills: list[Skill]) -> str:
    """모델이 보는 스킬 목록 — 진짜 코드의 formatCommandsWithinBudget 미니.

    1% 컨텍스트 예산 안에 맞춤. 한 항목 250 자 cap.
    """
    lines = []
    total_chars = 0

    for skill in skills:
        if skill.disable_model_invocation:
            continue  # ⭐ 모델 게이트

        # description + when_to_use 합치기
        if skill.when_to_use:
            desc = f"{skill.description} - {skill.when_to_use}"
        else:
            desc = skill.description

        # 한 항목 cap
        if len(desc) > MAX_LISTING_DESC_CHARS:
            desc = desc[:MAX_LISTING_DESC_CHARS - 1] + "…"

        line = f"- {skill.name}: {desc}"

        # 예산 체크
        if total_chars + len(line) > SKILL_BUDGET_CHARS:
            break

        lines.append(line)
        total_chars += len(line) + 1  # +1 for newline

    return "\n".join(lines)


@dataclass
class SkillTool:
    """모델이 *발견해서 부르는* 진짜 SkillTool 의 미니.

    9.3 의 Tool Protocol 을 따르므로 *다른 도구와 같은 풀에 들어간다*.
    9.4 의 권한 게이트도 그대로 통과한다.
    """

    name: str = "Skill"
    skills: list[Skill] = field(default_factory=list)
    input_model: type[BaseModel] = SkillToolInput

    @property
    def description(self) -> str:
        """모델이 보는 시스템 프롬프트 — 진짜 코드의 prompt.ts:173 의 압축.

        가장 중요한 두 가지를 *그대로* 옮긴다:
        1. *slash command = skill* 동일시
        2. *BLOCKING REQUIREMENT* + *NEVER mention without calling*
        """
        listing = format_skill_listing(self.skills)
        return f"""Execute a skill within the main conversation.

When users ask you to perform tasks, check if any of the available skills
match. Skills provide specialized capabilities and domain knowledge.

When users reference a "slash command" or "/<something>" (e.g., "/today",
"/pr-review"), they are referring to a skill. Use this tool to invoke it.

Available skills:
{listing}

Important:
- When a skill matches the user's request, this is a BLOCKING REQUIREMENT:
  invoke the relevant Skill tool BEFORE generating any other response.
- NEVER mention a skill without actually calling this tool.
"""

    def is_read_only(self) -> bool:
        return False  # 자식 스킬이 뭘 할지 모르므로 fail-closed

    def is_destructive(self) -> bool:
        return False

    def permission_summary(self, args: dict[str, Any]) -> str:
        return args.get("skill", "")

    async def call(self, args: dict[str, Any], context: ToolContext) -> str:
        skill_name = args["skill"]
        skill_args = args.get("args", "")

        skill = next(
            (s for s in self.skills if s.name == skill_name),
            None,
        )
        if skill is None:
            return f"Skill not found: {skill_name}"

        if skill.disable_model_invocation:
            return f"Skill {skill_name} is not available for model invocation."

        # 본문을 변환해서 *사용자 메시지처럼* 돌려준다.
        # 진짜 코드는 여기서 *서브 에이전트* 로 실행 (executeForkedSkill).
        # 미니는 단순화 — 부모가 다음 턴에서 이 텍스트를 보고 *해당 작업을* 한다.
        prompt = skill.get_prompt(skill_args)

        return f"Skill {skill_name} loaded. Now execute the following task:\n\n{prompt}"
```

## 핵심 정리

- **SKILL.md는 디렉토리가 단위** — 평탄 .md 형식이 명시적으로 거부된다 (`loadSkillsDir.ts:425`). 디렉토리 한 개 = 스킬 한 개의 1:1 대응이 `${CLAUDE_SKILL_DIR}`가 유일하게 잘 정의되기 위한 조건. 부속 스크립트 + 설정 + 마크다운이 한 곳에 산다.
- **두 가지 invoke 경로**: 사용자 `/myskill` (slash command)과 모델 `SkillTool` (자동 발견). 두 게이트 필드의 교차 가능 — `user-invocable` (사용자 자동완성), `disable-model-invocation` (모델 발견). 4가지 조합 모두 의미 있는 케이스가 있다.
- **충격 1**: 모델이 보는 SkillTool 시스템 프롬프트에 **"slash command = skill"**이 명시적으로 박혀 있다 (`prompt.ts:178`). 10.1의 **commands_DEPRECATED** 폭로의 진짜 의미: **두 시스템이 미래에 합쳐질 게 아니라, 모델 입장에서는 이미 합쳐져 있다**. 디렉토리 두 개는 사람의 멘탈 모델을 위한 과도기적 구분.
- **충격 2**: **"BLOCKING REQUIREMENT: invoke the Skill tool BEFORE generating any other response"** + **"NEVER mention a skill without actually calling this tool"** — 모델이 말로만 스킬을 언급하는 **흔한 LLM 함정**을 대문자로 강조해서 막는다. **production LLM 시스템 프롬프트의 작은 트릭** — 대문자 강조에 LLM이 민감하다는 사실을 활용.
- **`when_to_use`가 모델 결정에 직접 들어가는 자리**: `description`은 무엇인지, `when_to_use`는 언제 쓰는지. 두 필드가 역할 분리. 모델이 보는 형식 — `- skill_name: description - when_to_use`. 좋은 description보다 **좋은 when_to_use**가 자동 발견의 핵심.
- **1% 컨텍스트 예산** + 번들 스킬 항상 보호: 스킬 목록은 발견용이지 내용 전달용이 아니다. 8000자 (200k × 1%) 안에서 한 항목당 cap 250자. 예산 부족 시 비번들부터 잘리고, 최악엔 비번들은 이름만. **번들 14개는 항상 풀 description 보호** — 시스템 일관성과 매칭 정확도 우선.
- **`commands_DEPRECATED`도 `getSkillToolCommands`에서 그대로 노출된다** (`commands.ts:578`). 10.1에서 만든 마크다운 명령도 모델이 발견해서 부를 수 있다. **deprecated라도 호환성이 코드에 박혀 있다**.
- **`hasUserSpecifiedDescription || whenToUse`** 조건은 **plugin/MCP 명령**에만 적용. **자동 추출된 description** (본문 첫 줄)만 있는 것은 질이 낮을 수 있어서 모델 발견에는 안 쓴다. **명시적 메타데이터의 가치**.
- **9.3 회수**: **Python 클래스 + 5 구성** (Tool Protocol — name/description/input_model + call/is_read_only/is_destructive)와 **마크다운 + frontmatter 16 필드** (SKILL.md)가 같은 일을 다른 형식으로 한다. 둘 다 같은 도구 풀에 들어간다. **언어 형식의 차이가 기능의 차이가 아니다**.
- **다음 (10.3)**: MCP 서버를 직접 만들기. 지금까지는 기존 도구를 노출 (skill, command)하는 자리였다. 10.3은 밖에서 새 도구를 만들어 들여오기. **외부 프로세스 + JSON-RPC**라는 새 차원이 들어온다.
