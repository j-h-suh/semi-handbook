# 9.0 학습자 환경 설정 — Bedrock 첫 호출까지의 최소 셋업

미니 클로드를 AWS Bedrock 의 Claude 모델로 실행하려면 _Bedrock API key_ 한 개와 환경변수 네 개만 있으면 됩니다.

## 왜 Bedrock 의 Claude 인가 — 큰 그림

LLM API 는 _공급자_ (Anthropic / AWS / GCP / Azure / OpenAI / Google) 와 _인터페이스 모양_ (Anthropic / OpenAI / Google 세 가족) 두 레이어가 따로 움직입니다. 미니 클로드는 _AWS Bedrock 의 Claude 모델_ — _공급자는 AWS_, _인터페이스는 Anthropic 가족_ — 을 _기본_ 으로 씁니다. 사내 표준이 AWS 인 환경에서 가장 자연스러운 진입점이기 때문.

> 💡 **다른 옵션의 전체 매트릭스** (Vertex / Azure Foundry / vLLM 자체 호스팅 / Gemini / OpenAI 직접 등) 와 _3 인터페이스 가족 비교_ 는 [§10.5 §0 "LLM API 가족 — 한 장 정리"](/claude/10_5_API_클라이언트) 참조. 이번 9.0 은 _미니 클로드의 기본 자리_ — Bedrock 의 Claude — 셋업에 집중. _Vertex / vLLM_ 으로 가는 길은 맨 끝 §"다른 백엔드" 에.

## 전제

학습자가 _이미 갖추고 있어야_ 하는 것은 **AWS 자격증명** 한 묶음뿐입니다:

- **AWS 계정** + 결제(billing) 활성화
- **Amazon Bedrock 에서 Claude 모델 액세스 활성화** ([Bedrock Console](https://console.aws.amazon.com/bedrock) → Model access → Claude → Enable)
- **Bedrock API key** — Bedrock 콘솔에서 발급 (Bearer 토큰)
- 모델을 호출할 **AWS region** 결정 (예: `us-east-1`, `ap-northeast-2`)

> 위 전제가 안 갖춰져 있으면 _그것부터_ 해결하세요. 계정부터 시작한다면 [AWS 공식 — Amazon Bedrock 시작하기](https://docs.aws.amazon.com/bedrock/latest/userguide/getting-started.html) 의 _Set up_ 절을 따르면 됩니다.

_개발 환경 (Python / uv)_ 은 아래 §0 에서 처음부터 안내합니다.

## 0. 개발 환경 준비 — 빈 머신부터 시작하는 경우

이미 작업 디렉토리가 있고 `uv` 가 설치된 상태라면 §1 로 건너뛰어도 됩니다.

### 0-1. 필요한 도구 설치

| 도구 | 최소 버전 | 설치 (macOS / Linux) |
|---|---|---|
| Python | 3.12 | `brew install python@3.12` 또는 시스템 패키지 매니저 (`uv` 가 자동 관리 가능) |
| uv | 최신 | `curl -LsSf https://astral.sh/uv/install.sh \| sh` 또는 `brew install uv` |

> 💡 **Python 자체 설치가 부담스러우면 `uv` 만 깔아도 됩니다.** `uv sync` 가 `pyproject.toml` 의 `requires-python` 을 보고 _자동으로_ Python 3.12 를 download / pin 해줍니다 (`uv python install 3.12` 도 명시적으로 가능).

### 0-2. 작업 디렉토리 만들기 + uv 프로젝트 초기화

학습자 본인의 빈 디렉토리에서 `uv init` 으로 프로젝트 골격을 만듭니다:

```bash
mkdir -p ~/mini-claude
cd ~/mini-claude
uv init
```

이 디렉토리가 _이번 챕터 내내 작업 cwd_ 입니다. 이후의 `.env` / `uv sync` 모두 여기 기준.

`uv init` 이 자동으로 만드는 파일은 여섯 개입니다:

| 파일 | 역할 | 9.1 에서 |
|---|---|---|
| `.git/` + `.gitignore` | git 초기화 + Python 표준 ignore (`.venv`, `__pycache__` 등) | `.gitignore` 에 `.env` 추가 (§1) |
| `pyproject.toml` | _빈 dependencies_ 의 프로젝트 manifest | _덮어쓰기_ — 의존성 + `[project.scripts]` + `[build-system]` 추가 |
| `main.py` | 빈 hello world | 사용 안 됨 (진짜 진입점은 `src/mini_claude/main.py`) |
| `README.md` | 빈 README | 학습자 자유 |
| `.python-version` | `requires-python` 의 Python 버전 pin | 그대로 유지 |

> 💡 **`uv init` 의 _뼈대_ 위에 _살을 붙이는_ 흐름**. 9.1 부터 디렉토리 구조 / `pyproject.toml` 내용 / Python 스캐폴드를 _하나씩_ 채워 갑니다 — `uv init` 이 준 빈 골격 일부 (`pyproject.toml`) 는 _덮어쓰기_, 나머지 (`src/mini_claude/agent.py`, `messages.py`, `tools/...`) 는 _새로 작성_, root `main.py` 는 _그대로 두거나 삭제_.

## 1. API key 안전한 자리에 두기

Bedrock API key 는 _파일_ 이 아니라 _문자열 토큰_ 이라, 별도 키 파일 없이 `.env` 에 직접 둡니다 (9.1 끝에서 작성). 대신 `.env` 가 git 에 올라가지 않게, §0-2 의 `uv init` 이 만든 `.gitignore` 에 한 줄을 추가합니다:

```bash
cat >> .gitignore <<'EOF'

# 학습 환경 추가분
.env
EOF
```

이 한 줄로 9.1 에서 만들 `.env` 가 _git add 대상에서 제외_ 됩니다. 같이 만들 `.env.example` 은 _정확 매칭이 아니라_ 그대로 git 에 들어갑니다 — 학습자/팀이 _어떤 변수가 필요한지_ 보는 _구조 문서_ 역할 (실제 토큰 자리는 비워 둠).

> ⚠️ **API key 는 자격증명입니다**: `AWS_BEARER_TOKEN_BEDROCK` 토큰이 유출되면 _과금되는 모델 호출_ 에 그대로 쓰입니다. `.env` 를 git 커밋·압축 공유에 절대 포함하지 마세요. 유출이 의심되면 Bedrock 콘솔에서 키를 _폐기(revoke)_ 후 재발급하면 됩니다.

## 2. 환경 변수 — `.env` 가 받을 변수들의 의미

미니 클로드는 `python-dotenv` 가 시작 시 작업 cwd 의 `.env` 를 자동 로드해 아래 변수를 환경 변수로 올립니다. _실제 파일 작성과 첫 실행은 9.1 끝_ 에서 진행합니다. 여기서는 _각 변수가 무엇을 받는지_ 만 미리 알아둡니다.

| 변수 | 받는 값 | 예시 |
|---|---|---|
| `MINI_LLM_PROVIDER` | 백엔드 선택 (미설정 시 기본 `bedrock`) | `bedrock` |
| `AWS_BEARER_TOKEN_BEDROCK` | Bedrock 콘솔에서 발급한 API key | `ABSKQmVk...` |
| `AWS_REGION` | 모델을 호출할 region | `us-east-1` / `ap-northeast-2` |
| `MINI_LLM_MODEL` | 호출할 모델 ID (콘솔의 모델 카탈로그에서 복사) | `global.anthropic.claude-opus-4-8` |
| `MINI_LLM_MAX_TOKENS` | 한 응답의 max_tokens (선택 — 미설정 시 4096) | `4096` |

> 💡 **모델 ID 는 콘솔에서 그대로 복사**. AWS Console → Bedrock → 모델 카탈로그에서 호출하려는 Claude 모델의 ID 를 복사해 `MINI_LLM_MODEL` 에 붙여넣으면 됩니다. region 에 따라 호출 가능한 모델이 다르니, 액세스를 켠 region 과 `AWS_REGION` 을 맞추세요.

> 💡 **vLLM 등 다른 백엔드를 쓰려면** `MINI_LLM_PROVIDER=vllm` 과 다른 변수 묶음이 필요합니다. 이 챕터의 _주 흐름은 Bedrock_ 이라 §"다른 백엔드" 절에 따로 안내합니다.

여기까지가 _코드를 쓰기 전 환경_ 입니다. 이어지는 **9.1 설계 — 미니 클로드의 골격** 에서 디렉토리 구조 / `pyproject.toml` / Python 스캐폴드를 손으로 작성한 뒤, 그 챕터 끝에서 `.env.example` 작성 → `cp .env.example .env` → 값 편집 → `uv sync` → `uv run mini-claude` 첫 실행까지 한 흐름으로 진행합니다.

## 흔한 막힘

> 아래 에러는 _9.1 끝 첫 실행_ 또는 _9.2 이후 진짜 응답 호출_ 시 만나는 것들. 실행 단계에서 막히면 이 표로 돌아와 참조하세요.

| 에러 | 원인 | 해결 |
|---|---|---|
| `RuntimeError: ... AWS_BEARER_TOKEN_BEDROCK 환경변수 필수` | 토큰 미설정 / `.env` 미로드 | §1·§2 다시 |
| `ValueError: Unable to determine which files to ship inside the wheel` | `src/mini_claude/__init__.py` 누락 — `pyproject.toml` 의 `name = "mini-claude"` 를 hatchling 이 `mini_claude` 디렉토리로 찾는데 없음 | `mkdir -p src/mini_claude && touch src/mini_claude/__init__.py` (스캐폴드 작성 전 우회) |
| `403` (model not available for this account) | 계정에 해당 모델 액세스 미승인 | _전제_ 의 Model access 에서 Claude 활성화 |
| `400` (model identifier is invalid) | 모델 ID 형식 / region 불일치 | 콘솔 모델 카탈로그에서 정확한 ID 복사, `AWS_REGION` 과 일치 확인 |

> 💡 **403 과 400 의 구분**: 둘 다 _인증은 통과_ 한 상태다. `403` 은 _그 모델을 쓸 권한_ 이 없는 것 (Model access 켜기), `400` 은 _모델 ID 문자열_ 이 그 region 에서 안 통하는 것 (콘솔에서 정확한 ID 복사). 토큰 자체가 틀리면 `401` 이 난다.

## 비용 안내

- Bedrock 의 Anthropic Claude 는 _per-token 과금_ — _free tier 없음_
- _짧은 prompt + 짧은 max_tokens_ 권장 (미니 클로드 기본 `max_tokens=4096`)
- 사용량은 AWS Console → Billing (또는 Bedrock → Usage) 에서 확인

> 💡 **무료로 먼저 체험하고 싶다면** §"다른 백엔드" 의 _NVIDIA NIM_ 경로를 보세요. build.nvidia.com 의 무료 크레딧으로 OpenAI-호환 백엔드를 카드 없이 돌려볼 수 있습니다 (자세히는 [10.5](/claude/10_5_API_클라이언트)).

## 다른 백엔드

미니 클로드는 `MINI_LLM_PROVIDER` 한 줄로 백엔드를 바꿉니다. Bedrock 외의 자리:

### Vertex (GCP, Claude) — 대체

GCP project + Service Account JSON 이 있는 환경:

```bash
# .env (작업 cwd)
MINI_LLM_PROVIDER=vertex
GOOGLE_APPLICATION_CREDENTIALS=secrets/your-sa-key.json   # SA JSON 의 cwd 기준 상대 경로
VERTEX_PROJECT_ID=your-gcp-project                        # SA JSON 의 project_id 와 동일
VERTEX_LOCATION=global                                    # global / us-east5 / europe-west1 등
MINI_LLM_MODEL=claude-opus-4-7                            # Model Garden 에서 enable 한 alias
```

> 💡 **Vertex 는 SA JSON 키 파일** 을 쓰므로 `secrets/` 폴더에 키를 두고 (`chmod 600`), `.gitignore` 에 `secrets/` 도 추가하세요. Model Garden 에서 Claude 모델을 opt-in 해야 합니다.

### vLLM / NVIDIA NIM (OpenAI 호환) — 무료 체험

로컬 vLLM 서버 또는 NVIDIA NIM (무료 크레딧):

```bash
# .env (작업 cwd)
MINI_LLM_PROVIDER=vllm
MINI_LLM_MODEL=google/gemma-4-31b-it                # NIM 모델 ID (로컬이면 서빙 모델명)
VLLM_BASE_URL=https://integrate.api.nvidia.com/v1   # 로컬이면 http://localhost:8000/v1
VLLM_API_KEY=nvapi-xxx                              # 로컬 vLLM 은 보통 키 검증 안 함 (dummy)
```

`python-dotenv` 가 `mini-claude` 시작 시 `.env` 를 자동 로드 — 별도 `export` 불필요. 세 백엔드의 구조적 차이(구조적 타이핑 vs 어댑터)와 tool use 변환은 핸드북 **10.5 API 클라이언트** 챕터에서 자세히 다룹니다.
