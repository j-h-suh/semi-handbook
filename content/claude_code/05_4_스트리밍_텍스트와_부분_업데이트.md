# 5.4 스트리밍 텍스트와 부분 업데이트 — diff로 ANSI 셀만 다시 쓰기

---

## 이 챕터에서 배우는 것

- LLM 토큰이 한 글자씩 흘러나올 때 화면이 왜 안 깜빡이는지
- 매 토큰마다 전체 화면을 다시 그리지 않는다는 사실 — 바뀐 셀만 다시 쓴다
- `log-update.ts`의 `render(prev, next)` 함수가 두 프레임을 비교해서 **최소 ANSI escape 시퀀스**를 뽑는 메커니즘
- **style 전이**가 미리 캐시된 문자열로 처리되는 영리함
- Part 5(터미널 UI) 전체를 **셀 단위 diff**라는 한 줄로 마무리

---

## 사용자 경험에서 출발

LLM 응답이 한 글자씩 흘러나온다.

```
> 이 함수 설명해줘

이                    ← 토큰 1: "이"
이 함수는              ← 토큰 2: " 함수는"
이 함수는 두 숫자를     ← 토큰 3: " 두 숫자를"
이 함수는 두 숫자를 더한다.  ← 토큰 4: " 더한다."
```

각 토큰이 도착할 때마다 — 문자열이 점점 길어진다. 사용자가 보는 건 이미 있던 글자에 새 글자가 덧붙는 모습이다.

근데 5.1~5.3에서 본 걸 떠올리자. 이건 **React 컴포넌트**다. 상태가 바뀌면 React가 컴포넌트를 다시 렌더한다. 그 다음에 Ink가 그걸 **Screen 버퍼에 그린다**. 그러면 — 매 토큰마다 화면 전체를 다시 그리는 것이 아닌가? 그러면 깜빡여야 한다. 

그런데 안 깜빡인다. 이미 있는 글자는 그대로 있고, 새 글자만 추가된다. 어떻게? 답은 — **`log-update.ts`의 frame diff**.

## 본문

### 두 프레임을 비교한다 — `log-update.ts:123`

`src/ink/log-update.ts`의 `render` 메서드. 시그니처가 핵심을 다 말해준다.

```typescript
render(
  prev: Frame,
  next: Frame,
  altScreen = false,
  decstbmSafe = true,
): Diff
```

이전 프레임과 새 프레임을 받아서 — `Diff`를 돌려준다. `Diff`는 터미널에 보낼 명령들의 배열이다. 커서 이동, 문자 출력, 스타일 변경 같은 것들. (`decstbmSafe`는 뒤에 나오는 **DECSTBM 하드웨어 스크롤**에서 다시 등장한다.)

여기서 핵심 — **`next`를 통째로 그리지 않는다**. `prev`와 다른 부분만 찾아서, 그 부분만 명령으로 만든다. 

```typescript
diffEach(prev.screen, next.screen, (x, y, removed, added) => {
  if (added) {
    moveCursorTo(screen, x, y)              // 커서를 그 위치로
    const styleStr = stylePool.transition(currentStyleId, added.styleId)
    if (writeCellWithStyleStr(screen, added, styleStr)) {
      currentStyleId = added.styleId
    }
  }
})
```

```python
# Python 등가 — 셀 단위 diff의 핵심 로직
def diff_screens(prev: list[list[str]], next_: list[list[str]]) -> list[str]:
    """두 Screen을 비교해서 바뀐 셀만 ANSI 명령으로 만든다."""
    commands = []
    for y, (prev_row, next_row) in enumerate(zip(prev, next_)):
        for x, (prev_cell, next_cell) in enumerate(zip(prev_row, next_row)):
            if prev_cell != next_cell:
                commands.append(f"\x1b[{y+1};{x+1}H{next_cell}")
                # ↑ 커서 이동 + 새 문자 출력. 안 바뀐 셀은 건너뜀.
    return commands
```

`diffEach`는 셀 단위로 두 Screen을 비교한다. 같으면 건너뛴다. 다르면 콜백을 호출. 콜백 안에서 — 그 셀 하나에 대한 명령을 만든다.

```
prev:                  next:
  "Hello"                "Hello, world"
                                   ^
                                   여기부터 다름
```

`diffEach`가 위 둘을 비교하면 — **"Hello"는 같다**. **"d"(5번째)부터 다르다**. 콜백이 호출되는 건 5번째 셀부터 12번째 셀까지. **0~4번째 셀은 전혀 건드리지 않는다**.

### 그래서 터미널에 진짜로 보내지는 것

위 예시의 `prev → next` 변환을 위해 stdout에 보내지는 건 — 대략 이런 ANSI escape sequence다.

```
\x1b[5G          ← 커서를 5번째 컬럼으로
, world          ← 새 문자만
```

총 11바이트. 전체 12바이트짜리 새 메시지를 다시 안 보냈다. 전체 60줄짜리 화면을 다시 안 그렸다. **딱 11바이트.** 

이게 왜 깜빡이지 않는지의 답이다. **기존 글자가 터치되지 않으니까**. 터미널 입장에서는 — "5번째 위치로 가서 여기에 글자 좀 더 써라"라는 작은 패치만 받았다. 비는 순간이 없다. 재계산도 없다. 그냥 덧붙는다.

### Style 전이도 캐시한다

매 셀마다 색상이 다를 수도 있다. 예를 들어 `"Hello, "` 는 흰색이고 `"world"` 는 빨간색이라면 — 5번째 셀에서 흰색→빨간색 전이가 필요하다. ANSI escape는 `\x1b[31m`이다.

```typescript
const styleStr = stylePool.transition(currentStyleId, added.styleId)
```

이 한 줄이 영리하다. **`stylePool.transition(from, to)`**은 **(from, to) 쌍을 키로 캐싱**된 문자열을 돌려준다. 같은 전이가 두 번 일어나면 — 문자열을 다시 안 만든다. 캐시된 결과를 그대로 쓴다.

```
첫 번째: "white → red" 전이 → "\x1b[31m" 계산하고 캐시
두 번째: 같은 전이 → 캐시 히트, 0ms
세 번째: 같은 전이 → 캐시 히트, 0ms
...
```

긴 응답에서 같은 색 → 같은 색의 전이가 수만 번 발생한다. 캐싱으로 문자열 할당이 거의 없다. **GC 압력이 0에 가깝다**. 60Hz로 토큰이 흘러도 CPU가 놀고 있는 비결.

### DECSTBM 하드웨어 스크롤 — 더 영리한 한 단계

스크롤이 **셀 diff보다 더 빠르게** 처리되는 케이스가 있다. 사용자가 스크롤하면 — 모든 셀이 위로 한 줄씩 옮겨진다. 셀 단위 diff로 처리하면 수천 셀이 다 바뀐 것으로 보인다. 모두 다시 출력? 느리다.

`log-update.ts:166`의 **DECSTBM 최적화**.

```typescript
// (축약: top/bottom 경계 검사 생략)
if (altScreen && next.scrollHint && decstbmSafe) {
  const { top, bottom, delta } = next.scrollHint
  shiftRows(prev.screen, top, bottom, delta)
  scrollPatch = [{
    type: 'stdout',
    content: setScrollRegion(top + 1, bottom + 1) +
             (delta > 0 ? csiScrollUp(delta) : csiScrollDown(-delta)) +
             RESET_SCROLL_REGION + CURSOR_HOME,
  }]
}
```

해석: **"스크롤이 일어났다는 힌트가 있으면, 터미널의 하드웨어 스크롤 명령(CSI top;bot r → CSI n S/T)을 직접 보낸다. 셀들을 다시 그릴 필요 없이 터미널이 자체적으로 행을 옮긴다."**

**터미널 자체에 그 일을 시킨다.** 우리가 셀을 옮기지 않는다. ANSI escape sequence 두세 줄로 수천 셀이 한 번에 옮겨진다. 영리함의 절정이다.

> 🔬 **Deep Dive — 왜 화면 갱신이 그렇게나 어려운지.** `log-update.ts`는 약 770줄짜리 파일이다. 위에 본 **기본 diff**만으로는 안 끝난다. 진짜로 처리해야 하는 케이스: viewport 리사이즈(width 변경 → 텍스트 재줄바꿈 → 모든 게 어긋남), 커서 위치 추적(터미널마다 다르게 동작), wide character(CJK, 이모지)의 너비 처리, scroll region 안과 밖의 차이, **cursor-restore가 일으키는 1행 스크롤**, 이모지 너비를 잘못 아는 옛 터미널을 위한 **width compensation**. 한 줄짜리 코멘트가 다 과거의 사고다. `renderFrameSlice` 함수 안 (`log-update.ts:547` 부근)에는 이런 코멘트가 박혀 있다 — **"CSI CUD stops at the viewport bottom margin and cannot scroll, but LF scrolls the viewport to create new lines. Without this, when the cursor is at the viewport bottom, moveCursorTo's cursor-down silently fails, creating a permanent off-by-one between the virtual cursor and the real terminal cursor."** 한 줄짜리 코멘트 안에 "왜 LF여야 하는가", "틀리면 무슨 일이 벌어지는가", "어떤 가설이 깨지는가"가 다 들어 있다. 터미널은 환경이지 **API**가 아니다. 사양이 없고 경험적 합의만 있다. 모든 터미널에서 깜빡이지 않게 그리려면 — 이런 디테일을 수십 개 다 알아야 한다. 770줄이 과한 게 아니다.

### Part 5 통합 — 셀 단위 diff가 모든 것을 받친다

5장 전체를 한 줄로 정리하면 이렇게 된다.

> **터미널 UI는 셀 단위 diff에 모든 것을 건다.**

- **5.1** Ink가 React 트리를 **Screen 셀 버퍼**로 변환한다.
- **5.2** AppState는 부분 구독 (selector)으로 변화한 슬라이스만 컴포넌트에 알린다.
- **5.3** VirtualScroll은 보이지 않는 부분을 아예 **fiber로 만들지 않는다**.
- **5.4** `log-update`는 **Screen 버퍼 두 개를 비교**해서 바뀐 셀만 terminal에 쓴다.

각 층이 "안 바뀐 건 건드리지 않는다"는 같은 원칙을 따른다. **React → Ink → Yoga → cell → ANSI**의 다섯 층을 따라 내려가면서, 변화 없는 부분이 매 단계 걸러진다. 마지막에 stdout으로 나가는 건 **진짜로 바뀐 부분의 ANSI escape sequence**뿐이다.

이게 **60Hz 매끄러운 터미널 UI**의 비결이다. 그리고 왜 `printf`로는 만들 수 없었는지의 이유다. 아무 한 층이 빠지면, 다른 층의 효율이 무의미해진다. **다섯 층이 다 있어야** 진짜로 가벼운 UI가 된다.

## Python으로 옮기면

셀 단위 diff의 가장 작은 형태를 Python으로 옮기면 이렇게 생겼다.

```python
from __future__ import annotations
from dataclasses import dataclass, field


@dataclass
class Cell:
    char: str
    style: str = ""   # ANSI escape (e.g. "\x1b[31m" for red)


@dataclass
class Screen:
    width: int
    height: int
    cells: list[list[Cell | None]] = field(default_factory=list)
    
    def __post_init__(self) -> None:
        if not self.cells:
            self.cells = [[None] * self.width for _ in range(self.height)]


# ─── 핵심: 두 Screen을 diff해서 ANSI escape sequence를 만든다 ────────────────
def render_diff(prev: Screen, next_: Screen) -> str:
    """변경된 셀만 최소 escape sequence로."""
    out: list[str] = []
    current_style = ""
    
    for y in range(next_.height):
        for x in range(next_.width):
            old_cell = (
                prev.cells[y][x]
                if y < prev.height and x < prev.width
                else None
            )
            new_cell = next_.cells[y][x]
            
            # 같으면 건너뜀 — 핵심
            if old_cell == new_cell:
                continue
            
            if new_cell is None:
                # 삭제: 공백으로 덮어씀
                out.append(f"\x1b[{y + 1};{x + 1}H ")
                continue
            
            # 커서 이동 (1-based)
            out.append(f"\x1b[{y + 1};{x + 1}H")
            
            # 스타일 전이 (전이만 — 같으면 안 보냄)
            if new_cell.style != current_style:
                out.append("\x1b[0m")  # reset
                if new_cell.style:
                    out.append(new_cell.style)
                current_style = new_cell.style
            
            # 글자
            out.append(new_cell.char)
    
    return "".join(out)


# ─── 사용 ────────────────
prev = Screen(width=20, height=2)
prev.cells[0] = [Cell("H"), Cell("e"), Cell("l"), Cell("l"), Cell("o")] + [None] * 15

next_ = Screen(width=20, height=2)
next_.cells[0] = [
    Cell("H"), Cell("e"), Cell("l"), Cell("l"), Cell("o"),
    Cell(","), Cell(" "),
    Cell("w", style="\x1b[31m"),
    Cell("o", style="\x1b[31m"),
    Cell("r", style="\x1b[31m"),
    Cell("l", style="\x1b[31m"),
    Cell("d", style="\x1b[31m"),
] + [None] * 8

diff = render_diff(prev, next_)
import sys
sys.stdout.write(diff)
sys.stdout.flush()

# 출력 (보이지 않는 escape 포함):
# "\x1b[1;6H,\x1b[1;7H \x1b[1;8H\x1b[0m\x1b[31mw\x1b[1;9Ho\x1b[1;10Hr\x1b[1;11Hl\x1b[1;12Hd"
#
# 사람이 보는 건: 기존 "Hello" 뒤에 ", world"가 빨간색으로 덧붙어 나타남
# 깜빡임 없음.
```

핵심 셋이 다 있다.

1. **`if old_cell == new_cell: continue`** — 같으면 건너뜀. diff의 본질.
2. **`\x1b[y;xH`** — 커서 직접 이동. 화면 클리어 안 함.
3. **스타일 전이 비교** — **같은 색이면 escape를 안 보냄**.

진짜 `log-update.ts`는 여기에 **DECSTBM 스크롤**, **wide char 처리**, **resize 처리**, **style pool 캐싱** 등 수십 개 디테일이 더해진 게 약 770줄이다. 본질은 이 50줄이다.

> 💡 **Python 라이브러리 매핑.** `prompt_toolkit`이나 `rich` 같은 라이브러리도 내부적으로 **비슷한 셀 diff**를 한다. `rich.live`의 **Live display**가 정확히 이 패턴 — 이전 렌더와 새 렌더를 비교해서 변경된 부분만 다시 그린다. Textual은 더 정교하게 **fragment 단위 diff**를 한다. **모든 좋은 터미널 UI 라이브러리**가 이 본질을 공유한다.

## 핵심 정리

- 매 토큰마다 화면 전체를 다시 그리지 않는다. **`render(prev, next)`**가 두 Screen 버퍼를 셀 단위로 비교해서 바뀐 셀만 terminal에 쓴다.
- 변경된 셀에 대해서만 — 커서 이동 (`\x1b[y;xH`) + 스타일 전이 + 글자. 안 바뀐 셀은 터치하지 않는다 → 깜빡임 없음.
- **`stylePool.transition(from, to)`**가 ANSI escape 전이 문자열을 캐시. 같은 전이가 수만 번 일어나도 문자열 할당 0. GC 압력 거의 없음.
- **DECSTBM 하드웨어 스크롤** — 스크롤은 터미널 자체에 시킨다. 셀을 다시 그리지 않고 **세 줄짜리 escape sequence**로 수천 셀이 한 번에 옮겨진다.
- 약 770줄짜리 `log-update.ts`의 대부분은 터미널의 사양 없는 현실과 싸우는 코드 — viewport resize, 커서 추적, wide char/이모지 width compensation, scroll region 경계, cursor-restore의 부수효과 등.
- **Part 5 통합**: 터미널 UI는 "안 바뀐 건 건드리지 않는다"라는 한 원칙이 5층(React → Ink → Yoga → cell → ANSI)을 관통한다. 어느 한 층이 빠지면 다른 층의 효율이 무의미. 다섯 층이 다 있어야 **60Hz 매끄러운** 터미널 UI가 된다.
- **Part 5 끝.** 다음 Part 6는 공유 상태와 권한 시스템. 5.2에서 본 AppState가 권한 시스템의 무대가 된다.
