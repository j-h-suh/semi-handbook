# 7.4 컨텍스트 압축 — 한 세션이 영원할 수 있는 이유

---

## 이 챕터에서 배우는 것

- 컨텍스트 윈도우는 유한하다 (200K) — 그런데 대화는 무제한으로 이어진다. 어떻게?
- **2.3에서 잠깐 본 autocompact**의 진짜 메커니즘 — 모델이 자기 대화를 스스로 요약해서 자기 대화를 대체한다
- 9-섹션 요약 프롬프트 — "구조 강요"로 정보 손실을 막는 법
- 프로덕션 단단함: 13K 토큰 버퍼, 3회 회로 차단기, PTL 재시도, 캐시 키 재사용
- 컴팩션 경계 마커가 어떻게 재첨부(파일, 플랜, 스킬, 도구)로 컨텍스트를 재조립하는지

---

## 사용자 경험에서 출발

긴 세션을 한 번이라도 돌려본 적이 있으면 — 이 메시지를 봤을 거다.

```
This session is being continued from a previous conversation
that ran out of context. The summary below covers the earlier
portion of the conversation.

Summary:
1. Primary Request and Intent: …
2. Key Technical Concepts: …
3. Files and Code Sections: …
…

Continue the conversation from where it left off without asking
the user any further questions.
```

순간 — 한 번도 끊긴 적이 없는 것처럼 Claude가 일을 이어 한다. 직전 파일들도 다 알고, 어떤 함수를 짜고 있었는지도 알고, 사용자가 어떤 피드백을 줬는지도 안다. 토큰 카운터는 5% 였는데 다음 턴에는 95% 로 떨어져 있다.

잠깐, 이거 어떻게 가능하지? 컨텍스트 윈도우는 200K 토큰. 한 시간 코딩하면 쉽게 그걸 넘긴다. 새 세션을 띄우면 모든 게 사라진다. 그런데 — 사라지지 않았다. 모델이 자기가 했던 대화를 자기 손으로 압축한 것이다. 9개의 섹션으로. 그리고 그 압축본이 원래 대화를 대체한다.

이 챕터에서 — 그 마법이 실제로 어떻게 일어나는지 본다. 2.3에서 잠깐 만난 **autocompact**가 진짜로 어떻게 작동하는지.

> 💡 **자기언급 노트.** 이 챕터를 쓰는 LLM(나)도 방금 컨텍스트 압축을 겪었다. 내가 시작 부분에서 받은 "Summary:" 메시지가 바로 이 챕터의 결과물이다. 그래서 내가 이 챕터의 산증인이 되는 흔치 않은 경우.

## 본문

### 임계값 — 언제 발동하나

`autoCompact.ts` 의 상수 여섯 개가 전체 결정 정책을 정의한다 — 실제 파일에서는 세 곳에 흩어져 있어서 한 화면에 모았다.

```typescript
// autoCompact.ts:30
const MAX_OUTPUT_TOKENS_FOR_SUMMARY = 20_000  // 요약이 차지할 출력 토큰

// autoCompact.ts:62-65
const AUTOCOMPACT_BUFFER_TOKENS = 13_000      // 언제 발동하나
const WARNING_THRESHOLD_BUFFER_TOKENS = 20_000
const ERROR_THRESHOLD_BUFFER_TOKENS = 20_000
const MANUAL_COMPACT_BUFFER_TOKENS = 3_000    // 강제 차단 한계

// autoCompact.ts:70
const MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3  // 회로 차단기
```

발동 임계값은 단순한 식이다 — 챕터에서 보일 핵심만.

```typescript
// (축약: 실제는 Math.min(getMaxOutputTokensForModel(model), MAX_OUTPUT_TOKENS_FOR_SUMMARY) 분기 +
//  CLAUDE_CODE_AUTO_COMPACT_WINDOW env var override + getSdkBetas() 인자 등 포함)
function getEffectiveContextWindowSize(model: string): number {
  return getContextWindowForModel(model) - MAX_OUTPUT_TOKENS_FOR_SUMMARY
  // 200_000 - 20_000 = 180_000  (Sonnet 4.6 기준)
}

// (축약: 실제는 CLAUDE_AUTOCOMPACT_PCT_OVERRIDE env var 로 퍼센트 기반 override 가능 —
//  테스트 편의용)
function getAutoCompactThreshold(model: string): number {
  return getEffectiveContextWindowSize(model) - AUTOCOMPACT_BUFFER_TOKENS
  // 180_000 - 13_000 = 167_000
}
```

매 턴 시작에 — `tokenCountWithEstimation(messages)` 가 167K를 넘었으면 **autocompact 발동**.

세 가지가 우연이 아니다.

1. **20K 출력 토큰 예약**. 코멘트가 정직: **"Based on p99.99 of compact summary output being 17,387 tokens"**. 1만 세션 중 1개가 17,387 토큰의 요약을 만든다. 그래서 20K를 고정 예약. **컴팩션이 자기 자리를 못 잡는 사고를 막는다**.
2. **13K 안전 마진**. 167K에서 발동해야 — 압축 그 자체가 **180K - 13K = 167K** 까지 들어가서 압축을 만들 여유가 있다. 200K 한계를 넘기 전에 미리 발동해야 함.
3. **3회 회로 차단기**. BQ 데이터 (`autoCompact.ts:67-69` 코멘트 verbatim): **"BQ 2026-03-10: 1,279 sessions had 50+ consecutive failures (up to 3,272) in a single session, wasting ~250K API calls/day globally"**. 1,279개 세션이 50회 이상 연속 실패. 어떤 세션은 3,272회 실패. 이게 **하루에 25만 API 호출**을 낭비하고 있었다. 그래서 3번 실패하면 그 세션은 컴팩션 자체를 멈춘다.

### 9-섹션 요약 프롬프트

이게 진짜 핵심이다. `BASE_COMPACT_PROMPT` 가 `prompt.ts:61` 부터. 모델에게 "요약해줘" 한 마디로 시키면 — 중요한 걸 빠뜨린다. 그래서 Claude Code는 **9개 섹션을 강제**한다 (한국어 번역, 영문 verbatim 출처는 `prompt.ts:68-77`).

```
1. Primary Request and Intent: 사용자의 명시적 요청과 의도
2. Key Technical Concepts: 논의된 주요 기술/프레임워크
3. Files and Code Sections: 본 파일과 코드 (코드 스니펫 포함)
4. Errors and fixes: 만난 에러와 해결법 (사용자 피드백 강조)
5. Problem Solving: 해결한 문제와 진행 중인 디버깅
6. All user messages: 모든 도구 외 사용자 메시지 (의도 변화 포착)
7. Pending Tasks: 진행 중인 태스크
8. Current Work: 직전에 하던 일 (가장 최근에 집중)
9. Optional Next Step: 다음 한 단계 — 직접 인용까지 포함
```

각 섹션의 지시문이 극도로 구체적이다. 6번 보면 — **"List ALL user messages that are not tool results. These are critical for understanding the users' feedback and changing intent."** 강조까지 들어가 있다. 9번은 **"include direct quotes from the most recent conversation showing exactly what task you were working on and where you left off. This should be verbatim to ensure there's no drift in task interpretation."** — 유저 발화 그대로 인용하라고 시킨다.

> 💡 **9-섹션 틀은 같지만 세 변종으로 존재.** `prompt.ts` 에는 (a) **`BASE_COMPACT_PROMPT`** (line 61) — 전체 압축, (b) **`PARTIAL_COMPACT_PROMPT`** (line 145) — 피벗 이후만 요약 (`from` 방향, 캐시 보존), (c) **`PARTIAL_COMPACT_UP_TO_PROMPT`** (line 208) — 피벗 이전만 요약 (`up_to` 방향, 캐시 무효화). 9 칸의 형식은 같지만 8번/9번 칸의 내용이 다르다. `up_to` 변종은 8번이 **"Work Completed"**, 9번이 **"Context for Continuing Work"** — 이미 끝난 일을 먼 미래에서 회고하는 시점이라서 동사 시제가 바뀐다. **같은 9-틀로 세 가지 시나리오를 다 처리**. `partialCompactConversation` (`compact.ts:772`) 도 같은 패턴 위에서 작동.

이 프롬프트의 놀라운 부분은 따로 있다 — `<analysis>` 블록.

```
Before providing your final summary, wrap your analysis in
<analysis> tags to organize your thoughts and ensure you've
covered all necessary points.
```

**모델한테 드래프트 스크래치패드를 주는 것**. 9개 섹션을 잘 채우려면 모델이 생각을 해야 하는데, 그 생각을 별도 블록에 적고, 그 다음 `<summary>` 블록에 진짜 요약을 적게 한다. 왜? 그래야 요약 품질이 올라간다 (모델이 한 번 정리하고 쓰니까).

**그리고 — 그 `<analysis>` 블록은 컨텍스트에 안 남는다**:

```typescript
// prompt.ts:311

  // improves summary quality but has no informational value
  // once the summary is written.
  formattedSummary = formattedSummary.replace(
    /<analysis>[\s\S]*?<\/analysis>/,
    '',
  )
  // (축약: 이어서 <summary>...</summary> 태그를 "Summary:\n..." 헤더로 변환하는
  //  두 번째 단계 + \n\n+ → \n\n 공백 정리 단계 생략. 즉 단순 strip 이 아니라
  //  XML → 일반 텍스트 헤더 변환도 한다 — prompt.ts:322-332)
}
```

**드래프트는 버리고 완성본만 다음 컨텍스트에 넣는다**. 17K 토큰의 요약이 만약 30K 토큰의 분석을 거쳐 만들어졌다면 — 그 30K는 일회용. 작품만 저장하고 작업장은 비우는 정신.

아주 강력한 **No-tools 가드**도 같이 들어간다.

```typescript
// prompt.ts:19-26 (PREAMBLE — 맨 앞)
const NO_TOOLS_PREAMBLE = `CRITICAL: Respond with TEXT ONLY. Do NOT call any tools.

- Do NOT use Read, Bash, Grep, Glob, Edit, Write, or ANY other tool.
- You already have all the context you need in the conversation above.
- Tool calls will be REJECTED and will waste your only turn — you will fail the task.
- Your entire response must be plain text: an <analysis> block followed by a <summary> block.

`

// prompt.ts:269-272 (TRAILER — 맨 뒤)
const NO_TOOLS_TRAILER =
  '\n\nREMINDER: Do NOT call any tools. Respond with plain text only — ' +
  'an <analysis> block followed by a <summary> block. ' +
  'Tool calls will be rejected and you will fail the task.'
```

프롬프트 캐시 공유를 위해 컴팩션은 부모 대화의 도구 세트를 그대로 상속해야 한다 (cache-key 매칭). 근데 도구가 보이면 모델이 유혹받는다. 그래서 **대문자 CRITICAL**, **맨 앞 (PREAMBLE) 과 맨 뒤 (TRAILER) 에 두 번** 강조 — 같은 메시지를 다른 표현으로 두 번 박는다. 마지막 bullet 의 **"plain text: an `<analysis>` block followed by a `<summary>` block"** 은 응답 형식까지 못박는다. 코멘트가 솔직 (`prompt.ts:12-18`): **"on Sonnet 4.6+ adaptive-thinking models the model sometimes attempts a tool call despite the weaker trailer instruction. With maxTurns: 1, a denied tool call means no text output → falls through to the streaming fallback (2.79% on 4.6 vs 0.01% on 4.5). Putting this FIRST and making it explicit about rejection consequences prevents the wasted turn."** — **trailer 만으로는 부족해서 PREAMBLE 을 추가**했다는 사연.

### 컴팩션 흐름 — `compactConversation`

`compact.ts:387`. 흐름은 (실제 코드 순서로):

```
1. preCompact 훅 실행 (사용자 정의 지시 병합)
2. 9-섹션 프롬프트로 forked agent 호출 (cache key 공유)
   ├─ 정상: 요약 받음
   └─ PTL (prompt-too-long): 가장 오래된 메시지 잘라내고 재시도 (max 3회)
3. 재첨부 — 2개만 병렬 (Promise.all), 나머지는 순차:
   ├─ [parallel] 압축 전 읽었던 파일들 (FileReadTool 캐시 → preCompactReadFileState)
   ├─ [parallel] async agent 첨부
   ├─ [seq]      현재 플랜 첨부
   ├─ [seq]      플랜 모드 상태 (현재 plan 모드면)
   ├─ [seq]      활성 스킬
   ├─ [seq]      발견된 deferred tools 스키마 (delta)
   ├─ [seq]      Agent listing (delta)
   └─ [seq]      MCP 서버 instructions (delta)
4. SessionStart 훅 실행
5. 컴팩션 경계 마커 생성 (preCompactTokenCount + last UUID + preCompactDiscoveredTools)
6. 요약을 유저 메시지로 wrap (`getCompactUserSummaryMessage`)
7. <analysis> 스트립 + <summary> → "Summary:\n" 헤더 변환 (wrap 안에서 자동)
8. post_compact 훅 실행
9. 새 메시지 배열 반환 (`{ boundaryMarker, summaryMessages, attachments, hookResults, ... }`)
```

핵심은 3번이다. 요약 텍스트는 "우리가 무슨 일을 했는지"를 포착한다. 그런데 모델이 일을 이어 하려면 — 그 파일들의 실제 내용도 다시 필요하다. 그래서 컴팩션 직전에 `context.readFileState` 캐시를 떠서, 그 파일들을 다시 첨부한다. 플랜, 스킬, 도구 스키마도 마찬가지. **요약 + 작업 컨텍스트 재첨부 = 실질적으로 재시작되지만 기억은 이어진다**.

> ⚙️ **7번째 재첨부 — `preCompactDiscoveredTools`** (`compact.ts:606-611`). 위 6개 재첨부 외에 **경계 마커의 metadata 안에** 발견된 deferred 도구 이름들이 별도로 저장된다. 코멘트: **"summary doesn't preserve tool_reference blocks, so the post-compact schema filter needs this to keep sending already-loaded deferred tool schemas to the API"**. **요약은 코드만 잊는 게 아니라 도구 schema도 잊는다** — 그래서 **boundary marker** 의 metadata 가 그 schema 를 살려 둔다. 7번째 재첨부는 데이터가 아니라 이름만이라는 게 영리한 부분 — 이름을 알면 schema 는 다시 발견할 수 있다.

> 🎁 **6번째 프로덕션 단단함 조각 — cache 공유의 사연** (`compact.ts:431-438`). **"forked agent + cache key 공유"** 가 그냥 default 가 된 게 아니다. 코멘트: **"3P default: true — forked-agent path reuses main conversation's prompt cache. Experiment (Jan 2026) confirmed: false path is 98% cache miss, costs ~0.76% of fleet cache_creation (~38B tok/day), concentrated in ephemeral envs (CCR/GHA/SDK) with cold GB cache and 3P providers where GB is disabled. GB gate kept as kill-switch."** **38B 토큰/일** 의 cache_creation 이 걸린 결정 — 문서가 그 자리에서 Jan 2026 실험의 사연을 기록. 프로덕션 단단함의 또 한 정점.

### 요약은 유저 메시지로 들어간다

`prompt.ts:337` — `getCompactUserSummaryMessage`. 압축 결과물을 유저 메시지로 감싼다. **왜 user?** — 6.1에서 본 **CLAUDE.md가 user 메시지인 이유**와 같다. **시스템 프롬프트는 캐시 가능한 정적 영역**이고, 동적인 컨텍스트는 user 메시지로 들어가야 prompt cache가 깨지지 않는다.

```typescript
// (축약: transcriptPath 분기 — 전체 transcript 위치 안내,
//        recentMessagesPreserved 분기 — "Recent messages are preserved verbatim",
//        proactive/KAIROS 모드 추가 메시지 분기 등 생략)
let baseSummary = `This session is being continued from a previous
conversation that ran out of context. The summary below covers the
earlier portion of the conversation.

${formattedSummary}`

if (suppressFollowUpQuestions) {
  continuation = `${baseSummary}
Continue the conversation from where it left off without asking
the user any further questions. Resume directly — do not acknowledge
the summary, do not recap what was happening, do not preface with
"I'll continue" or similar. Pick up the last task as if the break
never happened.`
}
```

마지막 한 줄이 끝내준다 — **"as if the break never happened"**. 모델한테 **"끊긴 적 없는 것처럼 행동해"**. **이 한 줄이 사용자 경험의 핵심**. 사용자는 컴팩션이 일어났는지도 모른다 — Claude가 그냥 자기 일을 이어 한다.

> 💡 **9-섹션 압축은 큰 칼. 작은 칼도 따로 있다 — `microCompact.ts`.** 7.4 의 9-섹션 패턴은 전체 대화를 통째로 요약하는 큰 칼. 그런데 그 옆에 작은 칼 이 있다 — `services/compact/microCompact.ts` 의 마이크로 컴팩션. 이건 9-섹션 요약을 안 한다. 대신 오래된 도구 결과 본문 만 잘라서 `[Old tool result content cleared]` 로 교체. 대상도 한정 — `COMPACTABLE_TOOLS = {FileRead, Shell, Grep, Glob, WebSearch, WebFetch, FileEdit, FileWrite}` 8개. **9-섹션 압축 = 큰 칼** (전체 대화 요약), **마이크로 컴팩션 = 작은 칼** (오래된 도구 결과만 잘라냄). 두 개가 같이 작동해서 컨텍스트를 두 차원에서 관리한다 — 7.4 는 큰 칼 쪽 이야기.

## Python으로 옮기면

핵심만 압축해서:

```python
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any
import re


# ─── 임계값 정책 ────────────────
@dataclass(frozen=True)
class CompactThresholds:
    context_window: int = 200_000
    summary_output_reserve: int = 20_000  # p99.99 of summaries
    autocompact_buffer: int = 13_000
    max_consecutive_failures: int = 3  # 회로 차단기
    
    @property
    def effective_window(self) -> int:
        return self.context_window - self.summary_output_reserve
    
    @property
    def autocompact_threshold(self) -> int:
        return self.effective_window - self.autocompact_buffer


# ─── 9-섹션 요약 프롬프트 ────────────────
COMPACT_PROMPT = """CRITICAL: Respond with TEXT ONLY. Do NOT call any tools.

You already have all the context you need in the conversation above.
Tool calls will be REJECTED and will waste your only turn.

Your task is to create a detailed summary of the conversation so far.

Before providing your final summary, wrap your analysis in <analysis>
tags to organize your thoughts.

Your summary should include the following sections:

1. Primary Request and Intent
2. Key Technical Concepts
3. Files and Code Sections (include code snippets)
4. Errors and fixes
5. Problem Solving
6. All user messages (CRITICAL — these capture intent changes)
7. Pending Tasks
8. Current Work
9. Optional Next Step (include direct quotes from recent messages)

Wrap your response as <analysis>...</analysis><summary>...</summary>.

REMINDER: Do NOT call any tools. Plain text only.
"""


# ─── 추적 상태 + 회로 차단기 ────────────────
@dataclass
class AutoCompactTracking:
    compacted: bool = False
    consecutive_failures: int = 0


# ─── 발동 결정 ────────────────
def should_autocompact(
    messages: list[dict],
    thresholds: CompactThresholds,
) -> bool:
    token_count = estimate_tokens(messages)
    return token_count >= thresholds.autocompact_threshold


# ─── 핵심 함수 ────────────────
async def compact_conversation(
    messages: list[dict],
    file_state: dict[str, str],  # FileReadTool 캐시
    plan_state: Any | None,
    skills: list[Any],
    *,
    thresholds: CompactThresholds = CompactThresholds(),
    tracking: AutoCompactTracking,
) -> list[dict]:
    """대화를 압축하고 재첨부까지 마친 새 메시지 배열을 반환."""
    
    # 회로 차단기
    if tracking.consecutive_failures >= thresholds.max_consecutive_failures:
        return messages  # 포기
    
    try:
        # 1. 9-섹션 프롬프트로 모델 호출 (cache key 공유)
        raw_summary = await call_llm_no_tools(
            messages=messages + [{"role": "user", "content": COMPACT_PROMPT}],
            max_tokens=thresholds.summary_output_reserve,
        )
        
        # 2. <analysis> 스트립
        formatted = _format_summary(raw_summary)
        
        # 3. 요약을 유저 메시지로 wrap
        summary_message = {
            "role": "user",
            "content": _wrap_compact_summary(formatted),
            "is_compact_summary": True,
        }
        
        # 4. 컴팩션 경계 마커 생성
        boundary_marker = {
            "role": "system",
            "type": "compact_boundary",
            "pre_compact_token_count": estimate_tokens(messages),
            "last_uuid": messages[-1].get("uuid"),
        }
        
        # 5. 재첨부 — 파일/플랜/스킬을 새 첨부로
        re_attached = _create_post_compact_attachments(
            file_state=file_state,
            plan_state=plan_state,
            skills=skills,
        )
        
        tracking.consecutive_failures = 0  # 성공 시 리셋
        return [boundary_marker, summary_message, *re_attached]
    
    except Exception:
        tracking.consecutive_failures += 1
        return messages  # 다음 턴에 다시 시도 (3회까지)


def _format_summary(raw: str) -> str:
    """<analysis>는 버리고 <summary>만 남긴다 — 작업장은 비우고 작품만."""
    no_analysis = re.sub(r"<analysis>[\s\S]*?</analysis>", "", raw)
    match = re.search(r"<summary>([\s\S]*?)</summary>", no_analysis)
    return match.group(1).strip() if match else no_analysis.strip()


def _wrap_compact_summary(summary: str) -> str:
    """요약을 user 메시지의 본문으로 — prompt cache 친화."""
    return (
        "This session is being continued from a previous conversation "
        "that ran out of context. The summary below covers the earlier "
        "portion of the conversation.\n\n"
        f"Summary:\n{summary}\n\n"
        "Continue the conversation from where it left off without asking "
        "the user any further questions. Resume directly — do not "
        'acknowledge the summary, do not recap what was happening, do not '
        'preface with "I\'ll continue" or similar. Pick up the last task '
        "as if the break never happened."
    )
```

핵심 셋이 다 있다.

1. **`@dataclass(frozen=True)` 임계값** — 5개 상수가 명시적이고 불변. 매직 넘버 없음.
2. **9-섹션 강제** — 자유 형식 요약을 안 시킨다. 모델이 지정된 칸을 채워야 한다.
3. **재첨부** — 요약 텍스트만 다음 컨텍스트에 넣으면 코드는 못 본다. 파일 상태를 별도로 다시 끼워 넣어야 일을 이어 할 수 있다.

> 💡 **`<analysis>` 패턴은 모델에게 흔하다.** Anthropic이 권장하는 **thinking trace** 패턴 — 모델한테 "먼저 분석을 적고, 그 다음에 답해" 라고 시키면 답 품질이 급격히 올라간다. 특히 9개 섹션처럼 구조가 강제된 경우에 효과가 크다. 그리고 분석은 컨텍스트에 남길 필요가 없으니 버린다. 생각의 비계는 작품에 안 남긴다.

## 핵심 정리

- **컨텍스트 압축**은 모델이 자기 대화를 자기 손으로 9-섹션 요약으로 바꾸는 메커니즘. 200K 윈도우의 한계를 대화의 한계가 되지 않게 만든다.
- 발동 임계값은 6개 상수로 결정 (실제 파일에서 세 곳에 흩어져 있다 — `autoCompact.ts:30, 62-65, 70`). `effective = window - 20K(요약 예약)`, `threshold = effective - 13K(안전 마진)`. Sonnet 4.6 기준 **167K**에서 발동.
- **9-섹션 프롬프트**는 자유 형식이 아니라 각 칸을 채우라는 강제 — Primary Request, Key Concepts, Files, Errors, Problem Solving, 모든 user messages, Pending Tasks, Current Work, Next Step. 6번이 가장 중요 — 의도 변화를 잡기 위해 사용자 발화를 모두 보존. **9-틀은 세 변종으로 존재** (`BASE` / `PARTIAL` / `PARTIAL_UP_TO`) — 같은 9 칸을 세 가지 시나리오에 재사용.
- **`<analysis>` 드래프트 스크래치패드** 패턴 — 모델이 한 번 정리하고 요약을 쓰게 한다. 분석 블록은 컨텍스트에 안 남는다. 작품만 남기고 작업장은 비운다. `formatCompactSummary` 가 strip + `<summary>` → "Summary:\n" 헤더 변환까지 한 번에.
- 프로덕션 단단함 **6 조각**: (1) **3회 회로 차단기** (BQ 데이터 — 1,279개 세션이 50회+ 실패해서 25만 API 호출/일 낭비), (2) **PTL 재시도 (max 3)** (압축 자체가 prompt-too-long이면 가장 오래된 메시지 잘라내고 재시도), (3) **forked agent + cache key 공유** + Jan 2026 실험으로 검증된 default (false 경로는 98% cache miss + 38B tok/day 비용), (4) **No-tools 가드 두 번 강조** (PREAMBLE + TRAILER — Sonnet 4.6에서 2.79%, 4.5에서 0.01% 가 도구 호출 시도), (5) **`preCompactDiscoveredTools`** (요약은 도구 schema 도 잊으니 boundary marker metadata 에 이름 별도 보존), (6) **마이크로 컴팩션** (`microCompact.ts`) — 9-섹션 압축 옆에서 오래된 도구 결과 본문 만 잘라내는 작은 칼.
- **재첨부**가 마법의 절반이다 — 요약 텍스트만 있으면 코드는 못 본다. 압축 직전 `readFileState`에 있던 파일들 + async agents (2개만 병렬), 플랜, 플랜 모드 상태, 스킬, 발견된 도구 스키마, MCP instructions, agent listing 을 순차로 첨부. 기억(요약) + 책상(재첨부) = 일이 이어진다.
- **요약은 user 메시지로** 들어간다 (6.1의 CLAUDE.md와 같은 이유 — **prompt cache 친화**). 마지막 한 줄이 결정적: **"as if the break never happened"**. 사용자는 끊긴 줄도 모른다.
