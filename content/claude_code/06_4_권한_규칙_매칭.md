# 6.4 권한 규칙 매칭 — `Bash(git *)` 같은 와일드카드는 어떻게 작동하나

## 사용자 경험에서 출발

`/permissions`를 친다. 다이얼로그가 뜬다.

```
┌─ Permissions ─────────────────────────────┐
│  Allow rules:                             │
│    Bash(git status)        [user]         │
│    Bash(git diff:*)        [project]      │
│    Bash(git *)             [session]      │
│    Read(/Users/me/**)      [user]         │
│    Edit(*.py)              [local]        │
│                                           │
│  Deny rules:                              │
│    Bash(rm -rf *)          [policy]       │
└───────────────────────────────────────────┘
```

5개의 allow 룰. 각각 다른 출처(user, project, session, local). LLM이 `git push` 를 시도하면 — 어떤 룰이 매칭되는가? `Bash(git status)`는 **정확히 `git status`**만, `Bash(git diff:*)`는 **`git diff` 로 시작**하는 것만, `Bash(git *)`는 **`git`으로 시작**하는 모든 것. 

세 가지 다른 매칭 방식이 한 시스템에 같이 산다. 그리고 패턴 한 글자가 아주 영리하게 정규식이 된다. 이 챕터에서 본다.

### 룰의 3가지 타입

`shellRuleMatching.ts:159`의 `parsePermissionRule`. 룰 문자열 하나를 받아서 3가지 중 하나로 분류.

```typescript
// (축약: 한국어 코멘트 + 1줄 객체 리턴으로 paraphrase. 실제 파라미터명은 'permissionRule')
export function parsePermissionRule(rule: string): ShellPermissionRule {
  // 1. Legacy `:*` prefix syntax
  const prefix = permissionRuleExtractPrefix(rule)
  if (prefix !== null) {
    return { type: 'prefix', prefix }
  }
  
  // 2. New wildcard syntax (contains unescaped *)
  if (hasWildcards(rule)) {
    return { type: 'wildcard', pattern: rule }
  }
  
  // 3. Exact match (default)
  return { type: 'exact', command: rule }
}
```

3가지 타입과 예시.

| 타입 | 패턴 예시 | 매칭 |
|---|---|---|
| `exact` | `Bash(git status)` | 정확히 `git status` |
| `prefix` | `Bash(git:*)` (legacy) | `git`으로 시작하는 모든 명령 |
| `wildcard` | `Bash(git *)` (new) | 정확히 `git ...` — 더 똑똑함 |

`prefix`는 옛날 문법이다. 호환성으로 남아 있다. `wildcard`가 새 문법이고 — 훨씬 더 표현력이 있다. 와일드카드는 어디든 들어갈 수 있다 — `git */--force`, `npm run *`, `docker run --rm *`.

### 와일드카드 → 정규식 변환

`matchWildcardPattern` (`shellRuleMatching.ts:90-154`) 이 핵심. 단계별로 본다.

```typescript
// (축약: caseInsensitive = false 파라미터 + 마지막의 case insensitive flags 분기 생략)
export function matchWildcardPattern(
  pattern: string,
  command: string,
): boolean {
  // 1. 트림
  const trimmedPattern = pattern.trim()
  
  // 2. 이스케이프 시퀀스 처리: \* → 임시 placeholder
  let processed = ''
  let i = 0
  while (i < trimmedPattern.length) {
    const char = trimmedPattern[i]
    if (char === '\\' && i + 1 < trimmedPattern.length) {
      const nextChar = trimmedPattern[i + 1]
      if (nextChar === '*') {
        processed += ESCAPED_STAR_PLACEHOLDER  // \x00ESCAPED_STAR\x00
        i += 2; continue
      } else if (nextChar === '\\') {
        processed += ESCAPED_BACKSLASH_PLACEHOLDER
        i += 2; continue
      }
    }
    processed += char
    i++
  }
  
  // 3. 정규식 특수문자 이스케이프 (단, *는 제외)
  const escaped = processed.replace(/[.+?^${}()|[\]\\'"]/g, '\\$&')
  
  // 4. 이스케이프 안 된 *를 .*로 변환
  const withWildcards = escaped.replace(/\*/g, '.*')
  
  // 5. placeholder를 *진짜 이스케이프된 ** 로 복원
  let regexPattern = withWildcards
    .replace(ESCAPED_STAR_PLACEHOLDER_RE, '\\*')
    .replace(ESCAPED_BACKSLASH_PLACEHOLDER_RE, '\\\\')
  
  // 6. 트레일링 ' *' 옵셔널화 (단일 와일드카드일 때만)
  const unescapedStarCount = (processed.match(/\*/g) || []).length
  if (regexPattern.endsWith(' .*') && unescapedStarCount === 1) {
    regexPattern = regexPattern.slice(0, -3) + '( .*)?'
  }
  
  // 7. 전체 매칭하는 정규식 생성
  const regex = new RegExp(`^${regexPattern}$`, 's')
  return regex.test(command)
}
```

7단계. 각 단계가 함정 하나를 피한다.

### 함정 하나하나

**함정 1: `\*`을 어떻게 처리할까?** 사용자가 `Bash(echo \*)` 라고 썼다면 — 별표 자체를 매칭하고 싶다는 뜻. 그냥 변환하면 `.*`이 되어 모든 것과 매칭. 

해결: **null-byte sentinel placeholder**. `\*`를 임시로 `\x00ESCAPED_STAR\x00`로 바꿔둔다 (`shellRuleMatching.ts:14`). 정규식 변환이 다 끝난 다음에 이 placeholder를 진짜 이스케이프된 `\*`로 복원. **사용자 입력에 `\x00`이 들어올 일이 없다**(null byte는 일반 텍스트에 안 나옴) → 충돌이 없다. 우아한 트릭이다.

> ⚙️ **placeholder 가 모듈 레벨에 있는 이유.** `ESCAPED_STAR_PLACEHOLDER_RE` (`shellRuleMatching.ts:16`) 가 함수 안이 아니라 파일 최상단에 있다. 코드 코멘트 (`shellRuleMatching.ts:12-13`) 가 직접 설명한다 — verbatim: **"Null-byte sentinel placeholders for wildcard pattern escaping — module-level so the RegExp objects are compiled once instead of per permission check."** 권한 체크는 매번 일어나는 핫 패스다. 함수 안에서 `new RegExp(...)` 를 매번 만들면 — 매 권한 체크마다 정규식 컴파일. 모듈 레벨에 두면 프로세스 시작 시 한 번. 자주 호출되는 코드의 정규식은 모듈 레벨에 둔다는 Python의 `re.compile` 패턴과 같은 사고.

**함정 2: 정규식의 다른 특수 문자.** `Bash(grep .)` 의 `.` 은 정규식의 임의 문자다. 그대로 두면 `grep abc`도 매칭되어버린다. 

해결: 3단계에서 정규식 특수문자 모두 이스케이프 (`.`, `+`, `?`, `^`, `$`, `{`, `}`, `(`, `)`, `|`, `[`, `]`, `\`, `'`, `"`). 단, `*`는 제외 — 이건 와일드카드로 쓰일 거니까.

**함정 3: `git *`은 `git` 단독을 매칭해야 하나?** 사용자 직관: "git 명령은 다 허용". 그러면 `git` 단독도 허용되어야 하지 않나? 그런데 위 7단계에서 `git *`을 그대로 변환하면 — `git .*` → `git ` (공백) 이 반드시 있어야 매칭된다. `git` 단독은 안 매칭.

해결: **6단계의 트레일링 옵셔널화**. 

```typescript
if (regexPattern.endsWith(' .*') && unescapedStarCount === 1) {
  regexPattern = regexPattern.slice(0, -3) + '( .*)?'
}
```

`git .*` → `git( .*)?`으로 변환. **공백 + 인수를 옵셔널**로 만든다. `git`도 매칭, `git status`도 매칭. 

**함정 4: `* run *`은 옵셔널화하면 안 된다.** 만약 모든 트레일링 `*`을 옵셔널화한다면 — `npm run *`도 `npm run` (인수 없는 단독)을 매칭한다. 근데 사용자 의도는 `npm run <something>` — 인수가 있어야 한다.

해결: **`unescapedStarCount === 1` 가드**. 단일 와일드카드일 때만 옵셔널화. 다중 와일드카드는 그대로. 

코멘트가 친절하다. **"Multi-wildcard patterns like `* run *` are excluded — making the last wildcard optional would incorrectly match `npm run` (no trailing arg)."**

이 정도의 세심함이 각 라인에 박혀 있다. 룰 매칭 한 번에 수많은 사용자 의도 시나리오를 다 고려해야 한다.

### 짝수 백슬래시 카운트 — `hasWildcards`의 영리함

`hasWildcards` (`shellRuleMatching.ts:54-78`) 도 비슷하게 정교하다. 함수 최상단 에는 legacy `:*` early return 이 있어서 **옛 문법과 새 와일드카드**를 한 함수에서 분기시킨다 (`parsePermissionRule` 의 3-way 분기와 대칭이다).

```typescript
// (축약: 함수 시작의 'if (pattern.endsWith(":*")) return false' early return 생략. for 루프만 발췌)
for (let i = 0; i < pattern.length; i++) {
  if (pattern[i] === '*') {
    let backslashCount = 0
    let j = i - 1
    while (j >= 0 && pattern[j] === '\\') {
      backslashCount++; j--
    }
    if (backslashCount % 2 === 0) {  // 짝수 → 이스케이프 안 됨
      return true
    }
  }
}
```

`*` 앞의 백슬래시 개수를 센다. 짝수면 이스케이프 안 된 `*`. 왜?

- `*` → 0 backslashes → 이스케이프 안 됨 ✓
- `\*` → 1 backslash → 이스케이프 됨 (literal `*`)
- `\\*` → 2 backslashes → `\\`가 literal `\`, `*`는 이스케이프 안 됨 ✓
- `\\\*` → 3 backslashes → `\\`가 literal `\`, `\*`가 literal `*`
- `\\\\*` → 4 backslashes → `\\\\`가 literal `\\`, `*`는 이스케이프 안 됨 ✓

홀수냐 짝수냐가 의미를 결정한다. 백슬래시 개수만 세도 된다는 영리한 환원. C/C++ 컴파일러의 string literal 파싱과 같은 패턴.

### Part 6 통합 — 권한 시스템 전체를 한 줄로

6장 4개 챕터를 한 줄로 정리하면 이렇게 된다.

> **권한 시스템은 컨텍스트 + 모드 + 룰의 세 축으로 만들어진다.**

- **6.1** 컨텍스트: CLAUDE.md가 사용자 메시지로 주입되어 LLM의 행동 가이드가 됨.
- **6.2** 컨테이너: AppState가 모든 컨트롤 상태를 들고 있음. 메시지는 별도.
- **6.3** 모드: `mode` 한 글자가 **5개의 다른 권한 정책 regime**을 트리거. 그 중 plan은 프롬프트 주입으로 구현.
- **6.4** 룰: 8군데에서 온 룰을 한 리스트로 합치고, 3가지 타입(exact/prefix/wildcard)으로 매칭. 와일드카드는 수십 가지 함정을 수십 가지 트릭으로 피해서 정규식이 됨.

각 챕터가 서로 다른 자리에서 권한을 결정한다. 어떤 곳은 코드, 어떤 곳은 프롬프트, 어떤 곳은 데이터. 이 다층 구조가 **Claude Code의 권한 시스템 전체**다. 9장에서 미니 버전을 직접 만들 때 이 4개 챕터의 디자인이 다 회수된다.

> 🔬 **Deep Dive — 왜 이 정도까지 정교한가.** 와일드카드 한 개가 7단계 변환 + 4가지 함정 회피를 거치는 게 과해 보일 수 있다. 근데 권한 룰은 사용자가 직접 쓰는 문자열이고, 틀리면 보안 사고다. 사용자 직관(`git *`은 `git` 단독도 포함해야 한다)과 정규식 의미(`git .*`은 공백이 필요)의 간격이 사고를 만든다. 그 간격을 코드가 채워야 한다. 매 트릭이 과거의 사용자 보고에 대응한다 — 이슈 트래커를 보면 **"`Bash(git *)`이 git status는 매칭하는데 git만 치면 매칭 안 됨"** 같은 보고가 수도 없이 있을 것이다. 코드의 정교함은 정확히 그만큼의 사용자 사고에 대한 응답이다.

## Python으로 옮기면

같은 패턴을 Python으로 옮기면 이렇게 생겼다.

```python
from __future__ import annotations
import re
from dataclasses import dataclass
from typing import Literal


# ─── 8개 룰 출처 ────────────────
RULE_SOURCES = [
    "userSettings",
    "projectSettings",
    "localSettings",
    "flagSettings",
    "policySettings",
    "cliArg",
    "command",
    "session",
]


@dataclass
class PermissionRule:
    source: str
    behavior: Literal["allow", "deny", "ask"]
    pattern: str  # e.g., "Bash(git *)"


# ─── 룰을 한 리스트로 평탄화 ────────────────
def get_allow_rules(rules_by_source: dict[str, list[str]]) -> list[PermissionRule]:
    result = []
    for source in RULE_SOURCES:
        for pattern in rules_by_source.get(source, []):
            result.append(PermissionRule(source, "allow", pattern))
    return result


# ─── 와일드카드 패턴 → 정규식 ────────────────
ESCAPED_STAR_PLACEHOLDER = "\x00ESCAPED_STAR\x00"
ESCAPED_BACKSLASH_PLACEHOLDER = "\x00ESCAPED_BACKSLASH\x00"


def match_wildcard_pattern(pattern: str, command: str) -> bool:
    pattern = pattern.strip()
    
    # 1. 이스케이프 시퀀스 → null-byte placeholder
    processed = ""
    i = 0
    while i < len(pattern):
        if pattern[i] == "\\" and i + 1 < len(pattern):
            next_char = pattern[i + 1]
            if next_char == "*":
                processed += ESCAPED_STAR_PLACEHOLDER
                i += 2
                continue
            elif next_char == "\\":
                processed += ESCAPED_BACKSLASH_PLACEHOLDER
                i += 2
                continue
        processed += pattern[i]
        i += 1
    
    # 2. 정규식 특수문자 이스케이프 (단 *는 제외)
    escaped = re.sub(r"[.+?^${}()|[\]\\'\"]", lambda m: "\\" + m.group(), processed)
    
    # 3. * → .*
    with_wildcards = escaped.replace("*", ".*")
    
    # 4. placeholder 복원
    regex_pattern = (with_wildcards
                     .replace(ESCAPED_STAR_PLACEHOLDER, "\\*")
                     .replace(ESCAPED_BACKSLASH_PLACEHOLDER, "\\\\"))
    
    # 5. 트레일링 ' *' 옵셔널화 (단일 와일드카드일 때만)
    unescaped_star_count = processed.count("*")
    if regex_pattern.endswith(" .*") and unescaped_star_count == 1:
        regex_pattern = regex_pattern[:-3] + "( .*)?"
    
    # 6. 전체 매칭
    return bool(re.match(rf"^{regex_pattern}$", command, re.DOTALL))


# ─── 사용 ────────────────
# `git *` 패턴
print(match_wildcard_pattern("git *", "git"))         # True ← 트레일링 옵셔널화 덕분
print(match_wildcard_pattern("git *", "git status"))  # True
print(match_wildcard_pattern("git *", "git push -f")) # True
print(match_wildcard_pattern("git *", "github"))      # False (정확히 git으로 시작 + 공백)

# `* run *` 다중 와일드카드
print(match_wildcard_pattern("* run *", "npm run"))      # False ← 옵셔널화 *안* 됨
print(match_wildcard_pattern("* run *", "npm run dev"))  # True

# 이스케이프된 *
print(match_wildcard_pattern("echo \\*", "echo *"))   # True (literal *)
print(match_wildcard_pattern("echo \\*", "echo abc")) # False
```

핵심 셋이 다 있다.

1. **8 출처를 한 리스트로**.
2. **null-byte placeholder**로 `\*` 보호.
3. **단일 와일드카드 가드**로 `* run *` 같은 다중 케이스 분리.

> 💡 **Python의 `fnmatch`로는 부족한 이유.** Python 표준 라이브러리에 `fnmatch`가 있다 (글로브 패턴 → 정규식). 근데 `fnmatch`는 트레일링 옵셔널화를 안 한다. `git *`이 `git` 단독을 매칭하지 않는다. 권한 시스템에는 그게 치명적이다. 사용자 의도와 어긋나면 사고. 그래서 **직접 변환**하는 게 옳다. **표준 라이브러리는 대부분 케이스에 좋고, 엣지 케이스가 있는 도메인에서는 직접 짠다.**

## 핵심 정리

- 권한 룰은 8군데에서 온다: `userSettings`, `projectSettings`, `localSettings`, `flagSettings`, `policySettings`, `cliArg`, `command`(4.3), `session`. 각자 수명과 권한이 다르지만 — 결정 시점에는 한 리스트로 평탄화된다.
- 룰의 3가지 타입: **`exact`** (`git status`), **`prefix`** (legacy `git:*`), **`wildcard`** (new `git *`). `wildcard`가 가장 표현력 강함.
- **와일드카드 → 정규식**: 7단계 변환. 매 단계가 함정 하나씩 회피. 정규식 특수 문자 이스케이프, `\*` 보호, 등등.
- **null-byte sentinel placeholder** (`\x00ESCAPED_STAR\x00`) — `\*`를 임시로 안전한 자리로 옮겨두고, 정규식 변환 끝난 다음 복원. 우아한 트릭.
- **트레일링 `' *'` 옵셔널화** — `git *`가 `git` 단독도 매칭하도록 `git( .*)?`로 변환. 단, `unescapedStarCount === 1`일 때만 (`* run *`은 옵셔널화 안 함).
- **짝수 백슬래시 카운트** — `\*` 이스케이프 판별. 백슬래시 개수만 세서 홀짝으로 결정. C 컴파일러 string literal 파싱과 같은 패턴.
- **Part 6 통합**: 권한 시스템 = 컨텍스트(6.1) + 컨테이너(6.2) + 모드(6.3) + 룰(6.4). 코드, 프롬프트, 데이터의 세 자리에 분산. 9장 미니 구현에서 다 회수.
