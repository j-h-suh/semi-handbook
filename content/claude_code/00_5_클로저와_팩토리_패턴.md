# 0.5 클로저와 팩토리 패턴 — 함수가 상태를 캡슐화한다는 것

---

## 이 챕터에서 배우는 것

- JS/TS 클로저(closure) 의 정의 — Python 과의 미묘한 차이
- 함수가 어떻게 상태를 들고 다닐 수 있는가
- 팩토리 패턴 — 함수가 새 함수/객체를 만들어 반환
- "나중에 완성되는 객체" 패턴 (memoize, prefetch 등)

---

## 사용자 경험에서 출발

Claude Code 코드를 보면 다음 같은 패턴이 자주 등장한다.

```typescript
const init = memoize(async () => {
  // 무거운 초기화 작업
})
```

`memoize` 라는 함수가 함수를 받아서 함수를 반환한다. 그 새 함수는 "여러 번 호출해도 본문이 한 번만 실행되도록" 메모하는 능력을 갖는다.

또 이런 것도 있다.

```typescript
const ReadTool = buildTool({
  name: 'Read',
  description: '...',
  inputSchema: { ... },
})
```

`buildTool` 도 함수다. 도구 정의 객체를 받아 완성된 Tool 인스턴스를 만들어 반환한다.

Python 개발자에게 이런 패턴은 약간 신선하다. Python 에서는 보통 클래스를 쓴다 — `class Tool:`, `class Memoizer:`. 그런데 JS/TS 에서는 함수가 함수를 만들어 반환하는 게 흔한 패턴.

답을 풀어보면 두 가지가 보인다 — **클로저(closure)** 와 **팩토리 패턴(factory pattern)**. 그리고 그 둘의 핵심 발상은 한 줄로 — **함수가 자기 안에 상태를 들고 다닐 수 있다**. 객체 없이도 객체처럼.

이 챕터는 그 발상을 짚는다. 1.1(memoize 패턴, prefetch), 3.3(buildTool 팩토리), 9장(미니 Claude Code 구현) 같은 곳에서 이 패턴이 핵심이라, 미리 익혀두면 본문이 가벼워진다.

---

## 클로저 — 함수가 변수를 기억한다

함수 안에 또 다른 함수를 정의하면, 안쪽 함수는 바깥쪽의 지역 변수를 기억한다 — 바깥 함수가 끝난 뒤에도.

```typescript
function makeCounter() {
  let count = 0
  return () => ++count
}

const c = makeCounter()
c()   // 1
c()   // 2
c()   // 3
```

`makeCounter()` 가 호출 끝나면 일반적인 상식으로는 `count` 라는 지역 변수도 사라져야 한다. 그런데 반환된 함수가 `count` 를 계속 들고 있다. `c()` 호출마다 그 `count` 가 1씩 증가한다.

이게 **클로저(closure)**. 함수가 자기를 둘러싼(enclosing) 변수의 환경을 기억하는 것.

여기서 핵심 — **각 `makeCounter()` 호출은 새 클로저를 만든다**. 두 번 호출하면 두 개의 독립된 카운터가 생긴다.

```typescript
const a = makeCounter()
const b = makeCounter()
a(); a(); a()    // a 의 count: 3
b()              // b 의 count: 1 (a 와 무관)
```

각 카운터가 자기만의 `count` 를 들고 있다. 이게 함수가 상태를 캡슐화한다는 의미다.

---

## Python 과의 미묘한 차이

Python 에도 클로저가 있다. 다만 쓰기에서 한 가지 명시 단계가 더 필요하다.

```python
def make_counter():
    count = 0
    def increment():
        nonlocal count    # 명시 필요
        count += 1
        return count
    return increment

c = make_counter()
c()   # 1
c()   # 2
```

`nonlocal count` 가 없으면? Python 은 `count += 1` 을 "지역 변수에 쓰기" 로 해석해 `UnboundLocalError`. JS/TS 는 이런 명시가 필요 없다 — 안쪽 함수가 바깥 변수에 자동으로 읽기든 쓰기든 한다.

| | JS/TS | Python |
|--|-------|--------|
| 바깥 변수 읽기 | 자동 | 자동 |
| 바깥 변수 쓰기 | 자동 | `nonlocal` 명시 필요 |

차이는 작아 보이지만 코드 패턴에 영향이 있다. JS/TS 는 클로저로 상태를 만드는 게 더 가볍다 — 클래스 대신 함수를 쓰는 빈도가 높다.

---

## 함수가 상태를 캡슐화한다는 것

위 카운터 예시를 클래스와 비교해보자.

```typescript
// 클래스 방식
class Counter {
  count = 0
  increment() { return ++this.count }
}
const c = new Counter()
c.increment()
```

```typescript
// 클로저 방식
const makeCounter = () => {
  let count = 0
  return () => ++count
}
const c = makeCounter()
c()
```

두 방식 모두 상태를 가진 카운터를 만든다. 클래스는 데이터(`count`) 와 동작(`increment`) 을 클래스 안에 묶고, 클로저는 함수 스코프 안에 묶는다. 결과적으로 두 방식은 같은 효과 — 데이터와 동작이 한 묶음, 외부에서 직접 못 만지는 상태.

> **클래스가 상태와 메서드를 한 묶음으로 만들듯, 클로저는 변수와 함수를 한 묶음으로 만든다. 함수도 객체 같은 것을 만들 수 있다.**

이게 자유로워지는 순간이 있다. 객체가 메서드 하나뿐일 때 — 클래스 정의 + `new` 호출이 부담스럽다. 함수 하나 반환하면 끝. 이런 경우 JS/TS 에서는 보통 클로저 방식을 쓴다.

---

## 팩토리 패턴 — 함수가 새 것을 찍어낸다

위에서 본 `makeCounter()` 가 사실 **팩토리 패턴(factory pattern)** 의 가장 단순한 형태다. 함수가 호출될 때마다 새 무언가 — 함수든 객체든 — 를 만들어 반환하는 패턴. 아래 두 예시가 그 두 형태다 — `memoize` 는 함수를 반환하고, `buildTool` 은 객체를 반환한다.

`memoize` 도 팩토리다.

```typescript
function memoize<T>(fn: () => Promise<T>): () => Promise<T> {
  let cached: Promise<T> | null = null
  return () => {
    if (cached === null) cached = fn()
    return cached
  }
}

const init = memoize(async () => { /* 무거운 작업 */ })
init()   // 첫 호출 — 본문 실행, Promise 캐시
init()   // 두 번째 호출 — 캐시된 Promise 반환
```

`memoize` 는 함수를 받아 새 함수를 반환한다. 새 함수는 클로저로 `cached` 와 `fn` 을 들고 있고, 호출 시 한 번만 본문을 실행하도록 결정한다. 호출자는 그 결정 로직을 직접 짤 필요가 없다 — 그냥 `init()` 부르면 끝.

Python 으로 옮기면 형태가 거의 그대로다 (위 `make_counter` 와 같은 패턴 — `nonlocal` 만 추가).

```python
def memoize(fn):
    cached = None
    def wrapper():
        nonlocal cached
        if cached is None:
            cached = fn()
        return cached
    return wrapper

init = memoize(heavy_init)
init()   # 첫 호출 — 본문 실행, 결과 캐시
init()   # 두 번째 — 캐시 반환
```

(async 버전은 1.1 의 `async_once` 가 정확히 이 패턴이다 — `cached` 자리에 `asyncio.Task` 핸들이 들어간다.)

`buildTool` 도 같은 모양.

```typescript
function buildTool(def: ToolDef): Tool {
  return { ...TOOL_DEFAULTS, ...def, _id: generateId() }
}
```

도구 정의를 받아, 기본값과 합쳐서 완성된 Tool 객체를 만들어 반환. 매번 호출마다 새로운 객체.

Python 으로는 dict 또는 dataclass 로 같은 모양이 자연스럽다.

```python
TOOL_DEFAULTS = {...}

def build_tool(**kwargs) -> dict:
    return {**TOOL_DEFAULTS, **kwargs, "_id": generate_id()}

read_tool = build_tool(name='Read', description='...', input_schema={...})
```

팩토리 패턴의 가치 — **호출자는 "이런 게 필요하다" 만 적고, 팩토리가 알아서 만들어준다**. 안에서 일어나는 정리 (기본값 적용, 클로저로 상태 보관, ID 생성) 는 호출자가 신경 쓸 필요 없다.

---

## 한 가지 더 — "나중에 완성되는 객체"

`memoize` 가 만들어내는 함수는 약간 특별하다. 처음 만들어졌을 때는 아직 본문을 실행한 적 없는 상태. 첫 호출에서 본문이 실행되어 결과가 캐시된다. 그 이후로는 캐시된 결과를 반환.

이게 **나중에 완성되는 객체** 패턴. 객체가 만들어진 시점과 값이 결정되는 시점이 분리된다. JS/TS 에서는 클로저가 이런 패턴을 자연스럽게 만든다.

1.1 의 prefetch 도 같은 발상이다 — `startKeychainPrefetch()` 호출 시점에 결과는 아직 없지만, 나중에 `ensureKeychainPrefetchCompleted()` 호출 시 그 결과를 받는다. 클로저 자체는 아니지만 "결과가 나중에 도착하는 객체를 다룬다" 는 발상은 같다.

---

## 핵심 정리

- **클로저는 함수가 자기를 둘러싼 변수를 기억하는 능력.** `makeCounter()` 같은 함수의 반환값이 바깥 함수의 지역 변수를 계속 들고 다닌다 — 호출이 끝난 뒤에도.
- **함수도 객체 같은 것을 만들 수 있다.** 클래스가 상태와 메서드를 한 묶음으로 묶듯, 클로저는 변수와 함수를 한 묶음으로 묶는다 — 결과는 같은 캡슐화.
- **Python 과 차이 — JS/TS 는 바깥 변수 쓰기가 자동.** Python 은 `nonlocal` 명시 필요. 작은 차이지만 JS/TS 에서 클로저 패턴이 더 가볍게 쓰이는 이유.
- **팩토리 패턴은 함수가 새 함수/객체를 만들어 반환.** `memoize`, `buildTool`, `makeCounter` 모두 같은 형태. 호출자는 "필요한 것" 만 적고, 팩토리가 만들어준다.
- **본문 곳곳에서 등장.** 1.1 `memoize(async)`, 3.3 `buildTool`, prefetch 패턴, 9장 미니 Claude Code 구현 — 한 번 익히면 코드가 빠르게 읽힌다.
