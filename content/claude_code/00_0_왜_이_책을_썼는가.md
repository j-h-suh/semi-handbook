## 솔직한 출발점

당신은 이미 Claude Code를 잘 쓰고 있습니다. `/commit`을 치면 알아서 커밋 메시지를 만들어주고, "이 함수 좀 리팩토링해줘"라고 하면 알아서 파일을 읽고 고쳐줍니다. 어떻게 그게 가능한지는 잘 모르지만, 어쨌든 됩니다.

그래서 한 가지 의문이 생깁니다.

> "이거 안에서 정확히 무슨 일이 일어나고 있지?"

대부분의 사람은 이 의문을 가졌다가 그냥 지나갑니다. Claude Code 소스코드는 약 52만 줄의 TypeScript이고, 처음 열어보면 어디서부터 봐야 할지 막막합니다. 공식 문서는 사용법만 알려주고 내부 아키텍처는 거의 다루지 않습니다. GitHub 이슈를 뒤적이면 단편적인 답은 나오지만, 큰 그림은 안 보입니다.

이 책은 그 의문을 가졌지만 52만 줄 앞에서 멈춘 사람들을 위한 것입니다.

---

## 잘 쓰는 것 vs 이해하는 것

"근데 잘 쓰면 됐지, 굳이 안을 알아야 합니까?"라고 물으실 수 있습니다. 평소에는 그 말이 맞습니다.

비유를 하나 들어보겠습니다.

`asyncio.run(main())` 한 줄을 써본 Python 개발자는 많습니다. `async def`, `await`, `gather` 같은 문법도 알고, FastAPI 핸들러를 비동기로 짤 줄도 압니다. 그런데 어느 날 다음과 같은 상황이 생깁니다.

- `await`를 빼먹었더니 코루틴 객체가 그냥 출력으로 나옵니다.
- 한 핸들러 안에서 동기 라이브러리(예: `requests`)를 호출했더니 전체 서버가 멈춥니다.
- `asyncio.gather` 안에서 한 태스크가 예외를 던졌는데 다른 태스크들은 계속 도는 것 같기도, 멈춘 것 같기도 합니다.
- "`loop.run_until_complete`와 `asyncio.run`이 뭐가 다른가요?"라는 면접 질문 앞에서 막힙니다.

이 모든 상황에서 "왜?"라고 물을 수 있는 능력은 어디서 옵니까? **이벤트 루프가 어떻게 돌아가는지 한 번이라도 그려본 적이 있는가**에서 옵니다. 문법을 외워서 생기는 게 아니라, "코루틴이 yield할 때 이벤트 루프가 다른 태스크로 컨텍스트를 넘기는구나"를 머릿속에 한 번 그려본 사람이 그 능력을 갖습니다.

Claude Code도 마찬가지입니다.

- Claude가 도구를 호출하는 게 정확히 어떤 메커니즘인지
- 권한 체크가 몇 단계로 작동하는지, 그 사이 어디서 사용자에게 묻는지
- "방금 내가 시킨 작업이 왜 거부됐지?"를 디버깅할 때 어디부터 봐야 하는지
- 컨텍스트가 길어졌을 때 자동 압축이 언제 작동하는지
- 진짜로 비슷한 도구를 만들 수 있는지

이런 질문들 앞에서 자신 있게 답하려면 "안에서 무엇이 일어나는가"의 그림이 필요합니다. **그 그림을 그려주는 것이 이 책의 역할입니다.**

## 누가 읽으면 좋은가

이 책은 다음 네 가지를 가정합니다.

1. **Python을 주력으로 쓰는 개발자.** FastAPI나 Django, asyncio, Pydantic 정도는 손에 익었습니다. 백엔드든, ML이든, 데이터든, Python이 주력 도구입니다.
2. **Claude Code를 사용자로서 충분히 써본 사람.** 슬래시 명령이 뭔지, 도구가 뭔지, 권한 모드가 뭔지 — 사용자 매뉴얼 수준에서는 압니다. 머릿속에 "사용자 경험"이 그려져 있습니다.
3. **TypeScript / React / Bun은 본 적 없거나, 가벼운 정도.** "에이전트 루프", "스트리밍", "AsyncIterator" 같은 단어는 어디서 들어본 것 같지만, 정확히 어디에 쓰이는지는 모릅니다.
4. **단순한 호기심 이상의 동기가 있는 사람.** 그냥 "안이 궁금하다"가 아니라, "이걸 알면 비슷한 걸 만들거나, 확장하거나, 더 잘 쓸 수 있을 것 같다"는 약간의 야망이 있습니다.

이 네 가지가 다 맞다면 환영합니다.

## 누가 안 읽어도 되는가

- **Claude Code를 한 번도 써본 적 없는 사람.** 이 책은 사용법을 가르치지 않습니다. 사용자 경험을 출발점으로 삼기 때문에, 그 경험이 없으면 이야기가 시작되지 않습니다.
- **TypeScript를 처음부터 배우고 싶은 사람.** 이 책은 TypeScript 입문서가 아닙니다. TS 코드는 인용하더라도 "이 패턴이 무엇을 의미하는지"만 풀어 쓰고, 문법 자체는 가르치지 않습니다.
- **52만 줄을 다 읽고 싶은 사람.** 핵심 패턴만 봅니다. 의도적으로 생략하는 부분이 많습니다.

## 이 책이 약속하는 것

10개 Part(Part 0 포함하면 11개), 39개 챕터 + 에필로그를 다 읽고 나면, 두 가지가 가능해집니다.

**1. `claude` 명령을 칠 때 일어나는 일을 머릿속에서 전부 그릴 수 있습니다.**

사용자 입력이 어디로 가는지, LLM API 호출은 어디서 일어나는지, 도구 호출은 어떻게 디스패치되는지, 권한 체크는 몇 단계인지, 결과는 어떻게 다시 LLM으로 돌아가는지, 화면에는 어떻게 그려지는지. 마지막 비트까지는 아니어도, 큰 그림과 핵심 메커니즘이 손에 잡힙니다.

**2. Python으로 미니 Claude Code를 직접 만들 수 있습니다.**

400~500줄짜리 동작하는 미니 에이전트를 만듭니다. `Read`, `Write`, `Bash` 도구를 가지고, 권한 체크를 하고, 스트리밍 응답을 처리하고, 한 단계 서브 에이전트까지 합니다. 그리고 진짜 Claude Code에 사용자 정의 명령, 스킬, MCP 서버를 추가하는 방법까지 배웁니다.

---

## 이 책이 약속하지 않는 것

- **52만 줄을 모두 설명하지 않습니다.** 핵심 패턴 위주로만 봅니다.
- **모든 디테일을 다루지 않습니다.** Bun의 빌드 트릭, Anthropic API의 prompt cache 정책, IDE 확장의 모든 메시지 타입 — 이런 디테일은 Deep Dive 박스로 빼거나 아예 생략합니다.
- **TypeScript 문법을 가르치지 않습니다.**
- **에이전트 시스템 일반론을 가르치지 않습니다.** 이 책은 Claude Code라는 구체적 시스템을 봅니다. ReAct, Plan-and-Execute 같은 학술적 분류는 지나가듯 언급할 뿐입니다.

## 책의 구조 — 11개 Part

전체는 **11개 Part(Part 0 포함)** 로 구성됩니다. 각 Part가 무엇을 다루는지 한 줄 미리보기.

**Part 0: 들어가며.** 지금 이 챕터를 포함한 도입. 책 전체의 톤·약속·읽는 법을 잡고, "Claude Code = 도구를 쓸 줄 아는 챗봇"이라는 한 줄 요약과 그 뒤의 작은 루프 한 장을 머릿속에 박습니다.

**Part 1: 사용자가 `claude`를 칠 때.** 진입점에서 REPL이 뜨기까지의 부트스트랩 흐름. 실행 첫 30ms 동안 무엇이 어떤 순서로 일어나는지, REPL 루프는 어떻게 React 컴포넌트로 만들어졌는지.

**Part 2: 핵심 — LLM 도구 사용 루프 (🎯 승부처).** 책의 첫 번째 심장. Part 0에서 그렸던 에이전트 루프 한 장을 본격적으로 분해합니다. 비동기 제너레이터 파이프라인, 스트리밍, 10가지 재시도/복구 경로까지.

**Part 3: 도구 시스템 (🎯 승부처).** 두 번째 심장. Tool 인터페이스 50개 메서드, `buildTool` 팩토리, 단순 도구(FileRead) → 복잡 도구(BashTool), 셸 인젝션 방어. "왜 도구가 함수가 아니라 1급 시민인가"의 답.

**Part 4: 명령 시스템.** 슬래시 명령(`/commit`, `/review`)이 일반 채팅과 어떻게 다른지. prompt / local / local-jsx 세 가지 명령 타입과 `allowedTools` 화이트리스트.

**Part 5: 터미널 UI.** "터미널에 React?"라는 질문에 답합니다. Ink가 무엇을 하는지, AppState 스토어, 가상 스크롤로 1만 메시지를 100줄에 그리기, 스트리밍 텍스트의 부분 업데이트.

**Part 6: 메모리·상태·권한 (🎯 승부처).** "비슷한 걸 직접 만들 때 가장 위험한 부분". CLAUDE.md가 어떻게 시스템 프롬프트가 되는지, 권한 모드 4가지, `Bash(git *)` 같은 와일드카드 매칭.

**Part 7: 서비스 계층.** API 클라이언트, MCP 클라이언트, OAuth, 컨텍스트 자동 압축. 각 서비스가 어디서 초기화되고 어떻게 다른 영역에 주입되는지.

**Part 8: 멀티 에이전트와 IDE 브리지 (🎯 승부처).** AgentTool은 어떻게 도구이면서 LLM을 호출할 수 있는지(재귀!), Coordinator Mode의 fork-join, IDE 확장과의 HTTP 폴링 통신.

**Part 9: 미니 Claude Code 만들기.** **책의 클라이맥스.** 앞에서 본 모든 패턴을 Python 400~500줄로 직접 만듭니다. 도구, 권한, 스트리밍, 서브 에이전트까지. 동작합니다.

**Part 10: 진짜 Claude Code 확장하기.** 마지막. 진짜 Claude Code에 사용자 정의 슬래시 명령, 스킬, MCP 서버를 추가하는 방법. "다음 주부터 쓸 수 있는 결과물"을 손에 쥐고 책을 덮습니다.

**Part 2, 3, 6, 8** 네 곳을 승부처로 잡았습니다. 책 전체 분량의 절반 가까이가 이 네 곳에 집중되어 있습니다. 다른 Part는 가볍게 훑어도 되지만, 승부처는 단단히 짚어야 합니다.

## 각 챕터는 이렇게 생겼습니다

모든 챕터는 동일한 5단 구조를 따릅니다.

**1. 이 챕터에서 배우는 것.** 3~4줄짜리 미리보기. 이걸 읽고 "아, 이거 나한테 필요하다"면 읽고, "이건 이미 안다"면 건너뛰어도 됩니다.

**2. 사용자 경험에서 출발.** 이 책의 가장 큰 특징입니다. 모든 챕터가 "당신이 X를 할 때 무슨 일이 일어나는가" 또는 "이런 상황 본 적 있죠?" 같은 익숙한 지점에서 시작합니다. 추상 개념을 먼저 던지지 않습니다. 당신이 이미 가진 사용자 경험에 새 그림을 얹는 방식입니다.

**3. 본문.** 비유와 그림과 의사코드가 섞여 있습니다. 비유는 항상 Python 생태계에서 가져옵니다(FastAPI, asyncio, Pydantic, dataclass 등). TypeScript 코드는 인용하더라도 한 블록당 30줄을 넘지 않으려고 합니다. ASCII 다이어그램이 거의 모든 챕터에 한 장씩 들어 있습니다.

**4. Python으로 옮기면.** 앞에서 본 패턴을 Python 의사코드(또는 진짜 코드)로 다시 풀어봅니다. "이게 Python이라면 어떻게 생겼을까"의 답입니다. Part 9에서 만들 미니 Claude Code의 부품들이 여기서 미리 등장합니다.

**5. 핵심 정리.** "이것만 기억해." 글머리 기호 3~5개로 챕터의 핵심을 압축합니다. 나중에 레퍼런스로 돌아올 때 이 섹션만 훑으면 됩니다.

5단을 다 읽지 않아도 됩니다. 시간이 없으면 1번과 5번만 봐도 큰 그림은 잡힙니다.

## 어떻게 읽으면 좋은가

**순서대로 읽기를 권합니다.** 챕터들이 서로 연결되어 있어서, 앞 챕터에서 심은 떡밥을 뒤 챕터에서 회수하는 구조입니다. 건너뛰면 "어, 이게 뭐였더라?"가 생깁니다.

특히 **Part 2 (LLM 도구 사용 루프)** 와 **Part 3 (도구 시스템)** 은 책의 심장입니다. 이 두 Part를 단단히 짚지 않으면 뒤가 무너집니다.

대신 가벼운 부분도 있습니다.

- Part 5 (터미널 UI)는 React/Ink가 처음이라면 살짝 부담스럽지만, 본질에서는 부수적입니다. 한 번 훑고 넘어가도 됩니다.
- Part 7 (서비스 계층)도 비슷합니다. MCP만 챙기고 OAuth, LSP, 분석은 가볍게 봐도 됩니다.

그리고 한 가지 더 — **Python 코드는 직접 쳐보십시오.** "Python으로 옮기면" 섹션을 눈으로만 읽지 말고, 실제로 노트북을 열고 돌려보십시오. 에이전트 루프에 대한 직관은 그림을 보는 것과 직접 한 번 돌려보는 것 사이에 큰 차이가 있습니다. Part 9에서 미니 Claude Code를 만들 때, 그 직관이 있어야 코드가 흐름으로 읽힙니다.

## 마지막 한 가지 — 톤에 대해

이 책의 본문은 "옆자리 선배가 후배에게 알려주는" 느낌의 반말입니다. **0.1부터** 그렇게 됩니다. 지금 이 챕터(0.0)는 도입이라 존댓말을 유지하지만, 다음 챕터부터는 톤이 살짝 바뀝니다. 미리 알려둡니다.

학술서가 아니고 매뉴얼도 아닙니다. 가끔 직설적인 표현이 나옵니다.

> "이건 좀 이상해."
> "여기서 Python 직관을 따라가면 안 돼."
> "사실 단순해."

이런 표현들은 학술적 정중함을 포기한 게 아니라, 진짜로 그렇기 때문에 그렇게 씁니다. 8만 줄짜리 시스템 안에는 이상한 부분, 단순한 부분, 의외의 부분이 다 있고, 그걸 있는 그대로 부르는 게 가장 정확합니다.

## 핵심 정리

- 이 책은 **Python 개발자이면서 Claude Code를 매일 쓰는 사람**을 위한 책이다.
- **52만 줄 TypeScript를 다 읽지 않고**, Python의 머리로 핵심 패턴만 잡는다.
- 책은 **11개 Part**로 구성되어 있고, **Part 2 / 3 / 6 / 8이 승부처**다. 마지막 Part 9에서 미니 Claude Code를 직접 만들고, Part 10에서 진짜 Claude Code 확장까지 배운다.
- 모든 챕터는 **5단 구조** (배우는 것 → 사용자 경험 → 본문 → Python으로 옮기면 → 핵심 정리)를 따른다.
- **순서대로 읽기를 권장**한다. 그리고 Python 코드는 눈으로만 읽지 말고 직접 쳐보자.
