# 1.1 부트스트랩의 첫 30ms — 병렬 prefetch와 빠른 경로

---

## 이 챕터에서 배우는 것

- 터미널에 `claude`를 친 직후 무엇이 어떤 순서로 일어나는가
- 왜 어떤 명령(`--version`)은 다른 명령보다 훨씬 빠른가
- "병렬 prefetch"라는 트릭이 어떻게 사용자 체감 시간을 줄이는가
- Python의 부트스트랩 패턴과 어떻게 다르고 같은가

---

## 사용자 경험에서 출발

터미널에 `claude` 치고 엔터를 누른다. 거의 즉시 REPL이 뜨고 입력 프롬프트가 나타난다. *"잘 만들어졌네"* 정도로 지나치기 쉽다.

근데 잠깐 생각해보자. Claude Code는 52만 줄짜리 TypeScript 프로그램이다. Bun 런타임이 그 코드를 로드하고, MDM 정책을 확인하고, 사용자 설정을 읽고, OAuth 토큰을 꺼내고, Anthropic API에 사전 연결해야 한다. 이 모든 게 진짜로 빠르게 끝나는 걸까, 아니면 어떤 트릭이 있는 걸까?

답은 둘 다다. 진짜로 빠르긴 한데, 그게 빠르게 느껴지는 데에는 트릭도 있다. 그 트릭이 이 챕터의 주제다.

---

## 본문

### 진입점부터 보자

bin 진입점은 `src/entrypoints/cli.tsx`다. 사용자가 `claude`를 치면 Bun이 이 파일을 실행한다. 그런데 `cli.tsx`의 첫 줄들은 의외로 정적 import가 거의 없다. 이건 의도적이다.

이유는 한 가지 — **빠른 경로(fast path)**.

```
$ claude --version
0.1.234
```

이런 명령은 무거운 import 없이 1초 안에 끝나야 한다. 그래서 `cli.tsx`는 명령줄 인자를 먼저 슥 보고 다음과 같이 분기한다.

- `--version` / `-v` / `-V`이면? → 버전 문자열만 출력하고 종료. **한 번도 무거운 모듈을 import하지 않는다.** (`cli.tsx:37`)
- `claude daemon`, `claude bridge`, `--claude-in-chrome-mcp` 같은 특수 서브모드? → 그쪽 진입점만 **동적 import** 해서 점프. 메인 CLI 코드는 건드리지 않는다.
- 그 외(REPL, 일반 명령)? → `main.tsx`를 **동적 import** 해서 진입.

여기서 **동적 import (`await import('...')`)** 가 핵심이다. 정적 `import` 문은 모듈 평가 시점에 모든 의존성을 따라가지만, 동적 import 는 분기 안에서만 그 모듈을 로드한다. fast path 들은 이걸 활용해서 메인 CLI 의 ~135ms import 를 건너뛴다.

52만 줄을 안 건드리는 빠른 경로가 있는 거다. 이게 첫 번째 트릭이다. (`cli.tsx` 안에 fast path 가 13가지 정도 있다 — `--dump-system-prompt`, `--computer-use-mcp`, `--daemon-worker`, `claude ps/logs/attach/kill`, `claude environment-runner` 등.)

### main.tsx의 첫 20줄

본격 모드(REPL이나 특정 명령)로 들어가면 `main.tsx`가 시작된다. 그런데 main.tsx의 첫 20줄을 보면 흥미로운 패턴이 있다.

```typescript
// main.tsx (line 9-20, 단순화)
import { profileCheckpoint } from './utils/startupProfiler.js'
profileCheckpoint('main_tsx_entry')

import { startMdmRawRead } from './utils/settings/mdm/rawRead.js'
startMdmRawRead()       // MDM 정책 비동기 읽기 시작 (자식 프로세스 spawn)

import { ensureKeychainPrefetchCompleted, startKeychainPrefetch } from './utils/secureStorage/keychainPrefetch.js'
startKeychainPrefetch() // OAuth 토큰 미리 가져오기 (macOS Keychain)

import { feature } from 'bun:bundle'
// ... 60+ 개의 무거운 import 들이 줄줄이
```

`import` 문 사이사이에 호출이 끼어 있다. 이게 핵심이다. `profileCheckpoint('main_tsx_entry')` 는 성능 측정 마크고, `startMdmRawRead()` 와 `startKeychainPrefetch()` 가 진짜 prefetch 트리거다.

`startMdmRawRead()`는 MDM(Mobile Device Management) 정책을 읽는다. macOS에서는 자식 프로세스(`plutil`/`reg query`)를 spawn해야 하는 작업이라 60ms 정도 걸린다. `startKeychainPrefetch()`는 Keychain에서 OAuth 토큰을 미리 꺼내온다 — 이걸 안 하면 나중에 `applySafeConfigEnvironmentVariables()` 안에서 sync spawn 으로 ~65ms 가 그대로 주 스레드를 막는다 (`main.tsx:5-8` 주석에 명시되어 있다).

**중요한 건, 이 둘이 비차단(non-blocking)이라는 점이다.** 시작만 하고 결과를 기다리지 않는다. 그 결과는 나중에 필요할 때 가져간다.

### 왜 이렇게 만들었나? 시간축으로 보면 답이 보인다

```
시간 (ms)  ────────────────────────────────────────►
           0       50      100      150     200

주 스레드:  [import 135ms ─────────────] [main run]
            │
            ├─ startMdmRawRead()
            └─ startKeychainPrefetch()
                       │
배경:                  [MDM 60ms ─────]
                       [Keychain ~50ms ──]
```

만약 prefetch를 안 하고 import 끝난 후에 sequential로 실행했다면? 135 + 60 + 50 = **245ms**. 사용자가 체감하는 부트스트랩 시간이 그만큼 늘어난다.

근데 prefetch를 import와 겹쳐서 던져두면? import가 끝나는 시점(135ms)에는 MDM도 Keychain도 이미 끝나 있다. 사용자 체감 시간은 import 시간(**135ms**)만 지난 거다. 60ms + 50ms는 공짜가 됐다.

이게 두 번째 트릭이다. **무거운 import 시간을 background 일감으로 채워라.**

> 💡 **Python 비유:** `asyncio.create_task(read_mdm_policy())`를 호출하고 `await` 안 한 채로 다른 일 진행. 나중에 결과가 필요할 때 await. 단, Python에서는 보통 import가 끝난 후에 task를 만들 수밖에 없어서, 정확히 같은 효과를 내기는 어렵다. Bun/Node.js는 모듈 import가 진짜로 오래 걸리는데, 그 시간을 활용한다는 발상이 신선하다.

### Commander의 preAction hook — rendezvous + memoize(async)

import가 끝나면 `main.tsx`가 Commander.js (`@commander-js/extra-typings`) 로 CLI를 정의한다. 흥미로운 게 Commander의 **실행 전 훅(preAction hook)** — 명령 본체가 실행되기 직전에 끼어들어 공통 준비 작업을 돌리는 자리 — 이다.

```typescript
// main.tsx:907~ (단순화)
program.hook('preAction', async thisCommand => {
  // 1단계 — 위에서 던져둔 prefetch 들의 결과를 회수 (rendezvous point)
  await Promise.all([
    ensureMdmSettingsLoaded(),
    ensureKeychainPrefetchCompleted(),
  ])
  // 2단계 — 본격 초기화 (한 번만 실행 보장)
  await init()
  // ... 그 후 sinks, migrations, remote settings 등
})
```

여기가 **prefetch 의 짝꿍**, 곧 **만남점(rendezvous)** — 비동기로 던져둔 작업들의 결과를 한자리에서 회수하는 지점 — 이다. `main.tsx` 첫 20줄에서 `startMdmRawRead()` / `startKeychainPrefetch()` 로 던져둔 결과를, 여기서 `ensure*` 함수들로 회수한다. import 시간(135ms) 동안 background 에서 끝났을 테니 이 `await` 는 사실상 즉시 resolved.

그리고 `init()` 은 설정 로드, mTLS 적용, API 사전 연결 등을 한다. 그런데 한 가지 보장이 필요하다. **여러 번 호출해도 한 번만 실행되어야 한다.** (서브 명령이 또 다른 서브 명령을 부르면 preAction이 두 번 트리거될 수 있으니까.)

해법은 **메모이제이션(memoization)** — 같은 인자로 여러 번 불려도 실제 계산은 첫 호출에만 하고 이후엔 캐시된 결과를 반환하는 기법 — 이다. lodash의 `memoize(async)` 가 그 구현이다.

```typescript
export const init = memoize(async (): Promise<void> => {
  // ... 무거운 초기화 작업
})
```

이게 보장하는 것: 첫 호출은 진짜로 실행. 두 번째부터는 첫 호출이 반환한 같은 Promise를 그대로 반환. 이미 끝났으면 즉시 resolved Promise. 아직 진행 중이면 그 Promise를 그냥 기다림.

> ⚠️ **Python 함정:** Python의 `functools.lru_cache`는 async 함수와 호환되지 않는다. async 함수에 데코레이터를 붙이면 Coroutine 객체를 캐시하는데, 그 객체는 한 번 await하면 소진되어서 두 번째 await에서 깨진다. async memoize는 직접 만들거나 `async-lru` 같은 라이브러리를 써야 한다.

### init() 안에서 일어나는 일 — 그리고 init() 가 안 하는 것

`init()` (`entrypoints/init.ts:57`) 안의 흐름은 의외로 단계가 많다 — 그리고 **신뢰 다이얼로그가 init() 안에 없다는 것**이 핵심이다.

init() 의 주요 단계:

1. **설정 파일 로드** (`enableConfigs`) — `~/.claude/settings.json`, 프로젝트 디렉토리의 `.claude/settings.json`
2. **안전한 환경변수만 먼저 적용** (`applySafeConfigEnvironmentVariables`) — 전체 환경변수가 아니다. 신뢰가 통과되기 전까지는 안전한 것만 적용된다
3. **mTLS / 프록시 설정** (`configureGlobalMTLS`, `configureGlobalAgents`) — 회사 내부 프록시 환경 대응
4. **Anthropic API 사전 연결** (`preconnectAnthropicApi`) — TCP+TLS 핸드셰이크(~100-200ms) 를 미리 던져둠
5. (이외에 OAuth 사용자 정보 캐시, JetBrains 감지, GitHub 리포 감지, 정책 한도 로딩, scratchpad 디렉토리 초기화, LSP cleanup 등록 등 부차적 작업이 더 있다)

`init()` 이 끝나면 `main.tsx` 가 받아서 신뢰 다이얼로그를 띄운다 (`main.tsx:2241` 의 `showSetupScreens()`). 참고로 `main.tsx:372` 의 `checkHasTrustDialogAccepted()` 는 신뢰가 이미 수락되었는지 확인하여 시스템 컨텍스트 프리페치 여부를 결정하는 별도 용도다. 신뢰가 통과되면 그제서야 전체 환경변수가 `applyConfigEnvironmentVariables()` 로 적용된다 (`main.tsx:1965` 등).

**왜 이렇게 나눠놨을까?** 보안 경계 때문이다. 환경변수에는 임의의 명령 실행을 트리거할 수 있는 것들이 포함될 수 있다 (예: `NODE_OPTIONS`). 신뢰하지 않는 디렉토리의 `settings.json` 에서 그런 변수가 흘러나오면 위험하다. 그래서 안전한 것만 먼저 적용하고 (init 안), 신뢰가 통과된 후에 전체를 적용한다 (main.tsx 안). *"악의적인 디렉토리에서 환경변수를 통해 무언가를 주입할 수 있을까?"* 를 막기 위한 설계.

## Python으로 옮기면

이 패턴을 Python으로 흉내 내면 이렇게 생겼다.

```python
import asyncio
from functools import wraps

def async_once(fn):
    """async 함수용 단순 memoize. 첫 호출의 Future를 캐시한다."""
    cached_future = None
    @wraps(fn)
    async def wrapper():
        nonlocal cached_future
        if cached_future is None:
            cached_future = asyncio.ensure_future(fn())
        return await cached_future
    return wrapper

def start_background_tasks():
    """비차단으로 prefetch 시작. 결과는 나중에 필요할 때 await."""
    asyncio.create_task(read_mdm_policy())
    asyncio.create_task(prefetch_keychain_tokens())

@async_once
async def init():
    """preAction 안의 init() 에 해당. 한 번만 실행 보장.
    주의: 신뢰 다이얼로그는 여기 안에 없다! 아래 main() 의 다음 단계."""
    load_config()
    apply_safe_env_vars()           # 신뢰 전: 안전한 것만
    await setup_mtls_and_proxy()
    await prefetch_anthropic_api()
    # ... 그 외 OAuth 캐시, 정책 한도 로딩 등

async def main():
    start_background_tasks()        # 비차단으로 prefetch 시작 (fire)
    # ... 무거운 import (Python에서는 이미 끝났겠지만, 가정상) ...

    # rendezvous: 위에서 던져둔 prefetch 결과를 회수
    await asyncio.gather(
        ensure_mdm_loaded(),
        ensure_keychain_loaded(),
    )

    await init()                    # 안전한 환경변수까지만 적용

    if not has_trust_accepted():
        await ask_trust_dialog()    # 신뢰 다이얼로그는 init() *밖* 에서
    apply_full_env_vars()           # 신뢰 후: 전체 환경변수

    await run_repl()
```

핵심 장면 세 가지가 그대로 살아 있다.

1. `start_background_tasks()` — `await` 안 함. 던져두기만 함 (fire).
2. `await asyncio.gather(ensure_*())` — 던져둔 결과를 회수 (rendezvous).
3. `@async_once` — `init()`을 여러 번 호출해도 첫 호출만 실제 실행 (memoize).

> 💡 **팁:** `start_background_tasks()`처럼 task를 만들고 await 안 하면, 그 task의 예외가 조용히 사라지는 위험이 있다. 진짜 코드에서는 `task.add_done_callback(log_exception)` 같은 처리가 필요하다. Node.js의 `unhandledRejection` 경고도 같은 이유로 존재한다.

## 핵심 정리

- **빠른 경로(fast path)** — `--version` 같은 가벼운 명령은 무거운 import 자체를 피해서 1초 안에 끝낸다. `src/entrypoints/cli.tsx`가 명령줄 인자를 먼저 보고 분기. **동적 import (`await import('...')`)** 가 fast path 의 기술적 메커니즘이다.
- **병렬 prefetch + rendezvous** — `main.tsx`의 첫 20줄에서 MDM 정책, Keychain 토큰을 background로 던져두고, Commander 의 `preAction` hook 안에서 `ensureMdmSettingsLoaded` / `ensureKeychainPrefetchCompleted` 로 회수한다. 무거운 import 시간(135ms)에 그 결과가 공짜로 도착한다.
- **memoize(async)로 한 번만 실행 보장** — `preAction` hook이 매번 부르더라도 `init()`은 첫 호출만 실제 실행. 이후는 같은 Promise를 재사용. lodash 의 `memoize` 가 async 함수에서도 그대로 작동.
- **init() 밖에서 신뢰 다이얼로그가 처리된다** — `init()` 은 안전한 환경변수만 적용하고 멈춘다. 신뢰 다이얼로그는 main.tsx 가 init() 결과를 받은 후 띄우고, 통과되면 그제서야 전체 환경변수가 `applyConfigEnvironmentVariables` 로 적용된다. 보안 경계를 명확히 그은 설계.
- Python으로 옮기면 `asyncio.create_task` + 직접 만든 `async_once`로 비슷한 패턴이 가능하다. 단, `functools.lru_cache`는 async와 호환 안 됨에 주의.
