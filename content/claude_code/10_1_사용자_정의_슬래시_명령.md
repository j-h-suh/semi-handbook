# 10.1 사용자 정의 슬래시 명령 — 마크다운 한 파일이 명령이 된다

---

## 이 챕터에서 배우는 것

- 9.5에서 완성된 mini_claude에 **사용자 정의 명령 시스템**을 붙이는 전체 과정
- 마크다운 한 파일 = 하나의 명령. **코드 한 줄 안 치고** 에이전트를 커스터마이징한다
- frontmatter 파싱, 인자 치환 4가지, 디렉토리 walking + git 경계 — 각각의 설계 이유
- 4.3에서 분석한 **`allowedTools` 권한 슬롯**이 마크다운 한 줄로 동작하는 자리
- 진짜 클로드 코드의 `loadSkillsDir.ts`와 **같은 설계를 Python 150줄로 압축**하는 과정

## Part 10 의 골격 — 9.1 위에 무엇을 얹는가

9.1 에서 그린 미니 클로드의 한 장 그림은 9.5 까지의 완성형이었다. Part 10 의 여덟 챕터는 그 골격을 _깨뜨리지 않고_ 곁에 확장만 더한다. 9.1 의 그림에 _10.1~10.8 의 자리_ 를 표시하면:

## 왜 슬래시 명령인가

9.5를 마치면 mini_claude는 이런 에이전트다: 도구를 부르고, 권한을 묻고, 스트리밍으로 답하고, 서브 에이전트까지 돌린다. 하지만 — 한 가지 빠져 있다.

매일 같은 패턴으로 시키는 일이 있다. "오늘 한 git 작업을 한국어 3줄로 요약해줘". 매번 같은 문장을 친다. 5줄이면 짜증이 나고, 15줄이면 복사해서 붙여넣는다.

프로그래머의 반응은 정해져 있다 — **함수로 뽑자**. 그게 슬래시 명령의 본질이다. 반복되는 프롬프트를 **이름 하나로 부를 수 있게** 만드는 것. 그리고 그 형식이 **마크다운 한 파일**이면 — 코드를 안 짜도 된다.

이 챕터에서 mini_claude에 그 시스템을 구현한다.

## 구현 — 4단계

### 1단계: frontmatter 파싱

마크다운 명령의 구조는 단순하다: `---` 사이의 YAML 메타데이터 + 나머지 본문.

```python
# src/mini_claude/commands/markdown_loader.py
from __future__ import annotations
import re
import shlex
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any
import yaml


def parse_frontmatter(text: str) -> tuple[dict[str, Any], str]:
    """'---' 사이의 YAML frontmatter와 본문을 분리한다.

    Args:
        text: 마크다운 파일 전체 텍스트.

    Returns:
        (frontmatter dict, 본문 문자열) 튜플.

    Example:
        >>> fm, body = parse_frontmatter("---\\ndesc: hello\\n---\\nbody")
        >>> fm["desc"]
        'hello'
    """
    if not text.startswith("---\n"):
        return {}, text
    end = text.find("\n---\n", 4)
    if end == -1:
        return {}, text

    frontmatter_text = text[4:end]
    body = text[end + 5:]

    try:
        frontmatter = yaml.safe_load(frontmatter_text) or {}
    except yaml.YAMLError:
        frontmatter = {}

    return frontmatter, body
```

YAML 파싱이 실패하면 빈 dict — **사용자가 잘못된 YAML을 써도 본문은 살아남는다**. 관대한 파싱이 CLI 도구의 좋은 기본값이다.

> ⚠️ **`import yaml` — 의존성 추가**: 위 코드가 PyYAML 패키지를 쓴다. `pyproject.toml` 의 `dependencies` 에 `"pyyaml>=6.0"` 한 줄을 추가 (또는 `uv add pyyaml`). 없으면 `ModuleNotFoundError: No module named 'yaml'` 가 import 시점에 막는다. _10.5 의 `agents/loader.py`_ 는 의존성 회피 위해 _경량 직접 파싱_ 으로 가지만, 10.1 은 _YAML 전체_ 를 받아낼 필요가 있어 PyYAML 을 받아들였다.

### 2단계: MarkdownCommand 데이터 클래스

파싱된 결과를 담는 그릇. 4.2에서 본 `PromptCommand`의 미니 버전이다.

```python
@dataclass
class MarkdownCommand:
    """마크다운 파일 하나가 변환된 명령.

    진짜 코드의 createSkillCommand (loadSkillsDir.ts:270, 132줄) 결과를
    dataclass 한 개로 압축한 것.
    """
    name: str                                # /myCmd 의 myCmd
    description: str
    body: str                                # 본문 (치환 전)
    allowed_tools: list[str] = field(default_factory=list)
    argument_names: list[str] = field(default_factory=list)
    model: str | None = None
    context: str = "inline"                  # 또는 "fork"

    def get_prompt(self, args: str, session_id: str = "") -> str:
        """호출 시점에 본문을 변환해서 LLM에 보낼 텍스트를 만든다.

        Args:
            args: 사용자가 /myCmd 뒤에 입력한 문자열.
            session_id: 현재 세션 ID (${CLAUDE_SESSION_ID} 치환용).

        Returns:
            LLM user 메시지로 보낼 최종 텍스트.
        """
        content = self.body

        # ① 인자 치환
        content = substitute_arguments(content, args, self.argument_names)

        # ② ${CLAUDE_SESSION_ID} 치환
        content = content.replace("${CLAUDE_SESSION_ID}", session_id)

        return content
```

핵심 설계: **`get_prompt()`는 문자열을 만드는 함수일 뿐**. 이 결과를 9.5의 `query(user_input=...)`에 넘기면 끝이다. 명령 시스템은 에이전트 루프를 건드리지 않는다.

### 3단계: 인자 치환 — 4가지 방식

`/myCmd foo bar`를 쳤을 때 본문의 어디에 `foo`와 `bar`가 들어가는가?

```python
def parse_arguments(args: str) -> list[str]:
    """셸 인용 규칙으로 인자를 분리한다.

    Example:
        >>> parse_arguments('hello "world foo" bar')
        ['hello', 'world foo', 'bar']
    """
    try:
        return shlex.split(args)
    except ValueError:
        return args.split()


def substitute_arguments(
    content: str,
    args: str,
    argument_names: list[str] | None = None,
) -> str:
    """인자 치환 4가지 — 순서가 중요하다.

    더 구체적인 패턴부터 처리해야 일반적인 패턴이 침범하지 않는다.
    named → indexed[N] → shorthand → full → fallback append.
    """
    if not args:
        return content

    parsed = parse_arguments(args)
    original = content
    argument_names = argument_names or []

    # ① named — frontmatter의 arguments 필드와 매핑
    for i, name in enumerate(argument_names):
        if i >= len(parsed):
            break
        # negative lookahead: $foo 는 매칭, $foobar 는 매칭 안 함
        pattern = rf"\${re.escape(name)}(?![\[\w])"
        content = re.sub(pattern, parsed[i], content)

    # ② indexed — $ARGUMENTS[0], $ARGUMENTS[1]
    def replace_indexed(m: re.Match) -> str:
        idx = int(m.group(1))
        return parsed[idx] if idx < len(parsed) else ""

    content = re.sub(r"\$ARGUMENTS\[(\d+)\]", replace_indexed, content)

    # ③ shorthand — $0, $1 (뒤에 단어 글자 없을 때만)
    content = re.sub(r"\$(\d+)(?!\w)", replace_indexed, content)

    # ④ full — $ARGUMENTS (전체 문자열 한 덩어리)
    content = content.replace("$ARGUMENTS", args)

    # ⑤ fallback append — placeholder가 하나도 없었으면 끝에 박는다
    if content == original:
        content = content + f"\n\nARGUMENTS: {args}"

    return content
```

**⑤ fallback append**가 사용자 친화적 설계의 핵심이다. `$ARGUMENTS`를 깜빡 잊고 본문을 작성해도 — 인자가 사라지지 않는다. 그냥 본문 끝에 박아준다.

> 💡 **negative lookahead `(?![\[\w])`의 이유**: `$user`를 치환할 때 `$username`이 침범당하면 안 된다. `$user` 뒤에 단어 글자가 오면 매칭을 안 한다. 작은 정규식이지만 — 없으면 **silent bug**. 진짜 코드 `argumentSubstitution.ts:111`에도 같은 패턴이 있다.

### 4단계: 디렉토리 walking + git 경계

명령 파일을 어디서 찾느냐. cwd에서 부모 방향으로 걸어가되 — **git 경계에서 멈춘다**.

```python
def load_markdown_command(md_file: Path) -> MarkdownCommand:
    """*.md → MarkdownCommand 변환."""
    text = md_file.read_text(encoding="utf-8")
    frontmatter, body = parse_frontmatter(text)

    # description 자동 추출 fallback — 본문 첫 줄
    description = frontmatter.get("description")
    if not description:
        first_line = next(
            (line.strip() for line in body.split("\n") if line.strip()),
            "",
        )
        description = first_line[:80]

    return MarkdownCommand(
        name=md_file.stem,
        description=description,
        body=body,
        allowed_tools=_parse_allowed_tools(frontmatter.get("allowed-tools", "")),
        argument_names=_parse_argument_names(frontmatter.get("arguments", "")),
        model=frontmatter.get("model"),
        context=frontmatter.get("context", "inline"),
    )


def _parse_allowed_tools(value: str | list[str]) -> list[str]:
    """allowed-tools 필드는 문자열 또는 리스트 둘 다 허용."""
    if isinstance(value, list):
        return [str(v).strip() for v in value]
    if isinstance(value, str):
        return [t.strip() for t in value.split(",") if t.strip()]
    return []


def _parse_argument_names(value: str | list[str]) -> list[str]:
    if isinstance(value, list):
        return [str(v).strip() for v in value]
    if isinstance(value, str):
        return value.split()
    return []


def discover_commands(cwd: Path, home: Path) -> list[MarkdownCommand]:
    """cwd에서 부모로 걸어가며 .claude/commands/ 안의 마크다운을 모은다.

    git 경계에서 멈춘다 — 부모 repo의 명령이 자식으로 새지 않도록.
    """
    dirs: list[Path] = []

    # ① cwd → 부모로 walking, .git 경계에서 멈춤
    current = cwd.resolve()
    home_resolved = home.resolve()
    while current != current.parent and current != home_resolved:
        commands_dir = current / ".claude" / "commands"
        if commands_dir.is_dir():
            dirs.append(commands_dir)
        if (current / ".git").exists():
            break  # ⭐ git 경계 — 부모 repo leak 방지
        current = current.parent

    # ② home dir의 사용자 명령
    user_commands = home_resolved / ".claude" / "commands"
    if user_commands.is_dir():
        dirs.append(user_commands)

    # ③ 낮은 우선순위부터 로드, 같은 이름은 높은 우선순위가 덮어씀
    seen: dict[str, MarkdownCommand] = {}
    for d in reversed(dirs):
        for md in d.glob("*.md"):
            cmd = load_markdown_command(md)
            seen[cmd.name] = cmd

    return list(seen.values())
```

**git 경계에서 멈추는 이유**: 여러 프로젝트가 한 부모 디렉토리에 있는 건 흔하다. 프로젝트 A의 명령이 프로젝트 B에서 보이면 혼란스럽다. `.git` 디렉토리가 프로젝트의 논리적 경계가 된다.

**우선순위**: 프로젝트 명령 > 사용자 홈 명령. 같은 이름의 명령이 양쪽에 있으면 프로젝트 쪽이 이긴다. 프로젝트별 커스터마이징이 글로벌 기본값을 덮는 자연스러운 모델.

## main.py에 슬래시 명령 처리 연결

9.5의 `main.py` 루프에 한 블록만 추가한다:

```python
# src/mini_claude/main.py (변경분만)
from .commands.markdown_loader import discover_commands

async def main_async(args):
    # ... 9.5 까지의 초기화 코드 ...

    # ⭐ 시작 시점에 명령 발견
    md_commands = discover_commands(cwd=args.cwd, home=Path.home())

    while True:
        user_input = await asyncio.to_thread(input, "> ")

        # ⭐ 슬래시로 시작하면 명령 탐색
        if user_input.startswith("/"):
            parts = user_input[1:].split(maxsplit=1)
            cmd_name = parts[0]
            cmd_args = parts[1] if len(parts) > 1 else ""

            cmd = next((c for c in md_commands if c.name == cmd_name), None)
            if cmd is None:
                print(f"Unknown command: /{cmd_name}")
                continue

            # 본문 변환 → 9.5의 query()에 그대로 흘려보냄
            prompt = cmd.get_prompt(cmd_args, session_id="abc123")

            async for chunk in query(
                user_input=prompt,
                tools=parent_tools,
                permissions=permissions,
                cwd=str(args.cwd),
                state=state,
            ):
                if isinstance(chunk, TextDelta):
                    print(chunk.text, end="", flush=True)
                elif isinstance(chunk, ToolUseStarted):
                    print(f"\n[{chunk.name}] {chunk.input}", flush=True)
                elif isinstance(chunk, TurnDone):
                    print()
        else:
            # 일반 채팅 — 9.5 그대로
            async for chunk in query(user_input=user_input, ...):
                pass
```

**한 자리만 본다**: `cmd.get_prompt(cmd_args, ...)`가 마크다운 본문을 텍스트로 만들고, 그 결과를 `query(user_input=prompt, ...)`에 넘긴다. **마크다운 명령은 prompt를 만드는 함수일 뿐** — 9.x에서 만든 에이전트의 어떤 다른 부분도 안 바뀐다.

## frontmatter — 자주 쓰는 7개 필드

진짜 코드는 16개 필드를 인식하지만, 처음 만들 때 자주 쓰는 건 7개다.

| 필드 | 의미 | 예시 |
|---|---|---|
| `description` | 명령 설명 (`/` 자동완성에서 표시) | `description: 코드 리뷰` |
| `allowed-tools` | 권한 패키지 (4.3 회수) | `allowed-tools: Bash(git diff:*), Read` |
| `argument-hint` | 인자 힌트 (자동완성에 회색으로) | `argument-hint: "[파일 경로]"` |
| `arguments` | named arguments 정의 | `arguments: file lang` |
| `model` | 이 명령에서만 쓸 모델 | `model: opus` |
| `context` | 실행 컨텍스트 | `context: inline` (기본) 또는 `context: fork` |
| `version` | 명령 버전 (팀 공유용) | `version: 1.0.0` |

**`allowed-tools`**가 가장 중요하다. 이 명령이 도는 동안 권한 다이얼로그가 안 뜨는 도구의 화이트리스트. 4.3에서 본 capability-based security가 마크다운 한 줄로 동작하는 자리.

**`context: fork`**는 숨겨진 보석. 이걸 박으면 9.5의 AgentTool이 마크다운 한 줄로 발동된다 — 부모 대화를 안 더럽히고 격리된 conversation에서 돈다.

> 💡 **나머지 9개 필드**: `when_to_use` (모델이 자동 발견할 때의 트리거), `user-invocable` (사용자가 `/`로 부를 수 있는지), `disable-model-invocation`, `effort` (thinking 강도), `paths` (파일 매칭으로 자동 발동), `hooks`, `shell`, `agent`, `name` (display name 별칭). 10.2에서 `when_to_use`를 다룬다.

## 핵심 정리

- **마크다운 한 파일 = 하나의 명령**. `frontmatter(YAML 메타데이터)` + 본문(LLM에 보낼 텍스트). `get_prompt()`가 본문을 변환해서 9.5의 `query()`에 넘긴다. **에이전트 루프를 건드리지 않는다** — 슬래시 명령은 prompt를 만드는 함수일 뿐.
- **인자 치환은 순서가 중요하다**: named → indexed[N] → shorthand → full $ARGUMENTS → fallback append. 더 구체적인 패턴부터 처리해야 일반적인 패턴이 침범하지 않는다. Fallback append는 사용자 친화적 안전망.
- **디렉토리 walker는 git 경계에서 멈춘다**: 부모 repo의 명령이 자식 프로젝트로 leak 되지 않도록. 우선순위는 프로젝트 > 사용자 홈 — 같은 이름이면 프로젝트 쪽이 덮어쓴다.
- **`allowed-tools`가 4.3 권한 시스템의 마크다운 표현**: 이 명령이 도는 동안 자동 허용될 도구의 화이트리스트. 진짜 코드에서는 closure 패턴으로 부모 상태를 오염시키지 않고 inject.
- **`context: fork`가 9.5의 AgentTool을 마크다운 한 줄로 발동**: 격리된 conversation에서 명령이 돈다. 디렉토리 분석, 코드 리뷰처럼 부모 컨텍스트가 필요 없는 작업에 적합.
- **진짜 코드의 320줄이 Python 150줄로 압축**: 빠진 것은 inline shell, NFC 정규화, MCP carve-out. **남은 것은 동작 원리의 정수** — frontmatter 파싱, 4가지 인자 치환, git 경계 walker.
- **한 줄 폭로**: `.claude/commands/`는 deprecated 되어가는 중. 새 표준은 `.claude/skills/` (디렉토리 한 개 = 스킬 한 개). 두 시스템이 같은 함수가 처리한다. 10.2에서 그 새 형식을 mini_claude에 구현한다.
