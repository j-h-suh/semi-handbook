## 왜 슬래시 명령인가

9.5를 마치면 미니 클로드는 이런 에이전트다: 도구를 부르고, 권한을 묻고, 스트리밍으로 답하고, 서브 에이전트까지 돌린다. 하지만 — 한 가지 빠져 있다.

매일 같은 패턴으로 시키는 일이 있다. "오늘 한 git 작업을 한국어 3줄로 요약해줘". 매번 같은 문장을 친다. 5줄이면 짜증이 나고, 15줄이면 복사해서 붙여넣는다.

프로그래머의 반응은 정해져 있다 — **함수로 뽑자**. 그게 슬래시 명령의 본질이다. 반복되는 프롬프트를 **이름 하나로 부를 수 있게** 만드는 것. 그리고 그 형식이 **마크다운 한 파일**이면 — 코드를 안 짜도 된다.

이 챕터에서 미니 클로드에 그 시스템을 구현한다.

## 완성된 모습 먼저 보기

구현이 끝나면 이렇게 동작한다:

---

`git log --since=$since --oneline` 의 결과를
한국어로 *3 줄* 요약해줘. *명사형 종결*.

$ uv run mini-claude
> /today 00:00

[Bash] {'command': 'git log --since=00:00 --oneline'}
오늘 한 작업:
1. permissions.py 권한 게이트 리팩토링
2. EditTool 유일성 검증 추가

## 구현 — 4단계

### 1단계: frontmatter 파싱

마크다운 명령의 구조는 단순하다: `---` 사이의 YAML 메타데이터 + 나머지 본문.

```python
# src/mini_claude/commands/markdown_loader.py
from __future__ import annotations
import re
import shlex
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any
import yaml


def parse_frontmatter(text: str) -> tuple[dict[str, Any], str]:
    """'---' 사이의 YAML frontmatter와 본문을 분리한다.

    Args:
        text: 마크다운 파일 전체 텍스트.

    Returns:
        (frontmatter dict, 본문 문자열) 튜플.

    Example:
        >>> fm, body = parse_frontmatter("---\\ndesc: hello\\n---\\nbody")
        >>> fm["desc"]
        'hello'
    """
    if not text.startswith("---\n"):
        return {}, text
    end = text.find("\n---\n", 4)
    if end == -1:
        return {}, text

    frontmatter_text = text[4:end]
    body = text[end + 5:]

    try:
        frontmatter = yaml.safe_load(frontmatter_text) or {}
    except yaml.YAMLError:
        frontmatter = {}

    return frontmatter, body
```

YAML 파싱이 실패하면 빈 dict — **사용자가 잘못된 YAML을 써도 본문은 살아남는다**. 관대한 파싱이 CLI 도구의 좋은 기본값이다.

> ⚠️ **`import yaml` — 의존성 추가**: 위 코드가 PyYAML 패키지를 쓴다. `pyproject.toml` 의 `dependencies` 에 `"pyyaml>=6.0"` 한 줄을 추가 (또는 `uv add pyyaml`). 없으면 `ModuleNotFoundError: No module named 'yaml'` 가 import 시점에 막는다. _10.6 의 `agents/loader.py`_ 는 의존성 회피 위해 _경량 직접 파싱_ 으로 가지만, 10.1 은 _YAML 전체_ 를 받아낼 필요가 있어 PyYAML 을 받아들였다.

### 2단계: MarkdownCommand 데이터 클래스

파싱된 결과를 담는 그릇. 4.2에서 본 `PromptCommand`의 미니 버전이다.

```python
@dataclass
class MarkdownCommand:
    """마크다운 파일 하나가 변환된 명령.

    진짜 코드의 createSkillCommand (loadSkillsDir.ts:270, 132줄) 결과를
    dataclass 한 개로 압축한 것.
    """
    name: str                                # /myCmd 의 myCmd
    description: str
    body: str                                # 본문 (치환 전)
    allowed_tools: list[str] = field(default_factory=list)
    argument_names: list[str] = field(default_factory=list)

    def get_prompt(self, args: str) -> str:
        """호출 시점에 본문을 변환해서 LLM에 보낼 텍스트를 만든다.

        Args:
            args: 사용자가 /myCmd 뒤에 입력한 문자열.

        Returns:
            LLM user 메시지로 보낼 최종 텍스트.
        """
        return substitute_arguments(self.body, args, self.argument_names)
```

핵심 설계: **`get_prompt()`는 문자열을 만드는 함수일 뿐**. 이 결과를 9.5의 `query(user_input=...)`에 넘기면 끝이다. 명령 시스템은 에이전트 루프를 건드리지 않는다.

> ⚙️ **진짜 코드의 다른 필드들**: `model`, `context: fork`, `${CLAUDE_SESSION_ID}` 치환 같은 필드는 진짜 코드의 `MarkdownCommand` 에 있지만 미니 클로드에서는 _뺐다_. _model_ 은 10.5 의 provider 분기 자리, _context: fork_ 는 10.6 의 사용자 정의 에이전트 자리, _세션 ID_ 는 별도 발급 흐름이 필요한 자리 — 각 챕터에서 _그 챕터의 핵심_ 으로 회수한다. 10.1 의 정수는 _frontmatter → 본문 치환 → query()_ 의 한 줄 경로.

### 3단계: 인자 치환 — 4가지 방식

`/myCmd foo bar`를 쳤을 때 본문의 어디에 `foo`와 `bar`가 들어가는가?

```python
def parse_arguments(args: str) -> list[str]:
    """셸 인용 규칙으로 인자를 분리한다.

    Example:
        >>> parse_arguments('hello "world foo" bar')
        ['hello', 'world foo', 'bar']
    """
    try:
        return shlex.split(args)
    except ValueError:
        return args.split()


def substitute_arguments(
    content: str,
    args: str,
    argument_names: list[str] | None = None,
) -> str:
    """인자 치환 4가지 — 순서가 중요하다.

    더 구체적인 패턴부터 처리해야 일반적인 패턴이 침범하지 않는다.
    named → indexed[N] → shorthand → full → fallback append.
    """
    if not args:
        return content

    parsed = parse_arguments(args)
    original = content
    argument_names = argument_names or []

    # ① named — frontmatter의 arguments 필드와 매핑
    for i, name in enumerate(argument_names):
        if i >= len(parsed):
            break
        # negative lookahead: $foo 는 매칭, $foobar 는 매칭 안 함
        pattern = rf"\${re.escape(name)}(?![\[\w])"
        content = re.sub(pattern, parsed[i], content)

    # ② indexed — $ARGUMENTS[0], $ARGUMENTS[1]
    def replace_indexed(m: re.Match) -> str:
        idx = int(m.group(1))
        return parsed[idx] if idx < len(parsed) else ""

    content = re.sub(r"\$ARGUMENTS\[(\d+)\]", replace_indexed, content)

    # ③ shorthand — $0, $1 (뒤에 단어 글자 없을 때만)
    content = re.sub(r"\$(\d+)(?!\w)", replace_indexed, content)

    # ④ full — $ARGUMENTS (전체 문자열 한 덩어리)
    content = content.replace("$ARGUMENTS", args)

    # ⑤ fallback append — placeholder가 하나도 없었으면 끝에 박는다
    if content == original:
        content = content + f"\n\nARGUMENTS: {args}"

    return content
```

**⑤ fallback append**가 사용자 친화적 설계의 핵심이다. `$ARGUMENTS`를 깜빡 잊고 본문을 작성해도 — 인자가 사라지지 않는다. 그냥 본문 끝에 박아준다.

> 💡 **negative lookahead `(?![\[\w])`의 이유**: `$user`를 치환할 때 `$username`이 침범당하면 안 된다. `$user` 뒤에 단어 글자가 오면 매칭을 안 한다. 작은 정규식이지만 — 없으면 **silent bug**. 진짜 코드 `argumentSubstitution.ts:111`에도 같은 패턴이 있다.

### 4단계: 디렉토리 walking + git 경계

명령 파일을 어디서 찾느냐. cwd에서 부모 방향으로 걸어가되 — **git 경계에서 멈춘다**.

```python
def load_markdown_command(md_file: Path) -> MarkdownCommand:
    """*.md → MarkdownCommand 변환."""
    text = md_file.read_text(encoding="utf-8")
    frontmatter, body = parse_frontmatter(text)

    # description 자동 추출 fallback — 본문 첫 줄
    description = frontmatter.get("description")
    if not description:
        first_line = next(
            (line.strip() for line in body.split("\n") if line.strip()),
            "",
        )
        description = first_line[:80]

    return MarkdownCommand(
        name=md_file.stem,
        description=description,
        body=body,
        allowed_tools=_parse_allowed_tools(frontmatter.get("allowed-tools", "")),
        argument_names=_parse_argument_names(frontmatter.get("arguments", "")),
    )


_TOOL_PAREN_RE = re.compile(r"^(\w+)\((.*)\)$")


def _normalize_tool_rule(rule: str) -> str:
    """진짜 코드 본가 표기 `Bash(prefix:*)` 를 미니 클로드 내부 `Bash:prefix*` 로 변환.

    - `Bash(git log:*)` → `Bash:git log*`
    - `Bash(*)`         → `Bash:*`
    - `Read`            → `Read` (단독 도구명은 그대로)
    - `Bash:git *`      → `Bash:git *` (이미 내부 표기면 그대로)

    진짜 코드의 `:*` 는 "prefix 뒤 임의 인자" 의미인데, fnmatch 에서는 그냥 `*` 하나로 충분.
    """
    m = _TOOL_PAREN_RE.match(rule)
    if not m:
        return rule
    tool_name, inner = m.group(1), m.group(2)
    inner = inner.replace(":*", "*")
    return f"{tool_name}:{inner}"


def _parse_allowed_tools(value: str | list[str]) -> list[str]:
    """allowed-tools 필드는 문자열 또는 리스트 둘 다 허용.

    토큰별로 _normalize_tool_rule 을 통과시켜 진짜 코드 표기와 내부 표기 둘 다 수용.
    """
    if isinstance(value, list):
        return [_normalize_tool_rule(str(v).strip()) for v in value]
    if isinstance(value, str):
        return [_normalize_tool_rule(t.strip()) for t in value.split(",") if t.strip()]
    return []


def _parse_argument_names(value: str | list[str]) -> list[str]:
    if isinstance(value, list):
        return [str(v).strip() for v in value]
    if isinstance(value, str):
        return value.split()
    return []


def discover_commands(cwd: Path, home: Path) -> list[MarkdownCommand]:
    """cwd에서 부모로 걸어가며 .claude/commands/ 안의 마크다운을 모은다.

    git 경계에서 멈춘다 — 부모 repo의 명령이 자식으로 새지 않도록.
    """
    dirs: list[Path] = []

    # ① cwd → 부모로 walking, .git 경계에서 멈춤
    current = cwd.resolve()
    home_resolved = home.resolve()
    while current != current.parent and current != home_resolved:
        commands_dir = current / ".claude" / "commands"
        if commands_dir.is_dir():
            dirs.append(commands_dir)
        if (current / ".git").exists():
            break  # ⭐ git 경계 — 부모 repo leak 방지
        current = current.parent

    # ② home dir의 사용자 명령
    user_commands = home_resolved / ".claude" / "commands"
    if user_commands.is_dir():
        dirs.append(user_commands)

    # ③ 낮은 우선순위부터 로드, 같은 이름은 높은 우선순위가 덮어씀
    seen: dict[str, MarkdownCommand] = {}
    for d in reversed(dirs):
        for md in d.glob("*.md"):
            cmd = load_markdown_command(md)
            seen[cmd.name] = cmd

    return list(seen.values())
```

> ⚙️ **`_normalize_tool_rule` 가 두 표기를 모두 받는다**: 진짜 코드는 `Bash(git log:*)` (괄호 안에 콜론), 미니 클로드 내부는 `Bash:git log*` (콜론 한 개) — 9.4 의 `matches_rule()` 이 _첫 콜론으로 split_ 하는 단순화 결정 때문. 사용자가 _진짜 코드 표기로 마크다운을 써도_ load 단계에서 _내부 표기로 정규화_ 되어 권한 슬롯에 박힌다. _이미 내부 표기인 토큰_ 은 매치 X 로 그대로 통과 — 두 표기 호환의 정수.

**git 경계에서 멈추는 이유**: 여러 프로젝트가 한 부모 디렉토리에 있는 건 흔하다. 프로젝트 A의 명령이 프로젝트 B에서 보이면 혼란스럽다. `.git` 디렉토리가 프로젝트의 논리적 경계가 된다.

**우선순위**: 프로젝트 명령 > 사용자 홈 명령. 같은 이름의 명령이 양쪽에 있으면 프로젝트 쪽이 이긴다. 프로젝트별 커스터마이징이 글로벌 기본값을 덮는 자연스러운 모델.

## main.py에 슬래시 명령 처리 연결

9.5의 `main_async()`에 _딱 두 자리_ 만 끼운다 — 시그니처도, query 호출 자체도 그대로 둔다. 다만 슬래시 분기에서는 `cmd.allowed_tools` 를 _이 명령이 도는 동안만_ 자동 허용하는 _임시 권한 사본_ 을 만든다 — 부모 상태를 안 건드리는 진짜 코드의 closure 패턴.

```python
# src/mini_claude/main.py — 9.5 위의 add-up
from .commands.markdown_loader import discover_commands  # ⭐ 추가 import


async def main_async() -> None:
    # ... 9.5 의 argparse / VERTEX_PROJECT_ID 검사 / state / permissions / agent_tool ...

    # ⭐ 추가 ①: while 루프 진입 직전 — 시작 시점에 명령 발견
    md_commands = discover_commands(cwd=args.cwd, home=Path.home())

    print("mini-claude 시작 (Ctrl+D로 종료)")
    while True:
        try:
            user_input = await asyncio.to_thread(input, "> ")
        except (EOFError, KeyboardInterrupt):
            print("\nbye.")
            return
        if not user_input.strip():
            continue

        # ⭐ 추가 ②: 슬래시면 user_input 치환 + cmd.allowed_tools 의 임시 권한 사본
        active_permissions = permissions
        if user_input.startswith("/"):
            parts = user_input[1:].split(maxsplit=1)
            cmd_name = parts[0]
            cmd_args = parts[1] if len(parts) > 1 else ""

            cmd = next((c for c in md_commands if c.name == cmd_name), None)
            if cmd is None:
                print(f"Unknown command: /{cmd_name}")
                continue

            user_input = cmd.get_prompt(cmd_args)  # 본문 → LLM user 메시지
            # 이 명령이 도는 동안만 cmd.allowed_tools 가 자동 허용. 부모 permissions
            # 는 안 건드리는 closure 패턴 — 진짜 코드 loadSkillsDir.ts:374 의 같은 모양
            active_permissions = PermissionEngine(
                allow_rules=permissions.allow_rules | set(cmd.allowed_tools),
                deny_rules=permissions.deny_rules,
            )

        # 9.5 의 query() 호출 — 변경 없음. user_input 과 active_permissions 만 위에서 갈아끼움
        async for chunk in query(
            user_input=user_input,
            tools=parent_tools,
            permissions=active_permissions,
            cwd=str(args.cwd),
            state=state,
        ):
            if isinstance(chunk, TextDelta):
                print(chunk.text, end="", flush=True)
            elif isinstance(chunk, ToolUseStarted):
                print(f"\n[{chunk.name}] {chunk.input}", flush=True)
            elif isinstance(chunk, TurnDone):
                print()
```

**두 자리만 본다** — 추가 ① 은 _시작 시점 명령 발견_, 추가 ② 는 _슬래시면 user_input 갈아끼움 + 임시 권한 사본_. `query()` 호출은 9.5 그대로 한 번만 등장한다. **마크다운 명령은 _user_input 을 만들고 권한을 임시로 여는_ 전처리일 뿐** — 9.x 에서 만든 에이전트의 어떤 다른 부분도 안 바뀐다.

> 💡 **왜 사본인가, add_allow 가 아니라**: `permissions.add_allow(rule)` 로 부모에 _직접_ 주입하면 명령이 끝난 뒤에도 rule 이 남는다. 다음 일반 채팅이 _전 명령의 권한 누수_ 를 안고 도는 셈. 임시 사본은 query 호출이 끝나면 _Python GC_ 가 알아서 치운다. 부모 상태가 _불변_ 으로 보존되는 게 closure 패턴의 정수.

## frontmatter — 자주 쓰는 7개 필드

진짜 코드는 16개 필드를 인식하지만, 처음 만들 때 자주 쓰는 건 7개다. _미니_ 칸은 우리가 만든 코드가 _읽고 동작시키는지_ 여부.

| 필드 | 의미 | 예시 | 미니 |
|---|---|---|---|
| `description` | 명령 설명 (`/` 자동완성에서 표시) | `description: 코드 리뷰` | ✅ |
| `allowed-tools` | 권한 패키지 (4.3 회수) | `allowed-tools: Bash(git diff:*), Read` | ✅ |
| `arguments` | named arguments 정의 | `arguments: file lang` | ✅ |
| `argument-hint` | 인자 힌트 (자동완성에 회색으로) | `argument-hint: "[파일 경로]"` | ⚪️ |
| `version` | 명령 버전 (팀 공유용) | `version: 1.0.0` | ⚪️ |
| `model` | 이 명령에서만 쓸 모델 | `model: opus` | ⚪️ (10.5) |
| `context` | 실행 컨텍스트 | `context: inline` (기본) 또는 `context: fork` | ⚪️ (10.6) |

**`allowed-tools`** 가 이 챕터에서 _가장 중요한_ 필드다. 이 명령이 도는 동안 권한 다이얼로그가 안 뜨는 도구의 화이트리스트. 4.3 에서 본 capability-based security 가 마크다운 한 줄로 동작하는 자리 — 우리 `main.py` 가 _임시 권한 사본_ 으로 inject 한다.

**떡밥 두 개** — `model` 과 `context: fork`. 둘 다 dataclass 에서 _뺐다_. `model` 은 _명령마다 다른 LLM 을 쓰는 분기_ → 10.5 의 API 클라이언트 provider 분기와 함께 회수. `context: fork` 는 _이걸 박으면 9.5 의 AgentTool 이 마크다운 한 줄로 발동되는_ 자리 → 10.6 의 사용자 정의 에이전트에서 _격리 conversation 분기_ 까지 같이 회수.

> 💡 **나머지 9개 필드**: `when_to_use` (모델이 자동 발견할 때의 트리거), `user-invocable` (사용자가 `/`로 부를 수 있는지), `disable-model-invocation`, `effort` (thinking 강도), `paths` (파일 매칭으로 자동 발동), `hooks`, `shell`, `agent`, `name` (display name 별칭). 10.2에서 `when_to_use`를 다룬다.

## 핵심 정리

- **마크다운 한 파일 = 하나의 명령**. `frontmatter(YAML 메타데이터)` + 본문(LLM에 보낼 텍스트). `get_prompt()`가 본문을 변환해서 9.5의 `query()`에 넘긴다. **에이전트 루프를 건드리지 않는다** — 슬래시 명령은 prompt를 만드는 함수일 뿐.
- **인자 치환은 순서가 중요하다**: named → indexed[N] → shorthand → full $ARGUMENTS → fallback append. 더 구체적인 패턴부터 처리해야 일반적인 패턴이 침범하지 않는다. Fallback append는 사용자 친화적 안전망.
- **디렉토리 walker는 git 경계에서 멈춘다**: 부모 repo의 명령이 자식 프로젝트로 leak 되지 않도록. 우선순위는 프로젝트 > 사용자 홈 — 같은 이름이면 프로젝트 쪽이 덮어쓴다.
- **`allowed-tools`가 4.3 권한 시스템의 마크다운 표현**: 이 명령이 도는 동안 자동 허용될 도구의 화이트리스트. 우리 `main.py` 가 _임시 권한 사본_ 으로 inject — 부모 `permissions` 는 안 건드리는 진짜 코드의 closure 패턴 그대로.
- **진짜 코드의 320줄이 Python 150줄로 압축**: 빠진 것은 inline shell, NFC 정규화, MCP carve-out, 그리고 `model` / `context: fork` / `${CLAUDE_SESSION_ID}` — 마지막 세 가지는 10.5 / 10.6 의 떡밥. **남은 것은 동작 원리의 정수** — frontmatter 파싱, 4가지 인자 치환, git 경계 walker, 임시 권한 사본.
- **한 줄 폭로**: `.claude/commands/`는 deprecated 되어가는 중. 새 표준은 `.claude/skills/` (디렉토리 한 개 = 스킬 한 개). 두 시스템이 같은 함수가 처리한다. 10.2에서 그 새 형식을 미니 클로드에 구현한다.
