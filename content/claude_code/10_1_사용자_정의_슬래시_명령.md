# 10.1 사용자 정의 슬래시 명령 — `.claude/commands/` 마크다운으로 만들기

---

## 이 챕터에서 배우는 것

- 4장에서 본 3종 명령 타입 중 **prompt 타입**을 마크다운 한 파일로 만드는 법
- 가장 단순한 명령은 5줄짜리 마크다운 한 개 — 코드 한 줄도 안 친다
- frontmatter 16개 필드 중 진짜 자주 쓰는 7개
- 인자 치환 4가지 방식 — `$ARGUMENTS`, `$0/$1`, `$foo`, append fallback
- 4.3의 **`allowedTools` 권한 슬롯이 마크다운에서 어떻게 박히는지** — 진짜 코드의 closure 패턴
- 숨겨진 보석: `context: fork`로 마크다운 명령을 서브 에이전트로 실행, 그리고 `${CLAUDE_SKILL_DIR}` / `${CLAUDE_SESSION_ID}` 런타임 치환
- 작은 폭로: `.claude/commands/`는 **deprecated**. 진짜 코드에 `loadedFrom: 'commands_DEPRECATED'`가 박혀 있다 — 10.2의 스킬 시스템과 같은 길로 합쳐지는 중

## 사용자 경험에서 출발

당신이 매일 같은 패턴으로 Claude에게 시키는 것 — 예를 들어 "오늘 한 git 작업을 한국어로 3줄로 요약해줘". 매번 같은 5줄을 친다. 짜증 난다. 그게 슬래시 명령이 풀 자리.

진짜 클로드 코드의 `/commit`, `/init`, `/review` 같은 **prompt 타입** 명령은 **TypeScript로 코드를 짠** 것이다. 그런데 — 당신이 직접 만들 때는 마크다운 한 파일만 있으면 된다.

```markdown
---
description: 오늘 한 작업을 요약한다
allowed-tools: Bash(git log:*), Bash(date:*)
---

오늘 (`!\`date +%Y-%m-%d\``) 한 작업의 커밋들이야:

!`git log --since="00:00" --oneline`

위 커밋들을 한국어로 *3 줄* 요약해줘. *명사형 종결*.
```

이 11줄짜리 파일을 `.claude/commands/today.md`에 박아 두면 — 다음 번 `claude`를 켜자마자 `/today`가 자동으로 명령 목록에 뜬다. 자동완성도 된다. 매일 같은 5줄을 안 쳐도 된다. **코드 한 줄도 안 쳤다**.

이 챕터에서 그게 어떻게 가능한지 본다. 그리고 — 잘 만들기 위해 알아야 할 것들 (frontmatter 필드, 인자 치환, 권한, 디렉토리 우선순위)을 진짜 클로드 코드의 흔적과 같이 본다.

## 본문

### 가장 단순한 명령 — 5줄

```markdown
---
description: 오늘의 todo 를 정리한다
---

내 TODO.md 파일을 읽고, *오늘 해야 할 가장 중요한 3 개* 를 골라서 알려줘.
```

5줄. `---` 사이의 **frontmatter** 한 줄, 본문 한 줄, 그게 전부. 이걸 `.claude/commands/today.md`에 박는다.

`claude`를 켜고 `/today`를 친다. **본문이 LLM에게 그대로 user 메시지로 전달**된다. 4.2에서 본 **prompt 타입** 명령의 본질 — **`getPromptForCommand`가 문자열을 만들어 LLM으로 보낸다** — 가 여기서 마크다운으로 압축된 형태.

진짜 클로드 코드의 **마크다운 → Command 변환** 함수는 `loadSkillsDir.ts:270`의 `createSkillCommand`. 132줄. 마지막에 뭐가 나오느냐?

```typescript
return {
  type: 'prompt',                  // ← 4.2의 그 prompt 타입
  name: skillName,
  description,
  allowedTools,
  // ... 19개 필드 (userFacingName 메서드 포함)
  async getPromptForCommand(args, toolUseContext) {
    // ... 마크다운 본문을 변환해서 [{ type: 'text', text }]로 돌려준다
  },
} satisfies Command
```

**`type: 'prompt'`**. 4.2에서 본 세 가지 명령 타입 중 첫 번째. 마크다운 명령은 **`prompt` 타입의 작은 사본**이다. **TypeScript로 짠 명령과 완전히 같은 길**을 탄다.

### frontmatter의 진짜 자주 쓰는 7개 필드

진짜 코드는 16개 필드를 인식하지만, 처음 만들 때 자주 쓰는 건 7개다.

| 필드 | 의미 | 예시 |
|---|---|---|
| `description` | 명령 설명 (`/` 자동완성에서 표시) | `description: 코드 리뷰` |
| `allowed-tools` | 권한 패키지 (4.3 회수) | `allowed-tools: Bash(git diff:*), Read` |
| `argument-hint` | 인자 힌트 (자동완성에 회색으로) | `argument-hint: "[파일 경로]"` |
| `arguments` | named arguments 정의 | `arguments: file lang` |
| `model` | 이 명령에서만 쓸 모델 | `model: opus` (또는 `sonnet`, `inherit`) |
| `context` | 실행 컨텍스트 | `context: inline` (기본) 또는 `context: fork` |
| `version` | 명령 버전 (선택) | `version: 1.0.0` |

**한 마디씩 풀면**:

- **`description`**: 없으면 본문의 첫 줄이 자동으로 description이 된다. 진짜 코드의 fallback. 없어도 동작하지만 — `/`로 자동완성 띄울 때 무엇을 보여줄지가 결정되므로 항상 쓰는 게 좋다.

- **`allowed-tools`**: 4.3에서 본 그 권한 슬롯에 들어간다. 이 명령이 도는 동안 권한 다이얼로그가 안 뜨는 도구의 화이트리스트. 빈 칸이면 매번 묻는다.

- **`argument-hint`**: 사용자가 `/myCmd `까지 쳤을 때 회색 글자로 `"[파일 경로]"` 같은 힌트가 뜬다. UX 디테일.

- **`arguments`**: 본문에서 `$file`, `$lang` 같은 명명된 인자를 쓰려면 여기서 선언. `arguments: file lang`이라고 쓰면 본문의 `$file`은 첫 인자, `$lang`은 두 번째 인자.

- **`model`**: 이 명령만 다른 모델을 쓰고 싶을 때. `inherit`은 세션의 현재 모델을 그대로. 예: 가벼운 todo 정리는 `sonnet`, 긴 코드 리뷰는 `opus`.

- **`context: fork`**: ⭐ 숨겨진 보석. 이걸 박으면 — **이 명령이 서브 에이전트로 실행**된다. 9.5에서 본 그 `AgentTool`의 재귀 호출 한 단계가 마크다운 한 줄로 발동된다. 부모 대화를 안 더럽히고 **격리된 conversation에서** 도는 거다. 디렉토리 분석, 코드 리뷰처럼 부모 컨텍스트가 필요 없는 작업에 적합.

- **`version`**: 명령에 버전을 박는다. 팀에서 공유하는 명령에 유용. 다른 메타데이터.

> 💡 **나머지 9개 필드**는 `when_to_use` (모델 입장의 사용 시나리오 — Skill 도구 발견용), `user-invocable` (사용자가 `/`로 부를 수 있는지), `disable-model-invocation` (Skill 도구에서 숨김), `effort` (thinking 강도), `paths` (파일 매칭으로 자동 발동), `hooks` (생명주기 훅), `shell` (`bash` 또는 `powershell`), `agent` (`context: fork`와 짝), `name` (`/` 자동완성에 표시되는 **displayName 별칭** — 팀 공유 명령에서 종종 쓴다). 처음에는 안 써도 OK.

### 인자 치환 — 4가지 방식

`/myCmd foo bar`를 친다. 본문의 어디에 `foo`와 `bar`가 들어가는가? 4가지 방식이 있다.

```markdown
---
arguments: name lang
---

# 1. named — frontmatter 의 arguments 와 매핑
$name 이라는 함수를 $lang 로 작성해줘.

# 2. indexed — 위치로 직접
$ARGUMENTS[0] 이라는 함수를 $ARGUMENTS[1] 로 작성해줘.

# 3. shorthand — 짧은 indexed
$0 이라는 함수를 $1 로 작성해줘.

# 4. full — 전체 문자열 한 덩어리
사용자 인자: $ARGUMENTS
```

`/myCmd hello python`으로 부르면 — 1, 2, 3은 "hello라는 함수를 python으로 작성해줘"가 되고, 4는 "사용자 인자: hello python"이 된다.

진짜 코드 (`argumentSubstitution.ts:111-136`)는 이 순서로 치환한다 — named → indexed[N] → shorthand → full $ARGUMENTS. **순서가 중요**하다. 더 구체적인 패턴부터 처리해야 더 일반적인 패턴이 침범하지 않는다.

그리고 한 가지 **친절한 fallback**이 있다:

```typescript
// argumentSubstitution.ts:140
// If no placeholders were found and appendIfNoPlaceholder is true, append
if (content === originalContent && appendIfNoPlaceholder && args) {
  content = content + `\n\nARGUMENTS: ${args}`
}
```

**어떤 placeholder도 본문에 없는데** 사용자가 인자를 줬으면 — 그냥 본문 끝에 박아 준다. 사용자가 `$ARGUMENTS`를 깜빡 잊어도 인자가 사라지지 않는다. **사용자 친화적 fallback**의 작은 표본.

> 💡 **`$foo`와 `$foobar`.** 진짜 코드의 정규식은 `\\$${name}(?![\\[\\w])` — **negative lookahead**로 뒤에 단어 글자나 `[`가 오면 매칭 안 함. `$foo`는 매칭, `$foobar`는 매칭 안 함, `$foo[0]`도 안 함. 작은 정규식 디테일이지만 잘못하면 **silent bug** — `$user`를 박았는데 `$username`이 침범당해서 이상하게 잘리는 케이스를 막는다.

### `allowed-tools` — 4.3의 **권한 슬롯 inject**가 진짜로 동작하는 자리

4.3에서 우리는 **명령의 `allowedTools`가 `command` 슬롯에 박혀서 턴 동안 자동 허용된다**고 봤다. 그게 마크다운 명령에서도 같은 메커니즘인지 — 진짜로 같은 코드 경로를 탄다. `loadSkillsDir.ts:374`를 보면:

```typescript
// loadSkillsDir.ts:374
if (loadedFrom !== 'mcp') {
  finalContent = await executeShellCommandsInPrompt(
    finalContent,
    {
      ...toolUseContext,
      getAppState() {
        const appState = toolUseContext.getAppState()
        return {
          ...appState,
          toolPermissionContext: {
            ...appState.toolPermissionContext,
            alwaysAllowRules: {
              ...appState.toolPermissionContext.alwaysAllowRules,
              command: allowedTools,    // ⭐ 4.3의 그 슬롯
            },
          },
        }
      },
    },
    `/${skillName}`,
    shell,
  )
}
```

**closure의 마법**. `allowedTools`가 **getAppState 호출의 결과를 변형**하는 wrapper 안에 **closure로 캡처**돼 있다. 이게 부모 상태를 안 건드리고, 이 호출 동안만 `command` 슬롯에 **마크다운의 `allowed-tools`가 박혀 있게 한다**. 4.3의 capability-based security가 마크다운 한 파일에서도 진짜로 동작하는 자리.

> 🔬 **Deep Dive — MCP carve-out.** 위 코드의 첫 줄 `if (loadedFrom !== 'mcp')`를 보자. **MCP 스킬 (= 외부 MCP 서버에서 발견된 스킬)은 inline shell 절대 실행 안 함**. 코드 한 줄과 주석 두 줄. 왜? — MCP 서버는 원격이고 **untrusted**다. 그 서버가 임의의 셸 명령을 본문에 박아둘 수 있다. 그래서 **일반 마크다운 명령 (당신이 직접 만든 것)은 inline shell 동작**, **MCP 출신 명령은 동작 안 함**. **보안 가드가 if 한 줄에 압축**돼 있다.

### inline shell `!`...`` — 4.1의 실시간 데이터 박기 패턴이 마크다운에서도

4.1에서 본 `/commit`의 거대한 프롬프트는 `!\`git status\`` 같은 **inline shell**로 **실시간 git 상태**를 박아 넣었다. **마크다운 명령에서도 같은 게 된다**.

```markdown
---
description: 오늘 한 작업을 요약한다
allowed-tools: Bash(git log:*), Bash(date:*)
---

오늘 (`!\`date +%Y-%m-%d\``) 한 작업의 커밋들이야:

!`git log --since="00:00" --oneline`

이걸 한국어로 *3 줄* 요약해줘.
```

본문이 LLM으로 가기 직전에 — `!\`...\`` 블록들이 그 자리에서 셸 명령으로 실행되고, 결과 텍스트가 자리에 박힌다. LLM은 최종 결과만 본다.

이때 어떤 명령이 실행될 수 있느냐가 — frontmatter의 `allowed-tools`가 결정한다. 위 예시에선 `Bash(git log:*)`와 `Bash(date:*)`만 허용했으니 **`!\`rm -rf ~\`` 같은 건 안 통한다**. **권한과 inline shell이 한 자리에 묶여 있는** 게 번들 사고 (4.3의 마무리)의 직접적 회수.

### 디렉토리 발견 — 4가지 위치 + git 경계

당신이 만든 `.claude/commands/today.md`는 어떻게 발견 되나? 진짜 코드의 walker (`markdownConfigLoader.ts:234`의 `getProjectDirsUpToHome`)는 **cwd에서 부모 방향으로 걷는다**.

```
/Users/you/projects/myrepo/sub/dir   ← cwd에서 시작
   └─ .claude/commands/?
/Users/you/projects/myrepo/sub
   └─ .claude/commands/?
/Users/you/projects/myrepo            ← .git이 여기 있음
   └─ .claude/commands/?               ← 여기서 멈춤
/Users/you/projects                    ← 안 봄
/Users/you                             ← 별도로 user dir로 처리
```

코드의 멈춤 자리를 직접 보면:

```typescript
// markdownConfigLoader.ts:267-275
// Stop after processing the git root directory - this prevents commands
// from parent directories outside the repository from appearing in the project
if (
  gitRoot &&
  normalizePathForComparison(current) ===
    normalizePathForComparison(gitRoot)
) {
  break
}
```

**git 경계에서 멈춘다**. 주석에 왜가 박혀 있다 — "prevents commands from parent directories outside the repository from appearing in the project". **부모 디렉토리의 명령이 자식 repo로 leak 되지 않도록**. 작은 디테일이지만 — 여러 프로젝트가 한 부모 디렉토리에 있는 흔한 케이스에서 멘탈 모델이 깨끗해진다.

전체 우선순위 (높은 게 이김):

```
1. ~/.claude/managed/.claude/commands/   (시스템 관리자 정책)
2. ~/.claude/commands/                    (사용자 home)
3. ./.claude/commands/                    (현재 프로젝트, git 경계 안에서)
4. --add-dir 경로                         (CLI 옵션)
```

> 💡 **NFC 정규화 — 8.4와 같은 함정.** `getProjectDirsUpToHome`의 첫 줄: `const home = resolve(homedir()).normalize('NFC')`. **macOS의 한글 NFD 문제를 회피**한다. 8.4 IDE Bridge에서 본 그 **NFC vs NFD** 사고가 여기서도 등장. 한글 디렉토리 이름으로 `~/한국어프로젝트/` 같은 걸 만들면 — NFC 정규화가 없으면 walker가 **경로 비교를 실패해서 home break를 못 한다**. **같은 함정이 다른 자리에서 또 등장**하는 production 코드의 흔한 풍경.

### 작은 폭로 — `commands_DEPRECATED`

진짜 코드를 grep 하면 흥미로운 문자열이 나온다.

```typescript
loadedFrom: 'commands_DEPRECATED',
```

**`.claude/commands/`는 deprecated 되어 가는 중이다**. 새 표준은 `.claude/skills/` — 디렉토리 한 개당 한 스킬 형태 (`my-skill/SKILL.md`). 두 시스템이 완전히 같은 코드 경로 (`loadSkillsDir.ts`)를 탄다. **명령 = 스킬의 평탄한 형태**.

10.2가 그 새 길을 보여준다 — `SKILL.md` frontmatter와 자동 발견. 지금 만든 마크다운 명령이 그쪽으로 옮겨가는 흐름을 거기서 본다. **그러므로 이 챕터에서 만든 마크다운은 내일 deprecated 될 것이지만, 동작 원리는 영원히 같다** — 진짜 코드의 같은 함수가 둘 다 처리하니까.

## Python으로 옮기면

진짜 클로드 코드의 **마크다운 → PromptCommand 변환**을 Python으로 압축. 4.2에서 만든 `PromptCommand` 데이터 클래스에 마크다운 로더를 붙인다.

```python
# src/mini_claude/commands/markdown_loader.py
from __future__ import annotations
import re
import shlex
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any
import yaml


@dataclass
class MarkdownCommand:
    """진짜 코드의 createSkillCommand 결과의 *기하학적 압축*.

    진짜는 132 줄, 22 개 input 파라미터. 미니는 dataclass 한 개.
    """
    name: str                                # /myCmd 의 myCmd
    description: str
    body: str                                # 본문 (변환 전)
    allowed_tools: list[str] = field(default_factory=list)
    argument_names: list[str] = field(default_factory=list)
    model: str | None = None
    context: str = "inline"                  # 또는 "fork"

    def get_prompt(self, args: str, session_id: str = "") -> str:
        """*호출 시점* 에 본문을 변환해서 LLM 으로 보낼 텍스트를 만든다.

        진짜 코드의 getPromptForCommand 의 4 단계:
        ① 인자 치환
        ② ${CLAUDE_SESSION_ID} 치환
        ③ inline shell 실행 (생략 — 미니에선 단순화)
        ④ 텍스트 반환
        """
        content = self.body

        # ① 인자 치환 (4 가지 순서대로)
        content = substitute_arguments(content, args, self.argument_names)

        # ② ${CLAUDE_SESSION_ID} 치환
        content = content.replace("${CLAUDE_SESSION_ID}", session_id)

        # ③ inline shell 은 미니에선 OUT — executeShellCommandsInPrompt 가 큼.
        # 진짜 코드는 여기서 `!`...`` 블록을 실행하면서 *권한 슬롯에
        # allowed_tools 를 inject* 한다 (4.3 의 capability scope).

        return content


def parse_frontmatter(text: str) -> tuple[dict[str, Any], str]:
    """`---` 사이의 YAML frontmatter 와 본문을 분리.

    진짜 코드의 frontmatterParser.ts:130 의 미니.
    """
    if not text.startswith("---\n"):
        return {}, text
    end = text.find("\n---\n", 4)
    if end == -1:
        return {}, text

    frontmatter_text = text[4:end]
    body = text[end + 5:]

    try:
        frontmatter = yaml.safe_load(frontmatter_text) or {}
    except yaml.YAMLError:
        frontmatter = {}

    return frontmatter, body


def parse_arguments(args: str) -> list[str]:
    """`hello "world foo" bar` → `["hello", "world foo", "bar"]`.

    진짜 코드는 shell-quote 라이브러리 사용. 미니는 shlex 한 줄.
    """
    try:
        return shlex.split(args)
    except ValueError:
        return args.split()


def substitute_arguments(
    content: str,
    args: str,
    argument_names: list[str] | None = None,
) -> str:
    """인자 치환 4 가지 — 진짜 코드의 argumentSubstitution.ts:94 의 압축.

    *순서가 중요*. named → indexed[N] → shorthand → full → fallback append.
    """
    if not args:
        return content

    parsed = parse_arguments(args)
    original = content
    argument_names = argument_names or []

    # ① named — 진짜 코드의 negative lookahead 정규식 그대로
    for i, name in enumerate(argument_names):
        if i >= len(parsed):
            break
        # `\\$${name}(?![\\[\\w])` 의 Python 변환
        pattern = rf"\${re.escape(name)}(?![\[\w])"
        content = re.sub(pattern, parsed[i], content)

    # ② indexed via $ARGUMENTS[N]
    def replace_indexed(m: re.Match) -> str:
        idx = int(m.group(1))
        return parsed[idx] if idx < len(parsed) else ""

    content = re.sub(r"\$ARGUMENTS\[(\d+)\]", replace_indexed, content)

    # ③ shorthand $0, $1 (뒤에 단어 글자 없을 때만)
    content = re.sub(r"\$(\d+)(?!\w)", replace_indexed, content)

    # ④ full $ARGUMENTS
    content = content.replace("$ARGUMENTS", args)

    # ⑤ fallback append — placeholder 가 하나도 없었으면 끝에 박는다
    if content == original:
        content = content + f"\n\nARGUMENTS: {args}"

    return content


def load_markdown_command(md_file: Path) -> MarkdownCommand:
    """*.md → MarkdownCommand 변환*. 진짜 코드의 createSkillCommand 의 미니."""
    text = md_file.read_text(encoding="utf-8")
    frontmatter, body = parse_frontmatter(text)

    # description 의 자동 추출 fallback (첫 줄)
    description = frontmatter.get("description")
    if not description:
        first_line = next(
            (line.strip() for line in body.split("\n") if line.strip()),
            "",
        )
        description = first_line[:80]

    return MarkdownCommand(
        name=md_file.stem,
        description=description,
        body=body,
        allowed_tools=_parse_allowed_tools(frontmatter.get("allowed-tools", "")),
        argument_names=_parse_argument_names(frontmatter.get("arguments", "")),
        model=frontmatter.get("model"),
        context=frontmatter.get("context", "inline"),
    )


def _parse_allowed_tools(value: str | list[str]) -> list[str]:
    """frontmatter 의 allowed-tools 필드는 *문자열 또는 리스트* 둘 다 허용."""
    if isinstance(value, list):
        return [str(v).strip() for v in value]
    if isinstance(value, str):
        return [t.strip() for t in value.split(",") if t.strip()]
    return []


def _parse_argument_names(value: str | list[str]) -> list[str]:
    if isinstance(value, list):
        return [str(v).strip() for v in value]
    if isinstance(value, str):
        return value.split()
    return []


def discover_commands(cwd: Path, home: Path) -> list[MarkdownCommand]:
    """*디렉토리 walking* — 진짜 코드의 getProjectDirsUpToHome 의 미니.

    cwd → 부모로 걷다가 *git 경계* 에서 멈춘다. 그 다음 *home dir* 도 추가.
    """
    dirs: list[Path] = []

    # ① cwd 에서 부모로 walking, .git 경계에서 멈춤
    current = cwd.resolve()
    home_resolved = home.resolve()
    while current != current.parent and current != home_resolved:
        commands_dir = current / ".claude" / "commands"
        if commands_dir.is_dir():
            dirs.append(commands_dir)
        if (current / ".git").exists():
            break  # ⭐ git 경계 — 부모 repo 가 leak 되지 않도록
        current = current.parent

    # ② home dir 의 사용자 명령
    user_commands = home_resolved / ".claude" / "commands"
    if user_commands.is_dir():
        dirs.append(user_commands)

    # ③ 모든 .md 파일 로드 (낮은 우선순위가 먼저, 같은 이름은 높은 게 덮어씀)
    seen: dict[str, MarkdownCommand] = {}
    for d in reversed(dirs):  # 낮은 우선순위부터
        for md in d.glob("*.md"):
            cmd = load_markdown_command(md)
            seen[cmd.name] = cmd  # 덮어쓰기

    return list(seen.values())
```

**핵심**: 진짜 코드의 **132줄 createSkillCommand** + **56줄 walker** + **52줄 substituteArguments** — 합쳐서 240줄을 **Python 150줄로 압축**. 빠진 것: NFC 정규화 (한글 안 쓰면 OK), MCP carve-out (미니는 MCP 없음), `${CLAUDE_SKILL_DIR}` (skill 디렉토리 형식 안 씀), inline shell 실행 (`executeShellCommandsInPrompt`가 큼). **남은 것은 동작 원리의 정수**.

`main.py`에서 이걸 어떻게 쓰느냐 — **4.2의 dispatcher**가 받아먹기만 하면 된다.

```python
# src/mini_claude/main.py 안의 슬래시 명령 처리

async def main_async(args):

            prompt = cmd.get_prompt(cmd_args, session_id="abc123")

```

**한 자리만 본다**: `cmd.get_prompt(cmd_args, ...)`가 **마크다운 본문을 LLM으로 보낼 텍스트로 변환**. 그 결과를 9.5의 `query()`에 **user_input으로 넘긴다**. **마크다운 명령은 prompt를 만드는 함수일 뿐**, 9.x에서 만든 미니 에이전트의 어떤 다른 부분도 안 바뀐다.

## 핵심 정리

- 마크다운 한 파일이 4.2의 **prompt 타입 명령**의 작은 사본이다. 진짜 코드의 `createSkillCommand`가 마크다운을 **PromptCommand 객체로 변환**한다. **TypeScript로 짠 명령과 완전히 같은 코드 경로**를 탄다.
- frontmatter의 진짜 자주 쓰는 7개 필드: `description`, `allowed-tools`, `argument-hint`, `arguments`, `model`, `context`, `version`. 그 외 9개는 고급 또는 내부용.
- **`allowed-tools`가 4.3의 권한 슬롯 inject의 진짜 모습**: closure로 캡처된 `allowedTools`가 **getAppState 래핑**으로 부모 상태를 안 건드리고 `command` 슬롯에 박힌다. **capability-based security**의 마크다운 표현.
- 인자 치환은 **4가지 + fallback append**. 순서가 중요 — **named → indexed[N] → shorthand → full**. 더 구체적인 패턴부터 처리하지 않으면 침범된다. 그리고 어떤 placeholder도 못 찾았는데 인자가 있으면 — 본문 끝에 박아준다. **사용자 친화적 fallback**.
- inline shell `!\`...\``가 **마크다운 본문에서 그대로 동작**. 4.1의 `/commit` 패턴이 마크다운으로 회수. 실행 가능한 명령은 **frontmatter의 `allowed-tools`가 결정**. **권한과 inline shell이 한 자리에 묶여 있는** 게 4.3의 번들 사고의 직접적 회수.
- **MCP carve-out**: `if (loadedFrom !== 'mcp')` 한 줄. 외부 MCP 서버에서 발견된 스킬은 **inline shell 절대 실행 안 함** — 원격 untrusted 코드가 임의 명령을 본문에 박을 수 있기 때문. **보안 가드가 if 한 줄에 압축**.
- **walker는 git 경계에서 멈춘다** — **부모 repo의 명령이 자식 repo로 leak 되지 않도록**. 4가지 위치 (managed, user, project, --add-dir)에서 **managed > user > project** 우선순위. **NFC 정규화**까지 박혀 있다 — 8.4 IDE Bridge에서 본 한글 NFD 함정의 재등장.
- **숨겨진 보석 1**: `context: fork`로 마크다운 명령을 서브 에이전트로 실행. 9.5의 `AgentTool` 재귀 호출이 마크다운 한 줄로 발동된다. 부모 컨텍스트가 필요 없는 작업 (디렉토리 분석, 코드 리뷰)에 적합.
- **숨겨진 보석 2**: `${CLAUDE_SKILL_DIR}`, `${CLAUDE_SESSION_ID}` — 호출 시점에 치환되는 런타임 변수. 매크로처럼 정적 텍스트가 아니다.
- **작은 폭로**: `.claude/commands/`는 **deprecated** 되어 가는 중. 진짜 코드에 `loadedFrom: 'commands_DEPRECATED'`라는 문자열이 박혀 있다. 새 표준은 `.claude/skills/` — 디렉토리 한 개당 한 스킬 (`my-skill/SKILL.md`) 형식. **두 시스템이 완전히 같은 함수 (`loadSkillsDir.ts`)가 처리**. 명령 = 스킬의 평탄한 형태. 10.2가 그 새 길을 보여준다.
