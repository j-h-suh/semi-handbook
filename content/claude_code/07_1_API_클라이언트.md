# 7.1 API 클라이언트 — Anthropic / Bedrock / Vertex 추상화

---

## 이 챕터에서 배우는 것

- **같은 Claude**가 4개의 다른 클라우드(Anthropic 직접, AWS Bedrock, GCP Vertex, Azure Foundry)에서 산다는 사실
- 호출자 코드는 차이를 모른다 — 4개 SDK가 같은 인터페이스로 위장한다
- `getAnthropicClient()` 팩토리가 환경 변수 한 줄로 어떤 SDK를 만들지 결정하는 메커니즘
- **lazy import**가 시작 시간을 어떻게 지키는지 — 안 쓰는 SDK는 로드도 안 한다
- 진짜 코드의 코멘트 **"we have always been lying about the return type"** 의 의미

---

## 사용자 경험에서 출발

대부분의 사용자는 그냥 `claude`를 친다. 백엔드는 `api.anthropic.com`. 안 보이는 곳.

근데 회사가 **AWS Bedrock**을 통해서만 LLM을 쓰게 한다고 하자. 데이터가 회사 클라우드 안에서만 머물러야 함. 그러면 사용자는 환경 변수 한 줄만 추가한다.

```bash
export CLAUDE_CODE_USE_BEDROCK=1
claude
```

완전히 똑같이 동작한다. 같은 도구, 같은 응답, 같은 명령. 단지 **백엔드가 AWS**가 됐을 뿐. GCP를 쓰면 `CLAUDE_CODE_USE_VERTEX=1`, Azure는 `CLAUDE_CODE_USE_FOUNDRY=1`. 환경 변수 하나가 전체 백엔드를 바꾼다. 

이 챕터에서 — 이게 어떻게 가능한지 본다. 답: **4개 SDK가 같은 인터페이스를 흉내낸다**. 그리고 그걸 받아주는 팩토리 함수 하나.

## 본문

### 4개의 SDK, 하나의 형태

`@anthropic-ai/sdk`를 포함해 네 개의 패키지가 있다.

| 환경 변수 | SDK 패키지 | 백엔드 |
|---|---|---|
| (없음, 기본) | `@anthropic-ai/sdk` | `api.anthropic.com` |
| `CLAUDE_CODE_USE_BEDROCK=1` | `@anthropic-ai/bedrock-sdk` | AWS Bedrock |
| `CLAUDE_CODE_USE_VERTEX=1` | `@anthropic-ai/vertex-sdk` | GCP Vertex AI |
| `CLAUDE_CODE_USE_FOUNDRY=1` | `@anthropic-ai/foundry-sdk` | Azure AI Foundry |

네 패키지가 **각각 다른 인증, 다른 region 처리, 다른 endpoint**를 갖는다. **하지만 호출 인터페이스는 같다**. 호출자 코드는 항상:

```typescript
await anthropic.beta.messages.create({
  model,
  max_tokens,
  messages,
  // ...
})
```

이 한 형태로 부른다. 네 SDK 모두 — 이 호출을 받아 각자의 백엔드에 알맞게 변환한다. **OOP 인터페이스는 명시적으로 정의된 게 아니라, 형태가 같음으로 보장**된다. TypeScript의 구조적 타이핑과 덕 타이핑의 결합.

### `getAnthropicClient()` — 팩토리

4개 분기. 각 분기가 **자기 SDK**를 만들어 돌려준다. **반환 타입은 전부 `Anthropic`**. 그게 덕 타이핑 캐스팅 (`as unknown as Anthropic`)이다. 코멘트가 솔직하게 말한다.

> **"we have always been lying about the return type — this doesn't support batching or models"**

번역: **"우린 항상 반환 타입에 대해 거짓말을 해왔다. 이건 batching이나 models 메서드를 지원하지 않는다."**

이게 무슨 뜻인가? `Anthropic` 클래스는 사실 `messages.create` 외에도 `batches`, `models` 같은 메서드를 가진다. 근데 Bedrock SDK와 Vertex SDK는 그것들이 없다. 그래도 형태상 호환을 위해 `Anthropic`으로 캐스팅한다. **호출자가 `messages.create`만 쓰면 OK**. `batches`를 호출하면 런타임에 죽는다. 그래서 **"거짓말"** 이지만 — 현실적인 거짓말이다. 99%의 호출은 `messages.create`다.

> 💡 **TypeScript의 구조적 타이핑.** 자바/C# 같은 언어는 명시적으로 `implements`를 선언해야 인터페이스가 호환된다. TypeScript는 **형태만 같으면** 호환. `AnthropicBedrock`이 `Anthropic`을 명시적으로 상속받지 않아도 — 같은 메서드들이 있으면 호환된다. **Python의 ABC + duck typing** 과 비슷한 정신.

### Lazy import가 시작 시간을 지킨다

위 코드의 `await import('@anthropic-ai/bedrock-sdk')`가 핵심이다. 동적 import다. 이게 없으면 — **시작 시점에 모든 SDK 패키지를 다 로드**해야 한다. Bedrock SDK는 **AWS SDK 의존성이 수십 MB**. Vertex SDK는 **Google Auth 라이브러리 + 수십 MB**. Foundry SDK는 **Azure Identity**.

세 개 다 로드하면 — 시작 시간이 **수백 ms**가 더 든다. **그런데 대부분의 사용자는 한 SDK만 쓴다**. 셋 다 로드할 이유가 없다.

해결: **`await import(...)`** 으로 진짜 필요할 때만 로드. AWS 사용자는 **Bedrock SDK만**, GCP는 **Vertex만**. 다른 둘은 디스크에 안 닿는다.

특히 Foundry와 Vertex는 **두 개의 lazy import**를 한다. Foundry: `await import('@anthropic-ai/foundry-sdk')` + `await import('@azure/identity')`. Vertex: `Promise.all([import('@anthropic-ai/vertex-sdk'), import('google-auth-library')])`. **자기 SDK + 자기 인증 라이브러리**가 한 쌍으로 같이 lazy 로드된다 — 둘 다 큰 패키지고 둘 다 그 백엔드 사용자만 필요하다.

이게 1.1에서 본 **부트스트랩 30ms**가 가능한 이유 중 하나다. **각 의존성이 자기 호출 자리에서만 로드**된다. 코드 아키텍처가 시작 시간과 직접 연결.

**GCP Vertex**: 가장 복잡. 분기 진입 직후 `refreshGcpCredentialsIfNeeded()` 호출 (`client.ts:225`) — **AWS의 `refreshAndGetAwsCredentials()`와 대칭**인 자격증명 refresh. 그리고 **region도 모델별 처리** (`getVertexRegionForModel(model)`, `client.ts:292`) — Bedrock만 모델별 region인 게 아니라 Vertex도 같은 패턴이다. **project ID 발견**에만 4단계 우선순위가 있다. 코멘트가 수십 줄에 걸쳐 한 줄짜리 사고를 설명한다.

```typescript
// google-auth-library checks project ID in this order:
// 1. Environment variables (GCLOUD_PROJECT, GOOGLE_CLOUD_PROJECT, etc.)
// 2. Credential files (service account JSON, ADC file)
// 3. gcloud config
// 4. GCE metadata server (causes 12s timeout outside GCP)
//
// We only set projectId if user hasn't configured other discovery methods
// to avoid interfering with their existing auth setup
```

**4번 fallback**이 12초 타임아웃을 일으킨 사고. GCE 메타데이터 서버는 **GCE 안에서만** 응답한다. 사용자 노트북에서 부트하면 12초간 멈춘다. 그래서 **명시적으로 fallback projectId** 를 조건부로 제공해서 그 호출을 건너뛰게 한다. **부트스트랩 30ms 목표를 12초 타임아웃이 깨지 않게 하는 방어선.**

> 🔬 **Deep Dive — 왜 명시적 인터페이스를 안 만들었나.** OOP 정석대로면 — `interface ClaudeBackend { messages: { create(...): Promise<...> } }` 같은 추상 인터페이스를 만들고, 4개 구현체가 **명시적으로 implements**. Claude Code는 그렇게 안 한다. 대신 **4개 SDK를 그대로 캐스팅해서 쓴다**. 왜? **Anthropic SDK가 진실의 출처**이기 때문이다. 메시지 형태, 도구 형태, 응답 형태 — **모두 Anthropic이 정한다**. Bedrock/Vertex/Foundry SDK는 **Anthropic SDK의 형태를 그대로 따라가는** 식으로 구조적 호환성을 유지한다. 명시적 인터페이스를 정의하면 — **그 인터페이스가 진짜 SDK와 같이 진화해야** 한다. 하나가 새 필드를 추가하면 인터페이스도, 다른 구현체도. 동기화 부담이 크다. 캐스팅으로 **책임을 SDK 팀에게 위임**하면 — Anthropic SDK가 새 기능을 추가할 때 나머지가 자동으로 따라온다 (호환되는 한). 의도적인 결합이다.

그냥 `anthropic.beta.messages.create` 한 줄. **이 코드는 어느 백엔드에서 도는지 모른다**. Bedrock이든, Vertex든, Foundry든, 직접이든 — 완전히 같은 호출.

**이게 추상화의 제일 강력한 형태**다. 호출자가 다른 백엔드의 존재 자체를 모른다. 환경 변수 하나가 바뀌어도 — 호출자 코드는 한 글자도 안 바뀐다.

이 추상화를 만들기 위해 팩토리 한 함수가 모든 차이를 흡수한다. 그 함수 안의 분기 4개가 4개 백엔드의 어색함을 다 처리한다. 호출자는 깨끗하게 산다.

> ⚙️ **호출 자리는 사실 세 군데에 있다.** 위 line 864는 **non-streaming** 호출 자리 (`// non-streaming API call` 코멘트 직접 명시). **진짜 메인 호출은 `claude.ts:1822`**의 **streaming** 버전이다 — `await anthropic.beta.messages.create({ ...params, stream: true }, ...).withResponse()`. 추가로 line 555에는 API key **검증용 test 호출**도 있다 (`{ messages: [{role: 'user', content: 'test'}], max_tokens: 1 }`). **세 호출 자리 모두 백엔드를 모른다**. 같은 형태로 부른다. 호출자 무지라는 추상화의 강력함이 세 곳에서 동시에 보이는 셈.

## Python으로 옮기면

같은 패턴을 Python으로 옮기면 이렇게 생겼다.

```python
from __future__ import annotations
import os
from typing import Any, Protocol


# ─── 구조적 인터페이스 (Protocol) ────────────────
class MessagesAPI(Protocol):
    """형태로 정의된 인터페이스. implements 선언 안 해도 됨."""
    async def create(
        self,
        *,
        model: str,
        max_tokens: int,
        messages: list[dict],
        **kwargs: Any,
    ) -> Any: ...


class AnthropicLikeClient(Protocol):
    """모든 백엔드 클라이언트가 형태상 이걸 만족해야 함."""
    @property
    def messages(self) -> MessagesAPI: ...


# ─── 팩토리 ────────────────
async def get_anthropic_client(
    *,
    api_key: str | None = None,
    max_retries: int = 3,
    model: str | None = None,
) -> AnthropicLikeClient:
    """환경 변수 한 글자로 어떤 SDK를 만들지 결정."""
    
    common_args = {
        "max_retries": max_retries,
        "timeout": int(os.environ.get("API_TIMEOUT_MS", "600000")) // 1000,
    }
    
    if os.environ.get("CLAUDE_CODE_USE_BEDROCK"):
        # ── Lazy import — Bedrock 사용자만 anthropic_bedrock 로드
        from anthropic_bedrock import AnthropicBedrock  # type: ignore
        
        aws_region = (
            os.environ.get("ANTHROPIC_SMALL_FAST_MODEL_AWS_REGION")
            if model == "claude-haiku-4-5"
            and "ANTHROPIC_SMALL_FAST_MODEL_AWS_REGION" in os.environ
            else os.environ.get("AWS_REGION", "us-east-1")
        )
        
        return AnthropicBedrock(aws_region=aws_region, **common_args)  # type: ignore
    
    if os.environ.get("CLAUDE_CODE_USE_VERTEX"):
        # ── Lazy import — Vertex 사용자만 anthropic_vertex 로드
        from anthropic_vertex import AnthropicVertex  # type: ignore
        
        # GCP project ID 발견 우선순위
        # (Anthropic이 12초 타임아웃 사고를 겪고 추가한 분기)
        has_project_env = any(
            k in os.environ
            for k in ["GCLOUD_PROJECT", "GOOGLE_CLOUD_PROJECT"]
        )
        has_keyfile = "GOOGLE_APPLICATION_CREDENTIALS" in os.environ
        
        kwargs = {**common_args}
        if not has_project_env and not has_keyfile:
            # 마지막 fallback — GCE metadata 서버 호출 방지
            kwargs["project_id"] = os.environ.get("ANTHROPIC_VERTEX_PROJECT_ID")
        
        return AnthropicVertex(region=_get_vertex_region(model), **kwargs)  # type: ignore
    
    if os.environ.get("CLAUDE_CODE_USE_FOUNDRY"):
        from anthropic_foundry import AnthropicFoundry  # type: ignore
        
        if "ANTHROPIC_FOUNDRY_API_KEY" not in os.environ:
            from azure.identity.aio import DefaultAzureCredential  # type: ignore
            cred = DefaultAzureCredential()
            return AnthropicFoundry(azure_ad_credential=cred, **common_args)  # type: ignore
        
        return AnthropicFoundry(**common_args)  # type: ignore
    
    # 기본 — Anthropic 직접
    from anthropic import AsyncAnthropic
    return AsyncAnthropic(api_key=api_key or os.environ.get("ANTHROPIC_API_KEY"), **common_args)


# ─── 호출자 — 백엔드를 모른다 ────────────────
async def call_claude(prompt: str) -> str:
    client = await get_anthropic_client()
    response = await client.messages.create(
        model="claude-opus-4-6",
        max_tokens=1024,
        messages=[{"role": "user", "content": prompt}],
    )
    return response.content[0].text  # 어느 백엔드든 같은 형태
```

핵심 셋이 다 있다.

1. **Protocol** (Python의 구조적 타이핑) — `implements` 선언 없이 형태로 호환. TypeScript 캐스팅과 같은 정신.
2. **`if ... import ...`** — lazy import. 안 쓰는 SDK는 디스크에 안 닿음.
3. **호출자는 백엔드를 모른다** — `await client.messages.create(...)` 한 형태.


> 💡 **`Protocol` vs `ABC`.** Python에서 인터페이스를 표현하는 두 가지 방법. `ABC`는 명시적: 클래스가 `class Foo(MyABC):` 라고 선언해야 함. `Protocol`은 암묵적: 메서드 형태만 맞으면 자동으로 호환. 구조적 타이핑. `Protocol`이 **Anthropic SDK 추상화**에 더 잘 맞는다 — 외부 라이브러리가 우리 인터페이스를 명시적으로 implements할 리 없다.

## 핵심 정리

- 같은 Claude가 4개 클라우드에서 산다 — Anthropic 직접, AWS Bedrock, GCP Vertex, Azure Foundry. 환경 변수 하나(`CLAUDE_CODE_USE_*`)로 결정.
- **4개 SDK**가 같은 인터페이스를 흉내낸다 — 모두 `client.beta.messages.create(...)` 라는 형태로 호출 가능. **TypeScript의 구조적 타이핑 + `as unknown as Anthropic` 캐스팅**.
- **`getAnthropicClient()` 팩토리**가 차이를 한 자리에서 흡수. 4개 분기, 각자 자기 SDK 생성. 호출자는 어느 백엔드인지 모른다.
- **Lazy import** (`await import('@anthropic-ai/bedrock-sdk')`) — 안 쓰는 SDK는 로드도 안 한다. AWS 사용자는 Vertex/Foundry SDK가 디스크에 안 닿는다. 1.1의 30ms 부트스트랩의 일부.
- **"we have always been lying about the return type"** — 4개 SDK가 완벽히 호환되지는 않는다. `batches`, `models` 같은 부메서드는 빠질 수 있다. 현실적인 거짓말: 99%의 호출은 `messages.create`이고 그건 모두 호환.
- 백엔드별 고유한 함정: AWS는 **모델별 region**, Foundry는 **Azure AD 토큰 provider**, Vertex는 **GCE metadata 서버 12초 타임아웃 회피**. 각 함정에 수십 줄짜리 코멘트가 사고 분석.
- 추상화의 제일 강력한 형태 — 호출자가 다른 백엔드의 존재 자체를 모른다. 환경 변수 한 글자만 바뀌고 코드는 한 글자도 안 바뀐다.
- 다음 챕터(7.2): 백엔드가 아니라 외부 도구를 추상화하는 시스템 — **MCP 클라이언트**.
