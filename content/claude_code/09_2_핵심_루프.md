# 9.2 핵심 루프 — 에이전트 루프 + 메시지 관리

---

## 이 챕터에서 배우는 것

- **에이전트 루프의 Python 구현** — 0.1의 50줄과 2.1의 _정식 다이어그램_ 을 비동기 + 타입 안전하게 회수
- 메시지가 곧 기억이다 — LLM API (Anthropic 인터페이스) 가 **stateless**인 결과로 매번 전체 히스토리를 보내야 하는 이유
- `stop_reason`이 루프의 진짜 디스패처인 이유 — `end_turn` 대 `tool_use`
- **assistant content를 그대로** 다음 메시지에 다시 넣어야 하는 **API 약속**
- **tool_result는 user 메시지** — 가장 헷갈리는 부분
- 9.2 끝의 결과물: **한 개의 스텁 도구로 한 턴이 끝까지 동작하는 mini-claude**

## 본문

### 메시지가 곧 기억이다

먼저 기억부터. `messages.py` 가 책임진다.

LLM API (Anthropic 인터페이스) 는 **stateless**다. 0.1의 둘째 포인트에서 이미 봤다. 매 호출에 처음부터 지금까지의 모든 메시지를 다시 보내야 한다. 서버 쪽에서 대화 상태를 들고 있지 않다.

이건 제약이 아니다 — 기능이다. 우리가 메시지 리스트를 조작할 수 있다는 뜻이다. 7.4의 컨텍스트 압축, 8.1의 fork/agent, 6.1의 `CLAUDE.md` 주입 — 모두 **이 stateless 약속** 덕분에 가능했다. 코드 쪽에서 메시지 리스트를 자유롭게 만지고 다시 보내면 그게 곧 다음 컨텍스트가 된다.

미니 클로드에서는 조작 없이 그저 누적만 한다. `ConversationState` 한 클래스.

```python
# src/mini_claude/messages.py
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any


@dataclass
class ConversationState:
    """누적되는 대화 — 0.1의 messages 리스트의 살 붙은 버전."""
    
    messages: list[dict[str, Any]] = field(default_factory=list)
    
    def append(self, message: dict[str, Any]) -> None:
        """message dict 직접 추가 — 9.1 의 기본 진입점. add_user/add_assistant 의 내부 호출용."""
        self.messages.append(message)
    
    def add_user(self, content: str | list[dict[str, Any]]) -> None:
        """user 메시지 추가. content가 문자열이면 그대로, 리스트면 그대로."""
        self.append({"role": "user", "content": content})
    
    def add_assistant(self, content: list[dict[str, Any]]) -> None:
        """assistant 메시지 추가. 반드시 content 블록 리스트로 들어가야 한다."""
        self.append({"role": "assistant", "content": content})
    
    def to_api_format(self) -> list[dict[str, Any]]:
        """LLM API가 받는 형식 (Anthropic 표준; Vertex/vLLM 어댑터도 동일) — 우리는 이미 그 형식으로 저장 중."""
        return self.messages
    
    def __len__(self) -> int:
        return len(self.messages)
```

40줄 안 된다. **이게 우리의 메모리 시스템 전부다**. 6.2의 AppState? 없다. 5.2의 `store.ts`? 없다. **그냥 dict 리스트**.

그런데 작동한다. 왜냐하면 **LLM API의 메시지 형식 (Anthropic 표준) 이 곧 우리의 데이터 모델**이기 때문이다. 진짜 Claude Code도 내부 `Message` 타입이 **결국 API 형식으로 변환**되어 나간다 — 우리는 처음부터 API 형식으로 산다. 변환 단계 없음.

9.1 스캐폴드의 `ConversationState` 는 `append(msg: dict)` 한 메서드만 있었다. 9.2 에서 그 위에 **두 안전한 메서드를 추가한다** — `add_user / add_assistant`. user 와 assistant 가 받는 content 의 _형태가 다르기 때문_ (아래 콜아웃 — user 는 문자열·리스트 둘 다, assistant 는 리스트만). 두 호출 지점으로 쪼개면 **잘못된 조합을 타입 시스템이 컴파일 타임에 잡는다** — 0.4 의 _잘못된 상태를 표현 불가능하게_ 의 Python 버전. `append` 는 두 메서드의 내부 호출용으로 _그대로 유지_, 직접 호출도 가능하지만 _add_user / add_assistant 가 더 안전한 진입점_.

> 💡 **`add_user` vs `add_assistant` 비대칭.** user 메시지는 `content`가 **문자열도 OK**이고 **블록 리스트도 OK**. 사람이 쓴 텍스트는 보통 문자열, 도구 결과는 리스트. assistant 메시지는 반드시 블록 리스트 — Claude가 텍스트 + tool_use 블록을 섞어 응답할 수 있기 때문. 이 비대칭이 왜 인지 다음 섹션에서 본다.

### `stop_reason` — 루프의 진짜 디스패처

이제 심장. `agent.py`의 `query()` 함수.

매 API 호출의 응답에는 **`stop_reason` 필드**가 있다. Claude가 왜 멈췄는지를 말해준다. 우리한테는 두 값만 중요하다.

| `stop_reason` | 의미 | 우리가 할 일 |
|---|---|---|
| `end_turn` | Claude가 자기 할 말 다 했다 | 루프 종료 — 사용자한테 텍스트 보여주고 입력 대기 |
| `tool_use` | Claude가 도구를 부르고 싶다 | 도구 실행 + 결과를 메시지에 추가하고 **다시 API 호출** |
| (다른 값들) | `max_tokens`, `pause_turn`, `stop_sequence`, `model_context_window_exceeded`, `refusal`… | 미니 클로드에서는 에러로 처리 |

**이 두 값의 분기가 곧 에이전트 루프의 본질**이다. 0.1의 그림이 정확히 이걸 그린다 — 텍스트면 끝, 도구 호출이면 실행하고 다시. **2.1의 _정식_ 에이전트 루프 다이어그램**도 이 두 분기를 중심에 두고 _conversation lifecycle_ 의 모든 상태 전환을 stop_reason 두 값으로 압축한다. 우리는 그걸 정확히 그 모양으로 Python으로 옮긴다.

**진짜 Claude Code는 (다른 값들)도 다룬다**. `claude.ts:2279`에 `model_context_window_exceeded` 분기 — 이 값이 오면 7.4의 컨텍스트 압축을 트리거. `errors.ts:1188`에 `refusal` 분기 — Claude가 안전상 거부한 경우 특수 에러 처리. 그 외 `pause_turn`, `stop_sequence`, `max_tokens` 등도 각각 다른 처리. 미니 클로드에서 **RuntimeError 한 줄**로 처리하는 결정은 — **이 챕터들을 OUT한 결과**와 직접 대응. **압축이 OUT이니 `model_context_window_exceeded`도 OUT — 그저 에러로 죽는다**.

```python
while True:
    response = await client.messages.create(...)
    state.add_assistant(content_blocks_from(response))
    
    if response.stop_reason == "end_turn":
        break  # 끝
    
    if response.stop_reason == "tool_use":
        tool_results = await execute_tools(response.content, ...)
        state.add_user(tool_results)  # tool_result는 user 메시지
        continue  # 다시 API 호출
    
    raise RuntimeError(f"Unexpected stop_reason: {response.stop_reason}")
```

**이 7줄이 미니 클로드의 절반**이다. 나머지는 살. 진짜로.

### **assistant content를 그대로 다시 넣는다**

여기서 가장 헷갈리는 부분. Claude가 도구를 호출했을 때, 우리는 그 응답을 메시지 히스토리에 다시 넣어야 한다. 그것도 **Claude가 보낸 그대로**. 한 글자도 안 바꾸고.

왜? LLM API (Anthropic 인터페이스) 의 약속이다. 다음 API 호출에서 — **Claude는 자기가 직전 턴에 무슨 도구를 부르겠다고 했는지**를 **우리가 보낸 assistant 메시지에서** 본다. 우리가 그 메시지를 재구성하면 (예: tool_use 블록을 빼고 텍스트만 남기면) — Claude는 자기가 도구를 부른 적이 없다고 착각한다. 그런데 다음 user 메시지에 **tool_result**가 들어 있으면 — **어떤 tool_use에 대한 결과인지 알 수 없게 되어** API 400 에러.

```python
# ❌ 잘못된 방법 — 텍스트만 추출해서 넣음
text_only = [b for b in response.content if b["type"] == "text"]
state.add_assistant(text_only)  # tool_use 블록이 사라졌다 → 다음 호출 시 400

# ✅ 올바른 방법 — 내용 그대로, 형식만 dict 로 풀어서 저장
state.add_assistant([b.model_dump() for b in response.content])
```

**그래서 `add_assistant`가 블록 리스트만 받는다**. 문자열로 받으면 바로 잘못 쓸 위험이 있다. 타입 시스템이 우리를 막는다.

그런데 SDK 의 `response.content` 는 _dict 리스트가 아니라_ **Pydantic 객체 리스트** (`TextBlock`, `ToolUseBlock` 등 판별 유니온). 우리 `ConversationState.messages` 는 `list[dict]` 라 한 단계 _형식 변환_ 이 필요 — _내용은 그대로_, _형식만_ Pydantic → dict 로 풀어 준다. **Anthropic SDK** 가 그 변환을 친절하게 도와준다 — `[b.model_dump() for b in response.content]` 또는 `response.model_dump()["content"]` 로 **깔끔한 dict 리스트** 를 얻는다. 그걸 그대로 저장.

### **tool_result는 user 메시지**

두 번째 헷갈리는 부분. 도구 결과는 어디로 가지? 직관적으로는 "도구가 자기 메시지로 응답한다"라고 생각할 수 있다. 별도의 `role: "tool"` 같은 거.

아니다. LLM API (Anthropic 인터페이스) 는 도구 결과를 **user 메시지의 content 블록**으로 받는다. 0.1의 세 번째 포인트 다시 — **시스템이 자동으로 채워준 user 메시지**. 형식은:

```python
{
  "role": "user",
  "content": [
    {
      "type": "tool_result",
      "tool_use_id": "toolu_01abc...",  # ← 어느 tool_use에 대한 답인지
      "content": "파일 내용 여기...",
    },
    # 한 번에 여러 도구를 부르면 여러 tool_result가 한 user 메시지 안에
  ]
}
```

**`tool_use_id`**가 결정적이다. Claude가 동시에 여러 도구를 호출할 수 있다 (parallel tool use). Read 두 개를 동시에. 우리는 각각 실행하고 각각의 결과를 **원래 tool_use 블록의 ID**에 매칭시켜 돌려준다. ID가 안 맞으면 — 400 에러.

그리고 미니 클로드 코드가 이걸 자연스럽게 처리한다. 다음 섹션의 `for block in content_blocks`가 **모든 tool_use 블록을 순회**하면서 **각 결과를 한 user 메시지의 content list 안에** 모은다. Claude가 한 응답에 Read 두 개를 동시에 호출하면 — 우리는 두 개를 순차 실행하지만 **한 user 메시지로 묶어** 돌려준다. **API가 받는 모양은 동일** — Claude는 두 결과가 동시에 도착했다고 인식. 진짜 **parallel 실행** (`asyncio.gather`)은 9.5에서 추가하지만, **parallel의 와이어 포맷**은 이 챕터에서 이미 작동한다.

### 한 페이지 의사코드

위의 모든 걸 합치면 아주 짧은 함수가 된다.

```
async def query(state, tools, system_prompt, max_iterations=50):
    for _ in range(max_iterations):       # ← while True 대신 — 무한 루프 가드
        response = await anthropic.messages.create(
            messages=state.to_api_format(),
            system=system_prompt,
            tools=[t.to_anthropic_schema() for t in tools],
            model="claude-opus-4-7",
            max_tokens=4096,
        )
        
        # ① 응답을 그대로 저장 (텍스트 + tool_use 블록)
        content = [b.model_dump() for b in response.content]
        state.add_assistant(content)
        
        # ② end_turn이면 텍스트 출력하고 끝
        if response.stop_reason == "end_turn":
            for block in content:
                if block["type"] == "text":
                    print(block["text"])
            return
        
        # ③ tool_use면 모든 tool_use 블록을 실행, 결과를 user 메시지로
        if response.stop_reason == "tool_use":
            tool_results = []
            for block in content:
                if block["type"] != "tool_use":
                    continue
                tool = find_tool(tools, block["name"])
                result_text = await tool.call(block["input"])
                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block["id"],
                    "content": result_text,
                })
            state.add_user(tool_results)
            continue  # 루프 위로
        
        raise RuntimeError(f"Unexpected stop_reason: {response.stop_reason}")
    
    raise RuntimeError(
        f"max_iterations({max_iterations}) 초과 — Claude 가 도구 호출 루프를 못 빠져나옴"
    )
```

**이게 전부다**. 30줄 정도. 진짜로 동작하는 미니 클로드의 에이전트 루프. 단, 권한 체크 없음(9.4), 스트리밍 없음(9.5), 진짜 도구 없음(9.3 — 이 챕터에선 stub 도구).

`while True` 대신 `for _ in range(max_iterations)`를 쓰는 이유: Claude가 **계속 tool_use만 하고 end_turn을 안 하는 시나리오** (잘못된 도구 출력, 무한 루프 패턴, 모델 버그 등)에서 프로세스가 영원히 도는 것을 막기 위해. 진짜 Claude Code의 query loop (2.x)에도 같은 정신의 안전 장치가 있음 — **8.2가 가르친 fail-safe defaults 정신을 한 줄로 압축**.

```python
# src/mini_claude/tools/base.py
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any, Protocol


@dataclass
class ToolContext:
    """도구 실행 시 주변 컨텍스트 — 9.1 스캐폴드의 3 필드를 그대로 유지.

    `permissions` / `read_files` / `is_read_only` 는 9.2 에서는 _아직 안 쓰임_,
    9.4 에서 권한 시스템이 들어오면서 _쓰이기 시작_ 한다.
    """
    cwd: str
    permissions: Any  # PermissionEngine — 9.4에서 의미를 갖는다
    read_files: set[str] = field(default_factory=set)  # Read-before-Edit 추적 (9.3 EditTool)


class Tool(Protocol):
    """Tool 인터페이스 — 9.3에서 Pydantic으로 정식화."""
    name: str
    description: str
    input_schema: dict[str, Any]   # JSONSchema dict (9.3에서 자동 생성)

    async def call(self, args: dict[str, Any], context: ToolContext) -> str:
        ...

    def is_read_only(self) -> bool:
        """Fail-safe: 모르면 False (위험하다고 가정). 9.4 에서 권한 분기에 사용."""
        ...


def find_tool(tools: list[Tool], name: str) -> Tool:
    """이름으로 도구 찾기. 못 찾으면 에러."""
    for t in tools:
        if t.name == name:
            return t
    raise ValueError(f"Unknown tool: {name}")
```

```python
        "properties": {
            "message": {
                "type": "string",
                "description": "The message to echo back.",
            },
        },
        "required": ["message"],
    }
    
    async def call(self, args: dict[str, Any], context: ToolContext) -> str:
        return f"echo: {args['message']}"
```

```python
# src/mini_claude/agent.py — 이 챕터의 심장
from __future__ import annotations
import os
from anthropic import AsyncAnthropicVertex
from .messages import ConversationState
from .permissions import PermissionEngine
from .tools.base import Tool, ToolContext, find_tool


# 모델 / max_tokens — .env 의 MINI_LLM_MODEL / MINI_LLM_MAX_TOKENS 가 우선,
# 미설정 시 아래 fallback.
DEFAULT_MODEL = os.environ.get("MINI_LLM_MODEL", "claude-opus-4-7")
DEFAULT_MAX_TOKENS = int(os.environ.get("MINI_LLM_MAX_TOKENS", "4096"))


def _make_vertex_client() -> AsyncAnthropicVertex:
    """Vertex AI 의 Anthropic Claude 클라이언트. 9.x 동안에는 이 한 가지만.

    VERTEX_PROJECT_ID 환경변수 + Service Account JSON (GOOGLE_APPLICATION_CREDENTIALS)
    필요. 10.5 에서 provider 분기 (make_client) 가 도입되면 이 자리에 들어간다.
    """
    return AsyncAnthropicVertex(
        project_id=os.environ["VERTEX_PROJECT_ID"],
        region=os.environ.get("VERTEX_LOCATION", "global"),
    )


async def query(
    *,
    user_input: str,
    tools: list[Tool],
    permissions: PermissionEngine,
    cwd: str,
    state: ConversationState,
    system_prompt: str = "You are a helpful coding assistant.",
    client: AsyncAnthropicVertex | None = None,
    max_iterations: int = 50,
) -> None:
    """에이전트 루프 — 0.1의 50줄 챗봇 + 비동기 + 타입.

    `permissions` 는 9.2 에서는 ToolContext 에 _담아 두기만_ 하고 직접 쓰지 않는다.
    9.4 에서 도구 호출 직전 게이트로 _쓰이기 시작_. 9.1 의 query() 시그니처를 그대로 유지.

    스트리밍 / 서브 에이전트는 9.5 에서 추가.
    """
    client = client or _make_vertex_client()
    context = ToolContext(cwd=cwd, permissions=permissions, read_files=set())
    
    # 사용자 입력을 메시지 히스토리에 추가
    state.add_user(user_input)
    
    for _ in range(max_iterations):
        # ── ① API 호출 ────────────────────────────
        response = await client.messages.create(
            model=DEFAULT_MODEL,
            max_tokens=DEFAULT_MAX_TOKENS,
            system=system_prompt,
            tools=[
                {
                    "name": t.name,
                    "description": t.description,
                    "input_schema": t.input_schema,
                }
                for t in tools
            ],
            messages=state.to_api_format(),
        )
        
        # ── ② assistant content를 그대로 저장 ──────
        content_blocks = [b.model_dump() for b in response.content]
        state.add_assistant(content_blocks)
        
        # ── ③ end_turn — 텍스트 출력 후 종료 ─────────
        if response.stop_reason == "end_turn":
            for block in content_blocks:
                if block["type"] == "text":
                    print(block["text"])
            return
        
        # ── ④ tool_use — 각 도구 실행, 결과 user 메시지로 ──
        if response.stop_reason == "tool_use":
            tool_results: list[dict] = []
            for block in content_blocks:
                if block["type"] != "tool_use":
                    continue
                
                tool = find_tool(tools, block["name"])
                print(f"[{tool.name}] {block['input']}")  # 임시 로그
                
                try:
                    result = await tool.call(block["input"], context)
                    tool_results.append({
                        "type": "tool_result",
                        "tool_use_id": block["id"],
                        "content": result,
                    })
                except Exception as e:
                    tool_results.append({
                        "type": "tool_result",
                        "tool_use_id": block["id"],
                        "content": f"Error: {e}",
                        "is_error": True,    # ← 모델의 에러 회복 행동을 트리거
                    })
            
            state.add_user(tool_results)
            continue  # 루프 위로 — Claude한테 결과 보여주고 다음 결정
        
        raise RuntimeError(
            f"Unexpected stop_reason: {response.stop_reason}"
        )
    
    raise RuntimeError(
        f"max_iterations({max_iterations}) 초과 — Claude가 도구 호출 루프를 못 빠져나옴"
    )
```

### 진짜로 돌려보기

9.1 끝의 첫 실행은 `NotImplementedError` 까지 갔다 — _환경이 살아 있나_ 검증. 이번 챕터에서 `query()` 본체가 채워졌으니 같은 `uv run mini-claude` 한 줄로 이번엔 _진짜 응답_ 까지 간다 (`pyproject.toml` 이 안 바뀌어 `uv sync` 재실행은 불필요 — Python source 만 채운 셈).

```bash
$ uv run mini-claude
mini-claude 시작 (Ctrl+D로 종료)
> 안녕
안녕하세요! 무엇을 도와드릴까요?
> Echo 도구로 'hello world'를 한 번 돌려줘
[Echo] {'message': 'hello world'}
'hello world'를 Echo 도구로 돌렸어. 결과: "echo: hello world"
> 
```

**작동한다**. 두 번째 입력에서 — Claude가 **Echo 도구**를 인식하고, 직접 호출하고, 결과를 받아, 사용자한테 자연어로 보고했다. **이게 0.1의 50줄 챗봇이 비동기 + 타입 안전 + 클래스화된 정확한 결과**.

루프가 한 바퀴가 아니라 **N 바퀴** 돌 수도 있다. 세 번째 입력에서 "3 + 2 + 5를 Echo로 단계별로 보여줘" 하면 — Claude가 Echo를 세 번 연속 호출할 수도 있다. 우리 코드의 `while True:`가 그걸 자연스럽게 처리한다 — 매 턴 응답의 `stop_reason`이 `tool_use`이면 계속, `end_turn`이면 종료.

> 💡 **`b.model_dump()` vs `dict(b)`.** Anthropic SDK는 `pydantic` 기반이라 응답 객체가 **Pydantic 모델**. `.model_dump()`가 **재귀적으로 dict로**. `dict(b)`는 얕은 변환만. 중첩 객체가 깨진다. 항상 `model_dump()` 쓸 것.

> 💡 **`is_error: True`의 의미.** 단순히 에러 텍스트를 content로 보내도 작동은 한다. 하지만 `is_error: true` 플래그를 같이 보내면 — Claude가 명시적으로 "이 도구가 실패했다"를 인식해서 다음 턴의 결정을 재시도/우회/사용자 보고 중 적절한 쪽으로 조정. **API의 작은 플래그가 모델의 에러 회복 행동을 정확히 트리거**한다. 다만 미니 클로드는 이 플래그를 **OUT** — 도구 반환을 `str` 한 가지로 단순화 (KISS 결정 3 의 정신). 도구가 `"Error: ..."` 로 시작하는 텍스트를 반환하면 Claude 가 _내용으로 추측_ 한다 — 진짜 도구 인터페이스 정밀화는 _플러그인 / MCP 도구_ 가 들어오는 자리에서 검토할 후행 자리.

## 핵심 정리

- **LLM API (Anthropic 인터페이스) 는 stateless** — 매 호출에 전체 메시지 히스토리를 다시 보낸다. 이건 제약이 아니라 기능 — 우리가 메시지 리스트를 조작해서 컨텍스트를 만들 수 있다는 뜻 (7.4 압축, 8.1 fork, 6.1 `CLAUDE.md` 주입이 다 이 덕분).
- **메시지 = 기억**. `ConversationState` 한 클래스, 40줄 미만. 내부 표현이 **LLM API 형식 그대로 (Anthropic 표준)** — 변환 단계 없음.
- **`stop_reason`이 루프의 진짜 디스패처**. `end_turn` → 종료, `tool_use` → 도구 실행 + 결과 추가 + 루프 위로. 7줄짜리 분기가 에이전트 루프의 본질.
- **assistant content를 그대로 다시 저장** — LLM API (Anthropic 인터페이스) 의 약속. 텍스트만 추출해서 저장하면 다음 호출의 tool_result 매칭이 깨져 400 에러. `add_assistant`가 블록 리스트만 받게 해서 타입 시스템이 막아준다.
- **tool_result는 user 메시지의 블록**. 별도 role이 아님. **시스템이 자동으로 채워준 user 메시지**. **`tool_use_id`가 결정적** — Claude가 동시에 여러 도구를 부를 수 있고, 우리는 **각 결과를 원래 tool_use ID에 매칭**시켜야 한다.
- **이 챕터의 결과물**: 120줄 정도가 추가된 미니 클로드. 진짜로 동작. `EchoTool` 하나로 루프 끝까지 한 바퀴 돈다. 다음 챕터(9.3)에서 EchoTool을 **진짜 Read/Write/Bash**로 대체.
- 9.4에서 권한 체크가 추가될 자리는 이미 보인다 — `tool.call(...)` 직전. 9.5에서 스트리밍이 추가될 자리도 보인다 — `client.messages.create(...)` 를 `client.messages.stream(...)` 으로 바꾸고 `async for` 로 chunk를 yield. **골격이 제대로 잡혀 있어서 다음 챕터들이 정확한 자리에 정확한 살을 붙인다**.
