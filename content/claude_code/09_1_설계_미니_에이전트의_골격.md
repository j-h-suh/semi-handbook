### 5가지 KISS 결정

진짜 Claude Code는 52만 줄. 우리는 400줄 미만. 무엇을 과감하게 빼야 한다. 결정 5가지.

**결정 1 — 백엔드는 Anthropic 직접만**

7.1에서 본 4 SDK 추상화(Anthropic/Bedrock/Vertex/Foundry)는 과한 추상. 우리는 `anthropic` SDK 의 _한 가지_ 만 쓴다 — 학습자 환경에서 가장 흔한 **Vertex (GCP)**. **Lazy import**도, 팩토리 함수도 없음. `from anthropic import AsyncAnthropicVertex` 한 줄로 끝. (10.5 에서 _다른 백엔드_ — Anthropic 직접, vLLM — 가 어떻게 같은 인터페이스 위에 얹히는지 본다.)

**결정 2 — UI는 글자 스트리밍만, React 없음**

5장(터미널 React, AppState, 가상 스크롤)은 전부 생략. `print()` 와 `rich` 의 `console.print()` 면 충분. 글자 단위 스트리밍은 `async for` + 줄바꿈 처리로. 5.3의 가상 스크롤은 우리한테 필요 없다 — 100줄 스크롤하는 데 메모리 문제 없음.

**결정 3 — 도구는 네 개 + Agent**

진짜 Claude Code는 17개 내장 + N개 MCP (`getAllBaseTools()` 기본 케이스). 우리는 **`Read`, `Write`, `Bash`, `Edit`** 네 개. 그리고 9.5에서 `Agent` 한 개 추가. **이 다섯 개로 90%의 시나리오가 동작**한다. Glob/Grep은 **Bash로 우회**(`find`, `grep`). Edit만은 Bash(`sed`)로 우회하기엔 LLM이 정규식을 정확히 생성한다는 보장이 없어서 — 정확 문자열 매칭 전용 도구로 남긴다.

**결정 4 — 권한은 세 가지 결정만**

6.3의 5가지 권한 모드 (`default`/`acceptEdits`/`bypassPermissions`/`plan`/`dontAsk`)와 6.4의 7단계 와일드카드 변환은 과하다. 우리는:

- `allow` (자동 허용 규칙 매칭)
- `deny` (자동 거부 규칙 매칭)
- `ask` (사용자한테 한 번 물어봄, 이번 턴만 OR 영구)

세 가지. 와일드카드는 **prefix**만 (`Bash:git *` 같은 거). 6.4의 7단계 변환 대신 Python의 **`fnmatch`** 한 줄.

**결정 5 — 컨텍스트 압축, 멀티 에이전트 깊이, MCP, IDE Bridge — 전부 OUT**

7.4 컨텍스트 압축, 8.3 코디네이터 모드(위계), 8.4 에이전트 팀(peer), 7.2 MCP, 7.5 IDE Bridge, 7.3 OAuth, 6.1 `CLAUDE.md` — 전부 생략. 200K 토큰을 넘으면 그냥 에러. 서브 에이전트는 한 단계만 (자식이 손자 못 부름). MCP 없음 — 도구는 컴파일 타임에 박힌 4개. IDE 통합 없음. 인증은 GCP _Service Account JSON_ (`GOOGLE_APPLICATION_CREDENTIALS` 환경 변수 한 줄) + `VERTEX_PROJECT_ID`.

> 💡 **학습자 환경 — Vertex 가 기본**: 9.x 본문은 `AsyncAnthropicVertex` 한 가지로 진행한다. _Anthropic 직접 API 키_ 가 있는 학습자도 _Vertex 코드 그대로_ 따라가면 됨 — 10.5 에서 `make_client()` 가 _provider 분기_ 를 도입할 때 _같은 인터페이스 위에_ 다른 백엔드가 얹히는 걸 본다. GCP 환경 설정은 [mini-claude/SETUP.md](/claude/setup) 참조 (project + Vertex AI API 활성화 + Model Garden 의 Claude opt-in + Service Account JSON).

깊이 1 단순화의 진짜 위력: 8.2의 `createSubagentContext`가 **fail-safe defaults / WeakRef AbortController / PPID=1 zombie 회피** 같은 프로덕션 안전 장치들로 무장했던 건 — **재귀 깊이가 N이 될 수 있기 때문**이었다. 깊이 1로 제한하면 그 안전 장치 대부분이 필요 없어진다. 자식이 자식을 못 만드니 조상 추적이 필요 없고, 컨텍스트 격리도 한 층만 신경 쓰면 된다. **재귀 깊이를 1로 묶는 것이 8.2의 절반을 무효화**한다 — KISS의 진짜 위력이 여기 있다.

같은 단순화가 _두 갈래 협업 디자인_ 도 한꺼번에 OUT 시킨다. **8.3 코디네이터 모드(위계 기반, fork-join)** 와 **8.4 에이전트 팀(peer 기반, 메일박스 + Stop 훅 통신)** 이 _같은 `query` 재귀 + `createSubagentContext`_ 위에 서로 다른 토폴로지로 쌓아 올린 두 결과물인데 — 깊이 1 미니 클로드는 _그 위의 통신·정체성 레이어 전체_ 가 불필요. 8.4의 1,100줄 메일박스·peer DM·GrowthBook rollout 인프라는 우리가 _안 만든다_, _못 만들어서_ 가 아니라 _필요 없어서_.

**이 다섯 가지 결정이 52만 줄 → 400줄을 만든다**. 잘 생각해보면 — 빼는 것마다 한 챕터가 걸린다. 그게 우리가 이 책을 쓴 이유. 빠진 것들이 왜 거기 있는지는 이미 안다.

우리가 빼는 것이 곧 우리가 배운 것이다. 7.4 컨텍스트 압축은 OUT이지만 우리는 9-섹션 강제 검증과 **prompt cache 공유**가 왜 거기 있어야 했는지 안다 — 멀티 세션의 cache hit을 살리려는 **38B tok/day 규모의 사연**. 8.3 코디네이터 모드는 OUT이지만 우리는 분산 시스템이 대화 모델로 매핑되는 우아함 — `<task-notification>`이 user 메시지로 들어오는 디자인을 봤다. 7.5 IDE Bridge는 OUT이지만 우리는 파일시스템 랑데부가 **boundary 횡단의 정수**임을 안다. 7.1의 4-SDK 추상화도 OUT이지만 우리는 **lazy import가 cold start 30ms를 어떻게 지키는지** 안다. **OUT인 것이 우리가 모르는 것이 아니다 — 그저 우리 미니 버전의 범위가 아닐 뿐.** 단순함은 지식의 부재가 아니라 의도된 선택이다.

### 의존성

`pyproject.toml` 의 `dependencies` 가 네 줄.

```toml
[project]
name = "mini-claude"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "anthropic[vertex]>=0.40.0",   # LLM API + Vertex extra (google-auth 자동 포함)
    "pydantic>=2.0.0",             # 도구 입력 스키마 + JSONSchema 자동 생성
    "rich>=13.0.0",                # 스트리밍 출력 색깔/포맷
    "python-dotenv>=1.0.0",        # .env 파일 자동 로드 (SETUP.md §2)
]

[project.scripts]
mini-claude = "mini_claude.main:main"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

`uv add 'anthropic[vertex]' pydantic rich python-dotenv` 한 번. `uv run mini-claude` 로 실행. `[vertex]` _extra_ 가 `google-auth` 같은 GCP 인증 의존성을 자동으로 끌고 와야 9.2 의 첫 호출이 작동한다 — 없으면 `RuntimeError: Could not import google.auth, you need to install the SDK with pip install anthropic[vertex]` 로 막힌다. `python-dotenv` 는 `mini-claude/` 디렉토리의 `.env` 파일을 _자동으로_ 읽어 환경변수로 올리는 역할 — 학습자가 _shell rc_ 에 export 안 해도 `.env` 만 두면 작동한다.

> ⚠️ **`[build-system]` 블록이 _꼭_ 필요하다.** 없으면 `uv` 가 패키지를 빌드 가능한 형태로 인식하지 못해 **`[project.scripts]` 의 엔트리 포인트가 생성되지 않는다** — `uv run mini-claude` 가 "command not found" 로 실패. `hatchling` 은 가장 가벼운 백엔드라 의존성 부담이 거의 없다.

> ⚠️ **`uv sync` / `uv add` 실행 전에 `src/mini_claude/__init__.py` 가 _최소한 빈 파일로라도 존재_ 해야 한다.** `pyproject.toml` 의 `name = "mini-claude"` 를 hatchling 이 `mini_claude` (snake) 결로 normalize 한 뒤 `src/mini_claude/` 디렉토리에서 wheel 콘텐츠를 자동으로 찾기 때문. _스캐폴드 9 파일을 아래 "Python으로 옮기면 — 첫 스캐폴드" 절에서 작성한 뒤_ 첫 `uv sync` 를 돌리거나, _급하면_ `mkdir -p src/mini_claude && touch src/mini_claude/__init__.py` 로 빈 패키지 디렉토리만 먼저 만들면 통과한다. 없으면 `ValueError: Unable to determine which files to ship inside the wheel` 로 막힌다.

> 💡 **`pydantic`으로 도구 스키마를 공짜로 얻는다**. 진짜 Claude Code는 TypeScript의 `zod`로 같은 일을 한다. Pydantic 모델을 정의하면 `.model_json_schema()`가 **LLM API가 받는 JSONSchema (Anthropic 형식 — Vertex/vLLM 어댑터도 동일)** 를 자동으로 만들어준다. 도구 입력 검증도 공짜. **3.3의 `buildTool` 팩토리의 Python 버전**. 9.3에서 자세히 본다.

### 5장 로드맵

각 챕터가 골격의 어느 조각을 채우는지.

| 챕터 | 채우는 조각 | 추가되는 줄 수 (예상) |
|---|---|---|
| **9.1 (이 챕터)** | 설계 + 스캐폴드 (스텁만) | ~80줄 |
| **9.2 핵심 루프** | `agent.py`, `messages.py` | +120줄 |
| **9.3 도구 시스템** | `tools/{base,read,write,bash,edit}.py` | +230줄 |
| **9.4 권한 체크** | `permissions.py` | +60줄 |
| **9.5 스트리밍 + 서브 에이전트** | `streaming.py`, `tools/agent.py` | +80줄 |
| **합계** | | **~570줄** |

각 챕터가 증분으로 쌓는다. 9.2 끝나면 권한 없는 단순한 에이전트가 동작. 9.3 끝나면 4개 도구 다 작동. 9.4 끝나면 위험한 명령에 권한 묻기. 9.5 끝나면 **진짜 Claude Code의 99%의 사용 시나리오**가 작동.

**9.5 끝의 결과물이 책 전체의 summa**. 우리가 본 모든 패턴이 우리 손가락 끝에서 살아 움직인다.

## Python으로 옮기면 — 첫 스캐폴드

이 챕터에서는 스텁만 만든다. 9.2~9.5가 각 스텁을 채운다.

```python
# src/mini_claude/messages.py
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any, Literal


# LLM API의 메시지 형식 (Anthropic 표준) 을 그대로 dataclass로
@dataclass
class Message:
    role: Literal["user", "assistant"]
    content: list[dict[str, Any]] | str


@dataclass
class ConversationState:
    """누적되는 대화 — 0.1의 messages 리스트의 살 붙은 버전."""
    messages: list[Message] = field(default_factory=list)
    
    def append(self, message: Message) -> None:
        self.messages.append(message)
    
    def to_api_format(self) -> list[dict[str, Any]]:
        """LLM API가 받는 형식 (Anthropic 표준) 으로 변환."""
        return [{"role": m.role, "content": m.content} for m in self.messages]
```

# src/mini_claude/tools/base.py
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any, Protocol
from pydantic import BaseModel


@dataclass
class ToolContext:
    """도구 호출 시 주변 컨텍스트 — 8.2의 createSubagentContext의 미니 버전."""
    cwd: str
    permissions: Any  # PermissionEngine — 9.4에서 정의
    read_files: set[str] = field(default_factory=set)  # Read-before-Edit 추적 (9.3 EditTool)


class Tool(Protocol):
    """Tool 인터페이스 — 3.2의 47개 필드를 5개로 압축."""
    name: str
    description: str
    input_model: type[BaseModel]   # Pydantic으로 스키마 자동 생성
    
    async def call(self, args: dict, context: ToolContext) -> str:
        """도구의 실제 동작. 결과는 문자열 (LLM API가 받는 형식)."""
        ...
    
    def is_read_only(self) -> bool:
        """Fail-safe: 모르면 False (위험하다고 가정)."""
        ...
```

# src/mini_claude/permissions.py
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Literal


PermissionDecision = Literal["allow", "deny", "ask"]


@dataclass
class PermissionEngine:
    """6.3의 권한 모드와 6.4의 매칭을 3가지로 압축."""
    allow_rules: set[str] = field(default_factory=set)  # ["Bash:git *", "Read"]
    deny_rules: set[str] = field(default_factory=set)
    
    def check(self, tool_name: str, input_summary: str) -> PermissionDecision:
        # 9.4에서 구현
        return "ask"
```

```python
# src/mini_claude/agent.py
from __future__ import annotations
from typing import AsyncGenerator
from anthropic import AsyncAnthropicVertex
from .messages import ConversationState, Message
from .permissions import PermissionEngine
from .tools.base import Tool, ToolContext


async def query(
    *,
    user_input: str,
    tools: list[Tool],
    permissions: PermissionEngine,
    cwd: str,
    state: ConversationState,
    system_prompt: str = "You are a helpful coding assistant.",
) -> AsyncGenerator[str, None]:
    """에이전트 루프 — 0.1의 50줄 챗봇 + 권한 + 스트리밍 + 도구.
    
    9.2에서 구현. 이 함수가 Part 9 전체의 심장.
    """
    raise NotImplementedError("9.2에서 구현")
    yield  # type: ignore[unreachable]  # async generator로 인식시키기 위한 stub
```

> ⚠️ **stub 에 `yield` 가 한 줄 더 있는 이유**. Python 은 함수 본문에 `yield` 가 있어야 _async generator_ 로 분류한다 — 없으면 그냥 코루틴이 되고, `async for` 가 못 돌린다. `raise` 다음의 `yield` 는 실행되지 않지만 (unreachable), **타입 분류용 마커**다. 2.2에서 본 `async function*` 이 JS 문법으로 _선언_ 되는 것의 Python 등가. 9.2 에서 진짜 `yield chunk` 들이 채워지면 자연스럽게 사라진다.

    tools = default_tool_pool()
    
    print("mini-claude 시작 (Ctrl+D로 종료)")
    while True:

        ):
