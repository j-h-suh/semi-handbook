## 본문

### 9.4 미니 클로드의 침묵은 어디서 오는가

9.2에서 만든 `query()`의 한 자리를 보면:

```python
# 9.2: 핵심 루프
response = await client.messages.create(
    model="claude-opus-4-7",
    max_tokens=4096,
    system=system_prompt,
    messages=state.messages,
    tools=[tool_to_anthropic_schema(t) for t in tools],
)
```

`await client.messages.create(...)`. **이 한 줄이 5초를 잡아먹는 자리**다. Anthropic SDK는 응답을 처음부터 끝까지 받은 다음 `response` 객체로 돌려준다. 그동안 우리 코드는 멈춰 있다. 아무것도 못 한다.

진짜 클로드 코드는 같은 자리에서 완전히 다른 메서드를 부른다 — `client.messages.stream(...)`. 이 메서드는 서버가 토큰 하나 만들 때마다 청크를 흘려준다. 우리 코드는 그 청크들을 받아 즉시 화면에 그릴 수 있다. 5초가 사라지는 게 아니다 — 5초 동안 글자가 흐른다.

문제는 이걸 어떻게 받느냐. 한 번에 받는 객체랑 흐름은 코드 모양이 다르다. 흐름을 받으려면 흐름을 흘려보낼 수 있는 함수가 필요하다. **그게 2.2에서 본 async generator**.

### `async def + yield` — 2.2 매핑의 진짜 회수

2.2에서 우리는 TypeScript의 **async generator**와 Python의 매핑을 봤다:

:::tabs

```typescript
// TypeScript
async function* makeNumbers() {
  for (let i = 0; i < 3; i++) yield i
}
for await (const n of makeNumbers()) console.log(n)
```

```python
# Python
async def make_numbers():
    for i in range(3):
        yield i

async for n in make_numbers():
    print(n)
```

:::

**`async function*` ↔ `async def` (안에 `yield`가 있으면 자동으로 generator)**, **`for await (… of …)` ↔ `async for … in …`**. 그게 다였다. 2.2 끝에서 우리는 "이 매핑이 9.5에서 진짜로 쓰일 거다"라고 미리 예고했고 — 이 챕터가 그 회수다.

진짜 클로드 코드의 `query()`는 **async generator**다. `src/query.ts`를 열면 첫 줄이 이렇다:

```typescript
// src/query.ts:219
export async function* query(
  params: QueryParams,
): AsyncGenerator<...> {
  const consumedCommandUuids: string[] = []
  const terminal = yield* queryLoop(params, consumedCommandUuids)
  // ...
  return terminal
}
```

**한 줄에 봐야 할 게 두 개 있다**:

1. **`async function*`** — 별 표가 함수 이름 옆에 붙는다. 이게 generator라는 표시. 결과로 객체를 반환하는 게 아니라 값을 흘려보내는 함수.
2. **`yield*`** — 별 표가 또 붙었다. 이건 **다른 generator를 그대로 흘려보내는** 문법. Python에는 이게 없다 — 대신 **`async for`**로 풀어 쓴다:

```python
async def query(params):
    consumed = []
    async for x in query_loop(params, consumed):
        yield x
```

**진짜 클로드 코드의 최상위 `query()`는 16줄짜리 얇은 wrapper**다. 안의 `queryLoop()`가 1000줄짜리 본체. wrapper가 하는 일은 **generator를 그대로 흘려보내고** 끝나면 클린업 한 번. 이게 진짜 코드의 **async generator 합성**의 시작점.

### 스트림은 조각이 흐른다 — `+=` 누적의 예술

`queryLoop()` 안에서 LLM API를 부르는 자리는 또 한 단계의 generator 합성이다. 부르면 **generator**가 돌아오고, 그 안에서 또 부르면 더 안쪽 generator가 돌아온다. 진짜 스트림 파싱이 일어나는 곳은 가장 안쪽 — `src/services/api/claude.ts:1940`.

코드를 보기 전에 _스트림으로 날아오는 이벤트의 하이라키_ 를 먼저 그려 두면 아래 코드의 `match part.type` 분기가 _어떤 단계_ 에서 _무엇을_ 처리하는지 즉시 매핑된다.

```text
message_start                          ─ 메시지 시작 (메타 정보)
│
├─ content_block_start  (index=0)
│  │  type: "text"                     ─ 텍스트 블록 시작
│  │
│  ├─ content_block_delta
│  │  delta.type: "text_delta"
│  │  delta.text: "안녕"               ─ 글자 한 조각
│  │
│  ├─ content_block_delta
│  │  delta.type: "text_delta"
│  │  delta.text: "하세요"             ─ 또 한 조각
│  │
│  └─ content_block_stop               ─ 텍스트 블록 끝
│
├─ content_block_start  (index=1)
│  │  type: "tool_use"                 ─ 도구 호출 블록 시작
│  │  id: "toolu_…"
│  │  name: "Read"
│  │
│  ├─ content_block_delta
│  │  delta.type: "input_json_delta"
│  │  delta.partial_json: '{"fil'      ─ JSON 한 조각
│  │
│  ├─ content_block_delta
│  │  delta.type: "input_json_delta"
│  │  delta.partial_json: 'e":"a.py"}' ─ JSON 또 한 조각
│  │
│  └─ content_block_stop               ─ 도구 블록 끝
│
├─ message_delta                       ─ 메시지 메타 갱신 (stop_reason 등)
│
└─ message_stop                        ─ 메시지 끝
```

세 가지 관찰:

- **블록은 _start → delta × N → stop_ 시퀀스** — `match part.type` 의 네 case 가 이 시퀀스의 각 단계
- **블록 타입 두 종류** — `text` (`TextBlock`) / `tool_use` (`ToolUseBlock`). `content_block_start` 의 내부 `match part.content_block.type` 가 이 두 분기
- **delta 유형도 두 종류** — text 블록 → `text_delta.text`, tool_use 블록 → `input_json_delta.partial_json`. `content_block_delta` 의 내부 `if part.delta.type == ...` 가 이 두 분기

:::tabs

```typescript
// src/services/api/claude.ts:1940 — 핵심 루프
for await (const part of stream) {
  switch (part.type) {
    case 'message_start': {
      partialMessage = part.message
      break
    }
    case 'content_block_start':
      switch (part.content_block.type) {
        case 'tool_use':
          contentBlocks[part.index] = { ...part.content_block, input: '' }
          break
        case 'text':
          contentBlocks[part.index] = { ...part.content_block, text: '' }
          break
      }
      break
    case 'content_block_delta': {
      const contentBlock = contentBlocks[part.index]
      if (delta.type === 'input_json_delta') {
        contentBlock.input += delta.partial_json   // ⭐ 한 줄 누적
      } else if (delta.type === 'text_delta') {
        contentBlock.text += delta.text            // ⭐ 한 줄 누적
      }
      break
    }
    case 'content_block_stop': {
      const m: AssistantMessage = {
        type: 'assistant',
        message: {
          ...partialMessage,                        // ⭐ 메타 spread (id / model / role / usage)
          content: [contentBlocks[part.index]],     // ⭐ 누적된 한 블록
        },
      }
      newMessages.push(m)
      yield m                                       // ⭐ 즉시 흘려보냄
      break
    }
  }
}
```

```python
# Python 등가 — 스트리밍 누적 (+= 두 줄이 전부)
async for part in stream:
    match part.type:

            elif part.delta.type == "text_delta":
                block["text"] += part.delta.text            # ⭐ 한 줄 누적
        case "content_block_stop":

                type="assistant",
                message={
                    **partial_message,                       # ⭐ 메타 spread (id / model / role / usage)

            new_messages.append(m)
            yield m                                          # ⭐ 즉시 흘려보냄
```

전체 ~300줄짜리 switch 문이지만 본질은 위 30줄. 보고 있어야 할 것 네 가지:

**① `contentBlocks`는 인덱스로 접근되는 배열.** SDK가 보내는 청크는 어느 블록의 조각인지를 `part.index`에 담아 보낸다. 텍스트 블록 0의 첫 글자, 도구 호출 블록 1의 JSON 첫 조각, 텍스트 블록 0의 두 번째 글자 — 이런 식으로 인터리브 가능. 인덱스가 라우팅 키.

**② `content_block_start`에서 빈 문자열로 초기화.** 텍스트 블록은 `text: ''`, 도구 호출 블록은 `input: ''`. 비어 있는 그릇을 만들어 두고 조각이 올 때마다 거기에 부어 넣는다. dataclass의 기본값을 빈 컬렉션으로 두는 Python의 패턴과 같다.

**③ `content_block_delta`의 `+=` 두 줄.** 이게 전부다. 텍스트는 `text +=`, 도구 입력 JSON은 `input +=`. JSON 조각이 부분적으로 들어와서 **완전한 JSON이 아닐 때도** 그냥 문자열로 누적한다 — 파싱은 블록이 끝났을 때 한 번에. **별도 큐, 별도 파서, 상태 머신 같은 거 없다**. 문자열에 += 두 번.

**④ `content_block_stop`에서 즉시 yield.** 텍스트 블록 한 개가 끝났다 — 전체 메시지가 끝나기를 안 기다린다. `yield m` 한 줄로 **부모 generator에게 흘려보낸다**. 부모는 그걸 받아서 **또 yield 해서 그 부모에게 흘려보낸다**. 그렇게 **최상위 `query()`까지 흘러가서, 결국 터미널에 박힌다**. **5초가 아니라 블록 한 개 분량으로 응답이 흘러나오는 이유**.

> 💡 **왜 SDK가 직접 누적해주지 않나?** 사실 해준다. `client.messages.stream()`은 자체 누적 기능이 있어서, 끝까지 기다리면 완성된 메시지를 한 번에 돌려준다. 그런데 진짜 클로드 코드는 그걸 안 믿고 직접 누적한다. 코드에 박힌 주석: "the sdk mutates the contents of text blocks as it works. we want the blocks to be immutable, so that we can accumulate state ourselves." — SDK가 내부 객체를 변형해서 우리가 언제 어떤 상태인지를 단언할 수 없게 만든다는 것. 그래서 직접. **production 코드의 작은 강박**.

### **이미 yield 된 메시지를 나중에 변형하기**

여기서부터가 **production 디테일**의 정수. 위 `for await` 루프 안에는 한 가지 case가 더 있다 — `case 'message_delta'`.

:::tabs

```typescript
// src/services/api/claude.ts:2213 — 같은 루프 안의 다른 case
case 'message_delta': {
  // IMPORTANT: Use direct property mutation, not object replacement.
  // The transcript write queue holds a reference to message.message
  // and serializes it lazily (100ms flush interval). Object
  // replacement ({ ...lastMsg.message, usage }) would disconnect
  // the queued reference; direct mutation ensures the transcript
  // captures the final values.
  stopReason = part.delta.stop_reason

  const lastMsg = newMessages.at(-1)
  if (lastMsg) {
    lastMsg.message.usage = usage
    lastMsg.message.stop_reason = stopReason
  }
}
```

```python
# Python 등가 — 이미 yield된 객체를 직접 변형 (transcript queue reference 살아 있음)
case "message_delta":
    # 새 객체로 만들면 queue가 잡고 있는 reference와 disconnect
    # 직접 변형해야 100ms 후 직렬화 시점에 변형된 값이 박힌다
    stop_reason = part.delta.stop_reason

    last_msg = new_messages[-1] if new_messages else None
    if last_msg is not None:
        last_msg.usage = usage
        last_msg.stop_reason = stop_reason
        # Python의 dataclass는 mutable이라 이게 자연스럽다 — TS가 더 어려웠을 뿐
```

:::

**시간 순서**:

```
   t=0   stream 시작
   ...
   t=2   content_block_stop → AssistantMessage 만들어 yield
         (이 시점에 stop_reason은 null)
   t=2.1 yield 된 메시지가 부모 generator로 흘러간다
   t=2.2 부모가 또 위로 흘리고, 결국 transcript queue가 reference를 잡고
         100ms 후 직렬화 예약
   t=3   message_delta 도착 → stop_reason 값이 지금 들어왔다
   t=3.1 ??? 이제 어떻게 stop_reason을 이미 떠난 메시지에 박지?
```

**문제**: **yield 된 메시지는 이미 떠났다**. 새 객체로 만들면 **떠난 메시지는 stop_reason이 null인 채로** transcript에 박힌다. **cache가 깨지고**, 대화 재개가 망가지고, 권한 매칭이 어긋난다.

**해결**: 떠난 객체의 프로퍼티를 직접 변형. `lastMsg.message.usage = usage`. 같은 객체를 가리키는 transcript queue의 **reference가 살아 있으므로**, 100ms 후 직렬화될 때는 변형된 값이 박힌다.

이게 **왜 `{ ...lastMsg.message, usage }`면 안 되는지**에 대한 답. **object spread는 새 객체를 만들고, 그러면 transcript queue가 잡고 있는 원래 reference와 다른 객체가 된다**. 같은 변수에 대입해도 — `lastMsg.message = { ...lastMsg.message, usage }` — 변수만 새 객체를 가리킬 뿐 **queue는 옛 객체를 가리킨다**.

코드에 7줄짜리 주석이 박혀 있다. 왜 이렇게 했는지를 코드 자체보다 길게 설명하는 production 코드의 흔한 풍경. **이런 주석이 박혀 있다는 건 과거에 누군가가 이 함정에 빠진 적이 있다는 흔적**.

미니 클로드에서는 어떻게 옮기느냐? — Python의 dataclass는 **기본적으로 mutable**이고 프로퍼티 직접 할당이 자연스럽다. `last_msg.usage = usage`. 별 일 아니다. **TypeScript가 더 어려웠을 뿐**. **이 디테일을 알고서 미니 클로드를 짜는 것과 모른 채 짜는 것의 차이는, 나중에 transcript 같은 걸 붙일 때 드러난다**.

### `AgentTool` — **도구가 query()를 다시 부른다**

스트리밍은 끝났다. 이제 9.5의 두 번째 살 — 서브 에이전트 한 단계.

함수 자체는 974줄이지만 — 재귀의 본질은 위 한 줄. 나머지는 진행률 갱신, **사이드체인 transcript 기록**, **메트릭 forwarding**, **abort 처리**, **MCP setup** 등의 살이다. 미니 클로드에서는 살을 다 떼고 뼈만 남긴다.

**같은 재귀 위에 8.3 코디네이터 모드와 8.4 에이전트 팀이 다른 토폴로지로 쌓인다**. 8.3은 메인이 워커를 _부리는 위계_(fork-join, `<task-notification>` user XML), 8.4는 팀원끼리 메일박스로 _DM 하는 peer 네트워크_(`agent@team` 핸들, Stop 훅 통신, GrowthBook rollout). 두 디자인 모두 _이 한 줄의 `query()` 재귀_ 를 공통 기반으로 쓰고, 그 위에 정체성·통신·메모리·게이트 레이어를 다르게 얹는다. 미니 클로드는 _그 위의 모든 레이어가 OUT_ 이지만 — **`AgentTool` 재귀 한 줄이 두 갈래의 모든 시도를 떠받친다**는 사실은 변하지 않는다. 8.1의 재귀가 _가장 단순한 모드_, 8.3·8.4가 _그 위의 두 가지 협업 디자인_.

전체 호출 체인을 한 번 보자:

```

    │
    └─ AgentTool.call({ prompt, subagent_type, ... })   [AgentTool.tsx:239]
```

위에서 아래로 재귀가 한 번 일어난다. 부모 query()의 도구 루프 → AgentTool.`call()` → `runAgent()` → 격리 컨텍스트 만들기 → **다시 `query()`**. 그 안쪽 query()가 자기만의 도구 루프를 돌고, 끝나면 마지막 텍스트만 뽑아서 부모에게 문자열로 돌려준다.

미니 클로드의 기하학적 압축: **이 13개 중 한 개만 남긴다**.


그게 격리의 본질. 부모 `messages`가 아닌 새 그릇만 있으면 — 서브 에이전트가 부모의 대화 내역을 못 본다, 자기 결과가 부모에 안 새어 들어간다. **나머지 11개의 override는 각자의 production 문제를 푼다** (cache hit 유지, abort chaining, UI 차단, 권한 prompt 차단 등). 미니 클로드는 그 문제들이 없다 — 없으니까 안 푼다.

> 💡 **8.2의 권한 prompt 차단 디테일은 어디로 갔나?** 진짜 코드에선 `shareSetAppState: !isAsync`가 **비동기 서브 에이전트는 사용자한테 prompt를 못 띄우게** 막는다 (`forkedAgent.ts:362-374`의 `shouldAvoidPermissionPrompts` 강제). 미니 클로드에서는 서브 에이전트가 한 단계만 돌고, 부모가 동기로 기다린다 — 그래서 **권한 prompt가 떠도 부모 터미널에 뜨고 사용자가 답할 수 있다**. 9.4의 권한 게이트가 그대로 유효. **문제가 없으니까 해결도 없다**.

### 결과 추출 — 마지막이 아니라 마지막 텍스트

서브 에이전트가 끝났다. 부모에게 뭘 돌려주느냐? 9.4의 도구들이 그랬듯이 문자열 하나를 돌려줘야 한다 — 그래야 부모 query()의 messages에 `tool_result`로 박힐 수 있다.

순진하게 생각하면:

```python
return child_state.messages[-1].text  # ← 함정
```

**진짜 코드는 안 그렇다**. `agentToolUtils.ts:276`의 `finalizeAgentTool`:

:::tabs

```typescript
// src/tools/AgentTool/agentToolUtils.ts:276 (축약 — 함수 declaration + metadata destructure 생략, body 297 부터 인용)
const lastAssistantMessage = getLastAssistantMessage(agentMessages)
if (lastAssistantMessage === undefined) {
  throw new Error('No assistant messages found')
}
// Extract text content from the agent's response. If the final assistant
// message is a pure tool_use block (loop exited mid-turn), fall back to
// the most recent assistant message that has text content.
let content = lastAssistantMessage.message.content.filter(
  _ => _.type === 'text',
)

    if (m.type !== 'assistant') continue
```

```python

if last_assistant is None:
    raise RuntimeError("No assistant messages found")

# 마지막 assistant 메시지에서 text 블록만 추출

# 비어 있으면 (마지막이 tool_use only) — 거꾸로 fallback

            continue
        text_blocks = [b for b in m.content if b.type == "text"]
        if text_blocks:
            content = text_blocks
```

**되돌아가기 fallback**. 마지막 assistant 메시지를 가져온다 → 텍스트 블록만 필터 → 비어 있으면 거꾸로 거슬러 올라가서 **텍스트가 있는 가장 최근 assistant 메시지**를 찾는다.

왜 비어 있을 수 있나? — **마지막 메시지가 tool_use only**인 경우. 서브 에이전트가 도구를 부르려는 차에 `max_turns`에 걸렸거나, abort 됐거나, max_tokens에 걸렸거나. 그러면 마지막 assistant 메시지엔 "이 파일을 읽어볼게" 같은 텍스트 없이 **바로 ReadTool 호출만** 들어 있다. **그 메시지에서 텍스트를 뽑으면 빈 문자열**.

순진한 `[-1].text`는 그 케이스에서 빈 답을 부모에게 돌려준다. 부모는 서브 에이전트가 아무 말도 안 했다고 본다. **그게 production의 미세한 silent failure**. fallback 한 줄이 그걸 막는다.

미니 클로드에서도 같은 패턴으로 옮긴다. **production 같은 robustness가 30줄짜리 미니 클로드에 무료로 따라온다**.

## Python으로 옮기면

지금까지 본 모든 것을 Python으로 회수한다. 변경이 가는 자리 세 군데:

1. `agent.py` — `query()`가 **generator**가 된다 (+ 스트리밍 호출로 교체)
2. `tools/agent.py` — 새 파일, AgentTool 클래스
3. `main.py` — `async for chunk in query(...)`로 소비

### `agent.py` — query()를 generator로

```python
# src/mini_claude/agent.py
from __future__ import annotations
from dataclasses import dataclass
from typing import Any, AsyncIterator
import os
from anthropic import AsyncAnthropicVertex
from .tools.base import Tool, ToolContext, find_tool, tool_to_anthropic_schema
from .permissions import PermissionEngine, prompt_user
from .messages import ConversationState


# 위로 흘려보낼 청크 종류 ─────────────────────────────────
@dataclass
class TextDelta:
    """진행 중인 텍스트 한 조각."""
    text: str


@dataclass
class ToolUseStarted:
    """도구 호출이 시작됐다는 알림."""
    name: str
    input: dict[str, Any]


@dataclass
class TurnDone:
    """한 턴이 끝났다는 신호."""
    stop_reason: str


# 위로 흘려보내는 청크의 union
QueryChunk = TextDelta | ToolUseStarted | TurnDone


def _make_vertex_client() -> AsyncAnthropicVertex:
    """Vertex AI 의 Anthropic Claude 클라이언트. 9.x 동안에는 이 한 가지만.

    VERTEX_PROJECT_ID 환경변수 + Service Account JSON (GOOGLE_APPLICATION_CREDENTIALS)
    필요. 10.5 에서 provider 분기 (make_client) 가 도입되면 이 자리에 들어간다.
    """
    return AsyncAnthropicVertex(
        project_id=os.environ["VERTEX_PROJECT_ID"],
        region=os.environ.get("VERTEX_LOCATION", "global"),
    )


async def query(
    *,
    user_input: str,
    tools: list[Tool],
    permissions: PermissionEngine,
    cwd: str,
    state: ConversationState,
    system_prompt: str = "You are a helpful coding assistant.",
    client: AsyncAnthropicVertex | None = None,
) -> AsyncIterator[QueryChunk]:
    """*async generator*. 각 청크를 부모에게 흘려보낸다.

    9.4 에서는 `async def query(...) -> None` 이었다. 이제 yield 가
    들어가서 *generator 함수*로 변신. *호출자는 `async for` 로 받는다*.
    """
    client = client or _make_vertex_client()
    state.add_user(user_input)
    context = ToolContext(cwd=cwd, permissions=permissions, read_files=set())  # 9.4 권한 게이트 + 9.3 read_files 합류

    while True:
        # 9.2 의 messages.create() → stream() 으로 교체
        async with client.messages.stream(
            model="claude-opus-4-7",
            max_tokens=4096,
            system=system_prompt,
            messages=state.messages,
            tools=[tool_to_anthropic_schema(t) for t in tools],
        ) as stream:
            # 진짜 코드의 contentBlocks[part.index] 와 같은 *직접 누적*.
            # SDK 도 누적해주지만 *그걸 안 믿는* 진짜 코드의 패턴을
            # 따라간다. 우리는 텍스트만 yield 하면 되므로 dict 한 개로 충분.
            async for event in stream:
                # 진짜 코드의 switch (part.type) 에 해당
                if event.type == "content_block_delta":
                    delta = event.delta
                    if delta.type == "text_delta":
                        # ⭐ += 한 줄에 해당 — SDK 가 누적해 두지만 우리는
                        # *조각 자체* 를 부모에게 흘려보낸다.
                        yield TextDelta(text=delta.text)
                # content_block_start / content_block_stop / message_delta
                # 는 미니에서는 *그냥 흘려보낸다*. SDK 가 알아서 final
                # message 에 다 박아 준다.

            # 스트림이 끝나면 SDK 의 누적된 *완성된* 메시지를 가져온다.
            # 9.2 에서 받던 response 객체와 같은 모양.
            response = await stream.get_final_message()

        # 9.2 의 stop_reason 분기 — 변한 게 없다.
        # SDK Pydantic 객체 → dict 리스트로 *9.2~9.4 와 같은 모양* 으로 보존.
        content_blocks = [b.model_dump() for b in response.content]
        state.add_assistant(content_blocks)

        if response.stop_reason == "end_turn":
            yield TurnDone(stop_reason="end_turn")
            return

        if response.stop_reason != "tool_use":
            yield TurnDone(stop_reason=response.stop_reason)
            return

        # tool_use 분기 — 9.4 의 권한 게이트는 *한 줄도 안 바뀜*.
        tool_results: list[dict] = []
        for block in content_blocks:
            if block["type"] != "tool_use":
                continue

            tool = find_tool(tools, block["name"])
            yield ToolUseStarted(name=tool.name, input=block["input"])

            # ── 9.4 의 권한 게이트 (그대로) ─────────────
            decision = permissions.check(tool, block["input"])
            if decision == "deny":
                result_text = "Permission denied by deny rule."
                is_error = True
            elif decision == "ask":
                allowed, new_rule = await prompt_user(tool, block["input"])
                if new_rule:
                    permissions.add_allow(new_rule)
                if allowed:
                    try:
                        result_text = await tool.call(block["input"], context)
                        is_error = False
                    except Exception as e:
                        result_text = f"Error: {e}"
                        is_error = True
                else:
                    result_text = "Permission denied by user."
                    is_error = True
            else:  # "allow"
                try:
                    result_text = await tool.call(block["input"], context)
                    is_error = False
                except Exception as e:
                    result_text = f"Error: {e}"
                    is_error = True

            tool_results.append({
                "type": "tool_result",
                "tool_use_id": block["id"],
                "content": result_text,
                **({"is_error": True} if is_error else {}),
            })

        state.add_user(tool_results)
        # while 루프의 다음 iteration → 다음 LLM 호출
```

**바뀐 자리**: 함수 시그니처가 `-> None` → `-> AsyncIterator[QueryChunk]`. `messages.create()` → `messages.stream()`. 몇 군데에 `yield` 추가. **9.4의 권한 게이트, 9.3의 도구 시스템, 9.2의 stop_reason 분기 — 한 줄도 안 바뀜**. 계층화의 힘이 여기서 또 한 번 회수된다.

### `tools/agent.py` — 새 파일

```python
    description: str = (
        "읽기 전용 서브 에이전트를 한 번 돌립니다. 코드 분석, 문서 요약, "
        "검색 같은 read-only 작업에 적합. 결과는 텍스트로 돌아옵니다."
    )
    input_model: type[BaseModel] = AgentToolInput

    # 부모가 가진 도구 풀에서 *읽기 전용* 만 자식에게 넘긴다.
    parent_tools: list[Tool] = field(default_factory=list)
    permissions: Any = None  # PermissionEngine

    def is_read_only(self) -> bool:
        return False  # 자식이 뭘 할지 모르므로 fail-closed

    def is_destructive(self) -> bool:
        return False

    def permission_summary(self, args: dict[str, Any]) -> str:
        return args.get("prompt", "")[:80]

    async def call(self, args: dict[str, Any], context: ToolContext) -> str:
        prompt = args["prompt"]

        # ── ① 격리: *새 conversation state*. 13 개 override 의 압축 ──
        child_state = ConversationState()

        # ── ② 자식이 쓸 수 있는 도구는 *읽기 전용 + Agent 자기 제외* ──
        # AgentTool 자기 자신을 자식에게 안 주는 이유: 무한 재귀 방지.
        # 진짜 코드는 fork-path 에선 자기를 *준다* (cache hit 유지).
        # 미니는 그런 거 없으므로 그냥 뺀다.
        child_tools = [
            t for t in self.parent_tools
            if t.is_read_only() and t.name != self.name
        ]

        # ── ③ ⭐ 재귀 — query() 가 query() 를 부른다 ──
        # runAgent.ts:748 의 정수.
        query = _query_lazy()
        async for chunk in query(
            user_input=prompt,
            tools=child_tools,
            permissions=self.permissions,  # 부모와 공유
            cwd=context.cwd,
            state=child_state,             # ⭐ 격리된 새 그릇
            system_prompt=SUB_AGENT_SYSTEM,
        ):
            # 자식의 청크는 그냥 *드롭*. 진짜 코드는 부모로 forwarding 해서
            # 진행률을 보여주지만, 미니는 *부모가 동기로 기다리는 단순 모드*.
            pass

        # ── ④ finalizeAgentTool 의 *되돌아가기 fallback* 그대로 옮기기 ──
        last_text_blocks: list[str] = []
        for msg in reversed(child_state.messages):
            if msg.get("role") != "assistant":
                continue
            text_blocks = [
                getattr(b, "text", "") for b in msg.get("content", [])
                if getattr(b, "type", None) == "text"
            ]
            if text_blocks:
                last_text_blocks = text_blocks
                break

        if not last_text_blocks:
            return "(서브 에이전트가 텍스트 응답을 생성하지 못했다)"

        return "\n".join(last_text_blocks)
```

**`call()` 안의 의미 있는 줄 만 다시 짚으면**:

1. `child_state = ConversationState()` — 격리
2. `child_tools = [...]` — 읽기 전용 필터
3. `async for chunk in query(...)` — 재귀
4. `for msg in reversed(...)` — finalizeAgentTool의 fallback

**4줄**. 진짜 코드의 1398줄이 4줄로 압축된다. 그게 정수.

AgentTool은 **9.3의 Tool Protocol**을 그대로 따른다 — `name`, `description`, `input_model`, `is_read_only`, `is_destructive`, `permission_summary`, `call`. 다른 도구들과 똑같다. 9.4의 권한 게이트가 **AgentTool도 똑같이 통과시킨다** — 처음 부르면 물어본다, `t`를 누르면 세션 동안 자동 허용. **계층화의 힘** — `agent.py`의 어떤 다른 코드도 AgentTool을 위해 안 바뀐다.

### `main.py` — async for로 소비

```python
# src/mini_claude/main.py
import asyncio
from .agent import query, TextDelta, ToolUseStarted, TurnDone
from .permissions import PermissionEngine
from .messages import ConversationState
from .tools import default_tool_pool
from .tools.agent import AgentTool


async def main_async(args):
    state = ConversationState()
    permissions = PermissionEngine(
        deny_rules={"Bash:rm -rf *", "Bash:sudo *"},
    )

    # 9.4 의 도구 풀 + AgentTool 추가
    parent_tools = default_tool_pool()
    agent_tool = AgentTool(
        parent_tools=parent_tools,
        permissions=permissions,
    )
    parent_tools.append(agent_tool)

    print("mini-claude 시작 (Ctrl+D로 종료)")
    while True:
        try:
            user_input = await asyncio.to_thread(input, "> ")
        except EOFError:
            print("\nbye.")
            return

        if not user_input.strip():
            continue

        # ⭐ 9.5 의 핵심 변화: async for 로 청크를 받아 즉시 출력
        async for chunk in query(
            user_input=user_input,
            tools=parent_tools,
            permissions=permissions,
            cwd=str(args.cwd),
            state=state,
        ):
            if isinstance(chunk, TextDelta):
                print(chunk.text, end="", flush=True)
            elif isinstance(chunk, ToolUseStarted):
                print(f"\n[{chunk.name}] {chunk.input}", flush=True)
            elif isinstance(chunk, TurnDone):
                print()  # 마무리 줄 바꿈
```

**한 자리만 본다**: `async for chunk in query(...): ...`. 9.4까지는 `await query(...)` 한 줄이었다. **`await` → `async for`로 한 단어 두 단어 바뀐 게 전부** — 그리고 그게 벙어리 벽돌을 흐르는 텍스트로 바꾼다.

`TextDelta`를 받으면 `print(end='', flush=True)`로 글자 단위 즉시 출력. `ToolUseStarted`를 받으면 어떤 도구가 불렸는지 한 줄. `TurnDone`를 받으면 마무리 줄 바꿈. **세 가지 청크 타입을 분기 처리하는 게 9.5의 `main.py` 변경의 전부**.

## 핵심 정리

- **`async def + yield` = `async function*`** — 2.2에서 본 매핑이 9.5에서 진짜로 회수됐다. `query()`가 **generator 함수**가 되고, 호출자는 `async for`로 받는다. 함수 시그니처와 호출 사이트만 바뀌고, 본문 로직은 거의 그대로.
- **스트리밍은 `+=` 두 줄**: `contentBlock.text += delta.text`, `contentBlock.input += delta.partial_json`. 빈 그릇으로 init → 조각 누적 → `content_block_stop`에서 즉시 yield. **별도 큐, 별도 파서 없음**. 진짜 클로드 코드의 30줄짜리 본질.
- **`content_block_stop`에서 블록이 끝나는 즉시 yield** — 메시지 전체가 끝날 때까지 안 기다린다. **블록 한 개가 부모 generator로 흘러가고**, 그게 또 흘러가고, 결국 터미널에 박힌다. **이게 벙어리 벽돌을 흐르는 글자로 바꾸는 메커니즘**.
- **이미 yield 된 메시지의 프로퍼티를 직접 변형** — `message_delta`가 나중에 도착해서 `stop_reason`을 박을 때, **object spread로 새 객체 만들면 안 된다** (transcript queue의 reference가 끊김). Python dataclass의 직접 할당으로 자연스럽게 해결. **production 디테일이 7줄짜리 주석으로 박혀 있는 이유** — 과거에 누군가 빠진 함정의 흔적.
- **`AgentTool`의 정수는 한 줄**: `for await (const message of query({...}))` (`runAgent.ts:748`). 진짜 코드는 974줄짜리 `runAgent` 함수 안에 묻혀 있지만, 재귀의 본질은 그 한 줄. 미니 클로드에서는 `async for chunk in query(...)`로 그대로 옮긴다.
- **격리는 `messages = []` 한 줄로 충분하다** — 진짜 `createSubagentContext`의 13개 override 중 한 개만 남긴다. 부모와 다른 **새 conversation state**만 있으면 서브 에이전트가 부모 대화를 못 보고, 자기 결과가 안 새어 들어간다. 나머지 12개는 **각자 production 문제를 푸는데** (cache hit, abort chain, UI 차단, 권한 prompt 차단, speculation overlay 등) — 미니 클로드는 그 문제들이 없다.
- **결과 추출은 단순 `[-1]`이 아니라 되돌아가기 fallback** — `finalizeAgentTool`의 한 패턴. 마지막 assistant 메시지가 **tool_use only**일 수 있다 (max_turns/abort/max_tokens). 그러면 텍스트가 빈 채로 부모에게 돌아간다 → **silent failure**. 거꾸로 거슬러 텍스트가 있는 가장 최근 메시지를 찾는 8줄짜리 fallback이 그걸 막는다. **production 같은 robustness가 30줄짜리 미니 클로드에 무료로 따라온다**.
- **AgentTool도 9.3의 Tool Protocol을 그대로 따른다** — `name`, `description`, `input_model`, `is_read_only` (False, fail-closed), `permission_summary`, `call`. 다른 도구와 똑같이 9.4의 권한 게이트를 통과한다. **계층화의 힘** — `agent.py`의 어떤 다른 코드도 AgentTool을 위해 안 바뀐다.
- **Part 9 완성**. 9.1의 한 장 그림에서 9.2의 핵심 루프, 9.3의 도구 시스템, 9.4의 권한 체크, 9.5의 스트리밍 + 서브 에이전트 — **모든 살이 다 붙은 미니 클로드**. ~500줄짜리 미니 클로드가 52만 줄짜리 진짜 클로드 코드의 기하학적 압축으로 동작한다. **그리고 이제 다음 — Part 10에서 이 미니 클로드를 확장한다**. 슬래시 명령, 스킬 시스템, MCP 연결 — 9장의 기본 에이전트 위에 확장 시스템을 한 겹씩 쌓는다.
