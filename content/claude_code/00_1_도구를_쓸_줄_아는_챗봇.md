# 0.1 "도구를 쓸 줄 아는 챗봇" — Claude Code를 한 줄로 요약하면

## 이 챕터에서 배우는 것

- Claude Code의 본질을 한 줄로 요약하면 무엇인가
- 그 한 줄이 동작하기 위한 가장 작은 루프 (그림 한 장)
- 그 루프를 Python으로 옮기면 어떻게 생겼는가
- 52만 줄짜리 진짜 코드가 그 루프 위에 어떤 살을 붙였는가

이 챕터의 그림은 책 전체에서 계속 돌아온다. 머릿속에 단단히 박아두자.

## 사용자 경험에서 출발

Claude Code 켜고 다음과 같이 친다.

> `src/utils/parser.py 좀 읽어줘`

엔터 치는 순간부터 화면에 결과가 나오기까지, 짧으면 1초도 안 걸린다. 그 사이에 무슨 일이 일어났는지 차근차근 풀어보자.

직관적으로는 이렇게 생각할 수 있다.

> "Claude가 알아서 파일을 읽고 보여줬겠지."

근데 이 문장에는 작은 함정이 숨어 있다. **Claude는 파일을 직접 못 읽는다.** Claude는 그저 문자열을 입력으로 받고 문자열을 출력하는 LLM이다. 파일 시스템에 접근할 수 없다. 네트워크에도 접근할 수 없다. Claude가 할 수 있는 건 오로지 "텍스트 받고, 텍스트 뱉기"뿐이다.

그럼 어떻게 파일이 읽혔을까?

## 본문 — Claude Code의 한 줄 요약

답은 한 줄로 정리된다.

> **Claude Code = "도구를 쓸 줄 아는 챗봇"**

진짜로 이게 전부다. 풀어보면 이렇다.

1. 사용자 입력을 Claude에게 보낸다 — "src/utils/parser.py 좀 읽어줘"
2. 사용자 메시지와 함께 **사용 가능한 도구 목록**도 같이 보낸다 — "너 이런 도구 쓸 수 있어: Read, Write, Bash, Edit, Glob, Grep, ..."
3. Claude가 응답을 보낸다. 응답은 두 가지 중 하나다.
    - **A. 그냥 텍스트** — "안녕" 같은 거. 화면에 표시하고 끝.
    - **B. 도구 호출 요청** — "Read 도구를 써. file_path는 '/Users/.../parser.py'야."
4. **B의 경우**, 시스템이 진짜로 Read 도구를 실행한다. 파일을 디스크에서 읽는다.
5. 읽은 결과를 다시 Claude에게 보낸다 — "여기, Read 결과야: [파일 내용]"
6. Claude가 결과를 보고 다음 행동을 결정한다. 다시 3번으로 돌아간다.

이 루프가 Claude의 응답이 "그냥 텍스트"가 될 때까지 반복된다. 그러면 사용자에게 답이 보이고 한 턴이 끝난다.

그림으로 그리면 이렇게 생겼다.

```
    ┌──────────────────┐
    │    사용자 입력      │
    └────────┬─────────┘
             ↓
    ┌──────────────────┐
    │  Claude API 호출  │ ← 매 호출마다
    │  (메시지 + 도구)   │   메시지 누적해서 보냄
    └────────┬─────────┘
             ↓
        Claude의 응답
             │
       ┌─────┴─────┐
       ↓           ↓
   [그냥 텍스트]  [도구 호출 요청]
       ↓           ↓
    [화면 표시]   [도구 실행]
       ↓           ↓
      [끝]   [결과를 메시지에 추가]
                   ↓
                  ┌┘ (위의 "Claude API 호출"로)
                  ↓
```

이 루프를 **에이전트 루프(agent loop)** 또는 **도구 사용 루프(tool-use loop)** 라고 부른다. 학술 논문에 나오는 ReAct, Plan-and-Execute 같은 패턴들의 가장 단순한 형태이기도 하다.

여기서 짚고 넘어갈 포인트가 세 가지 있다.

**첫째, 결정권은 Claude한테 있다.** 어떤 도구를 쓸지, 인자는 뭘로 줄지, 도구를 또 부를지 말지 — 다 Claude가 결정한다. 시스템은 그저 Claude가 시키는 대로 도구를 실행하고 결과를 돌려주는 "집사" 역할만 한다. 이게 처음 보면 좀 이상하게 느껴질 수 있다. "내가 짠 프로그램인데 흐름 제어를 LLM한테 맡긴다고?" 그렇다. 바로 이 지점이 전통적인 프로그램과 에이전트의 가장 큰 차이다.

**둘째, 메시지는 누적된다.** 매번 API 호출에 보내는 메시지 리스트에는 처음 사용자 입력부터 지금까지의 모든 대화 + 도구 호출 + 도구 결과가 다 들어 있다. Claude는 stateless하기 때문에 (서버가 이전 호출을 기억하지 않는다) 매번 전체 컨텍스트를 다시 보내야 한다. 대화가 길어지면 이 리스트도 같이 커지고, 그래서 나중에 컨텍스트 압축 같은 게 필요해진다.

**셋째, 도구 결과는 사용자 메시지처럼 보인다.** Anthropic API 입장에서 도구 결과는 `role: "user"`의 특수한 메시지로 들어간다. Claude의 입장에서는 "방금 내가 부른 도구가 결과를 돌려줬구나" 하고 인식하는 셈이다. 사람이 답한 게 아니라 시스템이 자동으로 채워준 user 메시지다.

## 52만 줄은 이 루프 위에 쌓인 살이다

그럼 52만 줄짜리 Claude Code는 뭐냐?

**전부 이 루프 위에 쌓인 살이다.** 진짜로.

| 살 | 무슨 역할 |
|---|---|
| UI를 예쁘게 그리기 | 터미널에 박스, 색깔, 애니메이션 (Ink/React) |
| 도구를 안전하게 실행 | 파일을 정말 덮어써도 되나? 권한 묻기 |
| 도구를 많이 만들기 | Read, Write, Edit, Bash, Glob, Grep, WebFetch, ... 약 40개 |
| 멀티 에이전트 | 도구 안에서 또 다른 Claude를 호출 (AgentTool) |
| IDE 통합 | VS Code, JetBrains 확장과 통신 |
| MCP 서버 연결 | 외부에서 정의한 도구를 동적으로 가져옴 |
| 메모리·세션·권한 | CLAUDE.md, 권한 모드, 세션 저장 등 |
| 컨텍스트 압축 | 대화가 길어지면 자동으로 요약 |

이 살들이 다 흥미롭고, 책의 나머지가 이걸 하나씩 푼다. 하지만 **본질은 위의 단순한 루프 한 장**이다. 이걸 잊으면 안 된다. 챕터를 읽다가 머리가 어지러워지면 이 그림으로 돌아오면 된다.

## Python으로 옮기면

위 루프를 Python 의사코드로 옮기면 이렇게 생겼다. (진짜 동작하는 코드는 Part 9에서 만들 거다. 지금은 골격만 보자.)

```python
from anthropic import Anthropic

client = Anthropic()

TOOLS = [
    {
        "name": "Read",
        "description": "Read a file from disk",
        "input_schema": {
            "type": "object",
            "properties": {"file_path": {"type": "string"}},
            "required": ["file_path"],
        },
    },
    # Write, Bash, Edit, ... 도구가 더 들어간다
]

def execute_tool(name: str, args: dict) -> str:
    if name == "Read":
        return open(args["file_path"]).read()
    # Write, Bash, Edit, ...
    raise ValueError(f"Unknown tool: {name}")

def claude_code(user_input: str) -> None:
    messages = [{"role": "user", "content": user_input}]

    while True:
        response = client.messages.create(
            model="claude-opus-4-6",
            messages=messages,
            tools=TOOLS,
            max_tokens=4096,
        )

        # A: Claude가 텍스트로 답하고 끝낸 경우
        if response.stop_reason == "end_turn":
            for block in response.content:
                if block.type == "text":
                    print(block.text)
            return

        # B: Claude가 도구를 호출한 경우
        if response.stop_reason == "tool_use":
            # Claude의 응답(도구 호출 포함)을 메시지에 추가
            messages.append({"role": "assistant", "content": response.content})

            # 도구를 진짜로 실행
            tool_results = []
            for block in response.content:
                if block.type == "tool_use":
                    result = execute_tool(block.name, block.input)
                    tool_results.append({
                        "type": "tool_result",
                        "tool_use_id": block.id,
                        "content": result,
                    })

            # 도구 결과를 user 메시지로 추가
            messages.append({"role": "user", "content": tool_results})
            # 다시 while 위로 → Claude가 결과 보고 다음 결정
```

50줄 안 된다. 그리고 진짜 동작한다 (Anthropic API 키만 있으면).

이게 Claude Code의 **본질의 가장 작은 형태**다. Part 9에서 여기에 권한 체크, 스트리밍, Pydantic 스키마, 서브 에이전트를 붙여서 진짜 미니 Claude Code로 키울 거다. 하지만 **골격은 위 50줄에서 한 줄도 변하지 않는다.** 새로 추가되는 건 모두 "살".

> 💡 **팁:** 이 코드를 직접 돌려보고 싶으면 `pip install anthropic`만 하면 된다. `ANTHROPIC_API_KEY` 환경변수 설정하고 `claude_code("hello")`를 호출. Claude는 도구를 안 부르고 그냥 인사하고 끝낸다. `claude_code("/tmp/test.txt 읽어줘")` 같은 걸 시켜보면 도구 호출 분기가 발동한다.

## 잠깐, 너무 단순한 거 아닌가?

여기서 합리적인 의심이 들 수 있다.

> "고작 50줄짜리 루프가 본질이라고? 그럼 52만 줄은 다 뭐야? 그게 다 부수적이라고?"

진짜로 그렇다. 그리고 그 "부수적인 것들"이 매우 중요하다는 게 함정이다. 예를 들면:

- 위 코드는 `Bash` 도구를 그냥 `subprocess.run(args["command"], shell=True)`로 실행하면 된다. 근데 그러면 Claude가 "`rm -rf /` 좀 실행해줘"라고 했을 때 그대로 실행된다. 진짜 Claude Code는 권한 체크에 4단계, BashTool에만 보안 검사 23개를 박아뒀다.
- 위 코드는 응답을 다 받고 한 번에 출력한다. 근데 진짜 Claude Code는 글자 단위로 스트리밍한다. 사용자가 "아 이거 응답이 이상해, 멈춰야겠다"라고 판단할 수 있게.
- 위 코드는 한 번에 하나의 도구만 처리할 수 있다고 가정하지 않지만, 동시에 여러 도구 호출(parallel tool use)이 들어왔을 때 어떤 순서로 실행해야 할지 결정해야 한다 — 읽기는 동시에, 쓰기는 순차적으로.
- 위 코드는 메시지가 무한정 쌓인다. 토큰 한도에 부딪히면 그냥 에러. 진짜 Claude Code는 자동으로 요약해서 압축한다.

이런 디테일들이 52만 줄을 만든다. 본질이 바뀌지 않을 뿐이다. 책의 나머지에서 이 디테일들을 하나씩 풀어볼 거다.

## 핵심 정리

- **Claude Code는 본질적으로 "도구를 쓸 줄 아는 챗봇"이다.** 한 문장으로 정리되는 단순한 시스템이다.
- 메커니즘은 **에이전트 루프** 한 장: 사용자 입력 → Claude 호출 → (텍스트 or 도구 호출) → 도구 호출이면 실행 후 결과를 메시지에 누적 → 다시 Claude 호출 → 반복.
- **결정권은 Claude한테 있다.** 시스템은 도구를 실행하고 결과를 돌려주는 집사 역할만 한다.
- **52만 줄 코드는 이 단순한 루프 위에 쌓인 살이다.** UI, 권한, 도구 종류, 멀티 에이전트, IDE 통합, MCP — 본질은 변하지 않는다.
- Python 50줄로 같은 루프의 골격을 만들 수 있다. **Part 9에서 본격적으로 키워볼 거다.**
