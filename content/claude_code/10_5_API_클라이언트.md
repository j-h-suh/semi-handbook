# 10.5 API 클라이언트 — 두 family, 한 인터페이스

## 이 챕터에서 배우는 것

- **6 가지 용어** (Anthropic / Claude / Vertex / vLLM / OpenAI / Gemini API) 가 _3 레이어 (공급자 / 인터페이스 / SDK)_ 혼재된 자리를 _한 장_ 으로 정리
- *Anthropic API 키 없이도* mini_claude 가 돌아가는 길 — GCP Vertex 의 Claude + 로컬 vLLM
- 07_1 의 _4 SDK 추상화_ 가 mini 에서 _Vertex + vLLM 두 백엔드_ 로 압축되는 자리
- **구조적 타이핑** 으로 _Anthropic 가족_ (Vertex 포함) 을 _코드 한 줄 안 바꾸고_ 다 지원하는 패턴
- vLLM (OpenAI 호환) 을 _Anthropic SDK 의 인터페이스로 흉내_ 내는 어댑터의 디자인
- Anthropic ↔ OpenAI 의 _tool use 변환_ 의 비대칭 — 스키마, tool_calls 누적, finish_reason 매핑

## §0 LLM API 가족 — 한 장 정리

mini 가 _두 family_ 를 다루는 본격 본문 전에, _학습자가 자주 헷갈리는_ 6 가지 용어 — **Anthropic API / Claude API / Vertex API / vLLM API / OpenAI API / Gemini API** — 를 _한 장_ 으로 정리한다. mini 의 결정과 _향후 확장 자리_ 까지.

### 헷갈리는 이유 — _3 레이어_ 가 한 단어에 섞임

| 용어 | 정체 | 레이어 |
|---|---|---|
| **Anthropic API** | Anthropic 회사의 _직접 HTTPS 서비스_ (api.anthropic.com) + _그 서비스의 인터페이스 모양_ | 서비스 + 인터페이스 |
| **Claude API** | _Anthropic API_ 의 다른 이름 (Claude 모델을 부르는 API 의 일반 호칭) | 같음 (모호하게 쓰임) |
| **Vertex API** | _Google Cloud Platform_ 의 AI 서비스 (Vertex AI). Claude 도 _Model Garden_ 통해 제공 | 서비스 (공급자 = GCP) |
| **vLLM API** | _vLLM_ — 오픈소스 _LLM 서빙 엔진_. 자체 호스팅 + _OpenAI 호환 엔드포인트_ 노출 | 서빙 엔진 (인프라) |
| **OpenAI API** | OpenAI 회사의 _직접 서비스_ + _업계 표준 인터페이스_ 가 됨 (다른 회사들이 흉내) | 서비스 + 인터페이스 |
| **Gemini API** | Google 의 Gemini 모델 API. _AI Studio_ (개인) 와 _Vertex Gemini_ (엔터프라이즈) 두 진입점 | 서비스 (공급자 = Google) |

같은 _"API"_ 단어가 _서비스_ 를 가리키기도 하고 _인터페이스 모양_ 을 가리키기도 한다. 이 두 레이어를 분리해 보면 매트릭스가 정리된다.

### 인터페이스 가족은 _3 개_

| 차이 | **Anthropic 가족** | **OpenAI 가족** | **Google/Gemini 가족** |
|---|---|---|---|
| endpoint | `/v1/messages` | `/v1/chat/completions` | `/v1beta/models/{m}:generateContent` |
| system 처리 | 별도 필드 (`system=`) | `messages` 안 `role=system` | `system_instruction` 별도 필드 |
| 메시지 배열 이름 | `messages[]` | `messages[]` | `contents[]` |
| role 값 | `user` / `assistant` | `user` / `assistant` / `system` / `tool` | `user` / `model` |
| content 모양 | 블록 리스트 | 주로 문자열 | `parts[]` (text / functionCall / inlineData 등) |
| 도구 호출 | `tool_use` 블록 | `tool_calls[]` 배열 (별도 필드) | `functionCall` part |
| 도구 응답 | `tool_result` 블록 (user 메시지 안) | `role=tool` _별도 메시지_ | `functionResponse` part |

_같은 차원_ 을 _행 단위_ 로 보면 _세 가족이 어디서 갈리는지_ 가 빠르게 드러난다. Anthropic 과 Google 은 _system 별도 필드_ 라는 공통점이 있고, Anthropic 과 OpenAI 는 _messages 라는 이름_ 을 공유, Google 만 _parts/contents_ 어휘.

### 공급자 × 인터페이스 매트릭스

| 공급자/호스팅 | 모델 | 인터페이스 모양 | Python SDK | mini |
|---|---|---|---|---|
| Anthropic 직접 (회사 서비스) | Claude | Anthropic | `AsyncAnthropic` | _안전망_ ✓ |
| **GCP Vertex AI (Claude 코너)** | **Claude** | **Anthropic** | `AsyncAnthropicVertex` | **기본 ✓** |
| AWS Bedrock | Claude | Anthropic | `AsyncAnthropicBedrock` | OUT |
| Azure Foundry | Claude | Anthropic | `AsyncAnthropicFoundry` | OUT |
| **GCP Vertex AI (Gemini 코너)** | **Gemini** | **Google** | `google-genai` | OUT |
| Google AI Studio | Gemini | Google | `google-genai` | OUT |
| OpenAI 직접 | GPT | OpenAI | `AsyncOpenAI` | OUT |
| **vLLM (자체 호스팅)** | **Llama / Qwen 등** | **OpenAI (호환)** | `AsyncOpenAI(base_url=...)` | **어댑터 ✓** |

**핵심 관찰**:
- _Claude 모델_ 은 _어디서 호스팅되든_ (Anthropic 직접 / Vertex / Bedrock / Foundry) **모두 Anthropic 인터페이스 모양** — 같은 코드로 호출 가능 (구조적 타이핑)
- _다른 모델_ 들 (Llama, GPT 등) 은 **OpenAI 인터페이스 모양** — mini 는 _어댑터_ 로 _OpenAI 모양 → Anthropic 모양_ 변환
- _Gemini_ 는 **세 번째 가족 (Google 모양)** — mini OUT, _vLLM 어댑터 패턴_ 따라 확장 가능

### ⚠️ 혼동 자리 — Vertex 안에 _두 모양 공존_

_GCP Vertex AI_ 는 _한 서비스_ 인데 그 안에 _두 코너_ 가 _서로 다른 인터페이스 가족_ 으로 공존한다.

| 비교 | **Claude 코너** | **Gemini 코너** |
|---|---|---|
| 진입점 | Model Garden 에서 Claude 모델 enable (opt-in) | 네이티브 (Vertex AI 의 기본 모델 — opt-in 불필요) |
| 인터페이스 가족 | **Anthropic** | **Google** |
| Python SDK | `AsyncAnthropicVertex` (`anthropic[vertex]` extra) | `google-genai` |
| publisher 경로 | `.../publishers/anthropic/models/...` | `.../publishers/google/models/...` |

같은 _GCP project_, 같은 _Service Account JSON_ 으로 두 코너 모두 호출 가능 — 다만 _SDK 와 인터페이스 모양이 완전히 다름_. mini 는 _Claude 코너_ 만 쓴다.

### 비유 — 카페 메뉴판

> 같은 _커피 (Claude 모델)_ 를 _직영점 (Anthropic 직접)_, _스타벅스 매장 (GCP Vertex)_, _제휴 카페 (Bedrock / Foundry)_ 에서 살 수 있다. _메뉴판 모양 (Anthropic 인터페이스)_ 은 같음 — 직원이 익숙한 표현으로 주문 받음.
>
> _완전 다른 커피 (Llama / Qwen 등)_ 는 _다른 메뉴판 모양 (OpenAI 인터페이스)_. _어댑터 (통역사)_ 가 _같은 메뉴판처럼 보이게_ 변환해서 직원한테 전달.
>
> _스타벅스 매장 (Vertex)_ 안에서 _Claude 코너_ 가면 _Anthropic 메뉴판_, _Gemini 코너_ 가면 _Google 메뉴판_ — _건물은 하나, 메뉴판은 다름_.

### mini 의 결정 — 두 family 만, Gemini 는 향후 확장

mini 는 _Anthropic 가족_ (Claude 호스팅 4 자리) + _OpenAI 가족_ (vLLM 어댑터 한 자리) 두 family. _Google 가족_ (Gemini) 은 _세 번째 어댑터_ 가 필요한 자리.

> ⚙️ **Gemini 추가 — 향후 확장 자리**: vLLM 어댑터 (`clients/vllm_adapter.py`) 패턴을 그대로 따라 _Google 모양 → Anthropic 모양_ 변환 어댑터 한 파일이면 추가 가능. 가장 까다로운 자리 — `assistant ↔ model` role 매핑, `tool_use 블록 ↔ functionCall part` 매핑, `content 블록 리스트 ↔ parts 배열` 매핑. system 처리는 _운 좋게_ 둘 다 _별도 필드_ 라 쉬움.

이렇게 _3 레이어 + 3 가족 + 매트릭스_ 가 정리되면 — 아래 §07_1 회수부터의 본문이 _"4 SDK 추상화 vs mini 두 백엔드"_ 라는 _공급자_ 차원 + _구조적 타이핑 vs 어댑터_ 라는 _인터페이스_ 차원 _둘 다_ 명확히 분리되어 보인다.

## 07_1 회수 + mini 의 실제 상황

Part 7.1 은 _진짜 Claude Code_ 가 *4 개 백엔드* (Anthropic 직접 / AWS Bedrock / GCP Vertex / Azure Foundry) 를 _환경변수 한 글자_ 로 분기하는 패턴을 다뤘다. 핵심 셋:

1. **구조적 타이핑** — 4 SDK 가 모두 `client.messages.create(...)` 같은 형태. `implements` 선언 없음.
2. **Lazy import** — 안 쓰는 SDK 는 _디스크에 안 닿음_. `if ENV: from anthropic_bedrock import ...`.
3. **호출자 무지** — 위 게이트 안에서 어떤 클라이언트가 만들어지든, 호출자는 _같은 코드_.

mini 의 상황은 _다르다_:

- **Anthropic 직접 API 키 없음** — 기본 진입점이 _안 됨_
- **GCP Vertex 여유 있음** — Vertex 의 _Anthropic Claude_ 로 가능
- **vLLM 으로 서빙 계획** — 로컬에서 OpenAI 호환 엔드포인트

그래서 10.5 의 회수는 _07_1 패턴 그대로_ 가 아니라 _필요한 자리만_:

| 07_1 의 백엔드 | 10.5 IN/OUT | 이유 |
|---|---|---|
| Anthropic 직접 | _안전망 IN_ | 사용자가 키 생기면 쓸 수 있도록 |
| AWS Bedrock | **OUT** | 사용자 AWS 계정 없음 — _향후 자리_ |
| GCP Vertex | **IN — 기본** | 사용자의 실제 사용 자리 |
| Azure Foundry | **OUT** | 사용자 Azure 없음 — _향후 자리_ |
| vLLM (신규) | **IN** | OpenAI 호환 — 07_1 에 없는 자리. _별도 family_ 라 어댑터 필요 |

`MINI_LLM_PROVIDER` 환경변수가 _07_1 의 `CLAUDE_CODE_USE_*` 세 개_ 를 _한 변수의 값_ 으로 합친다. 미설정 시 _Vertex 기본_ — 사용자 환경 고려.

> 💡 **왜 mini 의 기본을 Vertex 로?** 07_1 (진짜 Claude Code) 의 기본은 _Anthropic 직접_. _Anthropic 이 그걸 만든 회사_ 라서 자연스러운 디폴트. mini 의 디폴트는 _사용자 환경_ 에 맞춰 — Anthropic API 키 없는 자리에서는 _Vertex 가 첫 진입점_ 이 되는 게 친절하다.

## 두 family 의 차이 — 구조적 타이핑 vs 어댑터

mini 가 지원하는 _3 가지 백엔드_ 가 두 family 로 갈린다.

### family A: Anthropic SDK 가족 (3)

- `AsyncAnthropic` (직접)
- `AsyncAnthropicVertex` (Vertex)
- `AsyncAnthropic` (Bedrock — `anthropic` 패키지에 `AsyncAnthropicBedrock` 도 포함되어 있지만 mini OUT)

이 셋은 _같은 `messages.stream(model, max_tokens, system, messages, tools)` 시그니처_. 응답 객체도 같은 형태. **구조적 타이핑** 으로 _코드 한 줄 안 바뀌고_ 호환:

```python
client = make_client()  # 어느 가족이든
async with client.messages.stream(...) as stream:  # 같은 호출
    async for event in stream:
        # event.type == "content_block_delta"
        # event.delta.type == "text_delta"
        # event.delta.text
        ...
    response = await stream.get_final_message()
    # response.content (블록 리스트), response.stop_reason
```

### family B: OpenAI 호환 (vLLM)

- `openai.AsyncOpenAI(base_url="http://...")` — vLLM 의 `/v1/chat/completions`

시그니처가 _완전 다름_:

```python
response_stream = await openai_client.chat.completions.create(
    model=model,
    messages=[{"role": "system", ...}, {"role": "user", ...}, ...],
    stream=True,
    max_tokens=4096,
    tools=[{"type": "function", "function": {...}}],
)
async for chunk in response_stream:
    chunk.choices[0].delta.content  # text 조각
    chunk.choices[0].delta.tool_calls  # 도구 호출 조각 (누적해야 함)
    chunk.choices[0].finish_reason  # "stop" / "tool_calls" / ...
```

### 답 — _어댑터_

mini 의 디자인: family B 를 _family A 의 인터페이스 위로 흉내_. `VLLMClient` 가 `client.messages.stream(...)` 메서드를 갖고, 안에서 OpenAI 의 `chat.completions.create(stream=True)` 를 부른다. 이벤트도 _family A 의 형태_ 로 변환.

```
┌─────────────────────────────────────────┐
│  agent.py (구조적 타이핑 — 호출자 무지)     │
│                                          │
│  client.messages.stream(...)             │
└──────────┬─────────────────────┬─────────┘
           │                     │
           ▼                     ▼
   AsyncAnthropic*         VLLMClient (어댑터)
   (가족 — SDK 그대로)            │
                                 ▼
                          openai.AsyncOpenAI
                          (OpenAI 호환)
                                 │
                                 ▼
                          vLLM 서버 /v1/chat/completions
```

> ⚙️ **왜 Anthropic 의 인터페이스를 _기준_ 으로?**: mini 의 _기존 코드_ (9.2~9.5) 가 모두 _Anthropic 인터페이스_ 로 작성되어 있다. 어떤 family 를 _기준_ 으로 정해도 _다른 family 의 어댑터_ 가 필요. _기존 코드를 안 바꾸는 방향_ 이 mini 의 선택.

## 구현 — 2 단계

신규 모듈 ~260 줄.

```
mini_claude/clients/
├── __init__.py       — make_client() + get_default_model() (~120줄)
└── vllm_adapter.py   — VLLMClient + 변환 함수 (~280줄)
```

### ① `clients/__init__.py` — 팩토리

핵심은 `make_client()`. 07_1 의 `getAnthropicClient()` 와 같은 정신.

```python
def make_client() -> Any:
    provider = os.environ.get("MINI_LLM_PROVIDER", "vertex").lower().strip()

    if provider == "vertex":
        from anthropic import AsyncAnthropicVertex  # ⭐ lazy
        project_id = (
            os.environ.get("VERTEX_PROJECT_ID")
            or os.environ.get("GCLOUD_PROJECT")
            or os.environ.get("GOOGLE_CLOUD_PROJECT")
        )
        if not project_id:
            raise RuntimeError("Vertex 사용 시 VERTEX_PROJECT_ID 환경변수 필수.")
        region = (
            os.environ.get("VERTEX_LOCATION")
            or os.environ.get("CLOUD_ML_REGION")   # Anthropic SDK 표준 fallback
            or "global"                            # Vertex 가 다중 region 자동 라우팅
        )
        return AsyncAnthropicVertex(project_id=project_id, region=region)

    if provider == "vllm":
        from .vllm_adapter import VLLMClient  # ⭐ lazy
        return VLLMClient(
            base_url=os.environ.get("VLLM_BASE_URL", "http://localhost:8000/v1"),
            api_key=os.environ.get("VLLM_API_KEY", "dummy"),
        )

    if provider == "anthropic":
        from anthropic import AsyncAnthropic  # ⭐ lazy
        return AsyncAnthropic()

    raise ValueError(f"Unknown MINI_LLM_PROVIDER: {provider!r}")
```

> ⚙️ **3 단 fallback 의 의도**: `GCLOUD_PROJECT` / `GOOGLE_CLOUD_PROJECT` / `CLOUD_ML_REGION` 은 _옛 환경변수_ 가 아니라 _다양한 GCP 도구 (gcloud CLI, Cloud Run, Cloud Functions 등) 가 각자 다른 이름을 쓰는 현실_ 을 흡수하는 _Anthropic SDK 표준 fallback chain_. mini 의 _기본_ 은 항상 `VERTEX_PROJECT_ID` / `VERTEX_LOCATION`, fallback 은 _사용자 환경이 이미 어느 이름을 쓰고 있던_ 그대로 받아주는 _친절_.

`get_default_model()` 도 provider 별로 분기. 환경변수 `MINI_LLM_MODEL` 이 우선:

```python
def get_default_model() -> str:
    if env := os.environ.get("MINI_LLM_MODEL"):
        return env
    provider = os.environ.get("MINI_LLM_PROVIDER", "vertex").lower().strip()
    if provider == "vertex":
        return "claude-opus-4-1@20250805"
    if provider == "anthropic":
        return "claude-opus-4-6"
    if provider == "vllm":
        raise RuntimeError("vLLM 사용 시 MINI_LLM_MODEL 환경변수 필수.")
```

> 💡 **Lazy import 의 의미**: `from anthropic import AsyncAnthropicVertex` 가 _함수 안_ 에 있다. provider 가 vertex 가 아니면 _절대 import 안 됨_. 진짜 07_1 은 _Bedrock SDK 가 수십 MB_ 라 lazy 가 시작 시간을 _초 단위_ 로 좌우. mini 는 _Bedrock 안 받으므로_ 의미 작지만 _패턴은 유지_.

> ⚠️ **Vertex 호출에 필요한 의존성 — `anthropic[vertex]`**: `from anthropic import AsyncAnthropicVertex` 는 import 자체는 _기본 anthropic 패키지_ 로 가능하지만, _실제 호출 시점_ 에 `google.auth` 를 동적으로 로드한다. 이게 _없으면_ `RuntimeError: Could not import google.auth, you need to install the SDK with pip install anthropic[vertex]` — mini 는 이걸 막기 위해 `pyproject.toml` 에 `anthropic[vertex]` extra 로 명시. _학습자가 GCP 환경에서 진짜 호출_ 하려면 추가 설정이 필요 — [mini_claude/SETUP.md](/claude/setup) 참조 (project + billing + Vertex AI API enable + Model Garden 의 Claude opt-in + Service Account JSON + IAM 역할).

### ② `clients/vllm_adapter.py` — Anthropic 인터페이스 흉내

세 클래스 + 세 변환 함수:

```python
        return self

    def __aiter__(self):
        return self._iterate()

    async def _iterate(self):
        # 누적 + 이벤트 yield (text only)
        ...

    async def get_final_message(self) -> VLLMResponse:
```

### ① `agent.py` — client 와 model 인자

```python
from .clients import make_client, get_default_model

    ...,

    model: str | None = None,
```

## tool_use 변환의 디테일

vLLM 어댑터의 _가장 까다로운 자리_. Anthropic 과 OpenAI 의 tool 형식이 _비대칭_.

### 스키마 변환

Anthropic:
```python
{"name": "Read", "description": "...", "input_schema": {"type": "object", ...}}
```

OpenAI:
```python
{"type": "function", "function": {"name": "Read", "description": "...", "parameters": {...}}}
```

변환 함수:
```python
def _convert_tools(tools):
    if not tools:
        return None
    return [
        {
            "type": "function",
            "function": {
                "name": t["name"],
                "description": t.get("description", ""),
                "parameters": t.get("input_schema", {}),
            },
        }
        for t in tools
    ]
```

### 메시지 변환

Anthropic 의 `content` 가 _문자열_ 일 수도, _블록 리스트_ 일 수도. 블록은 4 가지: text / tool_use / tool_result / (image). OpenAI 의 메시지 구조는 _완전 다름_ — `role=tool` 이 별도 메시지로 분리.

핵심 매핑:
- Anthropic `system=` 인자 → OpenAI `{"role": "system", "content": ...}` 첫 메시지
- Anthropic assistant 의 `tool_use` 블록 → OpenAI assistant 의 `tool_calls` 배열
- Anthropic user 의 `tool_result` 블록 → OpenAI `{"role": "tool", "tool_call_id": ..., "content": ...}` 별도 메시지

가장 미묘한 자리는 **assistant 의 텍스트 + tool_use 가 같이 있을 때**:

```python
# Anthropic
{
    "role": "assistant",
    "content": [
        {"type": "text", "text": "지금 ls 실행할게."},
        {"type": "tool_use", "id": "tu_1", "name": "Bash", "input": {"command": "ls"}},
    ],
}

# OpenAI 로 변환
{
    "role": "assistant",
    "content": "지금 ls 실행할게.",
    "tool_calls": [
        {
            "id": "tu_1",
            "type": "function",
            "function": {"name": "Bash", "arguments": '{"command": "ls"}'},
        }
    ],
}
```

`arguments` 가 _JSON 문자열_ 이라는 점이 핵심 — Anthropic 의 `input` 은 _dict_ 인데 OpenAI 는 _str_. `json.dumps()` 로 직렬화.

### tool_calls 응답 누적

OpenAI 의 stream 에서 `tool_calls` 가 _조각으로_ 온다 — `function.arguments` 가 한 청크에 `'{"path"'`, 다음 청크에 `': "/etc"}'` 식으로. `index` 기준으로 누적해야 함:

```python
class _ToolCallAcc:
    id: str = ""
    name: str = ""
    arguments: str = ""

# 청크 처리
if delta.tool_calls:
    for tc in delta.tool_calls:
        idx = tc.index
        if idx not in tool_calls:
            tool_calls[idx] = _ToolCallAcc()
        acc = tool_calls[idx]
        if tc.id: acc.id = tc.id
        if tc.function:
            if tc.function.name: acc.name = tc.function.name
            if tc.function.arguments: acc.arguments += tc.function.arguments

# 끝나면 누적된 arguments JSON parse
for idx in sorted(tool_calls.keys()):
    acc = tool_calls[idx]
    tool_input = json.loads(acc.arguments) if acc.arguments else {}
    content_blocks.append(ToolUseBlock(id=acc.id, name=acc.name, input=tool_input))
```

### finish_reason 매핑

OpenAI 와 Anthropic 의 _턴 종료 사유_ 어휘가 다름:

| OpenAI | Anthropic |
|---|---|
| `stop` | `end_turn` |
| `tool_calls` | `tool_use` |
| `length` | `max_tokens` |
| `content_filter` | `stop_sequence` |

`_map_finish_reason()` 한 함수가 한 줄로 매핑.

## 핵심 정리

- **mini 의 _기본_ 은 Vertex** — 사용자가 Anthropic 직접 API 키가 없는 상황. `MINI_LLM_PROVIDER` 환경변수 미설정 시 _Vertex_ 가 진입점. 07_1 의 _Anthropic 기본_ 디자인을 _사용자 환경에 맞춰 뒤집은_ 자리.
- **두 family — 구조적 타이핑 + 어댑터** — Anthropic SDK 가족 (Vertex 포함) 은 _시그니처 동일_ 이라 _코드 한 줄 안 바뀌고_ 호환. vLLM (OpenAI 호환) 은 _별도 어댑터_ 로 Anthropic 인터페이스를 _흉내_. `agent.py` 는 _어느 family 인지 모름_.
- **Lazy import 의 _의미_** — 안 쓰는 SDK 는 _디스크에 안 닿음_. mini 는 _Bedrock/Foundry 안 받으므로_ 의미 작지만 _패턴은 유지_ — 향후 백엔드 추가의 자리.
- **tool_use 변환은 _가장 까다로운 자리_** — 스키마 비대칭 (`input_schema` ↔ `parameters`), `tool_calls.arguments` 의 _조각 누적_ + _JSON 직렬화_, finish_reason 어휘 매핑. mini 는 _최소한의 변환만_ — 이미지 입력 등은 OUT.
- **mini 가 _뺀_ 자리는 _향후 확장 자리_** — Bedrock / Foundry 가 추가될 자리, 모델별 region 매핑, 이미지 변환. 모두 _07_1 패턴_ 또는 _vLLM 어댑터 확장_ 으로 자연스럽게 들어옴.
- **AI 엔지니어에게 이것이 중요한 이유** — 멀티 백엔드 추상화는 _도구가 자라기 위한 토대_. 같은 도구를 _다른 환경_ (회사 GCP, 개인 vLLM, 향후 Bedrock) 에서 _같은 코드_ 로 돌릴 수 있다는 사실이 _코드의 수명_ 을 결정한다. mini 의 ~260 줄 추상화가 _세 백엔드 + 향후 확장_ 자리를 _하나의 디자인_ 으로 묶는다는 것 — 이게 _실무 코드의 기본 자세_.
