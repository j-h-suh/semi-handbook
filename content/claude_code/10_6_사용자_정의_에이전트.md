# 10.6 사용자 정의 에이전트 — `.claude/agents/*.md` 한 파일이 새 에이전트가 된다

---

## 이 챕터에서 배우는 것

- 9.5 의 AgentTool 은 *built-in 에이전트* 만 spawn 한다 — 사용자가 새 에이전트를 만들려면 *코드를 짜야* 했다.
- `.claude/agents/<name>/AGENT.md` 한 파일이 *새 에이전트* 가 되는 메커니즘.
- 8.1 의 *느슨한 타이핑 (`z.string()`)*, *시스템 프롬프트 교체*, *도구 화이트리스트* 가 mini 에 어떻게 회수되는지.
- 10.1 (슬래시 명령) / 10.2 (스킬) 의 *마크다운 로더 패턴* 이 세 번째로 반복된다 — 같은 정신, 다른 자리.
- 진짜 Claude Code 의 *5 개 built-in 에이전트* 와 *사용자 정의 에이전트* 가 동일한 구조를 공유한다는 사실.

---

## 9.5 에서 빠진 것

9.5 의 `AgentTool` 은 *한 종류의 자식* 만 spawn 한다. `prompt` 한 줄을 받고, *고정된* 시스템 프롬프트 (`SUB_AGENT_SYSTEM`) 와 *고정된* 도구 필터 (read-only + 자기 제외) 로 자식을 돌린다.

```python
# 9.5 의 AgentToolInput
class AgentToolInput(BaseModel):
    prompt: str = Field(...)   # 이게 다였다
```

`subagent_type` 같은 분기 키가 *없으니까* 자식은 항상 같은 모양. *코드 분석* 도, *문서 요약* 도, *PR 리뷰* 도 같은 시스템 프롬프트로 받는다. 모델이 자식한테 *역할 가이드* 를 주려면 매번 prompt 안에서 "당신은 PR 리뷰 전문가입니다..." 같은 텍스트를 *수동으로* 박아야 한다.

8.1 에서 *진짜 코드* 는 다섯 가지 에이전트 (Explore, Plan, general-purpose, security-scanner, code-reviewer) 를 *built-in* 으로 제공하고, 사용자가 `.claude/agents/<name>/AGENT.md` 로 *새 에이전트* 를 추가할 수 있다고 짧게 짚었다. 그 자리가 *비어 있었다* 는 게 9.5 의 한계.

> 💡 **빠진 자리의 의미**: 자식 에이전트의 *역할* 을 *데이터로 정의* 할 수 있어야 한다. 코드를 안 짜고 마크다운 한 파일로. 그게 *사용자 정의 에이전트* 의 본질.

이 챕터에서 채울 것:

- **`subagent_type` 입력 필드** — 모델이 "어떤 에이전트로 돌리겠다" 를 명시
- **`.claude/agents/` 디렉토리 walking** — 10.1·10.2 와 같은 방식
- **AGENT.md frontmatter** — 시스템 프롬프트·도구 화이트리스트·발동 트리거를 *데이터로*
- **AgentTool 의 분기 로직** — `subagent_type` 에 따라 spec 조회 → 자식의 시스템 프롬프트·도구 풀 결정

## 완성된 모습 먼저 보기

두 디렉토리 + 한 파일.

```text
mini_claude_workspace/
└── .claude/
    └── agents/
        └── analyzer/
            └── AGENT.md
```

`AGENT.md`:

```markdown
---
name: analyzer
description: 코드 분석 전용 에이전트. 함수 호출 그래프, 의존성, 잠재 버그를 찾는다.
when_to_use: 사용자가 "이 코드 분석해줘" / "함수 어디서 호출되는지" / "버그 찾아줘" 같은 표현
allowed-tools: Read, Bash(grep:*), Bash(find:*)
---

You are a focused code analyzer. Your one job:

1. Read the requested files.
2. Use grep / find to trace symbol usage.
3. Return a CONCISE summary — file paths + line numbers + brief explanation.

Do NOT explain general programming concepts. Do NOT modify files.
Only output factual observations about the codebase.
```

미니 클로드를 실행하면:

```text
$ uv run mini-claude
[agents] 사용자 정의 에이전트 1 개 로드: analyzer
mini-claude 시작 (Ctrl+D로 종료)
> query 함수가 어디서 호출되는지 분석해줘

[Agent] {'subagent_type': 'analyzer', 'prompt': 'query 함수가 어디서 호출되는지 찾아줘'}
...
query 함수는 두 곳에서 호출됩니다 (정의는 src/mini_claude/agent.py:93):
- src/mini_claude/main.py:154 — REPL 루프가 사용자 입력마다 query() 실행
- src/mini_claude/tools/agent.py:125 — AgentTool 이 서브에이전트로 query() 를 재귀 호출
```

모델이 *자동으로* `subagent_type: "analyzer"` 를 선택했다 — `description` + `when_to_use` 가 *모델에게 노출* 되어서. AGENT.md 의 시스템 프롬프트가 *자식의 LLM 호출에 그대로* 주입됐고, 자식은 `Read`, `Bash(grep:*)`, `Bash(find:*)` 세 도구만 쓸 수 있다.

> ⚙️ **코드 한 줄 안 썼다**: 새 에이전트를 만들 때 *Python 파일을 안 건드린다*. `.claude/agents/<name>/AGENT.md` 한 파일이 *발견 → 메뉴 노출 → 자식 spawn* 의 전 과정을 만든다. 10.1·10.2 의 *마크다운 한 파일이 새 명령/스킬이 된다* 와 같은 정신.

## AGENT.md 의 5 개 필드

frontmatter 의 다섯 필드가 *에이전트 한 명의 정체성* 을 만든다.

| 필드 | 역할 | 진짜 코드 대응 |
|---|---|---|
| `name` | 디렉토리 이름과 다를 때 명시 (옵션, 기본은 디렉토리명) | `subagent_type` 의 값 |
| `description` | 모델이 보는 *한 줄 정체성*. AgentTool 의 description 메뉴에 노출 | 진짜 코드의 `description` 동일 |
| `when_to_use` | *자연어 발동 트리거*. 모델이 어떤 상황에 이 에이전트를 부를지 가이드 | 진짜 코드의 `description` 안에 녹아 있음 (mini 는 분리) |
| `allowed-tools` | 자식이 쓸 수 있는 도구 *화이트리스트*. 비어 있으면 모두 허용 | 8.1 의 `agentConfig.tools` |
| `disallowed-tools` | 명시적 차단 *블랙리스트* — allowed 보다 우선 | 8.1 의 `disallowedTools` |

본문 (`---` 뒤) 은 *시스템 프롬프트* 그대로. 자식의 LLM 호출에 `system=` 으로 들어간다.

> 💡 **`when_to_use` 가 분리된 이유**: 진짜 코드는 `description` 한 필드에 *역할 설명 + 발동 트리거* 가 섞여 있다. mini 는 분리해서 *모델에게 더 명확한 신호* 를 준다. 10.2 의 스킬에서 본 *모델 발견 트리거* 와 같은 정신.

### 1 단계: `spec.py` — AgentSpec dataclass

`AGENT.md` 한 파일이 만들어내는 *데이터* 의 모양.

```python
# src/mini_claude/agents/spec.py
from dataclasses import dataclass, field


@dataclass
class AgentSpec:
    name: str
    description: str
    when_to_use: str = ""
    system_prompt: str = ""
    allowed_tools: list[str] = field(default_factory=list)
    disallowed_tools: list[str] = field(default_factory=list)
```

여섯 필드. 한 줄짜리 *정체성 카드*. AgentTool 이 이걸 보고 자식의 *시스템 프롬프트* · *도구 풀* · *발동 가이드* 를 결정한다.

### 2 단계: `loader.py` — frontmatter 파싱 + 디렉토리 walking

frontmatter 파싱은 *직접 짜지 않는다*. 10.1 (슬래시 명령) 이 이미 만든 `parse_frontmatter` (PyYAML 의 `yaml.safe_load`) 를 *그대로 재사용* 한다 — 10.2 의 스킬 로더가 한 것과 똑같다.

```python
# src/mini_claude/agents/loader.py
from __future__ import annotations
from pathlib import Path

from ..commands.markdown_loader import parse_frontmatter  # 10.1 의 YAML 파서 재사용
from .spec import AgentSpec


def _normalize_list(value: object) -> list[str]:
    """allowed-tools 가 콤마 문자열이든 YAML 리스트든 list[str] 로."""
    if isinstance(value, list):
        return [str(v).strip() for v in value if str(v).strip()]
    if isinstance(value, str) and value:
        return [t.strip() for t in value.split(",") if t.strip()]
    return []
```

직접 두는 건 `_normalize_list` 하나뿐이다 — `allowed-tools` 를 `"Read, Bash(grep:*)"` (콤마 문자열) 로 쓰든 `- Read` (YAML 리스트) 로 쓰든 둘 다 `list[str]` 로 받기 위해서다. 파서 본체는 10.1 것을 빌려 쓰니 *없다*.

> ⚙️ **세 번째 같은 패턴 — 파서를 또 짜지 않는다**: 10.1 (슬래시 명령) · 10.2 (스킬) · 10.6 (에이전트) 는 *마크다운 + frontmatter 로더* 의 세 변주다. 10.2 가 10.1 의 `parse_frontmatter` 를 재사용했듯 10.6 도 재사용한다. `pyyaml` 은 10.1 에서 이미 의존성에 들어와 있으니 *새 비용 0* 이고, `yaml.safe_load` 가 따옴표 · 이스케이프 · 멀티라인까지 처리하므로 직접 파서보다 *견고하다*. commands · skills · agents 가 *한 파서* 로 통일되는 게 핵심.

> ⚠️ **이제 frontmatter 는 진짜 YAML**: 직접 파서는 `key: 아무 텍스트` 를 통째로 문자열로 받았지만, `yaml.safe_load` 는 *YAML 문법* 을 따른다. 대부분의 자유 텍스트 — 위 예시의 `when_to_use: 사용자가 "이 코드 분석해줘" / ...` 도 — plain scalar 로 무사히 통과한다 (값이 따옴표로 *시작* 하지 않으면 중간 따옴표는 리터럴이라서). 다만 값에 `: ` (콜론+공백) 가 들어가거나 값이 `[`, `{`, `&`, `"` 등으로 *시작* 하면 따옴표로 감싸야 한다 (`when_to_use: "기대: 한 줄 요약"`). *YAML 이스케이프를 의식해야 하는 것* 이 이 재사용의 유일한 비용이다.

`load_agent` 와 `discover_agents`:

```python
def load_agent(agent_dir: Path) -> AgentSpec | None:
    md_path = agent_dir / "AGENT.md"
    if not md_path.exists():
        return None

    text = md_path.read_text(encoding="utf-8")
    fm, body = parse_frontmatter(text)

    return AgentSpec(
        name=str(fm.get("name") or agent_dir.name),
        description=str(fm.get("description", "")),
        when_to_use=str(fm.get("when_to_use", "")),
        system_prompt=body.strip(),
        allowed_tools=_normalize_list(fm.get("allowed-tools", [])),
        disallowed_tools=_normalize_list(fm.get("disallowed-tools", [])),
    )


def discover_agents(cwd: Path, home: Path) -> list[AgentSpec]:
    """10.2 의 discover_skills 와 같은 walker — ``.claude/agents/`` 의 서브 디렉토리.

    cwd 에서 부모로 walking 하다 .git 경계에서 멈추고, 마지막에 홈.
    낮은 우선순위(홈)부터 덮어써서 *가장 가까운 프로젝트* 가 이긴다.
    """
    dirs: list[Path] = []

    # ① cwd → 부모로 walking, .git 경계에서 멈춤
    current = cwd.resolve()
    home_resolved = home.resolve()
    while current != current.parent and current != home_resolved:
        agents_dir = current / ".claude" / "agents"
        if agents_dir.is_dir():
            dirs.append(agents_dir)
        if (current / ".git").exists():
            break  # 부모 repo leak 방지
        current = current.parent

    # ② home dir 의 사용자 에이전트
    user_agents = home_resolved / ".claude" / "agents"
    if user_agents.is_dir():
        dirs.append(user_agents)

    # ③ 낮은 우선순위(홈)부터 로드, 같은 이름은 높은 우선순위(프로젝트)가 덮어씀
    seen: dict[str, AgentSpec] = {}
    for d in reversed(dirs):
        for entry in d.iterdir():
            spec = load_agent(entry)
            if spec is None:
                continue
            seen[spec.name] = spec
    return list(seen.values())
```

10.2 의 `discover_skills` 와 *글자 그대로 같은 구조* — cwd 에서 부모로 walking 하다 `.git` 경계에서 멈추고, 마지막에 홈. `reversed` 로 홈부터 깔고 프로젝트가 덮어쓰니 *가장 가까운 프로젝트* 가 이긴다. 모노레포의 상위 `.claude/agents/` 도 함께 잡되, `.git` 경계 덕에 부모 repo 로는 새지 않는다.

마지막으로 패키지 export — `tools/agent.py` 가 `from ..agents import AgentSpec` 로 가져갈 수 있도록:

```python
# src/mini_claude/agents/__init__.py
from .loader import discover_agents, load_agent
from .spec import AgentSpec

__all__ = ["AgentSpec", "discover_agents", "load_agent"]
```

### 3 단계: AgentTool 변경 — `subagent_type` 분기

여기는 *새 파일이 아니다* — 9.5 에서 만든 `src/mini_claude/tools/agent.py` 를 *수정* 한다. 먼저 파일 상단 import 에 한 줄 추가:

```python
# src/mini_claude/tools/agent.py 상단 — 기존 import 들 옆에
from ..agents import AgentSpec   # ← 10.6 에서 추가
```

그다음 9.5 의 `AgentTool` 에 *세 가지* 가 추가된다. (1) `subagent_type` 입력 필드, (2) `user_agents` 보관 필드, (3) `__post_init__` 에서 description 에 메뉴 prepend.

> ⚠️ **블록 첫 줄 태그로 *소속* 을 확인하라**: 아래 코드는 모두 `tools/agent.py` 안이지만 — `_rule_tool_name` 은 *모듈 함수* (클래스 밖, 0 들여쓰기), `_find_spec`·`_filter_tools`·`call` 은 `AgentTool` 의 *메서드* (클래스 안, 4 들여쓰기) 다. 메서드를 실수로 클래스 밖에 두면 `call()` 의 `self._find_spec(...)` 이 `AttributeError` 를 낸다. 각 블록 맨 위 주석이 *어디에 넣을지* 를 알려주니, 들여쓰기를 그대로 따라가면 된다.

```python
# src/mini_claude/tools/agent.py — AgentToolInput 과 AgentTool (클래스 정의)
class AgentToolInput(BaseModel):
    subagent_type: str = Field(
        default="default",
        description=(
            "에이전트 종류. `.claude/agents/<name>/AGENT.md` 에 정의된 이름. "
            "비워두거나 'default' 를 주면 기본 read-only 서브에이전트."
        ),
    )
    prompt: str = Field(description="서브 에이전트에게 시킬 작업 설명.")


@dataclass
class AgentTool:
    name: str = "Agent"
    description: str = (
        # 9.5 의 그 문자열 그대로 — 변화 없음
        "읽기 전용 서브 에이전트를 한 번 돌립니다. 코드 분석, 문서 요약, "
        "검색 같은 read-only 작업에 적합. 결과는 텍스트로 돌아옵니다."
    )
    input_model: type[BaseModel] = AgentToolInput
    parent_tools: list[Tool] = field(default_factory=list)
    permissions: Any = None
    user_agents: list[AgentSpec] = field(default_factory=list)   # ← 추가

    def __post_init__(self) -> None:
        """user_agents 가 있으면 description 에 메뉴 prepend."""
        if not self.user_agents:
            return
        menu = ["", "", "사용 가능한 에이전트 (subagent_type 값으로 지정):"]
        for spec in self.user_agents:
            line = f"- {spec.name}: {spec.description}"
            if spec.when_to_use:
                line += f" (트리거: {spec.when_to_use})"
            menu.append(line)
        self.description = self.description + "\n".join(menu)
```

`__post_init__` 가 *런타임에 description 을 동적으로 합성* 한다. 모델은 `tool_to_anthropic_schema(agent_tool)` 가 만든 description 안에서 *발견* 한 에이전트 목록을 본다.

> 💡 **8.1 의 attachment 패턴의 단순화**: 진짜 코드는 에이전트 메뉴를 *메시지 슬롯의 attachment* 로 분리해서 tool-schema 캐시 hit 을 유지한다 (8.1 의 *느슨한 타이핑* Deep Dive). mini 는 *description 에 그냥 박는다* — schema 가 바뀌어 캐시 hit 이 깨지는 비용을 *그냥 받아들임*. 학습용이라 OK.

`call()` 메서드의 분기:

```python
# src/mini_claude/tools/agent.py — AgentTool 의 *메서드* (클래스 안, 4칸 들여쓰기)
    async def call(self, args: dict[str, Any], context: ToolContext) -> str:
        prompt = args["prompt"]
        subagent_type = args.get("subagent_type", "default")

        # ① user agent spec 조회 (없으면 기본)
        spec = self._find_spec(subagent_type) if subagent_type != "default" else None

        # ② 격리: 새 conversation state (9.5 그대로)
        child_state = ConversationState()

        # ③ 도구 필터링 — user agent 면 allowed/disallowed, 아니면 read-only 기본
        child_tools = self._filter_tools(spec)

        # ④ 시스템 프롬프트 — user agent 면 AGENT.md 본문, 아니면 기본
        system_prompt = spec.system_prompt if spec else SUB_AGENT_SYSTEM

        # ⑤ 재귀 — query() 가 query() 를 부른다 (9.5 그대로)
        query = _query_lazy()
        async for chunk in query(
            user_input=prompt,
            tools=child_tools,
            permissions=self.permissions,
            cwd=context.cwd,
            state=child_state,
            system_prompt=system_prompt,
        ):
            pass

        # ⑥ 결과 회수 — 9.5 의 fallback 그대로: 마지막 assistant 텍스트 블록 합치기
        last_text_blocks: list[str] = []
        for msg in reversed(child_state.messages):
            if msg.get("role") != "assistant":
                continue
            content = msg.get("content", [])
            if not isinstance(content, list):
                continue
            text_blocks = [
                b.get("text", "")
                for b in content
                if isinstance(b, dict) and b.get("type") == "text"
            ]
            if text_blocks:
                last_text_blocks = text_blocks
                break
        if not last_text_blocks:
            return "(서브 에이전트가 텍스트 응답을 생성하지 못했다)"
        return "\n".join(last_text_blocks)
```

9.5 의 다섯 단계 (격리·도구 필터·재귀·청크 드롭·결과 회수) 가 그대로 살아 있고, *세 자리* (도구 필터·시스템 프롬프트·spec 조회) 만 *spec 따라 분기* 됐다. **9.5 의 본질은 한 줄도 안 바뀜**.

`_filter_tools` 가 화이트리스트·블랙리스트 처리. 먼저 한 줄 헬퍼 — allowed/disallowed 항목에서 *도구 이름만* 뽑는다 (`Bash(grep:*)` → `Bash`):

```python
# src/mini_claude/tools/agent.py — *모듈 함수* (클래스 밖, 0 들여쓰기)
def _rule_tool_name(rule: str) -> str:
    """allowed/disallowed 항목에서 도구 이름만 추출. 'Bash(grep:*)' → 'Bash'."""
    return rule.split("(", 1)[0].strip()
```

```python
# src/mini_claude/tools/agent.py — AgentTool 의 *메서드* (클래스 안, 4칸 들여쓰기)
    def _filter_tools(self, spec: AgentSpec | None) -> list[Tool]:
        if spec is None:
            # 기본 — 9.5 의 정책 그대로
            return [
                t for t in self.parent_tools if t.is_read_only() and t.name != self.name
            ]

        # allowed/disallowed 항목은 'Read' 또는 'Bash(grep:*)' 처럼 권한 스코프가
        # 붙을 수 있다. 도구 풀 필터는 *도구 이름* 으로만 판단 — 스코프(grep:*)는
        # 9.4 권한 게이트의 몫. 'Bash(grep:*)' → 'Bash'.
        disallowed = {_rule_tool_name(r) for r in spec.disallowed_tools}
        allowed = (
            {_rule_tool_name(r) for r in spec.allowed_tools}
            if spec.allowed_tools
            else None
        )

        result = []
        for tool in self.parent_tools:
            if tool.name == self.name:
                continue  # 무한 재귀 방지
            if tool.name in disallowed:
                continue  # 명시적 차단
            if allowed is not None and tool.name not in allowed:
                continue  # 화이트리스트
            result.append(tool)
        return result
```

세 단계 필터: 자기 자신 제외 → 블랙리스트 → 화이트리스트. 8.1 의 *진짜 코드와 같은 정책 순서*. 사용자가 `allowed-tools: Read` 라고 쓰면 `Read` 만, `disallowed-tools: Bash` 라고 쓰면 Bash 만 제외하고 나머지 다.

`call()` 이 부르는 `_find_spec` 은 `user_agents` 에서 이름으로 spec 을 찾는 한 줄짜리 헬퍼:

```python
# src/mini_claude/tools/agent.py — AgentTool 의 *메서드* (클래스 안)
    def _find_spec(self, name: str) -> AgentSpec | None:
        """user_agents 에서 이름으로 spec 조회. 없으면 None."""
        return next((s for s in self.user_agents if s.name == name), None)
```

> ⚠️ **9.4 의 권한 게이트는 그대로**: `_filter_tools` 가 *도구 풀에서 빼는* 건 *모델이 안 보게* 만드는 일. 모델이 어찌어찌 그 이름을 알고 호출해도, query() 안의 `find_tool` 이 *없으면 ValueError*. 그 너머에는 9.4 의 권한 게이트가 있고, 그 너머에는 (있다면) 10.3 의 hook 이 있다. *방어선이 여러 겹*.

## 진짜 코드에서는 — runAgent.ts 의 구조

진짜 코드의 사용자 정의 에이전트 로딩은 `loadAgents.ts` (약 *420 줄*) 와 `runAgent.ts` (약 *900 줄*) 에 흩어져 있다. mini 의 *100 + 70 = 170 줄* 과 *5 배 차이*.

### 1. 발견 — `loadAgents.ts`

진짜 코드는 *세 자리* 에서 에이전트를 찾는다.

| 자리 | mini 대응 |
|---|---|
| `~/.claude/agents/` (홈) | ✅ 동일 |
| `./.claude/agents/` (프로젝트) | ✅ 동일 |
| `node_modules/.claude/agents/` (NPM 패키지) | ❌ OUT — mini 는 Python, NPM 개념 무관 |

병합 정책도 같다: *프로젝트 우선*. *NFC 정규화* (한글 디렉토리 이름의 유니코드 정규화) 가 진짜 코드에는 있다 — mini 는 OUT.

### 2. 시스템 프롬프트 합성 — `runAgent.ts:475`

`AGENT.md` 의 본문이 *그대로* 시스템 프롬프트가 되는 게 아니다. 진짜 코드는 *세 가지* 를 합성:

1. `AGENT.md` 본문 (사용자 정의)
2. *공통 가이드* — "You are a focused agent...", "Use TodoWrite to track tasks..." 같은 *Anthropic 의 기본 행동 지침*
3. *환경 정보* — 현재 cwd, 모델 정보, 가용 도구 목록 등

mini 는 *(1) 만* 쓴다. (2) 와 (3) 은 *학습용 단순화* 로 OUT.

### 3. 도구 풀 정책 — `agentConfig.tools`

진짜 코드의 `agentConfig.tools` 는 *세 모양* 을 받는다:

- 명시적 리스트: `tools: ['Read', 'Grep']` (= mini 의 `allowed-tools`)
- `'inherit'`: 부모의 도구 풀 그대로 (= mini 는 OUT, 항상 명시)
- `'inherit-read-only'`: 부모 도구 중 read-only 만 (= mini 의 *기본* `default` 모드)

진짜 코드의 *세 정책* 이 mini 에서는 *두 정책* — *명시적 리스트* 또는 *read-only 기본*. inherit 의 *전체 풀 노출* 은 OUT (안전성 우려).

### 4. 캐시 hit 유지 — *attachment 패턴*

8.1 의 Deep Dive 에서 본 *느슨한 타이핑* + *attachment 분리*. 진짜 코드는:

- `subagent_type: z.string()` (enum 아님) — 새 에이전트가 추가돼도 schema 안 바뀜
- 에이전트 메뉴는 *메시지 슬롯의 attachment* 로 분리 — tool-schema 캐시 hit 유지

mini 는:

- ✅ `subagent_type: str` (enum 아님) — 같은 정책
- ❌ 메뉴는 *description 에 박음* — schema 바뀜, 캐시 hit 깨짐. mini 는 캐시 자체가 OUT 이라 비용 무시 가능.

### 5. 압축 비율 정리

| 진짜 코드 | mini | 비율 |
|---|---|---|
| `loadAgents.ts` 약 420 줄 | `agents/` 100 줄 | **4 : 1** |
| `runAgent.ts` 약 900 줄 | `tools/agent.py` 130 줄 | **7 : 1** |

| inherit/inherit-read-only 정책 | 둘 중 하나만 | — |
| attachment 분리 | description 직접 박음 | — |

**핵심 (subagent_type 분기, 시스템 프롬프트 교체, 도구 화이트리스트) 는 살아 있고**, 엔터프라이즈 기능 (NPM 디스커버리, NFC, attachment, 캐시 hit 유지) 만 빠진다.

## 진짜로 만들어 보기

*mini-claude 레포 안에서* 직접 돌려 보자 — analyzer 가 분석할 코드베이스가 바로 mini-claude 자신이다 (cwd 의 `src/` 를 grep 한다). 아래 명령은 모두 레포 루트에서 실행한다.

### 1. 에이전트 디렉토리 + AGENT.md 생성

```bash
mkdir -p .claude/agents/analyzer

cat > .claude/agents/analyzer/AGENT.md << 'EOF'
---
name: analyzer
description: 코드 분석 전용 에이전트. 함수 호출 그래프, 의존성, 잠재 버그를 찾는다.
when_to_use: 사용자가 "이 코드 분석해줘" / "함수 어디서 호출되는지" 같은 표현
allowed-tools: Read, Bash(grep:*), Bash(find:*)
---

You are a focused code analyzer. Your one job:

1. Read the requested files.
2. Use grep / find to trace symbol usage.
3. Return a CONCISE summary — file paths + line numbers + brief explanation.

Do NOT explain general programming concepts. Do NOT modify files.
Only output factual observations about the codebase.
EOF
```

세 줄짜리 shell — `mkdir` + `cat > heredoc`.

### 2. 미니 클로드 실행

```text
$ uv run mini-claude
[agents] 사용자 정의 에이전트 1 개 로드: analyzer
mini-claude 시작 (Ctrl+D로 종료)
> query 함수가 어디서 호출되는지 분석해줘
```

`[agents]` 줄이 *발견 결과* 를 출력. 모델은 description 메뉴에서 `analyzer` 를 보고 *자동으로* `subagent_type: "analyzer"` 를 골라 AgentTool 을 호출.

### 3. 흐름 추적

```text
[Agent] {'subagent_type': 'analyzer', 'prompt': 'query 함수가 어디서 호출되는지'}
  ↓
  자식 query() 가 system="You are a focused code analyzer..." 로 시작
  ↓
  자식의 도구 풀: [Read, Bash] 만 (grep:* / find:* 스코프는 9.4 권한 게이트)
  ↓
  자식이 Bash(grep -rn 'query(' src) → grep 결과 → 부모로 텍스트만 돌아옴
  ↓
query 함수는 두 곳에서 호출됩니다 (정의는 src/mini_claude/agent.py:93):
- src/mini_claude/main.py:154 — REPL 루프가 사용자 입력마다 query() 실행
- src/mini_claude/tools/agent.py:125 — AgentTool 이 서브에이전트로 query() 를 재귀 호출
```

자식이 자기 시스템 프롬프트에 따라 *분석가의 어투* 로 응답. 부모가 자식의 도구 호출 / LLM 호출 / 청크를 보지 않고 *최종 텍스트만* 받는다 — 9.5 의 *컨텍스트 격리* 가 그대로 작동.

### 4. 도구 차단 확인

`analyzer` 에이전트는 `allowed-tools: Read, Bash(grep:*), Bash(find:*)` 만 있다. 도구 풀 필터는 *도구 이름* 으로 판단하므로 자식은 `Read` 와 `Bash` 만 받는다 (`Write`/`Edit` 제외). 자식이 `Write` 를 호출하려고 하면? *find_tool 이 ValueError*. `Bash` 의 `grep:*` / `find:*` 스코프 제한은 그다음 9.4 권한 게이트가 본다 — *도구 가용성(이름) 과 명령 스코프(권한) 의 2 단 방어*.

> ⚠️ **시스템 프롬프트 vs allowed-tools 의 역할 분리**: 시스템 프롬프트는 *모델의 의도* 를 가이드한다. allowed-tools 는 *행동을 강제* 한다. 모델이 시스템 프롬프트를 무시하고 Write 를 부르려 해도 *물리적으로 차단*. 가이드 + 강제의 이중 방어.
