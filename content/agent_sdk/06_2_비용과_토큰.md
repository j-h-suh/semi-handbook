# 6.2 비용과 토큰 — 크레딧 추적

## 이 챕터에서 배우는 것

- 되돌리기는 저장공간에선 공짜지만, *토큰*에선 공짜가 아니라는 것
- 분기가 비용을 어떻게 곱하는가 — 갈래마다 도는 대화
- 사용량을 결과 메시지에서 읽는 법
- 비용을 *이벤트로* 적어, 갈래별 계량기를 Part 4 모델에서 공짜로 얻는 법
- 다가오는 Agent SDK 크레딧 모델(2026-06-15)에 대비하는 법

---

## 공짜로 되돌리지만, 토큰은 든다

4장에서 우리는 분기를 거의 공짜로 만들었다. 새 갈래는 거대한 사본이 아니라 `parent_id` 하나라고 했다. 그건 *저장공간*의 이야기다.

운영에 들어가면 다른 청구서가 날아온다. **토큰**이다. 갈래를 하나 칠 때마다 대화 세션이 하나 더 돌고(5.2의 `fork`), 그 세션이 주고받는 메시지가 토큰을 먹는다. 가설 다섯 개를 갈래로 탐색하면, 저장공간은 그대로여도 *대화 비용은 다섯 배*가 될 수 있다. 되돌리기의 자유에는 토큰 청구서가 따라온다.

그러니 6.1에서 관측을 시작한 김에, 신호 하나를 더 뽑아야 한다 — *지금 얼마를 쓰고 있나.*

## 전기요금과 계량기

토큰은 전기요금과 닮았다. 에이전트가 돌면 계량기가 돈다. 문제는 *집 전체에 계량기가 하나*면, 요금이 많이 나와도 어느 방이 먹었는지 모른다는 것이다.

우리에겐 방이 여럿이다 — 갈래 하나하나가 방이다. lot_id로 머지한 C 갈래와 wafer_id로 머지한 D 갈래는 각자 토큰을 먹는다. 집 전체 계량기 하나로는 "어느 가설이 비쌌나"를 못 본다. 그래서 우리는 **가구별 계량기(submetering)** — 갈래별 비용 계측 — 가 필요하다.

> 💡 **비유의 한계 — 토큰은 전기처럼 선형이 아니다**: 전기요금은 쓴 만큼 정직하게 는다. 토큰은 그렇지만은 않다 — 캐시된 대화 앞부분은 더 싸고, 같은 맥락을 거듭 보내면 단가가 달라진다. 그래서 계량기 숫자를 읽되, "단순히 길이×단가"로 넘겨짚지 않는다.

## 사용량은 결과 메시지에 실려 온다

다행히 측정값은 따로 구할 필요가 없다. 매 실행의 끝에 오는 결과 메시지가 사용량을 싣고 온다.

```python
async for msg in query(prompt=branch_prompt, options=options):
    if isinstance(msg, ResultMessage):
        usage = msg.usage                  # 입력/출력 토큰
        cost_usd = msg.total_cost_usd       # 환산 비용
        logger.info(f"in={usage['input_tokens']} out={usage['output_tokens']} ${cost_usd:.4f}")
```

`ResultMessage`는 1장에서 결과를 받을 때 이미 만난 타입이다. 거기 실린 `usage`와 `total_cost_usd`가 이번 실행이 먹은 양이다. 읽기만 하면 된다.

## 비용을 이벤트로 — 갈래별 계량기

여기서 Part 4가 다시 빛난다. 비용을 그냥 로그로 흘리는 대신, **현재 노드에 `cost` 이벤트로 적는다.**

```python
store.append_event(store.get_current(), op="cost", payload={
    "in": usage["input_tokens"],
    "out": usage["output_tokens"],
    "usd": cost_usd,
})
```

이 한 줄로 갈래별 계량기가 *공짜로* 생긴다. 비용이 노드에 붙으니, 노드를 따라 접으면 그 갈래가 지금까지 먹은 총비용이 나온다. 가구별 계량기를 따로 설치한 게 아니라, 이미 있던 이벤트 통로(4.3)에 비용도 흘려보냈을 뿐이다.

그럼 `show-tree`(5.4)에 비용을 얹어 한눈에 볼 수 있다.

```text
$ show-tree --cost
  A  (lot 원본 로드)            $0.02
  └─ B  (머지 전)               $0.05
     ├─ C  (lot_id 머지)        $0.41   ← 막다른 가설인데 비쌌다
     └─ D  (wafer_id 머지)      $0.12   ← current
```

이제 "C 가설은 결국 틀렸는데 $0.41을 먹었다"가 보인다. 팹이 *lot당 원가*를 따지듯, 우리는 *갈래당 원가*를 따진다. 비싸게 굴린 막다른 갈래는 분석판의 폐기 wafer다 — 보여야 줄인다.

## 다가오는 크레딧 모델 (2026-06-15)

마지막으로 운영 일정 하나. **2026-06-15부터 Agent SDK에 크레딧 모델이 도입된다.** 사용량이 크레딧으로 환산돼 차감되는 방식이라, 운영자는 두 가지를 미리 준비해 두는 게 좋다.

- **소비를 크레딧 기준으로도 집계한다.** 위에서 적은 `cost` 이벤트에 토큰뿐 아니라 크레딧 환산도 함께 남겨 두면, 모델 전환 시점에 그대로 이어진다.
- **탐색에 예산을 건다.** "이 분석 세션은 크레딧 N까지"처럼 상한을 두면, 갈래가 폭주해도 청구서가 폭주하진 않는다.

세부 단가와 환산율은 도입 시점 공지를 따라야 하니, 여기서는 *추적할 자리를 미리 비워두는* 데까지만 한다. 비용을 이벤트로 적어둔 덕에, 크레딧이 와도 바꿀 코드는 payload 한 칸뿐이다.

다음 Part에서는 방향을 튼다 — 이 에이전트를 *믿고 출시*할 수 있는가. 비결정적인 에이전트를 어떻게 테스트하고 신뢰하는지로 넘어간다.

> ✅ **검증됨 (검증 레포) / ⚠️ usage는 더 풍부**: `ResultMessage`에 `total_cost_usd`(float)와 `usage`가 실려 옴을 실측했다(`probes/basics_probe.py`, Bedrock opus-4-8). 책 주장대로 `usage`에 `input_tokens`·`output_tokens`가 있다 — 다만 실측 `usage`는 그보다 풍부한 dict로 `cache_creation_input_tokens`·`cache_read_input_tokens`·`service_tier` 등 캐시·티어 정보까지 담는다(위 두 키 접근은 그대로 유효). `cost` 이벤트 적재는 `store.append_event`(4.2·4.3 검증분)로 성립하고, 크레딧 환산은 도입 공지를 따른다.

## 핵심 정리

- **되돌리기는 저장공간에선 공짜지만 토큰에선 아니다.** 갈래마다 대화가 돌아, 가설 다섯 개 탐색은 대화 비용 다섯 배가 될 수 있다.
- **사용량은 `ResultMessage`의 `usage`·`total_cost_usd`에 실려 온다.** 따로 구할 필요 없이 읽으면 된다.
- **비용을 `cost` 이벤트로 적으면 갈래별 계량기가 공짜로 생긴다.** 노드에 붙은 비용을 접으면 갈래당 원가가 나오고, `show-tree`로 막다른 비싼 갈래가 보인다.
- **2026-06-15 크레딧 모델에 미리 자리를 비워둔다.** payload에 크레딧 환산을 함께 남기고 탐색에 예산 상한을 걸면, 전환이 와도 바꿀 코드는 한 칸뿐이다.
