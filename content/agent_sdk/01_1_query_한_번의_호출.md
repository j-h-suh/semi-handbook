# 1.1 `query()` — 한 번의 호출

## 이 챕터에서 배우는 것

- SDK를 *내 코드에서* 처음 돌리는 가장 작은 한 걸음 — `query()`
- `query()`가 *일회성* 호출이라는 것, 그리고 그게 무슨 뜻인지
- 결과가 한 덩어리가 아니라 async 스트림으로 *흘러나온다*는 것
- 스트림에서 필요한 메시지만 꺼내 쓰는 법
- `query()`로 충분할 때와, 대화를 이어야 해서 부족할 때

---

## 가장 작은 한 걸음

0.3에서 우리는 설치하고 인증하고 `query()` 한 줄을 돌려봤다. 이제 그 한 줄을 제대로 들여다본다. 이게 이 책에서 SDK를 *내 코드 안에서* 다루는 첫걸음이다.

**`query()`**는 에이전트를 *한 번* 실행하고 끝나는 호출이다. 프롬프트를 주면, 에이전트가 일하고, 결과가 흘러나온다. 그게 전부다.

```python
import anyio
from claude_agent_sdk import query, ClaudeAgentOptions

async def main():
    async for msg in query(
        prompt="wafer 수율 lot 데이터 파일의 행 수를 세어줘",
        options=ClaudeAgentOptions(allowed_tools=["Read", "Grep"]),
    ):
        print(msg)

anyio.run(main)
```

`prompt`로 할 일을 주고, `options`로 2장에서 배운 도구 권한을 건다. 그리고 `async for`로 결과를 받는다. 짧지만 이 안에 핵심 셋이 다 들어 있다 — 일회성, async, 스트림.

## 카운터에서 한 잔 — 일회성 호출

`query()`를 카운터에서 커피 한 잔 주문하는 것으로 그려 보자. 주문하면(`prompt`), 바리스타가 일하며 중계해 주고("원두 갈고… 샷 내리고…"), 잔을 받는다. 주문 하나가 `query()` 한 번이다.

그리고 카운터는 *주문이 끝나면 나를 잊는다.* 다음에 다시 가면 "아까 그거랑 같은 걸로"가 안 통한다 — 처음 보는 손님이다. `query()`가 **일회성(one-shot)**이라는 게 이 뜻이다. 한 호출은 이전 호출을 기억하지 못한다.

> 💡 **비유의 한계 — 바리스타는 손이 하나가 아니다**: 커피 비유는 "한 번 주문, 한 번 결과"를 잘 보여주지만, 에이전트는 그 한 번 안에서 *여러 도구를 여러 번* 쓸 수 있다. lot 파일을 읽고, 그 안을 grep하고, 다시 세는 식으로. 일회성은 "한 번의 *대화*"지 "한 번의 *동작*"이 아니다.

## async 스트림으로 받는다

왜 결과를 `return` 값 하나로 안 받고 `async for`로 받을까. 에이전트는 한 번에 답을 뱉지 않기 때문이다. 생각하고, 도구를 부르고, 그 결과를 보고, 또 움직인다. 그 과정을 *끝날 때까지 기다렸다 한 덩어리로* 받는 대신, **벌어지는 대로 메시지가 흘러나온다.**

이건 제너레이터를 `for`로 도는 것과 같은 결이다. `query()`는 비동기 제너레이터처럼 동작해, 에이전트가 한 걸음 뗄 때마다 메시지를 하나씩 내놓는다. 그래서 진행 상황을 실시간으로 볼 수 있다 — 바리스타의 중계처럼.

> ⚙️ **왜 async인가**: 에이전트는 대부분의 시간을 *기다리며* 보낸다 — 모델 응답을, 도구 실행을. async 스트림은 그 기다림 동안 프로그램이 멈추지 않게 한다. 스트림을 어떻게 더 깊이 소비하는지는 3.1에서 앱을 만들 때 다시 판다.

## 결과만 필요할 때

진행 과정은 됐고 *최종 답만* 필요할 때도 많다. 스트림에서 결과 메시지만 골라내면 된다.

```python
from claude_agent_sdk import query, ResultMessage

async def count_rows() -> str:
    async for msg in query(prompt="wafer 수율 lot 데이터 파일의 행 수를 세어줘"):
        if isinstance(msg, ResultMessage):
            return msg.result        # 마지막에 오는 최종 결과
    return ""
```

흘러나오는 메시지엔 종류가 여럿이다 — 에이전트의 말, 도구 호출, 그리고 맨 끝의 `ResultMessage`. 지금은 "결과는 `ResultMessage`에 있다"만 쥐면 된다. 메시지 타입을 제대로 가려 쓰는 법은 1.3에서 지도처럼 정리한다.

## 이걸로 충분할 때, 아닐 때

`query()`는 *독립적인 한 번*이면 충분하다. "이 파일 행 수 세줘", "이 테이블 요약해줘" 같은 단발 작업.

하지만 우리가 만들 건 단발이 아니다. lot_id로 머지하고, wafer 수율을 보고, "그럼 이번엔 wafer_id로" 하며 *대화를 잇는* 분석이다. 그러려면 카운터가 나를 기억해야 한다 — 일회성으론 안 된다. 그 "대화를 잇는" 방법이 다음 챕터의 `ClaudeSDKClient`다.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요**: 위 `query()`·`anyio.run`·`ResultMessage.result` 사용은 설계 초안이다. 러너(`anyio` vs `asyncio`)와 결과 필드명은 검증 레포에서 실제 SDK 버전으로 확인해야 한다.

---

## 핵심 정리

- **`query()`는 에이전트를 한 번 실행하는 일회성 호출이다.** 프롬프트를 주면 일하고 끝난다 — 카운터의 커피 한 잔 주문처럼, 끝나면 나를 잊는다.
- **결과는 한 덩어리가 아니라 async 스트림으로 흘러나온다.** 비동기 제너레이터처럼 `async for`로 돌며, 에이전트가 한 걸음 뗄 때마다 메시지를 받는다.
- **최종 답은 `ResultMessage`에 있다.** 진행이 필요 없으면 그것만 골라내면 된다. 메시지 타입 전체는 1.3에서 다룬다.
- **일회성으론 대화를 못 잇는다.** 머지하고 되돌리며 *이어가는* 분석에는 다음 챕터의 `ClaudeSDKClient`가 필요하다.
