# 1.2 `ClaudeSDKClient` — 대화 잇기 (둘 중 무엇을 언제)

## 이 챕터에서 배우는 것

- 대화를 *이어가는* 호출 방식 — `ClaudeSDKClient`
- `query()`와 `ClaudeSDKClient` 중 무엇을 언제 고르나
- 클라이언트가 *세션*을 손에 쥔다는 것, 그리고 그 세션이 뒤에서 무엇이 되는가
- 멀티턴이 우리 분석 에이전트의 기본값인 이유

---

## 카운터에 자리를 잡다

1.1의 `query()`는 카운터에서 한 잔 주문하고 떠나는 일이었다. 끝나면 나를 잊으니, "방금 그거 다시"가 안 통했다.

그런데 우리 분석은 한 잔으로 안 끝난다. "lot 데이터 로드해줘" → (결과를 보고) → "방금 그거 lot_id로 머지해줘" → "wafer 수율 컬럼만 남겨줘"처럼 *앞을 딛고* 다음을 말한다. 그러려면 카운터가 나를 기억해야 한다. 자리를 잡고 앉아야 한다.

## 탭을 연다 — `ClaudeSDKClient`

**`ClaudeSDKClient`**는 그 "자리 잡기"다. 카운터에 탭(tab)을 열듯 세션을 열어두고, 같은 자리에서 여러 번 말을 건다. 매 턴이 앞 턴의 맥락을 그대로 물려받는다.

```python
from claude_agent_sdk import ClaudeSDKClient, ClaudeAgentOptions

async def main():
    async with ClaudeSDKClient(options=ClaudeAgentOptions(...)) as client:
        await client.query("wafer 수율 lot 데이터를 로드해줘")
        async for msg in client.receive_response():
            ...   # 첫 턴 결과

        # 새 query지만 같은 세션 — '방금 그거'를 기억한다
        await client.query("방금 그거 lot_id로 머지해줘")
        async for msg in client.receive_response():
            ...   # 둘째 턴: 앞 턴 맥락 위에서 답한다
```

`async with`로 세션을 열고, `query()`로 말을 걸고, `receive_response()`로 그 턴의 응답을 받는다. 둘째 `query()`는 첫 턴을 *기억한 채* 답한다 — "방금 그거"가 통한다. 같은 함수 이름이지만, 1.1의 모듈 수준 `query()`(일회성)와 클라이언트의 `client.query()`(세션 유지)는 다른 물건이다.

> 💡 **비유의 한계 — 탭은 기억의 일부만 비춘다**: 탭은 *얼마어치 달아놨나*만 기억한다. 클라이언트 세션은 그보다 풍부하다 — 오간 말, 부른 도구, 그 결과까지 다 들고 있다. "자리를 잡는다"는 결을 위해 탭에 빗댔을 뿐, 세션이 담는 건 영수증이 아니라 대화 전체다.

## 일회성이냐 멀티턴이냐

그럼 둘 중 무엇을 언제 고르나. 기준은 하나다 — **다음 말이 앞 말을 딛는가.**

| 상황 | 고르는 것 |
|---|---|
| 독립적인 단발 작업 ("이 파일 행 수 세줘") | **`query()`** |
| 앞을 딛고 잇는 대화 ("그거 머지", "그럼 다른 키로") | **`ClaudeSDKClient`** |
| 한 번 묻고 끝, 상태 없음 | `query()` |
| 분석을 굴리며 맥락을 쌓음 | `ClaudeSDKClient` |

단발이면 `query()`가 가볍고, 잇는 대화면 `ClaudeSDKClient`가 맞다. 억지로 `query()`로 멀티턴을 흉내 내려고 직전 대화를 매번 프롬프트에 욱여넣지 마라 — 그게 클라이언트가 하는 일이다.

## 세션을 손에 쥔다

클라이언트가 기억할 수 있는 건 **세션(session)**을 쥐고 있어서다. 세션엔 id가 있고, 초기화 메시지에서 그 id를 꺼내 둘 수 있다.

```python
from claude_agent_sdk import SystemMessage

session_id = None
async for msg in client.receive_response():
    if isinstance(msg, SystemMessage) and msg.subtype == "init":
        session_id = msg.data["session_id"]
```

이 `session_id`를 왜 굳이 잡아둘까. 뒤에서 이게 *주인공*이 되기 때문이다. 4.3에서 우리는 이 id를 데이터 노드에 묶고(`session_id` 칸), 5.2에서 이 세션을 `fork`해 대화 갈래를 친다. 지금 1.2에서 연 이 세션이, 5장에서 되돌리고 분기할 바로 그 대화 축이다.

## 우리는 멀티턴이다

정리하면, 우리가 만들 분석 에이전트는 천생 멀티턴이다. 머지하고, 보고, 되돌리고, 다시 가는 *이어지는* 대화. 그러니 이 책의 기본 도구는 `ClaudeSDKClient`다. `query()`는 단발 점검에 곁들여 쓴다.

다음 챕터는 지금까지 슬쩍 넘긴 두 가지를 지도로 편다 — `options`로 무엇을 조절할 수 있고, 흘러나오는 메시지를 어떻게 가려 받는가.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요**: 위 `ClaudeSDKClient`·`receive_response()`·`SystemMessage`/`init`/`session_id` 사용은 설계 초안이다. 클라이언트 컨텍스트 관리와 세션 id 추출 경로는 검증 레포에서 실제 SDK 버전으로 확인해야 한다.

---

## 핵심 정리

- **`ClaudeSDKClient`는 세션을 열어두고 대화를 잇는다.** `async with`로 자리를 잡고 여러 턴을 보내면, 매 턴이 앞 턴 맥락을 물려받아 "방금 그거"가 통한다.
- **고르는 기준은 "다음 말이 앞 말을 딛는가"다.** 독립 단발이면 `query()`, 잇는 대화면 `ClaudeSDKClient`. 멀티턴을 `query()`로 흉내 내려 프롬프트에 과거를 욱여넣지 마라.
- **클라이언트는 `session_id`를 쥔다.** 이 id가 4.3에서 데이터 노드에 묶이고 5.2에서 `fork`되는, 5장 되돌림의 대화 축이다.
- **우리 분석은 천생 멀티턴이다.** 그래서 이 책의 기본 도구는 `ClaudeSDKClient`이고, `query()`는 단발 점검에 곁들인다.
