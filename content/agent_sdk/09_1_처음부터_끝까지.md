# 9.1 처음부터 끝까지 — A→B→C→(롤백 B)→D 시나리오

## 이 챕터에서 배우는 것

- 앞의 조각들을 *하나의 실제 시나리오*로 끝까지 흘려보기
- 각 Part가 그 흐름의 어디에서 맞물리는지
- 되돌리기·분기가 실제로 "공짜"로 작동하는 모습
- 솔직한 회고 — 잘한 일 / 꺼림칙한 일 / 막힌 일

---

## 흩어진 조각을 한 번에 흘려본다

지금까지 우리는 조각을 따로 만들었다 — 호출(1), 도구(2), 앱(3), 상태(4), 시간(5), 관측(6), 신뢰(7), 배포(8). 팹은 모듈을 다 지으면 *첫 lot을 끝까지 흘려보는* 종합 시운전을 한다. 라인 전체가 맞물리는지, 진짜 웨이퍼 하나로 확인하는 것이다. 9.1이 그 시운전이다 — 0.1에서 예고한 A→B→C→(롤백 B)→D를, 이제 SDK를 부려 진짜로 굴린다.

> 💡 **비유의 한계 — 시운전은 양산 검증이 아니다**: 첫 lot을 끝까지 흘려본다고 모든 케이스가 검증되는 건 아니다. 시운전은 *통합*을 보이는 것이고, 빠짐없는 검증은 7장(eval·TC·견고함)의 몫이다. 9.1은 "조각들이 한 흐름으로 맞물린다"를 보이는 데까지다.

## 첫 lot을 끝까지 — 시나리오

세션을 열고(1.2), 한 흐름을 끝까지 흘려본다.

```python
async def run_scenario(client, ui):
    A = store.create_node(parent_id=None); store.set_current(A)

    # A → B: lot 데이터 로드 후 머지 직전까지
    await run_turn(client, ui, "wafer 수율 lot 데이터를 로드해줘")     # 3.1
    B = await branch(store, A, "공정 파라미터 머지 준비")              # 5.2

    # B → C: lot_id로 머지 (에이전트가 merge_tables 도구 호출 → 이벤트로 적힘)
    await checkout(store, duck, B)
    C = await branch(store, B, "lot_id로 머지")
    await run_turn(client, ui, "process_params를 lot_id로 머지해줘")   # 2.2 → 4.2

    # C가 약하다 → B로 롤백 (C는 남는다, TC-1)
    await rollback(store, duck, B)                                    # 5.3

    # B → D: wafer_id로 다시 (C 오염 없음, TC-4)
    D = await branch(store, B, "wafer_id로 머지")
    await run_turn(client, ui, "process_params를 wafer_id로 머지해줘")
    return A, B, C, D
```

그리고 트리를 본다(5.4) — 비용까지 얹어서(6.2).

```text
$ analyze show-tree --cost
  A  (lot 원본 로드)            $0.02
  └─ B  (머지 전)               $0.05
     ├─ C  (lot_id 머지)        $0.41   ← 약한 가설, 그래도 남아 있다
     └─ D  (wafer_id 머지)      $0.13   ← current
```

C는 롤백 뒤에도 남았고(TC-1), C와 D는 나란히 산다(TC-2). `← current`는 D 하나뿐이고(TC-3), D는 C의 흔적 없이 깨끗하다(TC-4). 0.1에서 그림으로만 그렸던 장면이, 실제 트리로 섰다.

## 조각들이 맞물리는 자리

이 짧은 흐름 안에 책 전체가 들어 있다.

- `run_turn`이 스트림을 소비하고(**3.1**), 에이전트는 켜둔 도구만 쓰며(**2.1**) `merge_tables`로 머지한다(**2.2**).
- 그 머지는 곧장 실행되지 않고 *이벤트로 적힌다*(**4.2**) — `nodes`/`events`에(**4.3**). 상태는 그 이벤트를 접어 만든다(**4.4**).
- `branch`는 대화와 데이터를 한 동작으로 가르고(**5.2**), `rollback`은 `current`만 옮기며 C를 남긴다(**5.3**). C와 D가 공존하고(**5.4**), 두 축은 1:1로 맞물린다(**5.5**).
- 매 머지 직후 hook이 `audit`을 돌리고(**6.1**), 비용이 노드에 쌓여 갈래별로 보인다(**6.2**).
- 이 전체가 TC-1~4(**7.2**)를 통과하고, 헤드리스로 CI에서 재현된다(**8.1**).

하나의 결정 — 상태를 이벤트로(ADR-001) — 이 흐름 곳곳에서 배당을 준다. 그게 이 예제를 떠받치는 척추다.

## 회고 — 잘한 일 / 꺼림칙한 일 / 막힌 일

시운전을 마쳤으니, 솔직하게 돌아본다.

**잘한 일.** 상태를 스냅샷이 아니라 이벤트로 둔 단 하나의 결정이 끝까지 배당을 줬다. 롤백이 "덜 접기"로(5.3), 분기가 "형제 삽입"으로(5.2), 재시도 무오염이 "조상만 접기"로(5.5·TC-4), 비용 추적이 "노드에 적기"로(6.2), 테스트가 "결과 상태 대조"로(7.1) — 전부 *공짜로* 떨어졌다. 한 결정이 여러 곳에서 갚이는 설계가 좋은 설계다.

**꺼림칙한 일.** fork와 node의 1:1을 *쓰기 시점에* 완벽히 강제하지 못했다(5.5) — 고아 세션이라는 잔여물을 감사로 청소하는 선에서 타협했다. 스냅샷 캐시의 무효화 규칙도 미뤘고(8.2), 크레딧 모델(6.2)은 도입 전이라 자리만 비워뒀다. 돌아갈 때마다 한 번씩 마음이 걸리는 자리들이다.

**막힌 일.** SQLite와 SDK 세션이라는 *두 시스템에 걸친 진짜 원자성*은 끝내 깔끔히 풀지 못했다 — 순서(외부 먼저, 장부 나중)로 위험을 한쪽에 몰아넣는 차선책에 머물렀다(5.5·7.3). 시계열 연결은 아예 Phase 1 범위 밖으로 미뤘다. 이건 못 푼 게 아니라 *이 책의 범위에서 안 푼* 것이고, 8.2의 부채와 다음 권으로 넘긴다.

> ⚠️ **회고는 변명이 아니라 지도다.** 꺼림칙한 일과 막힌 일을 적는 건 사과하려는 게 아니라, 다음 사람이(혹은 다음 분기의 우리가) 어디부터 보강할지 알려주려는 것이다. 잘한 일만 적은 회고는 회고가 아니다.

## 여기서 멈추고, 다음으로

빈 `query()` 한 줄(0.3)에서 시작해, 되돌릴 수 있는 분석 에이전트를 끝까지 끌고 왔다. A에서 D까지, 두 가설이 나란히 살아 비교되는 그 장면 — 0.1에서 예고한 예제가 SDK를 끝까지 부린 끝에 트리 하나로 섰다.

남은 건 그 너머다. 마지막으로, 이 책이 *안* 다룬 것들이 어디로 이어지는지 짚으며 닫는다.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요**: 위 `run_scenario` 통합 흐름은 설계 초안이다. 각 단계의 실제 연결(특히 `run_turn`↔`branch`↔`rollback`의 세션·노드 귀속)은 검증 레포에서 끝까지 돌려 확인해야 한다.

## 핵심 정리

- **하나의 시나리오가 책 전체를 꿴다.** A→B→C→(롤백 B)→D 한 흐름 안에 호출·도구·앱·상태·시간·관측·신뢰가 다 맞물린다.
- **한 결정이 곳곳에서 갚인다.** 상태를 이벤트로 둔 ADR-001이 롤백·분기·재시도·비용·테스트에서 전부 공짜로 떨어졌다 — 그게 이 예제를 떠받치는 척추다.
- **회고는 세 칸이다 — 잘한 일·꺼림칙한 일·막힌 일.** 이벤트 모델의 배당(잘함), fork↔node 정합·스냅샷(꺼림칙), 두 시스템 원자성·시계열(막힘). 회고는 변명이 아니라 다음을 위한 지도다.
- **0.1에서 예고한 예제가 트리로 완성됐다.** 되돌리기가 공짜라 두 가설이 나란히 산다 — query부터 배포까지 SDK를 끝까지 부려 만든 장면이다.
