# 에이전트 SDK 핸드북 — 목차 (초안 v4)

**대상 독자**: 공식 문서·Client SDK는 봤지만 "그래서 어떻게 설계·운영하나"에서 막힌 엔지니어
**목표**: Claude Agent SDK로 *상태를 되돌릴 수 있는 에이전트 앱*을 빈 스크립트 → 프로덕션까지 끌고 가기
**분량**: 약 150페이지 (29챕터 · 기초 4p / 심장 6–7p / 운영 5p)
**언어**: 한국어 (기술 용어 영어 병기)
**자매서**: 클로드 핸드북 — 엔진 내부 메커니즘(루프·hook·세션 구현)은 그쪽에 위임하고, 이 책은 *활용·운영*만 다룬다.

> 한 줄 컨셉: **"만드는 법은 안다, 이제 굴린다."**

---

## Part 0: 왜 되돌릴 수 있어야 하나 (들어가며)

이 책이 어디 서는지, 무엇을 *안* 다루는지부터 못박는다.

- 0.1 만드는 법은 안다, 이제 굴린다 — SDK 실용서 정체성과 관통 예제(되돌리기)
- 0.2 이 책의 자리 — 경계 긋기 + 네 갈래 선택 (Agent SDK / Client SDK / CLI / Managed Agents)
- 0.3 환경과 첫 호출 — 설치 · Bedrock 인증 · `query()` 한 줄

## Part 1: 첫 에이전트

SDK를 *내 코드에서* 처음 돌려본다. 호출과 결과만, 내부 동작은 자매서.

- 1.1 `query()` — 한 번의 호출
- 1.2 `ClaudeSDKClient` — 대화 잇기 (둘 중 무엇을 언제)
- 1.3 Options 지도와 결과 처리

## Part 2: 능력 주기 — 내 시스템을 도구로

에이전트에 내 데이터·시스템을 다룰 능력을 쥐어준다.

- 2.1 내장 도구 고르기 — 가용성 vs 권한
- 2.2 커스텀 도구로 내 로직 노출
- 2.3 MCP로 기존 시스템 연결 — 커스텀 도구 vs MCP, 언제 무엇

## Part 3: 앱으로 감싸기

터미널 스크립트를 사용자가 부르는 인터페이스로 감싼다.

- 3.1 에이전트 루프를 앱이 돌리기 — 스트림 소비
- 3.2 인터페이스 — CLI와 그 너머 (`merge` / `show-tree` / `rollback` / `branch`)

## ★Part 4: 상태를 로그로 표현 (무게중심)

데이터 상태를 *스냅샷*이 아니라 *변경 이벤트의 누적*으로 표현한다. 이 결정이 Part 5의 롤백·분기를 공짜로 만든다.

- 4.1 세션이 담지 않는 것 — 대화 상태 ≠ 데이터 상태
- 4.2 스냅샷이 아니라 event append (ADR-001)
- 4.3 데이터 모델 — nodes와 events
- 4.4 replay — 로그를 접어 상태를 만들기 (저장소 역할 분리)

## ★Part 5: 시간을 다루기 — 롤백과 분기 (이 책의 심장)

대화 시간축(SDK `fork`)과 데이터 시간축(event 트리)을 하나로 묶는다. 공식 문서·자매서 어디에도 없는 영역.

- 5.1 두 개의 시간축 — 대화와 데이터
- 5.2 분기 만들기 — `fork()` + 새 node
- 5.3 롤백 하기 — 과거로 `current` 옮기기
- 5.4 분기 공존과 트리 탐색
- 5.5 두 축을 어긋나지 않게 — 정합과 함정

## Part 6: 관측성 — 운영 신호

운영 중 무슨 일이 일어나는지 보이게 한다.

- 6.1 hook으로 신호 뽑기 — 로그·트레이스·감사
- 6.2 비용과 토큰 — 크레딧 추적 (2026-06-15 Agent SDK 크레딧)

## Part 7: 믿게 만들기 — 신뢰성

비결정적인 에이전트를 어떻게 믿고 출시하나.

- 7.1 비결정 에이전트 테스트 · eval
- 7.2 인수 조건을 코드로 — TC-1~4 (롤백 후 잔존 · 분기 공존 · current · 머지 재시도)
- 7.3 견고함과 안전 — 권한 정책 · 에러 · 재시도 · abort

## Part 8: 배포·부채

내보내고, 다음을 위한 자리를 남긴다.

- 8.1 내보내기 — 헤드리스 · CI · 컨테이너
- 8.2 다음을 위한 자리 — 기술부채 · Managed Agents 이전 판단

## Part 9: 실전 — 하나를 끝까지

앞의 조각들을 한 제품으로 합친다.

- 9.1 처음부터 끝까지 — A→B→C→(롤백 B)→D 시나리오 (+ 마지막 섹션: 회고 — 잘한 일 / 꺼림칙한 일 / 막힌 일)

## 작성 가이드 (이 핸드북 특유)

상위 스타일은 `/CLAUDE.md`("핸드북 콘텐츠 작성 스타일 가이드"), 세부 표기는 `docs/handbook-conventions.md`. 아래는 이 책만의 추가 가드레일.

- **직교 원칙**: 엔진 내부 메커니즘(루프·hook·세션 구현)은 클로드 핸드북(자매서)에 위임. 이 책은 *How to wield*(활용·통합·운영·의사결정)만. 같은 단어(hook·session·tool)가 나와도 **메커니즘 재설명 금지**.
- **도메인**: 반도체 데이터 분석 예제는 유지(생생함). 단 **내부 제품명은 쓰지 않음** — "상태를 되돌리는 분석 에이전트"로 일반화.
- **코드**: 본문 코드는 실제 작성·검증된 것만 (검증 레포에서 add-up). 추측 코드 금지.
- **무게중심**: Part 4·5(상태·시간)에 분량의 ~40%. 기초(0~3)는 빠르게 통과.
- **각 챕터**: CLAUDE.md 챕터 구조 따름 — "이 챕터에서 배우는 것" → 본문 → 핵심 정리 → 다음 챕터 티저.
- **품질 합격선**: 매 챕터는 `chapter-rubric.md`(A 객관 가드 + B 질적 기준)를 통과해야 한다. 기준 챕터 = `05_1_두_개의_시간축.md`(살아있는 예시).
