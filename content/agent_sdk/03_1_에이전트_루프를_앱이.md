# 3.1 에이전트 루프를 앱이 돌리기 — 스트림 소비

## 이 챕터에서 배우는 것

- 터미널 스크립트를 *앱*으로 바꾸는 첫걸음 — 스트림을 앱이 소비한다는 것
- 최종 결과만 기다리지 않고 *중간 이벤트*를 흘려보내는 법
- "바깥 루프"는 앱이 쥐고, "안쪽 루프"는 엔진이 돈다는 경계
- 소비 로직이 곧 CLI·UI의 엔진이 된다는 것

---

## 이제 앱이 운전한다

Part 1에서 에이전트를 부르고, Part 2에서 능력을 줬다. 지금까진 결과를 `print`로 흘려보는 스크립트였다. 이제 사용자가 부르는 *앱*으로 감쌀 차례다.

앱으로 감싼다는 건 한 가지로 요약된다. **앱이 스트림을 소비하며 운전한다.** 1.3에서 메시지를 타입별로 가려 받는 법을 배웠는데, 그걸 앱의 제어 흐름 안에 넣어 — 화면에 그리고, 로그로 흘리고, 다음 턴을 언제 보낼지 정하는 — 운전석에 앉히는 것이다.

## 관제석에 앉는다

그림은 관제석이다. 비행기를 *모는* 건 SDK다 — 모델에 묻고, 도구를 부르고, 그 결과로 다음을 정하는 *안쪽 루프*를 SDK가 돈다. 앱은 그 옆 **관제석**에 앉아, 흘러나오는 라이브 피드(스트림)를 받아 처리한다. 무엇을 화면에 띄울지, 무엇을 기록할지, 언제 "그만"이라 말할지를 앱이 정한다.

## 중간 이벤트를 흘려보지 않는다

가장 흔한 초보 실수는 최종 `ResultMessage`만 기다리는 것이다. 그러면 사용자는 머지가 30초 도는 동안 빈 화면을 본다. 앱의 일은 *벌어지는 대로* 보여주는 것이다 — 에이전트의 말이 나오면 그리고, 도구가 불리면 "실행 중"을 띄운다.

```python
async def run_turn(client, ui, prompt: str):
    """앱이 한 턴을 돌린다 — 스트림을 소비하며 중간 이벤트에 반응."""
    await client.query(prompt)
    async for msg in client.receive_response():
        if isinstance(msg, AssistantMessage):
            for block in msg.content:
                if isinstance(block, TextBlock):
                    ui.show(block.text)                       # 말은 실시간으로 그린다
                elif isinstance(block, ToolUseBlock):
                    ui.status(f"⏳ {block.name} 실행 중…")      # 진행을 띄운다
        elif isinstance(msg, ResultMessage):
            ui.done(cost=msg.total_cost_usd)                  # 끝나면 마무리
            return msg
```

이 한 함수가 1.3의 메시지 분기를 앱 안으로 들여놓은 것이다. 차이는 `print`가 아니라 `ui`로 — 화면이든 웹소켓이든 — 흘려보내고, 중간 진행까지 사용자에게 보인다는 점이다. wafer 수율 lot 머지가 도는 동안 "merge_tables 실행 중…"이 떠야, 사용자가 멈춘 게 아님을 안다.

## 앱이 바깥 루프를 쥔다

`run_turn`은 *한 턴*이다. 앱은 그 위에 *바깥 루프*를 두른다 — 다음 프롬프트를 언제 보낼지, 언제 멈출지, 매 턴 무엇을 기록할지를 앱이 정한다.

```python
async def run_session(client, ui):
    while True:
        prompt = await ui.ask()           # 사용자 입력 (또는 스크립트된 다음 수)
        if prompt is None:
            break                          # 앱이 종료를 결정한다
        result = await run_turn(client, ui, prompt)
        logger.info(f"턴 종료 node={store.get_current()} ${result.total_cost_usd:.4f}")
```

여기서 경계가 분명해진다. **안쪽 루프(모델↔도구)는 엔진이, 바깥 루프(턴↔턴, 사용자↔앱)는 앱이 쥔다.** "에이전트 루프를 앱이 돌린다"는 이 챕터 제목의 정확한 뜻이 이거다 — 우리는 루프를 *구현*하는 게 아니라, 그 흐름을 *소비하고 바깥을 운전*한다.

이 소비 로직이 곧 인터페이스의 엔진이 된다. `ui.ask`/`ui.show`를 터미널에 연결하면 CLI가, 웹소켓에 연결하면 웹이 된다. 다음 챕터는 이걸 `merge`·`rollback`·`show-tree`·`branch`라는 사용자 명령으로 빚는다.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요**: 위 `run_turn`/`run_session`·`receive_response()` 소비 패턴·블록 처리는 설계 초안이다. 스트림 소비 중 백프레셔와 동시성 경계는 검증 레포에서 실제로 돌려 확인해야 한다.

## 핵심 정리

- **앱으로 감싼다는 건 스트림을 앱이 소비하며 운전한다는 것이다.** 1.3의 메시지 분기를 앱의 제어 흐름 안에 들여, 화면·로그·다음 턴을 앱이 정한다.
- **중간 이벤트를 흘려보지 않는다.** 최종 결과만 기다리면 사용자는 빈 화면을 본다. 말이 나오면 그리고, 도구가 불리면 진행을 띄운다.
- **안쪽 루프는 엔진, 바깥 루프는 앱.** 모델↔도구 루프는 SDK가 돌고(자매서), 턴↔턴·사용자↔앱 루프는 앱이 쥔다. "앱이 돌린다"는 소비하며 운전한다는 뜻이다.
- **이 소비 로직이 인터페이스의 엔진이다.** `ui`를 터미널에 붙이면 CLI, 웹소켓에 붙이면 웹 — 그 빚기가 다음 챕터다.
