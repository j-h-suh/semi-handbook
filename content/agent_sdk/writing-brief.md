## 1. 한 줄 미션

Claude Agent SDK로 *"상태를 되돌릴 수 있는 반도체 데이터 분석 에이전트"*를 빈 스크립트→프로덕션까지 만드는 **활용·통합·운영 실용서**. 엔진 내부 메커니즘은 자매서(클로드 핸드북)에 위임한다. 컨셉: **"만드는 법은 안다, 이제 굴린다."**

## 2. 절대 가드레일

- **직교 (메커니즘 0%)** — 엔진 내부 구현(루프·hook·세션 복제)은 서술하지 않는다. 필요하면 🔬 Deep Dive 안에서 "자매서 위임" 형태로만.
- **도메인** — 반도체 데이터 분석 예제 유지(wafer 수율·`lot_id` 등). **내부 제품명은 0건** (책 표면은 "상태를 되돌리는 분석 에이전트"로 일반화).
- **톤** — 평서체 `~다`. 중심 비유 1개 + 한계 명시. 기준 챕터(5.1·5.2)의 결을 따른다.
- **코드** — 미검증이면 초안으로 쓰되, **"검증 레포에서 실행 확인"을 rubric 밖 별도 게이트로 표시**한다. 본문 확정 코드는 실제로 돌아간 것이어야 한다.

## 3. 작성 방식

- **챕터 하나씩**, `chapter-rubric.md`의 A1~A6 + B1~B6를 통과할 때까지.
- 매 챕터 = `handbook-toc.md`의 챕터 한 줄을 *출발점*, `chapter-rubric.md`를 *합격선*, 기준 챕터(5.1·5.2)를 *톤 견본*으로.
- `/goal`로 양산할 때는 `chapter-rubric.md`의 `/goal` 종료조건 템플릿에서 `<NN_제목>`만 갈아끼운다. (단 `/goal`은 객관 rubric 검증엔 강하나 질적 완성·코드 실검증은 사람·별도 단계 필요)

### 전체 양산 커맨드 (새 세션에서 이거 하나)

```
/goal projects/semi-handbook의 "에이전트 SDK 핸드북"을 toc대로 완성한다.
[준비] 첫 턴에 content/agent_sdk/writing-brief.md 와 §0 링크 파일(handbook-toc.md,
  chapter-rubric.md, 기준 챕터 05_1·05_2, /CLAUDE.md, docs/handbook-conventions.md)을
  읽어 컨텍스트를 잡는다.
[작성] writing-brief.md §5 권장순서(Part4 → 5.3~5.5 → 정형 P2·6·8 → P0·9)대로
  미집필 챕터를 하나씩 쓴다. 각 챕터는 handbook-toc.md 방향을 출발점,
  chapter-rubric.md를 합격선, 기준 챕터(05_1·05_2)를 톤 견본으로 삼는다.
[매 턴 출력] (1) 작업 중 챕터의 rubric A1~A6 체크표(제품명·분량은 grep/줄수로 증명)
  (2) 적대적 비평가가 본 B1~B6 잔여 약점(심각도).
[완료] writing-brief.md §4의 모든 미집필 챕터가 각각: 파일 존재 · A1~A6 통과
  · B 잔여약점 심각도 '중' 이상 0개.
[코드 게이트] 코드 든 챕터는 본문 끝에 "⚠️ 코드 미검증 — 검증 레포 실행 필요"를
  남긴다. 실행 검증은 이 goal 범위 밖.
```

> 매우 긴 자율 실행이다. `/goal`로 진행 확인, `/goal clear`로 중단. 한 번에 부담되면 `[완료]`를 `Part 4(4.1~4.4)만` / `Part 5 나머지(5.3~5.5)만`처럼 **Part 단위로 좁힌다**.

1. **토대 먼저** — Part 4(상태 모델)는 Part 5의 전제이므로 5.3~5.5보다 먼저 채우면 참조가 깔끔하다.

3. **정형 챕터는 `/goal` 양산** — Part 2·6·8처럼 구조가 정형적인 챕터에 `/goal` 적합.
