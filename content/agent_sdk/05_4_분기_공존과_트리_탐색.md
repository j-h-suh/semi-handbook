# 5.4 분기 공존과 트리 탐색

## 이 챕터에서 배우는 것

- 한 부모 아래 여러 갈래가 *동시에 살아 있다*는 것 — B→C와 B→D의 공존(**TC-2**)
- 갈래는 여럿이어도 "지금 여기"는 늘 하나라는 것 — `current` 단일(**TC-3**)
- 갈래 사이를 오가는 동작 `checkout` — 그리고 그것이 *두 축을 함께* 데려가야 하는 이유
- 트리를 한눈에 보는 `show-tree`
- 왜 여러 갈래를 한 번에 섞어 보지 않는가 (5.5 정합으로 이어짐)

---

## 갈래가 둘이 되었다

5.3에서 우리는 C에서 B로 롤백하고, 거기서 lot_id 대신 wafer_id로 다시 머지해 D를 만들었다. 이제 트리는 이렇게 생겼다.

```text
  A
  └─ B
     ├─ C   (lot_id로 머지)
     └─ D   (wafer_id로 머지)  ← current
```

B 아래 C와 D가 나란히 매달려 있다. **둘 다 살아 있다.** C는 롤백했다고 사라지지 않았고(5.3의 TC-1), D는 방금 새로 났다. 같은 wafer 수율 데이터를 두고 두 가설이 동시에 트리에 존재한다 — 이게 이 책이 처음부터 노린 그림이다. 되돌리기가 공짜라, 분석가가 두 길을 *모두* 살려둔 채 비교할 수 있다.

이 공존이 인수 조건 **TC-2**다. 그런데 공존이 가능해지는 순간 새 질문이 생긴다. **여러 갈래가 있는데, "지금"은 어디인가?**

## 여러 탭, 하나의 활성 — `current`는 늘 하나 (TC-3)

5.1에서 우리는 대화를 셀, 데이터를 커널이라 했고, 5.2에서 분기를 노트북 파일 통째 복제라 했다. 그 그림을 이어 보자. 지금 우리에겐 `C.ipynb`와 `D.ipynb`, 두 노트북이 있다.

브라우저에 탭 두 개를 열어둘 순 있다. 하지만 키보드를 두드리는 *활성 탭*은 언제나 하나다. C 탭에 있으면 C의 셀과 커널을 보고, D 탭으로 옮기면 D의 셀과 커널을 본다. 동시에 둘 다 "활성"일 수는 없다.

`current`가 바로 그 활성 탭이다. 갈래는 트리에 몇이든 있어도, `current`는 늘 정확히 하나의 노드를 가리킨다. 이게 인수 조건 **TC-3**이다.

> 💡 **왜 단 하나여야 하나**: `current`가 둘이면 "지금 테이블"이 둘이 되고, 에이전트는 어느 쪽 위에서 분석하는지 알 수 없다. 5.1의 어긋남이 곧장 돌아온다. 단일 `current`는 "지금 서 있는 좌표는 모호하지 않다"는 보증이다 — 갈래가 아무리 많아도.

## `checkout` — 탭을 바꾼다, 양 축을 함께

탭을 바꾸는 동작이 **`checkout`**이다. `current`를 트리의 *임의* 노드로 옮긴다 — 조상이든, 형제든, 자손이든.

```python
async def checkout(store, duck, node_id: str, *, fresh: bool = False) -> str:
    """current를 트리의 임의 노드로 옮긴다. 두 축을 그 시점으로 함께 데려간다."""
    target = store.get_node(node_id)

    # 데이터 축: 그 노드까지 접는다 (4.4)
    replay(store, duck, node_id)

    # 대화 축: 그 노드에 묶인 세션으로 (resume) 또는 새 갈래로 (re-fork)
    session_id = (await fork_from(target.session_id)) if fresh else target.session_id

    # 단 하나의 current를 옮긴다
    store.set_current(node_id)
    return session_id
```

5.3의 `rollback`이 눈에 익을 것이다. 맞다 — **`rollback`은 조상으로 가는 `checkout`의 특수한 경우**다. 과거(조상)로 가면 롤백, 형제 C↔D로 가면 갈래 전환, 자손으로 가면 되돌렸던 길로의 복귀. 셋 다 같은 한 동작이다.

핵심은 이 함수가 **두 축을 한 번에** 옮긴다는 데 있다. D 탭에서 C 탭으로 갈 때, C의 커널(데이터)만 불러오고 셀(대화)은 D인 채로 두면 어떻게 될까. C의 테이블 위에서 D의 대화 기억으로 분석하는, 5.1이 경고한 바로 그 조용한 버그다.

> ⚠️ **`checkout`은 반드시 양 축을 함께 옮긴다.** 데이터만 바꾸고 대화를 두거나, 그 반대는 즉시 어긋남을 만든다. 탭을 바꾼다는 건 셀과 커널을 *함께* 바꾸는 일이다 — 둘 중 하나만이란 없다.

> 💡 **비유의 한계 — 우리는 커널을 N개 띄우지 않는다**: 진짜 노트북 탭 N개는 커널도 N개라 메모리가 N배다. 90GB 데이터라면 감당이 안 된다. 우리는 탭을 바꿀 때마다 `replay`로 그 시점 데이터를 *다시 접어* 만든다. 살아있는 커널은 늘 하나뿐 — 그래서 갈래가 수십이어도 메모리는 하나치다. 진짜 노트북보다 싸다.

## `show-tree` — 갈래를 본다 (TC-2)

갈래가 여럿이면 지도가 필요하다. `show-tree`는 트리를 그리고 `current`를 표시한다. 5.2에서 분기점마다 남긴 `branch_reason` 이벤트가 여기서 이정표가 된다.

```python
def show_tree(store) -> str:
    current = store.get_current()
    lines = []
    for node, depth in store.walk_preorder():          # 루트부터 전위 순회
        reason = store.branch_reason(node.id) or ""
        marker = "  ← current" if node.id == current else ""
        lines.append("  " * depth + f"{node.short_id} {reason}{marker}")
    return "\n".join(lines)
```

```text
$ show-tree
  A  (lot 원본 로드)
  └─ B  (공정 파라미터 머지 전)
     ├─ C  (lot_id로 머지)
     └─ D  (wafer_id로 머지)  ← current
```

C와 D가 둘 다 그려진다(TC-2). 그리고 `← current`는 단 한 곳에만 붙는다(TC-3). 이 한 장의 그림이 "지금 어디 있고, 어떤 길들이 살아 있는가"를 답한다.

## 왜 한 번에 하나만 보나

마지막 질문. C와 D를 *동시에* 보면 안 되나? 둘을 나란히 띄워 비교하면 편하지 않나.

결과를 *비교*하는 건 좋다 — 그건 두 갈래를 각각 접어 산출물을 옆에 놓는 일이고, 얼마든 한다. 하지만 `current`를 둘로 두는 건 다르다. C는 lot_id로 머지한 테이블이고 D는 wafer_id로 머지한 테이블이다. 두 데이터 상태를 하나의 "지금"으로 합치면, 에이전트가 딛고 선 바닥이 모호해진다. 어느 키로 합쳐진 행을 보고 있는지조차 흐려진다.

그래서 규율은 분명하다. **갈래는 공존하되, 딛는 자리는 하나다.** 여러 갈래를 살려두는 자유(TC-2)와 지금 좌표가 모호하지 않은 안전(TC-3)은 동전의 양면이다. 이 둘이 충돌 없이 맞물리려면 두 축이 늘 함께 움직여야 하는데 — 그 정합이 어디서 깨질 수 있는지, 마지막 챕터에서 정면으로 본다.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요**: 위 `checkout`·`show_tree`는 설계 초안이다. `walk_preorder`의 순회 순서, `branch_reason` 조회, `fresh` 분기 시 세션 귀속은 검증 레포에서 돌려 확인해야 한다.

## 핵심 정리

- **갈래는 공존한다 (TC-2).** 한 부모 아래 C와 D가 동시에 살아, 같은 데이터를 둔 두 가설을 모두 남겨 비교할 수 있다 — 되돌리기가 공짜라 가능한 일이다.
- **`current`는 늘 하나다 (TC-3).** 갈래가 몇이든 활성 탭은 하나. 단일 `current`가 "지금 좌표는 모호하지 않다"를 보증한다.
- **`checkout`은 두 축을 함께 옮긴다.** `rollback`은 조상으로 가는 그 특수 경우일 뿐. 데이터만, 혹은 대화만 옮기면 5.1의 어긋남이 즉시 돌아온다.
- **공존과 단일 `current`는 한 쌍이다.** 여러 길을 살려두는 자유와 지금 자리가 분명한 안전은 두 축이 함께 움직일 때만 충돌 없이 맞물린다 — 그 경계가 5.5.
