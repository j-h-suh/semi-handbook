## 1. 한 줄 미션

에이전트에 *어떤 기억을 어떻게 설계해 줄지* 판단하고 직접 구현하는 **설계서**. 프레임워크 카탈로그가 아니다. 컨셉: **"도구는 바뀐다, 기억의 원리는 남는다."**

## 2. 절대 가드레일

- **직교** — 원리 → 의사결정 → 직접 구현. **프레임워크 사용법 나열 금지**(Part 6도 원리로 분류·평가). 자매서(Agent SDK·클로드 핸드북) 메커니즘은 재설명하지 않는다.
- **도메인** — 반도체 데이터 분석 예제 유지(lot 수율 등). 내부 제품명 0건.
- **톤** — 평서체 `~다`. 중심 비유 1개 + 한계. 기준 챕터(04_3)의 결.
- **닫기** — 원리·이론으로 끝내지 말고 "그래서 내 메모리를 어떻게"로 의사결정·구현에 잇는다.

## 3. 작성 방식

- 챕터 하나씩, `chapter-rubric.md`의 A1~A6 + B1~B7 통과까지.
- 매 챕터 = `handbook-toc.md`의 챕터 줄을 *출발점*, `chapter-rubric.md`를 *합격선*, 기준 챕터(04_3)를 *톤 견본*으로.

### 전체 양산 커맨드 (새 세션에서 이거 하나)

```
/goal projects/semi-handbook의 "에이전트 메모리 핸드북"을 toc대로 완성한다.
[준비] 첫 턴에 content/memory/writing-brief.md 와 §0 링크 파일(handbook-toc.md,
  chapter-rubric.md, 기준 챕터 04_3, /CLAUDE.md, docs/handbook-conventions.md)을 읽어
  컨텍스트를 잡는다.
[작성] writing-brief.md §5 권장순서대로 미집필 챕터를 하나씩 쓴다. 각 챕터는
  handbook-toc.md 방향을 출발점, chapter-rubric.md를 합격선, 기준 챕터(04_3)를
  톤 견본으로 삼는다.
[매 턴 출력] (1) 작업 중 챕터의 rubric A1~A6 체크표(제품명·분량은 grep/줄수로,
  프레임워크 사용법 나열 0 확인) (2) 적대적 비평가가 본 B1~B7 잔여 약점(심각도).
[완료] writing-brief.md §4의 모든 미집필 챕터가 각각: 파일 존재 · A1~A6 통과
  · B 잔여약점 심각도 '중' 이상 0개.
[코드 게이트] 코드(특히 Part 5)가 든 챕터는 본문 끝에 "⚠️ 코드 미검증 —
  검증 레포 실행 필요"를 남긴다. 실행 검증은 이 goal 범위 밖.
```

> 매우 긴 자율 실행. `/goal`로 진행 확인, `/goal clear`로 중단. 부담되면 `[완료]`를 Part 단위(예: `Part 4(4.1·4.2·4.4)만`)로 좁힌다.

## 5. 권장 작성 순서 (원칙)

1. **원리 기초 먼저** — Part 1·2·3(유형·저장·인출). 4장이 그 위에 선다.
2. **무게중심 4장 완성** — 4.1·4.2·4.4 (4.3 기준 챕터는 완성됨).
3. **5장 직접 만들기** — 1~4의 원리를 mini로 구현. 5.3에서 프레임워크로 다리.
4. **적용** — Part 6(프레임워크)·7(Claude). 6은 5의 원리로 평가.
5. **도입·실전 마지막** — Part 0과 8.1은 전체를 조망한 뒤 써야 잘 나온다.

## 6. 하지 말 것

- 프레임워크 *사용법* 나열 (→ 원리로 분류·평가)
- 자매서(Agent SDK·클로드)와 중복되는 메커니즘 서술
- 내부 제품명 노출
- 원리·이론 나열로 끝내기 (→ 의사결정·구현으로 닫기)
- 검증 안 된 코드를 "확정 코드"처럼 제시
