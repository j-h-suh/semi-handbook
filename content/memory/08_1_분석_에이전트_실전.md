# 8.1 분석 에이전트에 기억을 붙이다 — 처음부터 끝까지 + 회고

## 이 챕터에서 배우는 것

- Part 1~7의 원리를 분석 에이전트 하나에 처음부터 끝까지 엮기
- 다섯 결정을 한 시나리오에서 실제로 내려보기
- 한 분석 요청이 기억을 통해 흐르는 전체 장면
- 돌려본 뒤의 회고 — 무엇이 갈리고 무엇이 남는가

---

## 7.2에서 8.1로

여기까지 원리(Part 1~4), 직접 구현(Part 5), 도구 평가(Part 6~7)를 모두 봤다. 조각은 다 모였다.

이제 하나로 엮는다. 반도체 fab의 lot 수율을 분석하는 에이전트에 기억을 붙이는 일을, 결정부터 회고까지 처음부터 끝까지 따라가 본다. 이 챕터는 새 원리를 더하지 않는다 — 앞의 모든 장을 한 자리에 *조립*한다.

## 준공과 입주 (비유)

Part 1~7이 설계도와 자재, 부품이었다면, 이 챕터는 **준공**이다.

기초(어떤 유형의 기억인가)를 놓고, 골조(어디에 저장)를 세우고, 배관(어떻게 인출)을 깔고, 안전장치(망각과 시간)를 단다. 따로 보던 것들을 한 건물로 올려 *입주 가능한* 상태로 만드는 일이다.

> 💡 **비유의 한계**: 준공검사를 통과한 건물도, 살아봐야 하자가 드러난다 — 겨울에 결로가 생기고, 동선이 불편한 게 보인다. 메모리 설계도 같다. 돌려보기 전에는 안 보이던 빈틈이, 실제 분석을 몇 번 거치면 드러난다. 그래서 이 챕터는 준공에서 끝나지 않고 *입주 후 점검*, 즉 회고까지 간다. 설계는 한 번에 완성되지 않는다.

## 다섯 결정을 내린다

lot 수율 분석 에이전트를 짓는다고 하자. 0.3에서 본 다섯 결정을 차례로 내린다.

1. **유형(Part 1)** — 무엇을 어느 갈래에 둘까. lot의 수율 값은 *시맨틱*(사실), "3월에 lot_A를 분석해 이상치를 찾았다"는 *에피소딕*(사건), "수율 이상이면 장비부터 본다"는 *절차적*(방법).
2. **저장(Part 2)** — poly-store로 간다. 사실은 bi-temporal 표에, 분석 노트는 벡터에, lot–장비 연결은 그래프에.
3. **인출(Part 3)** — 하이브리드. 유사도·시간(`as_of`)·관계를 각각 돌려 RRF로 합치고, 컨텍스트 예산에 맞춰 자른다.
4. **망각·시간(Part 4)** — 갱신은 무효화로, 결론에는 의존성과 시점을 박아 원천이 바뀌면 stale 표시.
5. **도구(Part 6~7)** — Claude memory tool을 인터페이스로 쓰되, 그 백엔드에 위 bi-temporal을 직접 구현한다. 세션 회고는 플러그인 층에 맡긴다.

이 다섯이 한 인터페이스로 모이면 이런 골격이 된다.

```python
class AnalysisMemory:
    """Part 1~7을 하나로 엮은 분석 메모리 골격."""

    def remember_fact(self, subject, value, valid_from, at):
        ...  # 5.2: 같은 subject의 옛 기록을 무효화하고 새 사실을 추가 (4.2)

    def remember_episode(self, text, at):
        ...  # 에피소딕 사건을 벡터로 (1.2·2.1)

    def remember_conclusion(self, claim, depends_on, as_of):
        ...  # 파생 결론에 의존성·시점을 박는다 (4.4)

    def recall(self, query, as_of, k=5):
        ...  # 유사도+시간+관계를 RRF로 합쳐 예산만큼 (3.3)

    def on_fact_changed(self, subject):
        ...  # 바뀐 사실에 기댄 결론을 stale로 (4.4)
```

각 메서드 이름 옆 주석이 그것이 어느 Part에서 왔는지 가리킨다. 흩어져 배운 원리가 여기 한 클래스에 모였다.

## 한 장면이 흐른다

이제 실제 요청 하나를 흘려보자. 사용자가 묻는다 — "지난 분기 lot들 수율이 왜 낮았지?"

```python
mem = AnalysisMemory()

# 1) 떠올린다 — 그 분기 시점의 시야로, 세 축을 합쳐 (3.3)
context = mem.recall("분기 수율 저하 원인", as_of="2026-04-01", k=5)
#   → 과거 유사 분석(유사도) + 그 무렵 lot 측정(시간) + 공통 장비(관계)

# 2) 분석하고, 결과를 기억한다
mem.remember_episode("2026 1분기 수율 저하 분석: equip_X 과열 의심", at="2026-04-02")
mem.remember_conclusion("1분기 평균 수율 91%, 원인 equip_X",
                        depends_on=["lot_A", "lot_B", "lot_C"], as_of="2026-04-02")

# 3) 한 달 뒤, 원천이 정정된다
mem.remember_fact("lot_A.yield", 0.89, valid_from="2026-03", at="2026-05-10")  # 92→89
mem.on_fact_changed("lot_A")   # → "1분기 평균 91%" 결론이 stale로 표시된다
```

기억이 분석의 *흐름*에 녹아 있다. 떠올려 분석을 돕고(recall), 결과를 남기고(remember_*), 원천이 흔들리면 옛 결론에 깃발을 세운다(on_fact_changed). 그리고 결정적으로, lot_A가 89%로 정정돼도 4월 2일의 결론은 *지워지지 않는다* — `as_of`와 함께 남아, "그때는 왜 91%였나"에 답한다. 4.3에서 말한 그 변호가, 완성된 에이전트에서 실제로 작동한다.

## 돌려보고 회고한다

준공했으니 살아본다. 몇 번 돌려보면 회고가 나온다.

- **잘 된 것** — `as_of` 덕에 과거 분석을 그 시점 시야로 재현하고, 정정이 들어와도 옛 결론을 변호한다. 분석의 신뢰성이라는 가장 중요한 칸이 채워졌다.
- **남은 함정** — 무엇을 기억할지의 판단(1.3)은 여전히 사람 손이 간다. 너무 적게 남기면 다음 분석이 맥락을 잃고, 너무 많이 남기면 인출이 시끄럽다. 이 경계는 도메인을 돌려보며 조율할 수밖에 없다.
- **다음 일** — 절차적 기억(점검 순서)을 분석 성공·실패에서 자동으로 다듬는 것은 아직 숙제다. 자동 추출을 어디까지 믿을지도.

회고가 설계의 일부라는 게 핵심이다. 건물을 살아봐야 하자가 보이듯, 메모리도 돌려봐야 빈틈이 보인다. 그 빈틈이 다음 설계의 출발점이 된다.

## 그래서 — 원리가 남는다

이 에이전트의 구체적 구현은 영원하지 않다. 6개월 뒤 더 나은 도구가 나오면 `AnalysisMemory`의 속은 갈아끼워질 것이다. 그러나 다섯 결정의 *원리* — 유형을 가르고, 인출에서 역산해 저장하고, 하이브리드로 떠올리고, 무효화로 갱신하고, 시점을 박는 것 — 은 남는다.

이 책 전체가 그 한 문장을 향했다. 유형(1)에서 시작해 저장(2)·인출(3)을 거쳐 무게중심인 잊기·시간(4)에 이르고, 손으로 구현하고(5), 도구를 평가하고(6·7), 끝내 하나로 엮었다(8). **도구는 바뀐다, 기억의 원리는 남는다.**

남은 것은 이 여정의 다음 자리를 가리키는 일뿐이다. 에필로그로 간다.

> ⚠️ **코드 미검증 — 검증 레포 실행 필요.** 위 `AnalysisMemory`는 Part 1~7을 한 인터페이스로 종합한 골격으로, 메서드 속이 비어 있다(앞 장들의 구현을 조립하면 채워진다). Part 5의 모든 코드와 마찬가지로 별도 검증 레포에서 실행·확인해야 한다.

## 핵심 정리

- **실전은 다섯 결정의 조립이다.** 유형·저장·인출·망각·도구를 한 시나리오에서 차례로 내리면, 흩어진 원리가 하나의 `AnalysisMemory` 골격으로 모인다.
- **기억은 분석의 흐름에 녹는다.** 떠올려 분석을 돕고, 결과를 남기고, 원천이 흔들리면 옛 결론에 stale 깃발을 세우되 — `as_of`와 함께 지우지 않는다.
- **회고가 설계의 일부다.** 살아봐야 하자가 보이듯, 돌려봐야 저장 가치 판단·절차 학습 같은 빈틈이 드러나고, 그게 다음 설계의 출발점이 된다.
- **구현은 갈려도 원리는 남는다.** 도구가 바뀌면 속은 갈아끼워지지만, 다섯 결정의 원리는 그대로다 — 이 책 전체의 결론이다.
