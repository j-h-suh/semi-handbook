## 1.3에서 2.1로

1장에서 우리는 무엇을 어느 갈래(에피소딕·시맨틱·절차적)에 넣을지 정했다. 갈래를 갈랐으니, 이제 질문은 *물리적으로 어떻게 담느냐*로 넘어간다.

시맨틱 기억부터 보자. 시맨틱은 사실과 개념의 기억이고, 우리는 그것을 보통 *의미로* 떠올린다. "수율 떨어진 lot 있었나?"라고 물으면 글자가 정확히 일치하는 기록이 아니라 *의미가 비슷한* 기록을 꺼내고 싶다. 그러려면 의미를 다룰 수 있는 저장이 필요하다.

## 의미를 좌표로 바꾼다

문제를 또렷이 해 보자. "lot A 수율 이상"과 "lot A 양품률 저하"는 글자가 다르지만 거의 같은 말이다. 키워드 매칭으로는 이 둘을 잇지 못한다 — 겹치는 단어가 "lot A"뿐이다.

여기서 **임베딩(embedding)**이 등장한다. 임베딩은 텍스트를 고차원 벡터(숫자의 배열)로 바꾸는 함수다. 핵심은 학습 방식에 있다 — *의미가 비슷한 텍스트일수록 벡터가 가깝도록* 훈련된다. 그래서 "수율 이상"과 "양품률 저하"는 글자가 달라도 벡터 공간에서 이웃이 된다.

비유하면 임베딩은 **지도 위의 좌표**를 매기는 일이다. 모든 문장에 좌표를 주되, 의미가 비슷한 문장끼리 가까운 자리에 찍는다. 그러면 "비슷함"이라는 모호한 관계가 "가까움"이라는 잴 수 있는 거리로 바뀐다. 검색은 이제 "의미가 통하는 걸 찾아라"가 아니라 "좌표가 가까운 걸 찾아라"가 된다.

## 가까움을 재는 법

좌표가 생겼으니 거리를 재야 한다. vector store에서 가장 흔히 쓰는 척도는 **코사인 유사도(cosine similarity)** — 두 벡터가 이루는 *각도*다.

$$\text{sim}(a, b) = \cos\theta = \frac{a \cdot b}{\|a\|\,\|b\|}$$

여기서 $a, b$는 두 임베딩 벡터, $a \cdot b$는 내적(코드의 `a @ b`), $\|a\|$는 벡터의 길이다. 값은 $-1$부터 $1$까지다 — 방향이 완전히 같으면 1, 직교하면 0, 정반대면 -1이다.

왜 유클리드 거리가 아니라 각도일까. 많은 임베딩에서 벡터의 *방향*이 의미를 담고 *길이*는 들쭉날쭉해 의미와 덜 묶이기 때문이다. 같은 뜻을 길게 쓰든 짧게 쓰든 방향은 비슷해야 하므로, 길이에 휘둘리지 않는 각도가 더 안정적이다. (길이를 1로 정규화한 임베딩이라면 코사인과 유클리드 순위는 같아져, 어느 쪽을 써도 무방하다.)

## 최소 vector store

원리를 코드 몇 줄로 박아 보자. 임베딩 모델 호출 자체는 `embed()`로 추상화하고 — 그건 모델마다 다르니 — 우리가 직접 짜는 것은 *저장*과 *유사도 인출*이다.

```python
import numpy as np

# embed(): 텍스트 → 고차원 벡터. 실제로는 임베딩 모델 호출(여기선 추상화).
def embed(text: str) -> np.ndarray: ...

def cosine(a: np.ndarray, b: np.ndarray) -> float:
    """두 벡터의 코사인 유사도. 방향이 같을수록 1에 가깝다."""
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))

# 저장: (원문, 벡터) 쌍을 쌓아둔다
memory: list[tuple[str, np.ndarray]] = []
for note in ["lot A 수율 이상 관찰", "장비 X 교정 완료", "lot B 양품률 저하"]:
    memory.append((note, embed(note)))

# 인출: 질의와 가장 가까운 top-k 기록
def recall(query: str, k: int = 2) -> list[str]:
    q = embed(query)
    scored = sorted(
        ((cosine(q, vec), text) for text, vec in memory),
        reverse=True,
    )
    return [text for _, text in scored[:k]]

recall("수율이 떨어진 lot")  # → ["lot A 수율 이상 관찰", "lot B 양품률 저하"]
```

실제 vector store(예: 그 흔한 벡터 데이터베이스들)는 여기에 색인을 얹어 수백만 개 중에서도 빠르게 top-k를 찾도록 최적화한 것일 뿐, *원리는 위 열몇 줄과 같다.* "장비 X 교정"이 결과에서 빠진 것을 보자 — 글자로는 "lot"이 안 겹쳐도, 의미로 수율과 무관하기 때문에 멀리 찍힌 것이다.

## vector store가 못 하는 것

유사도 검색은 강력하지만, 만능이 아니다. 오히려 *못 하는 것*을 아는 게 설계에서 더 중요하다.

- **정확 조회**가 약하다. "정확히 lot A의 기록만"을 원하면 유사도가 아니라 일치 검색이어야 한다. 의미가 비슷한 lot B까지 딸려 온다.
- **시간**을 모른다. "가장 최근 분석"은 좌표의 가까움과 무관하다. 에피소딕 기억이 원하는 시간순 인출은 벡터로 안 된다.
- **관계**를 모른다. "lot A와 같은 장비를 쓴 lot들"처럼 연결을 따라가는 질문도 유사도 밖이다.
- **진위**를 모른다. 의미가 가까워도 사실이 *틀린* 기록일 수 있다. 유사도는 가까움만 알지 옳고 그름은 모른다.

> 💡 **비유의 한계**: 지도 좌표는 2차원이고 거리가 물리적 실재다. 임베딩 공간은 수백~수천 차원이고, 그 "거리"는 모델이 학습으로 *만들어낸* 의미 구조의 투영일 뿐이다. 그래서 임베딩 모델을 바꾸면 좌표 전체가 바뀐다 — 쌓아둔 기억을 통째로 다시 임베딩해야 한다. 지도를 새로 그리는 일이 공짜가 아니듯, 모델 교체도 그렇다.

## 그래서 — 시맨틱엔 맞지만 전부는 아니다

vector store는 시맨틱 기억의 기본 살림이다. 사실을 의미로 떠올려야 하는 한, 가장 먼저 손이 가는 도구다.

하지만 방금 봤듯, 1.2의 세 갈래 중 시맨틱 *하나*에 주로 맞는다. 에피소딕이 원하는 시간순, 그리고 사실들 사이의 관계는 다른 저장 구조가 더 잘 담는다. 그래서 내 메모리를 설계할 때 첫 결정은 이렇게 선다 — 의미 유사가 인출의 주축이면 vector store를 깔되, *그것만으로는* 정확 조회·시간·관계를 못 한다는 걸 전제하고 다른 저장과 섞을 준비를 한다.

그 "다른 저장"의 첫째가 관계와 시간을 담는 그래프다. 다음 챕터로 넘어간다.

## 핵심 정리

- **임베딩은 "비슷함"을 "가까움"으로 바꾼다.** 텍스트를 좌표로 매겨, 의미 유사를 거리 계산이라는 다룰 수 있는 문제로 만든다.
- **코사인 유사도는 길이가 아니라 방향을 잰다.** 임베딩에서 의미는 방향에 담기므로, 길이에 휘둘리지 않는 각도가 안정적이다.
- **vector store의 원리는 열몇 줄이다.** 실제 제품은 거기에 색인·확장성을 얹은 것일 뿐, 핵심은 저장과 top-k 인출이다.
- **유사도는 정확 조회·시간·관계·진위를 모른다.** 그래서 vector store는 시맨틱 기억에 맞되 전부가 아니며, 다른 저장과 섞을 것을 전제로 깐다.
