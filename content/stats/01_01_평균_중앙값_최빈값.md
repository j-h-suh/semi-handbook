# 1.1 평균, 중앙값, 최빈값 — mean()의 함정

## 이 챕터에서 배우는 것

- 평균(mean), 중앙값(median), 최빈값(mode)이 각각 "대표값"으로서 갖는 성격 차이
- `np.mean()`을 습관적으로 쓸 때 어떤 함정에 빠지는지
- 손실함수 선택(MSE vs MAE)이 사실은 "어떤 대표값을 믿을 것인가"의 문제라는 것
- 왜도(skewness)가 이 세 값의 관계를 어떻게 바꾸는지

---

## np.mean()을 치기 전에

데이터를 받으면 가장 먼저 뭘 하는가?

```python
df.describe()
```

여기서 첫 번째로 눈이 가는 숫자가 `mean`이다. 당연하다. 우리는 학교에서 "평균"을 세상에서 가장 자연스러운 요약 방법으로 배웠다. 시험 평균, 키 평균, 연봉 평균. 데이터를 하나의 숫자로 요약하라고 하면 본능적으로 평균을 떠올린다.

그런데 이 본능이 ML에서는 종종 문제를 일으킨다.

한 가지 상황을 보자. 어떤 반도체 공정에서 웨이퍼 50장의 overlay 오차를 측정했다. 49장은 1~3 nm 범위에 깔끔하게 분포하는데, 딱 1장이 45 nm짜리 이상치다. 장비 이상이든 측정 오류든 이유는 모르겠고, 일단 데이터에 들어가 있다.

```
[1.2, 1.5, 1.8, 2.1, 2.3, ..., 2.8, 3.0, 45.0]  # 50개
```

`np.mean()`을 치면? 약 2.9 nm. 49장의 실제 수준(~2.0 nm)보다 거의 1 nm나 뻥튀기된 값이 나온다. 단 하나의 이상치가 평균을 끌어올린 것이다.

`np.median()`을 치면? 약 2.1 nm. 이상치의 영향을 거의 받지 않는다.

이것이 평균의 첫 번째 함정이다. **평균은 이상치에 취약하다.** 통계학에서는 이를 **비강건(Non-robust)**하다고 말한다.

## 세 가지 대표값의 성격

"데이터를 하나의 숫자로 요약하라"는 주문에 대해, 통계학은 세 가지 다른 철학을 제시한다.

### 평균 (Mean): 무게중심

평균은 데이터의 **무게중심**이다. 물리학에서 질량 분포의 중심을 구하는 것과 같다.

$$\bar{x} = \frac{1}{n} \sum_{i=1}^{n} x_i$$

모든 데이터 포인트가 평균에 "힘"을 행사한다. 값이 클수록 더 세게 당긴다. 그래서 이상치 하나가 전체 평균을 확 끌어갈 수 있다. 이건 버그가 아니라 평균의 본질적인 성질이다.

평균의 좋은 점은 **수학적으로 다루기 쉽다**는 것이다. 미분 가능하고, 합과 곱에 대해 예쁜 성질들을 갖는다. 통계학의 거의 모든 이론이 평균 위에 세워진 이유다. 나중에 배울 기댓값(Expected Value), 분산, 정규분포 전부가 평균을 중심으로 돌아간다.

### 중앙값 (Median): 줄 세우기의 한가운데

데이터를 크기 순서로 줄 세웠을 때 정확히 가운데 있는 값이다.

- 데이터가 홀수 개면: 가운데 하나
- 데이터가 짝수 개면: 가운데 두 개의 평균

중앙값의 핵심 성질은 **이상치에 강건(robust)**하다는 것이다. 아까 그 45 nm 이상치를 450 nm로 바꿔도, 100,000 nm로 바꿔도, 중앙값은 꿈쩍도 안 한다. 가운데 위치가 바뀌지 않으니까.

대신 중앙값은 수학적으로 다루기 까다롭다. "순서"에 의존하는 값이라 미분이 안 되고, 이론적 성질을 유도하기 어렵다. 이것이 통계학 교과서에서 평균이 주인공이고 중앙값이 조연인 이유다.

### 최빈값 (Mode): 가장 인기 있는 값

데이터에서 가장 빈번하게 등장하는 값이다.

솔직히 연속형 데이터에서 최빈값을 직접 계산할 일은 거의 없다. 연속 변수에서는 정확히 같은 값이 반복될 확률이 0에 가까우니까. 하지만 **분포의 봉우리(peak)**라는 개념으로 확장하면 이야기가 달라진다.

<!-- [DIAGRAM: 세 가지 대표값을 하나의 분포 위에 표시한 그림. 오른쪽으로 꼬리가 긴(right-skewed) 분포에서 mode < median < mean 순서로 위치. 각 값에 화살표와 레이블.] -->

위 그림에서 보듯, 분포가 대칭이면 세 값은 같다. 하지만 분포가 한쪽으로 치우치면(skewed) 세 값이 서로 다른 위치에 놓인다. 이 **차이 자체**가 데이터의 형태에 대한 정보를 준다.

## ML에서 이것이 중요한 진짜 이유: 손실함수

여기서부터가 핵심이다. 지금까지의 이야기가 "통계 교양" 수준이었다면, 이제 ML 실무와 직접 연결된다.

질문 하나. `sklearn`에서 회귀 모델을 학습할 때, 기본 손실함수가 뭔가?

MSE(Mean Squared Error)다.

$$\text{MSE} = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2$$

MSE를 최소화하는 예측값 $\hat{y}$가 뭔지 아는가? **평균이다.** 만약 모델이 아무 피처도 안 쓰고 하나의 상수만 예측한다면, MSE를 최소화하는 상수는 정확히 $\bar{y}$, 즉 타겟의 평균이다.

그러면 MAE(Mean Absolute Error)를 최소화하는 예측값은?

$$\text{MAE} = \frac{1}{n} \sum_{i=1}^{n} |y_i - \hat{y}_i|$$

**중앙값이다.**

MSE는 모든 편차의 "무게"에 반응하는 균형점(= 평균)을 찾고, MAE는 데이터의 "어느 쪽에 있느냐"만 세는 중간점(= 중앙값)을 찾는다. 이 차이가 이상치에 대한 민감도 차이의 근본 원인이다.

<details>
<summary>🔬 Deep Dive — 왜 MSE 최적해는 평균이고, MAE 최적해는 중앙값인가?</summary>

**MSE → 평균**

상수 $c$에 대해 MSE를 미분하면:

$$\frac{\partial}{\partial c} \frac{1}{n} \sum_{i=1}^{n} (y_i - c)^2 = \frac{-2}{n} \sum_{i=1}^{n} (y_i - c) = 0$$

이것을 $c$에 대해 풀면:

$$\sum_{i=1}^{n} (y_i - c) = 0 \quad \Rightarrow \quad c = \frac{1}{n}\sum_{i=1}^{n} y_i = \bar{y}$$

제곱 손실을 미분하면 "모든 데이터까지의 편차 합 = 0"이 되는 지점을 찾게 된다. 그것이 평균이다. 양쪽 편차가 정확히 상쇄되는 **균형점**. 문제는, 이 균형점이 이상치의 거대한 편차에 의해 끌려간다는 것이다. 45 nm짜리 하나가 나머지 49개의 작은 편차들을 압도해 버린다.

**MAE → 중앙값**

$|y_i - c|$는 $c = y_i$에서 미분이 안 된다. 대신 이렇게 생각하자.

$c$를 약간 오른쪽으로 옮기면 어떤 일이 벌어지는가? $c$보다 왼쪽에 있는 $k$개의 데이터는 거리가 1씩 늘어나고, 오른쪽에 있는 $(n-k)$개는 거리가 1씩 줄어든다. 총 변화량은 $k - (n-k) = 2k - n$이다.

- $k < n/2$이면 (왼쪽에 절반 미만) → 총 거리가 줄어든다 → 오른쪽으로 더 가야 한다
- $k > n/2$이면 (왼쪽에 절반 초과) → 총 거리가 늘어난다 → 왼쪽으로 돌아가야 한다
- $k = n/2$이면 → 움직여도 이득이 없다 → **최적점**

즉, MAE가 최소가 되는 지점은 **데이터의 절반이 왼쪽에, 절반이 오른쪽에 있는 지점** — 중앙값이다. 각 데이터가 최적점에 미치는 영향은 **"얼마나 멀리 있느냐"가 아니라 "어느 쪽에 있느냐"**뿐이다. 45 nm짜리든 4,500 nm짜리든, 오른쪽에 있다는 사실은 같으므로, 중앙값은 움직이지 않는다.

</details>

이것이 의미하는 바를 잠깐 생각해 보자.

**손실함수를 선택하는 것은, "어떤 대표값을 더 신뢰하는가"를 선택하는 것이다.**

MSE를 쓴다는 것은 "나는 평균을 믿는다"고 선언하는 것이고, MAE를 쓴다는 것은 "나는 중앙값을 믿는다"고 선언하는 것이다.

<!-- [GRAPH: 동일한 skewed 분포 데이터에 대해 MSE 최적 예측(평균)과 MAE 최적 예측(중앙값)을 각각 수직선으로 표시. 이상치가 MSE 최적 예측을 얼마나 끌어가는지 시각적으로 보여주는 그림.] -->

이상치가 많은 데이터에서 MSE로 학습하면, 모델이 이상치 쪽으로 끌려간다. 평균이 이상치에 끌려가는 것과 같은 원리다. 이럴 때 MAE나 **후버 손실(Huber Loss)** — MSE와 MAE의 절충안으로, 작은 오차에는 제곱, 큰 오차에는 절대값을 적용한다 — 로 바꾸면 성능이 극적으로 올라가는 경우가 있다. 이유를 몰랐다면 이제 알게 된 것이다. 손실함수를 바꾼 것이 아니라, **"대표값의 철학"을 바꾼 것**이다.

## 왜도: 세 값의 간격이 말해주는 것

분포가 대칭이면 평균 = 중앙값 = 최빈값이다. 현실에서 데이터가 완벽히 대칭인 경우는 거의 없다. 대부분은 한쪽으로 꼬리가 길다.

**왜도(Skewness)**는 이 비대칭의 정도를 수치화한 것이다.

$$\text{Skewness} = \frac{1}{n} \sum_{i=1}^{n} \left( \frac{x_i - \bar{x}}{s} \right)^3$$

세제곱을 쓰는 이유가 있다. 제곱은 부호를 없애지만, 세제곱은 부호를 보존한다. 평균보다 큰 값은 양수, 작은 값은 음수로 기여하므로, 어느 쪽 꼬리가 더 무거운지가 합산 결과에 반영된다.

| 왜도 | 형태 | 대표값 관계 | ML에서 흔히 만나는 예시 |
|------|------|------------|----------------------|
| ≈ 0 | 대칭 | mean ≈ median ≈ mode | 정규화된 피처, 잔차 (이상적) |
| > 0 (양의 왜도) | 오른쪽 꼬리 | mode < median < mean | 가격 데이터, 응답 시간, 결함 수 |
| < 0 (음의 왜도) | 왼쪽 꼬리 | mean < median < mode | 만족도 점수 (대부분 높고 일부 낮음) |

![분포 형태에 따른 대표값의 위치](/content/images/stats/01_01/central_tendency_comparison.svg)

ML 실무에서 왜도를 왜 신경 써야 하는가? 두 가지 이유가 있다.

**첫째, 피처 전처리.** 왜도가 큰 피처를 그대로 선형 모델에 넣으면 성능이 떨어진다. `np.log1p()`로 로그 변환을 하면 양의 왜도가 줄어든다. 로그가 **"큰 값일수록 덜 키우는"** 함수이기 때문이다. 오른쪽으로 길게 뻗은 꼬리는 압축되고, 왼쪽에 뭉쳐 있던 값들은 펼쳐진다. 결과적으로 분포가 대칭에 가까워진다.

<details>
<summary>🔬 Deep Dive — 로그 변환이 양의 왜도를 줄이는 원리</summary>

$\log(10) = 1$, $\log(100) = 2$, $\log(1000) = 3$. 10배씩 커져도 로그 값은 1씩만 커진다. 이것이 양의 왜도를 가진 분포에 마법처럼 작동하는 이유다.

양의 왜도 = 오른쪽 꼬리가 길다 = 큰 값들이 드문드문 멀리 퍼져 있다. 로그를 씌우면:
- 왼쪽에 뭉쳐 있는 작은 값들 (1~10) → 0~1로 변환. 간격이 상대적으로 넓어진다.
- 오른쪽으로 길게 뻗은 큰 값들 (100~1000) → 2~3으로 변환. 간격이 극적으로 좁아진다.

결과적으로 길었던 오른쪽 꼬리는 압축되고, 뭉쳐 있던 왼쪽은 펼쳐진다. 분포가 대칭에 가까워지는 것이다.

<!-- [DIAGRAM: 로그 변환 전후 비교. 왼쪽: 양의 왜도가 심한 분포(오른쪽 꼬리 긺). 가운데: y=log(x) 함수 곡선, 작은 x 구간은 y가 빠르게 증가하고 큰 x 구간은 y가 천천히 증가하는 것을 화살표로 표시. 오른쪽: 로그 변환 후 대칭에 가까워진 분포.] -->

효과적인 조건도 명확해진다. 데이터가 **양수이고, 오른쪽 꼬리가 길 때**. 이미 대칭인 데이터에 로그를 씌우면 오히려 왼쪽으로 왜도가 생긴다. 음수가 있으면 로그 자체가 정의되지 않는다 (`log1p`를 쓰는 이유가 이것이다 — $\log(1+x)$로 0 이상의 값에 적용 가능하게 만든 것).

</details>

**둘째, 타겟 변수 진단.** 회귀 타겟이 심하게 skewed되어 있으면, MSE 손실함수(= 평균 기반)가 소수의 극단값에 과도하게 반응한다. 이때 두 가지 전략이 있다. **로그 변환은 분포의 모양을 바꿔서 평균이 중앙값에 가까워지게 만드는 것**이고, **MAE 전환은 아예 중앙값을 기준으로 학습하겠다고 선언하는 것**이다. 같은 문제에 대한 서로 다른 각도의 해법이다.

## 가중평균: 평균의 확장

ML에서 "단순 평균"보다 훨씬 자주 마주치는 것이 **가중평균(Weighted Mean)**이다.

$$\bar{x}_w = \frac{\sum_{i=1}^{n} w_i \cdot x_i}{\sum_{i=1}^{n} w_i}$$

어디서 많이 본 형태 아닌가?

- **클래스 불균형 처리**: `class_weight='balanced'`를 쓰면, 소수 클래스의 샘플에 더 큰 가중치를 준다. 이것은 손실의 가중평균을 바꾸는 것이다.
- **앙상블 모델**: 여러 모델의 예측을 합칠 때 `weights=[0.3, 0.5, 0.2]` 같이 가중치를 주는 것.
- **Attention 메커니즘**: Transformer의 self-attention은 본질적으로 value 벡터의 가중평균이다. 가중치가 query-key 유사도에서 나올 뿐이다.

가중치를 어떻게 정하느냐가 곧 "무엇이 더 중요한가"에 대한 설계자의 판단이다. 클래스 불균형에서는 희소 클래스의 중요도를, 앙상블에서는 개별 모델의 신뢰도를, Attention에서는 문맥적 관련성을 가중치로 인코딩한다. 가중평균의 수식은 같지만, **가중치의 출처가 달라지면 전혀 다른 의미의 평균이 된다.**

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V$$

softmax 출력이 가중치, V가 값이라고 보면, Attention의 출력은 **V의 가중평균**이다. Transformer를 매일 쓰면서 가중평균을 "기초 통계"라고 무시할 수는 없는 노릇이다.

## 조화평균과 기하평균: 쓰고 있었는데 몰랐던 것

평균에는 사실 여러 종류가 있다. ML에서 자주 쓰이는 두 가지를 더 짚고 넘어가자.

### 기하평균 (Geometric Mean)

$$\bar{x}_{\text{geo}} = \left( \prod_{i=1}^{n} x_i \right)^{1/n}$$

로그 스케일에서의 산술평균과 같다. 비율이나 성장률의 평균을 낼 때 쓴다. 직접 계산할 일은 드물지만, **로그 변환 후 평균 → 역변환** 과정이 사실은 기하평균을 구하는 것이라는 점은 알아두면 좋다.

### 조화평균 (Harmonic Mean)

$$\bar{x}_{\text{harm}} = \frac{n}{\sum_{i=1}^{n} \frac{1}{x_i}}$$

이건 확실히 쓰고 있다. **F1-score**가 뭔가?

$$F_1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$$

이것이 바로 Precision과 Recall의 **조화평균**이다.

왜 산술평균이 아니라 조화평균을 쓸까? 산술평균은 하나가 극단적으로 높으면 다른 하나가 낮아도 평균이 그럭저럭 나온다. Precision = 0.99, Recall = 0.01이면 산술평균은 0.50이다. "반은 맞췄다"는 뉘앙스. 하지만 조화평균은 0.02다. 한쪽이 처참하면 가차 없이 값이 내려간다.

조화평균은 **"둘 다 높아야만 높은 값이 나오는"** 평균이다. F1-score가 조화평균인 이유가 이것이다. "Precision과 Recall 모두 일정 수준 이상이어야 의미 있다"는 철학이 수학적으로 내장되어 있다.

## Python으로 확인하기

```python
import numpy as np
from scipy import stats

# 이상치가 있는 데이터
data = np.concatenate([np.random.normal(2.0, 0.5, 49), [45.0]])

print(f"평균:   {np.mean(data):.2f}")      # ~2.9 (이상치에 끌려감)
print(f"중앙값: {np.median(data):.2f}")     # ~2.0 (안정적)
print(f"왜도:   {stats.skew(data):.2f}")    # 강한 양의 왜도

# 손실함수와 대표값의 관계
from scipy.optimize import minimize_scalar

# MSE를 최소화하는 상수 = 평균
mse_opt = minimize_scalar(lambda c: np.mean((data - c)**2))
# MAE를 최소화하는 상수 = 중앙값
mae_opt = minimize_scalar(lambda c: np.mean(np.abs(data - c)))

print(f"\nMSE 최적 상수: {mse_opt.x:.2f} (≈ 평균)")
print(f"MAE 최적 상수: {mae_opt.x:.2f} (≈ 중앙값)")
```

```python
# F1-score가 조화평균임을 확인
precision, recall = 0.99, 0.01

arithmetic = (precision + recall) / 2
harmonic = 2 * precision * recall / (precision + recall)

print(f"산술평균: {arithmetic:.2f}")   # 0.50 — 허울 좋은 숫자
print(f"조화평균: {harmonic:.2f}")     # 0.02 — 냉정한 현실 (= F1)
```

## 핵심 정리

- **평균은 이상치에 취약하다.** `np.mean()`을 무의식적으로 쓰기 전에, 데이터의 분포 형태를 먼저 확인하라.
- **MSE를 최소화하는 것은 "평균을 예측하겠다"는 선언이다.** MAE는 "중앙값을 예측하겠다"는 선언이다. 손실함수 선택은 대표값의 철학 선택이다.
- **왜도는 평균과 중앙값의 괴리를 측정한다.** 왜도가 크면 로그 변환이나 MAE 전환을 고려하라.
- **F1-score는 Precision과 Recall의 조화평균이다.** "둘 다 높아야 높다"는 철학이 수학에 내장되어 있다.
- **Attention은 가중평균이다.** 기초 통계의 개념이 최신 아키텍처의 핵심에 살아 있다.
