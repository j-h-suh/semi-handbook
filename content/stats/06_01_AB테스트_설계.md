- A/B 테스트가 Part 3의 가설검정 프레임워크 그 자체라는 것

- 조기 종료(peeking)의 위험 — 왜 중간에 결과를 보면 안 되는가
- 실무에서 자주 저지르는 함정 5가지

---

## A/B 테스트 = 가설검정의 실전

A/B 테스트의 구조를 Part 3의 언어로 번역하면:

| A/B 테스트 | Part 3 대응 |
|-----------|-----------|
| 컨트롤(A) vs 실험(B) | 두 그룹 비교 |
| "B가 A보다 나은가?" | 대립가설 $H_1$ |
| "차이가 없다" | 귀무가설 $H_0$ |
| 전환율 차이 | 검정 통계량 |
| p < 0.05면 출시 | 유의수준 α |
| 효과를 놓칠 위험 | 제2종 오류 β |

Part 3에서 배운 모든 개념이 A/B 테스트에 그대로 적용된다. 이 챕터는 "이론을 실전에 쓸 때 주의할 점"에 집중한다.

---

## 사전 샘플 사이즈 계산

A/B 테스트에서 가장 흔한 질문: **"얼마나 오래 돌려야 하나?"**

3.3에서 배운 검정력 분석의 직접적인 응용이다.

필요한 정보 4가지:

1. **기저 전환율** ($p_0$): 현재 A의 전환율. 예: 5%
2. **최소 감지 효과** (MDE, Minimum Detectable Effect): 의미 있는 최소 차이. 예: 0.5%p (5% → 5.5%). MDE는 "이 정도 차이 이하는 비즈니스적으로 의미 없다"는 선으로, 기술적 결정이 아니라 비즈니스 판단이다. 설정 방법: (1) 이전 실험의 평균 효과 크기를 참고하거나, (2) 출시에 필요한 최소 ROI를 전환율 개선으로 역산하거나, (3) 팀의 직관적 "이 정도면 출시할 가치가 있다"는 합의를 잡는다
3. **유의수준** α: 보통 0.05
4. **검정력** $1-\beta$: 보통 0.80

```python
from statsmodels.stats.power import NormalIndPower
import numpy as np

p0 = 0.05           # 기저 전환율 5%
mde = 0.005          # 최소 감지 효과 0.5%p
alpha = 0.05
power = 0.80

# 효과 크기 (Cohen's h for proportions)
h = 2 * (np.arcsin(np.sqrt(p0 + mde)) - np.arcsin(np.sqrt(p0)))

analysis = NormalIndPower()
n_per_group = analysis.solve_power(effect_size=h, alpha=alpha, power=power)
print(f"각 그룹 필요 샘플: {n_per_group:,.0f}")
print(f"총 필요 샘플: {2*n_per_group:,.0f}")

# 일일 트래픽이 10,000이면
daily_traffic = 10000
days = 2 * n_per_group / daily_traffic
print(f"일일 트래픽 {daily_traffic:,}일 때 필요 기간: {days:.0f}일")
```

### MDE를 작게 잡을수록 필요 샘플이 폭증한다

2.5의 $\sqrt{n}$ 법칙. MDE를 절반으로 줄이면 필요 샘플이 4배.

| MDE | 필요 n (각 그룹) | 기간 (1만/일) |
|-----|-----------------|-------------|
| 2%p | ~2,000 | 1일 미만 |
| 1%p | ~8,000 | 2일 |
| 0.5%p | ~31,000 | 6일 |
| 0.1%p | ~780,000 | 156일 |

0.1%p 차이를 잡으려면 5개월이 필요하다. "작은 효과를 확실히 잡으려면 엄청난 비용이 든다"는 것이 A/B 테스트의 현실이다. MDE를 비즈니스 관점에서 현실적으로 잡는 것이 중요하다.

## 조기 종료(Peeking)의 위험

A/B 테스트의 가장 흔하고 가장 위험한 함정.

테스트를 돌리면서 매일 p-value를 확인한다. 3일 차에 p = 0.03이 나왔다. "유의미하다! 출시하자!"

**이것은 3.6에서 배운 다중검정 문제의 시간 축 버전이다.**

매일 p-value를 확인하는 것은 매일 검정을 반복하는 것과 같다. 7일 동안 매일 확인하면 7번 검정. FWER = $1 - 0.95^7 = 30\%$. 진짜 차이가 없어도 30% 확률로 어느 날 p < 0.05를 보게 된다.

```python
import numpy as np
from scipy import stats

# peeking 시뮬레이션: 효과 없는데 유의미하게 보이는 비율
n_sim = 10000
n_days = 14
daily_users = 500  # 하루 각 그룹 500명
p_true = 0.05      # 두 그룹 모두 같은 전환율

false_positive = 0
for _ in range(n_sim):
    a_total, b_total = 0, 0
    a_conv, b_conv = 0, 0
    
    for day in range(n_days):
        a_new = np.random.binomial(daily_users, p_true)
        b_new = np.random.binomial(daily_users, p_true)
        a_total += daily_users; b_total += daily_users
        a_conv += a_new; b_conv += b_new
        
        # 매일 p-value 확인
        p_a, p_b = a_conv/a_total, b_conv/b_total
        p_pool = (a_conv+b_conv)/(a_total+b_total)
        se = np.sqrt(p_pool*(1-p_pool)*(1/a_total+1/b_total))
        if se > 0:
            z = (p_b - p_a) / se
            p_val = 2*(1 - stats.norm.cdf(abs(z)))
            if p_val < 0.05:
                false_positive += 1
                break  # "유의미하다"고 중단

print(f"14일 매일 확인 시 거짓 양성률: {false_positive/n_sim:.1%}")
print(f"(기대 5%인데 실제로는 이보다 높다)")
```

### 대응: 사전에 기간을 정하고 끝까지 돌려라

**고정 기간 설계(Fixed Horizon)**가 가장 간단한 해법. 사전에 필요 샘플을 계산하고, 그 기간이 끝날 때까지 결과를 보지 않는다. 끝나고 한 번만 검정한다.

더 유연한 대안:
- **순차 검정(Sequential Testing)**: 중간에 봐도 되지만, α를 보정한다. O'Brien-Fleming, Pocock 방법.
- **베이지안 A/B 테스트**: 사후확률로 판단. "B가 A보다 나을 확률이 95% 이상이면 종료." 고정 α가 필요 없다.

## 실무 함정 5가지

### 1. 네트워크 효과 무시

소셜 미디어에서 A 그룹 사용자가 B 그룹 사용자에게 영향을 미치면, 두 그룹이 독립이 아니다. 3.4에서 독립성 위반이 가장 위험하다고 했다.

### 2. 다중 지표 동시 평가

전환율, 클릭률, 체류시간, 이탈률을 동시에 보면 3.6의 다중검정 문제. "하나라도 유의미하면 성공"은 거짓 양성을 부풀린다. 주요 지표를 하나 정하고, 나머지는 보조.

### 3. 선택 편향

파워 유저만 실험에 참여하거나, 모바일 유저만 포함하면, 전체 유저로 일반화할 수 없다. 3.1의 "표본이 모집단을 대표하는가?" 문제.

### 4. 참신성 효과 (Novelty Effect)

새로운 UI를 보여주면 초기에 관심이 높아져 전환율이 오르지만, 시간이 지나면 원래로 돌아간다. 업계 경험칙으로, 참신성 효과는 보통 1~2주 내에 감쇠한다. 따라서 테스트 기간은 최소 2~4주를 확보하는 것이 안전하다. 1주 만에 유의미한 결과가 나오더라도, 2주차에 효과가 절반으로 줄어드는 경우가 흔하다.

### 5. 비율이 아닌 지표의 함정

전환율은 이항분포로 깔끔하게 다뤄지지만, 매출이나 체류시간은 분포가 skewed되어 있다 (1.1의 왜도 문제). 이상치 하나가 평균을 크게 흔든다. 이런 지표에는 중앙값 비교, **윈저화(Winsorization)**, 또는 로그 변환이 필요하다. 윈저화란 극단값을 특정 백분위수(예: 상하위 1%)에서 잘라내어 그 백분위수의 값으로 대체하는 방법이다. 이상치를 삭제하지 않고 "눌러주기"만 하므로 표본 크기가 보존된다.

## Python으로 확인하기

```python
import numpy as np
from scipy import stats

# A/B 테스트 전체 워크플로우
np.random.seed(42)

# 1. 사전 계획
p_control = 0.05
mde = 0.005  # 0.5%p
alpha = 0.05

h = 2 * (np.arcsin(np.sqrt(p_control + mde)) - np.arcsin(np.sqrt(p_control)))
from statsmodels.stats.power import NormalIndPower
n_needed = NormalIndPower().solve_power(effect_size=h, alpha=alpha, power=0.80)
print(f"=== 1. 사전 계획 ===")
print(f"필요 샘플: {n_needed:,.0f}/그룹")

# 2. 데이터 수집 (시뮬레이션)
n_per_group = int(n_needed)
a_conversions = np.random.binomial(n_per_group, 0.050)  # 컨트롤: 5.0%
b_conversions = np.random.binomial(n_per_group, 0.055)  # 실험: 5.5% (진짜 효과 있음)

p_a = a_conversions / n_per_group
p_b = b_conversions / n_per_group

# 3. 검정
p_pool = (a_conversions + b_conversions) / (2 * n_per_group)
se = np.sqrt(p_pool * (1-p_pool) * 2/n_per_group)
z = (p_b - p_a) / se
p_value = 2 * (1 - stats.norm.cdf(abs(z)))

# 4. 효과 크기와 CI
diff = p_b - p_a
se_diff = np.sqrt(p_a*(1-p_a)/n_per_group + p_b*(1-p_b)/n_per_group)
ci = (diff - 1.96*se_diff, diff + 1.96*se_diff)

print(f"\n=== 2~4. 결과 ===")
print(f"컨트롤: {p_a:.4f} ({a_conversions}/{n_per_group})")
print(f"실험:   {p_b:.4f} ({b_conversions}/{n_per_group})")
print(f"차이:   {diff:.4f}")
print(f"95% CI: ({ci[0]:.4f}, {ci[1]:.4f})")
print(f"z = {z:.3f}, p = {p_value:.4f}")
print(f"결론: {'출시 추천' if p_value < alpha else '추가 데이터 필요'}")
```

## 핵심 정리

- **A/B 테스트 = 가설검정의 실전.** Part 3의 모든 개념(α, β, 검정력, SE)이 직접 적용된다.
- **사전에 샘플 사이즈를 계산하라.** MDE를 비즈니스 관점에서 정하고, 필요 기간을 계산한 뒤, 끝까지 돌려라.
- **중간에 보지 마라(Peeking).** 매일 확인하면 다중검정 문제. 14일 매일 확인하면 거짓 양성률이 5%를 크게 초과한다.
- **MDE를 절반으로 줄이면 필요 샘플이 4배.** √n 법칙. 비현실적으로 작은 MDE를 잡으면 테스트가 끝나지 않는다.
- **5가지 함정**: 네트워크 효과, 다중 지표, 선택 편향, 참신성 효과, skewed 지표. 실험 설계 단계에서 대비하라.
