## 문제: 적분을 못 풀겠다

5.3에서 완전 베이즈 예측이 이렇다고 했다:

$$P(y \mid x, \text{data}) = \int P(y \mid x, \theta) \cdot P(\theta \mid \text{data}) \, d\theta$$

문제는 이 적분이 대부분의 경우 풀리지 않는다는 것이다. 켤레 사전을 쓰면 닫힌 형태로 풀리지만, 실제 모델에서 켤레가 성립하는 경우는 드물다.

해결책: **적분을 직접 풀지 말고, 사후분포에서 샘플을 뽑아서 근사하자.**

$$\int g(\theta) \cdot P(\theta \mid \text{data}) \, d\theta \approx \frac{1}{N}\sum_{i=1}^{N} g(\theta^{(i)}), \quad \theta^{(i)} \sim P(\theta \mid \text{data})$$

2.6에서 배운 LLN + 몬테카를로. 사후분포에서 $N$개 뽑아서 평균 내면 적분을 근사할 수 있다.

하지만 사후분포에서 직접 뽑을 수 없다면? 이것을 가능하게 하는 것이 **MCMC (Markov Chain Monte Carlo)**다.

---

## MCMC의 핵심 아이디어

MCMC는 사후분포의 **정규화 상수를 모르는 채로** 그 분포에서 샘플을 뽑는 방법이다.

우리가 아는 것: $P(\theta \mid \text{data}) \propto P(\text{data} \mid \theta) \cdot P(\theta)$. 우도 × 사전은 계산할 수 있지만, 분모 $P(\text{data})$를 모른다.

MCMC의 트릭: **비율만 알면 된다.** 두 점 $\theta_a$와 $\theta_b$에서 사후확률의 비율:

$$\frac{P(\theta_b \mid \text{data})}{P(\theta_a \mid \text{data})} = \frac{P(\text{data} \mid \theta_b) \cdot P(\theta_b)}{P(\text{data} \mid \theta_a) \cdot P(\theta_a)}$$

분모 $P(\text{data})$가 상쇄된다! 비율만 계산할 수 있으면 된다.

---

## Metropolis-Hastings: 가장 기본적인 MCMC

알고리즘:

1. 임의의 시작점 $\theta^{(0)}$를 잡는다
2. 현재 위치 $\theta^{(t)}$에서 제안 분포를 통해 후보 $\theta^*$를 생성한다 (예: $\theta^* = \theta^{(t)} + N(0, \sigma^2)$)
3. 수락 확률을 계산한다: $\alpha = \min\left(1, \frac{P(\text{data} \mid \theta^*) P(\theta^*)}{P(\text{data} \mid \theta^{(t)}) P(\theta^{(t)})}\right)$
4. 확률 $\alpha$로 $\theta^{(t+1)} = \theta^*$ (수락), 확률 $1-\alpha$로 $\theta^{(t+1)} = \theta^{(t)}$ (거절)
5. 2~4를 수천~수만 번 반복

직관: **확률이 높은 쪽으로의 이동은 항상 수락, 낮은 쪽으로의 이동은 확률적으로 수락.** 장기적으로 이 체인이 방문하는 빈도가 사후분포에 비례하게 된다.

비유: 안개 속에서 산의 정상을 찾는다. 위로 가는 것은 항상 허용하지만, 아래로 가는 것도 가끔 허용한다 (골짜기에 빠지는 것을 방지). 충분히 오래 돌아다니면, 높은 곳을 더 자주 방문하게 된다.

```python
import numpy as np

def metropolis_hastings(log_posterior, theta_init, n_samples, proposal_sd):
    """간단한 Metropolis-Hastings 구현"""
    theta = theta_init
    samples = [theta]
    accepted = 0
    
    for _ in range(n_samples):
        # 후보 제안
        theta_star = theta + np.random.normal(0, proposal_sd)
        
        # 로그 수락 확률
        log_alpha = log_posterior(theta_star) - log_posterior(theta)
        
        # 수락/거절
        if np.log(np.random.random()) < log_alpha:
            theta = theta_star
            accepted += 1
        
        samples.append(theta)
    
    return np.array(samples), accepted / n_samples

# 예: 동전 문제 — Beta(8,4) 사후분포에서 샘플링
def log_posterior(p):
    if p <= 0 or p >= 1:
        return -np.inf
    return 7 * np.log(p) + 3 * np.log(1-p)  # Beta(8,4)의 로그

samples, accept_rate = metropolis_hastings(log_posterior, 0.5, 10000, 0.1)
burn_in = samples[1000:]  # 처음 1000개는 버림 (burn-in)

print(f"수락률: {accept_rate:.2f}")
print(f"사후 평균: {burn_in.mean():.3f} (이론: {8/12:.3f})")
print(f"사후 95% CI: ({np.percentile(burn_in, 2.5):.3f}, "
      f"{np.percentile(burn_in, 97.5):.3f})")
```

## MCMC의 실무적 고려사항

### Burn-in

체인의 초기 샘플은 시작점에 의존한다. 사후분포에 "수렴"하기 전의 샘플을 버려야 한다. 이 기간을 **burn-in**이라 한다.

### 수락률

제안 분포의 폭(proposal_sd)이 너무 크면 거의 항상 거절(수락률↓), 너무 작으면 느리게 탐색(효율↓). 최적 수락률은 약 **20~50%**로 알려져 있다.

### 자기상관

연속된 샘플이 상관되어 있다. 독립 샘플의 유효 수(effective sample size)는 전체 샘플 수보다 적다. 얇게 뽑기(thinning)로 자기상관을 줄일 수 있다.

## 실무에서 MCMC를 만나는 곳

직접 MCMC를 구현할 일은 거의 없다. 라이브러리가 해준다:

- **PyMC**: Python 베이지안 모델링의 표준. 내부적으로 NUTS (No-U-Turn Sampler, 개선된 MCMC) 사용
- **Stan (PyStan)**: 고성능 MCMC. HMC (Hamiltonian Monte Carlo) 기반
- **NumPyro**: JAX 기반. GPU 가속 MCMC

```python
# PyMC 예시 (개념적)
import pymc as pm

with pm.Model():
    # 사전분포
    mu = pm.Normal('mu', mu=0, sigma=10)
```

### MCMC 없이 베이지안: 변분 추론 (VI)

MCMC가 너무 느릴 때의 대안. 사후분포를 간단한 분포(보통 정규)로 근사한다. 정확도는 떨어지지만 속도가 빠르다.

- PyTorch의 `torch.distributions`와 VI 라이브러리
- VAE (Variational Autoencoder)가 VI의 대표적 응용

| | MCMC | 변분 추론 (VI) |
|--|------|-------------|
| 정확도 | 높음 (수렴하면 정확) | 근사 (분포 가족에 제한) |
| 속도 | 느림 | 빠름 |
| 확장성 | 수만 파라미터까지 | 수백만 파라미터 가능 |
| 대표 도구 | PyMC, Stan | PyTorch, TensorFlow Probability |

## 핵심 정리

- **MCMC는 사후분포에서 정규화 상수 없이 샘플을 뽑는 방법이다.** 비율만 계산할 수 있으면 된다.
- **Metropolis-Hastings**: 높은 쪽으로는 항상, 낮은 쪽으로는 확률적으로 이동. 장기적으로 사후분포에 비례하게 방문.
- **실무에서 직접 구현할 일은 없다.** PyMC, Stan이 해준다. NUTS, HMC가 더 효율적인 현대적 방법.
- **MCMC가 느리면 변분 추론(VI).** 정확도를 희생하고 속도를 얻는다. VAE가 대표적 응용.
- **Part 5의 메시지**: 베이지안을 "쓰지 않더라도" 이해하면, 이미 쓰고 있는 도구(정규화, Dropout)를 더 깊이 이해할 수 있다.
