# 1.3 백분위수와 IQR — 이상치를 다루는 첫 번째 무기

## 이 챕터에서 배우는 것

- 백분위수(Percentile)와 사분위수(Quartile)가 데이터의 "위치"를 말하는 법
- IQR(사분위 범위)이 왜 분산보다 강건한 산포 측도인지
- 1.5×IQR 규칙 — 가장 널리 쓰이는 이상치 탐지법의 원리와 한계
- ML 피처 엔지니어링에서 이상치를 "제거"하면 안 되는 이유

---

## "상위 몇 퍼센트"의 정확한 의미

백분위수는 일상에서도 익숙한 개념이다. 수능 백분위, 아이 성장 백분위, 서버 응답 시간의 p99. "상위 몇 퍼센트에 해당하는가"를 말해주는 숫자다.

정의는 단순하다. **p번째 백분위수(p-th percentile)**는, 데이터를 크기 순으로 정렬했을 때 아래에서부터 p%에 해당하는 값이다.

- 25번째 백분위수 (p25) = **제1사분위수 (Q1)**: 아래에서 25% 지점
- 50번째 백분위수 (p50) = **제2사분위수 (Q2)** = 중앙값
- 75번째 백분위수 (p75) = **제3사분위수 (Q3)**: 아래에서 75% 지점

1.1에서 평균은 "무게중심"이라고 했다. 백분위수는 "줄 세운 위치"다. 평균이 모든 데이터의 값에 영향을 받는 반면, 백분위수는 **순서만 본다.** 45 nm짜리 이상치가 있든 45,000 nm짜리가 있든, Q1과 Q3는 바뀌지 않는다. 이유는 간단하다 — 순서 기반 통계량은 "몇 번째인가"만 보고 "얼마나 큰가"는 무시하기 때문이다. 극단값이 아무리 커져도 그 값의 "등수"는 여전히 마지막이고, 나머지 데이터의 등수에는 영향을 주지 않는다.

ML 엔지니어라면 `df.describe()`의 출력을 매일 보고 있을 것이다.

```
count    1000.000000
mean        3.245000
std         2.891000
min         0.010000
25%         1.230000    ← Q1
50%         2.540000    ← 중앙값
75%         4.180000    ← Q3
max        45.000000
```

이 출력에서 mean과 std만 보고 넘어갔다면, 데이터의 절반을 놓치고 있었던 것이다. 25%, 50%, 75%가 말해주는 이야기를 읽는 법을 알아보자.

---

## IQR: 강건한 "흩어짐"

**IQR(Interquartile Range, 사분위 범위)**은 Q3에서 Q1을 뺀 값이다.

$$\text{IQR} = Q3 - Q1$$

데이터의 "가운데 50%"가 차지하는 범위를 말한다. 아래 25%와 위 25%를 잘라내고, 중앙에 몰려 있는 절반이 얼마나 퍼져 있는지를 재는 것이다.

1.2에서 분산은 "이상치에 민감하다"고 했다. IQR은 정반대다. 양 극단의 25%를 무시하므로, 이상치가 아무리 극단적이어도 IQR은 꿈쩍하지 않는다.

|  | 분산 / 표준편차 | IQR |
|--|----------------|-----|
| 이상치에 | 민감 (비강건) | 강건 |
| 수학적 성질 | 좋음 (미분, 합산 가능) | 제한적 |
| 기반 | 평균으로부터의 거리 | 순서(순위) |
| ML에서 주 용도 | 모델 학습, 이론 | 탐색적 분석, 이상치 탐지 |

둘 중 뭐가 "더 좋은" 측도가 아니다. 목적이 다를 뿐이다. 분산이 모델을 학습시키는 엔진이라면, IQR은 데이터를 진단하는 청진기다.

---

## 1.5×IQR 규칙: 이상치의 경계선

이상치(Outlier)를 정의하는 가장 보편적인 기준이 **1.5×IQR 규칙**이다.

$$\text{Lower Fence} = Q_1 - 1.5 \times \text{IQR}$$
$$\text{Upper Fence} = Q_3 + 1.5 \times \text{IQR}$$

이 범위 밖에 있는 데이터를 이상치로 간주한다.

구체적으로 보자. 아까의 overlay 데이터에서:
- Q1 = 1.5 nm, Q3 = 2.8 nm → IQR = 1.3 nm
- Lower Fence = 1.5 - 1.95 = **-0.45 nm**
- Upper Fence = 2.8 + 1.95 = **4.75 nm**

45 nm짜리는 Upper Fence를 한참 벗어나므로 이상치. 깔끔하다.

![박스플롯 해부도](/content/images/stats/01_03/boxplot_anatomy.svg)

### 왜 하필 1.5인가?

이 숫자는 통계학자 존 튜키(John Tukey)가 박스플롯을 제안하면서 정한 것이다. 정규분포를 가정하면 1.5×IQR 바깥에 해당하는 데이터는 전체의 약 0.7%다. 적당히 드문 값을 "이상치"로 잡는 실용적인 기준이다.

하지만 1.5는 절대적인 규칙이 아니다. 3×IQR을 쓰면 "극단적 이상치"만 잡고, 1.0×IQR을 쓰면 더 공격적으로 잡는다. 도메인에 따라 조절해야 한다. 반도체 공정처럼 데이터가 극도로 정밀한 영역에서는 1.5×IQR도 너무 느슨할 수 있고, 금융 데이터처럼 꼬리가 원래 두꺼운 영역에서는 너무 공격적일 수 있다.

---

## 이상치를 "제거하면 되지"의 함정

여기서 한 가지 중요한 이야기를 해야 한다. 이상치를 탐지하는 방법을 배우면, 자연스럽게 이런 유혹이 온다:

> "이상치 찾았으니까 그냥 삭제하면 되는 거 아니야?"

**위험한 생각이다.**

이상치에는 최소 세 가지 종류가 있다.

**1. 측정 오류 (Measurement Error)**
센서가 오작동해서 생긴 45 nm. 이건 삭제해도 된다. 데이터 자체가 잘못된 것이니까.

**2. 입력 오류 (Data Entry Error)**
단위를 잘못 넣어서 nm 대신 μm로 기록된 값. 이것도 수정하거나 삭제해도 된다.

**3. 진짜 이상치 (True Outlier)**
장비가 실제로 45 nm만큼 틀어진 것. 이건 삭제하면 **안 된다.** 이것이야말로 가장 중요한 데이터다. 이 값을 버리는 것은 "문제를 발견했는데 무시하는 것"이다.

ML에서 이상치를 무조건 삭제하면 벌어지는 일:

- **학습 데이터에서 삭제** → 모델이 극단적 상황을 학습하지 못한다. 프로덕션에서 비슷한 값이 들어오면 엉뚱한 예측을 한다.
- **테스트 데이터에서 삭제** → 성능 지표가 인위적으로 좋아진다. "어려운 문제를 빼고 시험 봤더니 성적이 올랐다"와 같다.
- **타겟 변수의 이상치 삭제** → 소수의 중요한 이벤트(장비 이상, 수율 급락)를 통째로 없애는 것이다.

올바른 접근은 이렇다:

1. **먼저 원인을 파악한다.** 이상치가 왜 생겼는지 모르면 삭제 여부를 판단할 수 없다.
2. **측정/입력 오류면 수정하거나 삭제한다.**
3. **진짜 이상치면 그대로 두되, 모델링 전략을 바꾼다.**
   - 이상치에 강건한 손실함수 (MAE, Huber Loss)
   - 이상치에 강건한 스케일러 (`RobustScaler`)
   - 이상치를 별도 클래스로 다루는 이상 탐지(Anomaly Detection)

---

## RobustScaler: IQR 기반 스케일링

1.2에서 `StandardScaler`가 평균과 표준편차로 정규화한다고 했다. 이상치가 있으면 평균과 표준편차가 왜곡되므로, 스케일링 결과도 왜곡된다.

`RobustScaler`는 이 문제를 IQR로 해결한다.

$$z_i = \frac{x_i - \text{median}}{IQR}$$

평균 대신 **중앙값**을 빼고, 표준편차 대신 **IQR**로 나눈다. 둘 다 이상치에 강건한 통계량이므로, 이상치가 있어도 스케일링이 안정적이다.

```python
from sklearn.preprocessing import StandardScaler, RobustScaler
import numpy as np

# 이상치가 포함된 데이터
X = np.array([1.2, 1.5, 1.8, 2.0, 2.1, 2.3, 2.5, 2.8, 3.0, 45.0]).reshape(-1, 1)

standard = StandardScaler().fit_transform(X)
robust = RobustScaler().fit_transform(X)

print("StandardScaler 결과 (일부):")
print(f"  정상값 2.0 → {standard[3][0]:.2f}")
print(f"  이상치 45.0 → {standard[9][0]:.2f}")

print("\nRobustScaler 결과 (일부):")
print(f"  정상값 2.0 → {robust[3][0]:.2f}")
print(f"  이상치 45.0 → {robust[9][0]:.2f}")
```

<!-- [OUTPUT:
StandardScaler 결과 (일부):
  정상값 2.0 → -0.34
  이상치 45.0 → 3.00

RobustScaler 결과 (일부):
  정상값 2.0 → -0.23
  이상치 45.0 → 48.91
] -->

`StandardScaler`에서는 이상치(45.0)가 겨우 3.00으로 변환된다. 이상치가 평균과 표준편차를 끌어올려서, 스케일링 후에도 "별로 안 극단적인 값"처럼 보인다. 정상값들은 좁은 범위에 뭉개져 버린다.

`RobustScaler`에서는 이상치가 48.91로 변환된다. 중앙값과 IQR이 이상치에 영향을 받지 않으므로, 이상치는 이상치답게, 정상값은 정상값답게 스케일링된다. 각자의 "성격"이 보존되는 것이다.

## 백분위수의 실전 응용: p50, p90, p99

ML 서비스를 운영해 본 적이 있다면, 모니터링 대시보드에서 이런 지표를 봤을 것이다:

```
추론 지연시간 (Inference Latency)
  p50:  12 ms
  p90:  45 ms
  p99: 230 ms
```

왜 평균이 아니라 백분위수를 쓸까?

추론 지연시간은 전형적인 오른쪽 꼬리 분포다. 대부분의 요청은 빠르게 처리되지만, 소수의 요청이 극단적으로 느리다. 이 상황에서 평균은 무의미하다. "평균 지연시간 25 ms" 라고 하면, 50%의 사용자는 12 ms만에 응답을 받고, 1%의 사용자는 230 ms를 기다린다는 사실이 가려진다.

백분위수별로 보면 서비스의 실체가 드러난다:

- **p50 (중앙값)**: "보통의 사용자" 경험. 절반은 이보다 빠르고 절반은 느리다.
- **p90**: "대부분의 사용자" 경험. 10명 중 9명은 이 시간 안에 응답을 받는다.
- **p99**: "최악의 경우". 100명 중 1명이 겪는 지연. SLA(서비스 수준 협약)에서 가장 중요한 숫자.

이 패턴은 추론 지연만이 아니라 ML 관련 많은 곳에 적용된다:

- 학습 시 배치당 처리 시간의 p99 → 병목 배치 식별
- 예측 오차의 p95 → "대부분의 예측이 이 오차 안에 들어온다"
- 피처 분포의 p01, p99 → 클리핑(clipping) 경계 설정에 활용

## Quantile Regression: 백분위수를 직접 예측하기

보통의 회귀 모델은 조건부 **평균** $E[Y|X]$을 예측한다. 하지만 때로는 "평균적인 예측"이 아니라, "최악의 경우 어디까지 갈 수 있는가"가 더 중요할 때가 있다.

**분위 회귀(Quantile Regression)**는 조건부 **백분위수**를 예측한다. 예를 들어 p90 회귀는 "주어진 X에서 Y가 90% 확률로 이 값 이하일 것"을 예측한다.

손실함수가 다를 뿐이다. 일반 회귀의 MSE 대신, **핀볼 손실(Pinball Loss)**을 쓴다:

$$L_\tau(y, \hat{y}) = \begin{cases} \tau \cdot (y - \hat{y}) & \text{if } y \geq \hat{y} \\ (1-\tau) \cdot (\hat{y} - y) & \text{if } y < \hat{y} \end{cases}$$

$\tau = 0.5$면 중앙값 회귀(= MAE)가 되고, $\tau = 0.9$면 p90 회귀가 된다.

LightGBM에서는 이렇게 쓴다:

```python
import lightgbm as lgb

# p90 예측 모델
model = lgb.LGBMRegressor(
    objective='quantile',
    alpha=0.9  # tau = 0.9 → p90 예측
)
model.fit(X_train, y_train)
y_p90 = model.predict(X_test)  # "90%는 이 값 이하"
```

이것이 유용한 상황은 많다. 수율 예측에서 "평균 수율"도 중요하지만, "하위 10% 시나리오"가 얼마나 나쁜지를 아는 것이 리스크 관리에는 더 중요할 수 있다. 재고 관리에서도 "평균 수요"보다 "수요의 p95"에 맞춰 재고를 쌓아야 품절을 막을 수 있다.

## Python으로 확인하기

```python
import numpy as np

# 이상치가 포함된 데이터
data = np.concatenate([np.random.normal(2.0, 0.5, 99), [45.0]])

# 사분위수와 IQR
q1, q3 = np.percentile(data, [25, 75])
iqr = q3 - q1

lower_fence = q1 - 1.5 * iqr
upper_fence = q3 + 1.5 * iqr

outliers = data[(data < lower_fence) | (data > upper_fence)]

print(f"Q1: {q1:.2f}, Q3: {q3:.2f}, IQR: {iqr:.2f}")
print(f"Fence: [{lower_fence:.2f}, {upper_fence:.2f}]")
print(f"이상치 {len(outliers)}개: {outliers}")

# 산포 측도 비교: 분산 vs IQR
print(f"\n=== 이상치의 영향 ===")
print(f"표준편차: {data.std():.2f}")   # 이상치에 끌려감
print(f"IQR:      {iqr:.2f}")          # 안정적

# 이상치 제거 후 표준편차
clean = data[(data >= lower_fence) & (data <= upper_fence)]
print(f"이상치 제거 후 표준편차: {clean.std():.2f}")
print(f"IQR은 동일: {np.subtract(*np.percentile(clean, [75, 25])):.2f}")
```

## 핵심 정리

- **백분위수는 "순서 기반" 요약이다.** 값의 크기가 아니라 위치를 말해주므로, 이상치에 강건하다.
- **IQR = Q3 - Q1.** 데이터의 가운데 50%가 차지하는 범위. 강건한 산포 측도.
- **1.5×IQR 규칙**은 가장 보편적인 이상치 탐지 기준이지만, 도메인에 따라 조절이 필요하다.
- **이상치를 무조건 삭제하지 마라.** 원인을 먼저 파악하고, 진짜 이상치면 모델링 전략으로 대응하라. `RobustScaler`, MAE, Huber Loss가 무기다.
- **p50, p90, p99**는 평균보다 서비스의 실체를 정확히 보여준다. 분위 회귀로 직접 예측할 수도 있다.
